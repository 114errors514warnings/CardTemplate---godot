# 状态系统

状态（State）是战斗中附着在单位身上的标记，每个状态有自己的 `StateType` 编号、衰减规则、是否可叠层、是否属于弱化/高等效果。

## 一、State 生命周期

```
附加（AddOrUpdateState）
  │
  ▼
驻留（Stacks > 0）
  │  ── 回合开始 / 回合结束 ──> 衰减 N 层（按 DecayTiming）
  │
  ▼
移除（RemoveState）── 触发状态结束回调（StateEndedContext）
  │
  ▼
回收（StatePile → 所属角色弃牌堆，仅 State 牌有此阶段）
```

### 1.1 衰减规则（双维度：DecayTiming × DecayMode）

P0 #8 起，每个状态有**两个独立字段** + 一个**辅助字段**共同决定其衰减行为：

| 字段 | 决定什么 | CSV 列 | 取值 |
|------|----------|--------|------|
| `DecayTiming` | **什么时候**触发衰减 | 第 6 列 | `Never` / `OnTurnStart` / `OnTurnEnd` / `OnAttackPlayed` / `OnDamaged` |
| `DecayMode` | **按什么规则**移除 stacks | 第 7 列 | `None` / `Flat` / `Half` / `ClearAll` |
| `StacksToRemove` | `Flat` 模式每次移除几层 | 第 8 列 | `>= 0` 整数（仅 `Flat` 模式有效）|

> **历史**：P0 #7 之前用 `IsPermanent=true` + `int TurnStartDecayAmount` 两个字段；P0 #8 起合并为 `DecayTiming=Never`（替代 `IsPermanent`）+ `DecayMode=Flat + StacksToRemove`（替代 `TurnStartDecayAmount`）。

#### 1.1.1 `DecayTiming` 五个时机

- **`Never`**：永久状态——任何时机都不衰减（**替代 P0 #7 之前的 `IsPermanent=true`**）
- **`OnTurnStart`**：任意回合开始时（玩家回合开始 + 怪物回合开始都触发）
- **`OnTurnEnd`**：任意回合结束时（玩家回合结束 + 怪物回合结束都触发）
- **`OnAttackPlayed`**：打出**攻击牌**后（玩家出攻击牌 + 怪物执行攻击意图都触发）
- **`OnDamaged`**：受到伤害后（HP 实际减少时触发，0 伤害不触发）

#### 1.1.2 `DecayMode` 四种模式

- **`None`**：不衰减（与 `DecayTiming=Never` 配合表示永久——**只配一个即可**，推荐 `DecayTiming=Never, DecayMode=None, StacksToRemove=0`）
- **`Flat`**：按 `StacksToRemove` 层数衰减（每次触发 -N 层；常用于 "每回合 -1" 这类叠层衰减）
- **`Half`**：衰减一半（向上取整，例如 3 层 → 减 2 层剩 1；2 层 → 减 1 层剩 1）
- **`ClearAll`**：全部清除（一次性移除所有 stacks，触发 `StateEndReason.Expired` 回调）

#### 1.1.3 跳过条件（命中任一条就跳过该状态）

- `DecayTiming == Never`（永久）
- `DecayMode == None`（不衰减）
- `DecayTiming` 与调点的 `DecayTrigger` 不匹配（见 §1.1.5 调点表）

衰减到 0 层后自动从 `unit.States` 移除并触发 end callback（`StateEndReason.Expired`）。

#### 1.1.4 衰减处理入口（4 个调点）

| 调点 | 调用入口 | 触发位置 |
|------|----------|----------|
| `OnTurnStart` | `StateSystem.OnTurnStart(unit)`（给资源/护盾/cap）**→** `StateDecayProcessor.ProcessDecayAtTiming(unit, OnTurnStart)` | 玩家回合开始（`BattleSytem.StartPlayerTurn`）+ 怪物循环每只开始（`StartMonsterTurn`） |
| `OnTurnEnd` | `StateDecayProcessor.ProcessDecayAtTiming(unit, OnTurnEnd)` | 玩家回合结束（`EndPlayerTurn` 末尾）+ 怪物循环末尾（`StartMonsterTurn` 末尾） |
| `OnAttackPlayed` | `StateDecayProcessor.ProcessDecayAtTiming(source, OnAttackPlayed)` | 玩家出攻击牌（`CardPlayController.PlayHandCard` 末尾，`card.Category == Attack`）+ 怪物执行攻击意图（`BattleSytem.ExecuteMonsterIntention` 末尾）|
| `OnDamaged` | `StateDecayProcessor.ProcessDecayAtTiming(target, OnDamaged)` | `EffectSystem.ApplyAttack` 实际扣血时（`hpDamage > 0`） |

**调点顺序原则**：
- `OnTurnStart` 调点：先 `OnTurnStart`（状态机制效果给资源/护盾）**后** `ProcessDecayAtTiming`（按 `ClearAll` 移除）—— 保证"给资源在先，移除在后"
- 其他调点：直接调 `ProcessDecayAtTiming`

#### 1.1.5 调点执行流程（伪代码）

```csharp
// 玩家回合开始（BattleSytem.StartPlayerTurn）
foreach (player in alivePlayers)
{
    StateSystem.OnTurnStart(player);              // 1) 给资源 / 护盾 / cap
    StateDecayProcessor.ProcessDecayAtTiming(player, DecayTrigger.OnTurnStart);  // 2) 按 DecayMode 移除
}

// 玩家回合结束（EndPlayerTurn 末尾）
foreach (player in alivePlayers)
{
    StateDecayProcessor.ProcessDecayAtTiming(player, DecayTrigger.OnTurnEnd);
}

// 怪物循环（StartMonsterTurn）—— 依次对每只存活怪物
foreach (monster in aliveMonsters)
{
    StateSystem.OnTurnStart(monster);
    StateDecayProcessor.ProcessDecayAtTiming(monster, DecayTrigger.OnTurnStart);
    /* 怪物意图结算（含攻击时） */
    if (monsterAttack) StateDecayProcessor.ProcessDecayAtTiming(monster, DecayTrigger.OnAttackPlayed);
    StateDecayProcessor.ProcessDecayAtTiming(monster, DecayTrigger.OnTurnEnd);  // 末尾
}

// 玩家出攻击牌（CardPlayController.PlayHandCard 末尾）
if (card.Category == CardCategory.Attack)
{
    StateDecayProcessor.ProcessDecayAtTiming(source, DecayTrigger.OnAttackPlayed);
}

// 玩家/怪物受伤害（EffectSystem.ApplyAttack hpDamage > 0 时）
StateDecayProcessor.ProcessDecayAtTiming(target, DecayTrigger.OnDamaged);
```

#### 1.1.6 枚举关系

`StateDecayTiming`（状态定义属性，5 值含 `Never`）与 `DecayTrigger`（调点，4 值不含 `Never`）**保持独立枚举**——

- `Never` 是状态定义属性（"我不衰减"），**不是**调点（不存在"从不被触发"调点）
- 通过 `StateDecayProcessor.ShouldDecayAtTiming(timing, trigger)` 映射函数按同名时匹配（见 `Scripts/System/StateDecayProcessor.cs:133`）

```csharp
// 枚举定义
public enum StateDecayTiming { Never=0, OnTurnStart=1, OnTurnEnd=2, OnAttackPlayed=3, OnDamaged=4 }
public enum DecayTrigger     { OnTurnStart=0, OnTurnEnd=1, OnAttackPlayed=2, OnDamaged=3 }
```

#### 1.1.7 公开 API 兼容

P0 #8 重构后保留 2 个公开 API 以兼容调用方：

- `StateSystem.IsPermanent(type)` 内部改为 `def.DecayTiming == StateDecayTiming.Never` 判定
- `StateSystem.GetTurnStartDecayAmount(type)` 内部改为 `def.DecayTiming == Never ? 0 : def.StacksToRemove`（永久状态返回 0，否则返回 `StacksToRemove`）

### 1.2 回调机制

- 状态被移除时（任何原因：衰减、ClearState、ClearAllStates），若存在 end callback，调用 `unit.OnStateEnded` 通知。
- 用于实现"状态结束时把 State 牌从状态牌堆移回弃牌堆"。

### 1.3 State 牌回收

- 状态牌打出后进入**目标状态牌堆**（`unit.StatePile`），不进入弃牌堆。
- 状态结束（衰减到 0）时若有注册回调，状态牌自动移回**所属角色**的弃牌堆。
- 同一张状态牌当前不支持同时进入多个不同单位的状态牌堆。

### 1.4 状态无"倒计时"概念

状态系统只有"叠层、衰减、特定情况移除"三种生命周期，**不暴露"剩N回合"等倒计时文本**。chip 显示仅 `name + (stacks>1 ? "x" + stacks : "")`，不显示"剩N回合"。

## 二、IsDebuff × IsElite 四象限分类

每个状态有**两个布尔字段**共同决定其分类：

| | `IsElite=false` | `IsElite=true` |
|---|---|---|
| **`IsDebuff=false`** | **普通强化** | **高等强化** |
| **`IsDebuff=true`** | **普通弱化** | **高等弱化** |

### 2.1 字段语义

- **`IsDebuff`**：该状态对持有者是否产生负面效果。
  - `true` = 是弱化（如易伤、虚弱、点燃、虚无、护盾上限 cap 等负面限制）
  - `false` = 是强化或中性（如反击、增攻、护盾增益）
- **`IsElite`**：是否是"高等/精英"效果。
  - `true` = 高等（更稀有、更强力、不被"清除普通弱化"清掉）
  - `false` = 普通（可被"清除普通弱化"清掉）

- **高等弱化** 1 个：Void（**目前**只有 1 个，对应"驱散"等"清普通弱化"卡不会动它）

## 三、运行时 API（StateSystem 静态方法）

```csharp
// 字段查询（按 StateType 取 StateDefinition）
StateSystem.IsStackable(type)             // 能否叠层
StateSystem.IsPermanent(type)             // 是否永久（true = 永久）
StateSystem.IsDebuff(type)                // 是否弱化
StateSystem.IsElite(type)                 // 是否高等
StateSystem.IsNormalDebuff(type)          // ★ 是否普通弱化（IsDebuff && !IsElite）

// 状态操作
StateSystem.AddOrUpdateState(unit, type, stacks, ...)
StateSystem.RemoveState(unit, type)
StateSystem.RemoveStateStacks(unit, type, stacks)
StateSystem.TryRemoveFirstNormalDebuff(unit, out removed)
StateSystem.TryRemoveFirstNormalDebuffs(unit, count, out removedList)

// 生命周期
StateSystem.OnTurnStart(unit)              // 回合开始时统一处理衰减
```

### 3.1 IsNormalDebuff 定义

```csharp
public static bool IsNormalDebuff(StateType type)
{
    StateDefinition definition = GetStateDefinition(type);
    return definition != null && definition.IsDebuff && !definition.IsElite;
}
```

8月文档 2.5 节要求的"普通弱化 = `IsDebuff && !IsElite`"语义。**用于 `ClearFirstNormalDebuff` 筛选**。

## 四、ClearFirstNormalDebuff 行为

调用链：

```
Card.ApplyClearFirstNormalDebuffEffect
  └─ StateSystem.TryRemoveFirstNormalDebuffs(target, count, out removed)
       └─ 遍历状态，跳过 !IsNormalDebuff(type)
            └─ RemoveState
```

按 `EffectType.ClearFirstNormalDebuff` 的参数 `[1] count`（默认 1）清除目标状态栏中**前 count 个**满足 `IsNormalDebuff` 的状态。

**实际筛选效果**（基于当前 CSV）：

| 状态 | 被清除？ |
|------|----------|
| Vulnerable / Weak / Ignite / HpLossPerCardPlayed / BattleCardBlocked / DrawLock | ✅ |
| Void（高等弱化）| ❌ |
| 任何强化（CounterAttack / AddAttack / CourageArmor / 阵地 / 城墙 / 蓄势待发 等）| ❌ |

重剑手「奋力一击」`11002002,ClearFirstNormalDebuff|Damage,1;1|2;4` 就是这条链路——攻击前先清自身一个普通弱化，再造成 +4 伤害。

## 五、未来设计扩展（4 象限用途）

| 场景 | 行为 | 消费哪些象限 |
|------|------|---------------|
| 「驱散」「净化」类卡 | 清所有 debuff | 普通弱化 + 高等弱化 |
| 「清流」「冷静」类卡 | 只清普通弱化 | 仅普通弱化 |
| 「专注」「冷静」类卡 | 移除自身所有负面 | 普通弱化 + 高等弱化（强化保留）|
| 「专注强化」「深谋远虑」类卡 | 清自身所有弱化效果 | 同上 |
| 「高等抵抗」「豁免」类卡 | 完全免疫高等弱化 | 仅高等弱化（`IsElite=true`） |

只要状态字段落地到运行时，4 象限自然支持以上设计，**无需修改核心代码**。
