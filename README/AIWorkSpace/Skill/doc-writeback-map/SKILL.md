# 文档回写地图

> 功能 / 配置落地后，**哪些文档必须跟着改**。归属与写法的权威源是 [文档编写规则.md](../../AgentOps/文档编写规则.md)，这里给的是可执行清单。

## 一、落地后要回写的地方

| # | 位置 | 写什么 |
|---|---|---|
| 1 | 当月施工文档 `README/施工文档/<年>/<年.月>/<月>施工文档.md` | **新增 `## §N`**（N = 当月已有最大编号 +1）：实现了什么 + 验证方式与结论 + 遗留 |
| 2 | 案 / 待做清单文件自身 | 顶部「完成情况（日期）」：已实现 / 部分实现 / 未实现逐条列，指向 §N |
| 3 | 功能 / 交互说明文档（`功能说明文档/**`、`交互说明文档/**`） | **只写已实现**；未实现的就地标注 `**未实现（遗留）**：…` 并指向施工文档 |
| 4 | 玩法规则（`玩法说明文档/**`） | 规则口径变化时同步（数值口径冲突以平衡文档为准） |
| 5 | 新增 / 改动调试指令 | [调试API.md](../../../功能说明文档/AI接口/调试API.md)、[AI接口 README](../../../功能说明文档/AI接口/README.md)、[跑测使用说明](../../../功能说明文档/AI接口/跑测使用说明.md)（配方 + 脚手架） |
| 6 | 待做清单（如 `代码需求清单.md`） | 对应条目标状态、补落地接口行 |
| 7 | `README/施工文档/README.md` | 在办案索引该行标注（如「已迁出」） |

- **不要估时**、不要写「本文档记录…」这类自言自语，见 [文档编写规则 §一、§二](../../AgentOps/文档编写规则.md)。

## 二、案 与 说明文档的边界

| 类型 | 判断 | 位置 |
|---|---|---|
| 执行案 / 需求案 / 待做清单 | 描述「要做什么、做到哪一步」 | `README/施工文档/<年>/<年.月>/<玩法\|交互\|战斗>/`（跨类放月份根目录） |
| 功能 / 交互 / 玩法说明 | 描述「现在是什么」，**只写已实现** | `README/功能说明文档/`、`README/交互说明文档/`、`README/玩法说明文档/` |
| 过程记录 | 生成 / 讨论 / 调查过程 | `README/施工文档/<年>/<年.月>/<分类>/` |

**已实现的案随实现迁出**（`git mv` 到说明文档 + 去掉文件名里的「案」+ 正文改说明语气），详见 [文档编写规则 §9.1](../../AgentOps/文档编写规则.md)。
反向要求：**只有已实现的案才迁**；未实现的设计案与待做清单留在施工文档。

## 三、新增文档：先看位置与命名

- AI 协作**规范** → `README/AIWorkSpace/AgentOps/<规范名>.md`；AI **操作流程 skill** → `README/AIWorkSpace/Skill/<skill-name>/SKILL.md`（目录名与 frontmatter 的 `name` 同名、小写连字符；`description` 写「何时用 + 关键词」；入口固定 `SKILL.md`，索引 [Skill/README.md](../README.md)）；`AIWorkSpace/` **不放**任何具体执行案。
- 命名跟 [命名规范.md](../../AgentOps/命名规范.md)（运行时系统用 `XX系统`、索引固定 `README.md`、旧文件改 `.md.archived` 不删）。
- 索引文件：任何含子目录的目录都要有 `README.md`，新增文档要登记进去。

## 四、链接与索引（新增 / 搬迁必做）

1. **相对链接深度**：目录深一层，`../` 多一个；`git mv` 搬迁后全库改引用（历史施工文档只改链接目标、保留当时的案名标签）。
2. **跑链接体检**：见 [改动收尾体检](../change-final-check/SKILL.md) §三（含已知误报基线）。
3. **同步索引**：源目录与被指向目录的 `README.md` 都要更新。
4. **行尾**：与原文保持一致，不要用批量替换「顺手统一」。

## 五、完成情况写两处

| 位置 | 内容 |
|---|---|
| 案文件自身 | 顶部 `## 完成情况（日期）`：逐条 + 指向当月施工文档 § |
| 当月施工文档 | 新增 `## §N`：同一份实现情况 + 验证方式与结论 |

待做清单类文件用「已实现（日期）/ 待做」两个分区表达状态，同样算完成情况。**执行案是方案文本**：不要为了反映现状去改执行案正文，现状写在完成情况 + 当月施工文档里。

## 六、引用别用编号

写文档 / 回应时引用必须有**三要素**：文件:行号 + 一句话梗概 + 状态（已查证 / 实施中 / 待批 / 已完成）。不要写 `#1 #2`，见 [问题分析与解决规范 §十三](../../AgentOps/问题分析与解决规范.md)。
