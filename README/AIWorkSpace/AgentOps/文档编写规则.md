# 文档编写规则

> AI Agent 维护本项目（卡牌模拟器 / Godot 4.6 + C#）时的**文档编写规范**。本规范适用于 `README/施工文档/` 下所有月度 / 周度施工文档，以及 `README/系统规则/` 下系统说明文档。
> **示例样板**见 [示例/8月施工文档.md](示例/8月施工文档.md)。

---

## 一、严格记录，不要"自言自语"

文档是用来**严格记录开发流程**的，不是给 AI 表达"我做了什么 / 我怎么想"的载体。

### ❌ 不要写

- "本文档记录当前项目..."（自我介绍）
- "本部分内容是 XXX 基线，回答'为什么要做'"（解释这一节是干嘛的）
- "这部分回答'做了什么'——BattleSystem 的更迭 + 5 张新卡的接入"（解释这一节是干嘛的）
- "以下为原文保留"（迁移说明是脚注，不是正文）
- "文档元信息：创建 / 重整 / 维护 / 上一版"（元叙述）
- 任何"这段回答什么 / 这是干嘛的 / 我加的"等元评论

### ✅ 写

- 章节标题（一级 / 二级 / 三级）
- 表格 / 代码块 / 命令 / 文件路径
- 决策记录（"已决策：xxx"）
- 改动清单（"方案 A 改了什么"）
- 测试结果（"X/Y 全绿"）
- 关键修复根因 + 修复（"问题 → 根因 → 修复"）

## 二、禁止估时

不要写"X 天 / Y 周"这类主观工作量估算。

### ❌ 不要写

- "预期工作量：3~5 天"
- "总周期预估：2~3 周"
- "建议 1~2 个迭代内完成"
- "持续 1~2 周"

### ✅ 写

- 实际产出数字（"~500 行"、"10 测例"、"-38%"、"~2900 行"）
- 期望产出的代码体量（"单文件 100KB 降到 20~30KB 级别"）
- 收益分析（"每次修改只在对应文件定位"）

> 区别：估时是"我估计要多久"（主观、不准）；实际产出 / 目标是"做到了什么"（客观、已发生）。

## 三、按 3 大部分组织施工文档

施工文档（`README/施工文档/<年>/<年.月>/<月>施工文档.md`）的**推荐结构**：

```
# §1 <月> 之前需求       — 项目现状、关键问题、改善方案、决策依据
# §2 执行的修改         — BattleSystem 更迭 + 新增卡牌 + 文件清单
# §3 测试方法           — 编译 / 测试命令、覆盖现状、关键修复
# §4 后续建议（可选）   — 引用扩展方向文档
```

### §1 8月之前需求
- 1.1 项目类型 / 1.2 场景 / 1.3 模块 / 1.4 已实现功能
- 1.5 关键问题清单（代码规模 / 待施工事项 / 未实现卡 / 内容缺口 / 文档同步）
- 1.6 改善方案（P0 / P1 / P2）
- 1.7 推荐优先组合
- 1.8 待决策项（标注"已决策"标记）

### §2 执行的修改
- 2.1 BattleSystem 更迭（方案 A + B + csproj 修复）
- 2.2 新增卡牌（按"机制 / CSV / 改动"3 段式记每张卡）
- 2.3 改动文件总清单（表格）

### §3 测试方法
- 3.1 测试前置条件
- 3.2 编译命令
- 3.3 测试命令
- 3.4 测试覆盖现状
- 3.5 关键修复（如 CS0579 重复 attribute）
- 3.6 不能单测的原因（每张卡一行表）

### §4 后续建议（可选）
- 引用 `README/施工文档/<月>/` 下的扩展方向文档

## 四、严格按需求文档实施，不超出范围

施工时**只做**当前需求文档里列出的项，**不要**基于"完整游戏应该有什么"自行扩展。

### ❌ 不要做

- 8月文档只说"主菜单→关卡→战斗→战利品"，不要**自己加**商店 / 休息 / 事件 / 章节 / 存档 / 升级 / 遗物 / 难度 / 多角色
- 5.17 需求设计调整只说要"加 IsDebuff / IsElite"，不要**自己加** `ChipColor` / `EffectDescription` / `DurationTextTemplate` 等设计文档没说的字段
- 用户明确说"不新增第二/第三个角色卡牌"，不要**自己加**法师 / 精灵

### ✅ 做法

- 自己想加的功能 → 写到 `扩展方向/XXX打磨说明.md`（明确标"我自创 / 8月文档未提"）
- 让用户**显式批准**后，再加到主流程

## 五、卡牌记录格式

每张新卡用**统一 3 段式**：

```
### X.Y <卡名>（<类别> <CardId>，CSV <状态>）

- **机制**：<核心效果>
- **CSV 现状/新增**：`<CardId>,<Name>,...`
- **改动**：<具体文件 + 行号 + 关键代码点>
```

例：

```
### 2.2.2 城墙（State 卡 31002007，CSV 新增）

- **机制**：拥有护盾时，敌人单体攻击仅会以你为目标（多人时随机选一个）；**要求持有者 Shield > 0**
- **CSV 新增**：`31002007,城墙,State,1,AddState,1;15;1,`
- **改动**：`MonsterIntentionService.ResolveRandomAlivePlayerTarget` 优先筛 `ForcedTaunt && Shield > 0` 的玩家
```
