# 命名规范

> 来源：2026-08-29 用户在 `README/系统规则` 重构时显式建立的项目级命名偏好。
> 同时存在于 Agent user memory（跨会话保留）。

## 一、文件命名

| 类别 | 后缀 | 示例 |
|------|------|------|
| **运行时游戏系统** | `XX系统` | `状态系统.md` / `Effect系统.md` / `关键词系统.md` / `目标系统.md` / `回合系统.md` / `能量系统.md` |
| 工程规范 | `规则` | `开发记录规则.md` / `命名规范.md` |
| UI 使用 | `指南` | `战斗使用指南.md` |
| 设计 / 思路 | `思路` / `设计` | `总体卡牌设计.md` |
| 实体 / 标识 | 直接命名（无后缀）| `UniqueInGameId.md` |
| 卡牌分类对比 | `分类` / 描述式 | `State牌与Skill施加State.md` |
| 总览索引 | `README.md` | `README.md`（固定）|

**核心原则**：

- "**运行时游戏系统**" 类**必须**用 `XX系统` 作为文件后缀
- 其他类允许用 `规则` / `指南` / `说明` / `思路` / `分类` 等
- **不在文件名里放"系统"** 的运行时系统类文档（`战斗循环.md` / `目标规则.md` / `能量与费用.md` 等）需要按"系统"格式补齐
- 索引文件固定用 `README.md`（不是 `INDEX.md` / `总览.md`）

## 二、子目录命名

子目录按**主题归类**，不用 "XX系统" 格式（除非子目录本身是"系统集合"）：

| 主题 | 目录 |
|------|------|
| 战斗 / 状态 / Effect / 关键词 | `战斗系统/` |
| 卡牌 / CSV / 设计 | `卡牌与配置/` |
| 实体 / 标识 / ID | `实体与标识/` |
| 工程 / 规范 | `工程规范/` |
| UI / 操作 | `UI使用/` |
| AI 协作 | `AIWorkSpace/AgentOps/`（规范）、`AIWorkSpace/AgentOps/美术/`（美术）、`AIWorkSpace/Skill/<skill-name>/SKILL.md`（操作 skill，目录名与 frontmatter `name` 同名） |

## 三、旧文件处理

**不删**。硬安全策略拦了 `Remove-Item`（PowerShell delete 命令被拦截；`mavis-trash` 也受限）。改用以下流程：

1. **`Rename-Item` 改名** — 原文件加 `.archived.md` 后缀：

   ```powershell
   Rename-Item "战斗规则.md" "战斗规则.md.archived"
   ```

2. **写入迁移说明** — 用 `write` 覆盖 `.archived` 文件，**顶部**加 ⚠️ 块：

   ```markdown
   > ⚠️ **本文档已迁移（YYYY-MM-DD）**。内容已拆分为 [新位置](新位置.md)。
   > 详见 [README.md 总览](README.md) 附录 A。下方为原文保留。
   ```

3. **不删 .archived** — 保留历史追溯路径，避免外部引用断链

## 四、README.md 总览索引

每个含子目录的目录**必须有** `README.md`：

- 列出所有子文档
- **附录 A**（旧文件迁移表）：旧文件 → 新位置映射
- 索引格式参考 `README/玩法说明文档/系统规则/README.md`

## 七、实体标识与显示名（怪物 `Id` / `Name`）

> 2026-10-02 由 F1-008 / F1-009 的「学徒 / 教授**同名不同号**」需求反推出来的口径。
> 出处与完整证据：[核心区法师怪设计 §1.1](../../玩法说明文档/怪物设计/核心区法师怪设计.md)。

- **`Id` 是唯一键，`Name` 是显示字符串**：`Monster.csv` 的 `id` 决定一切 —— `LoadingSystem.MonsterDictionary` 是 `Dictionary<int, Monster>`；`EnemyIntent.csv` 按 `(MonsterId, IntentionIndex)`、`Balance/MonsterValue.csv` 按 `MonsterId`、关卡 CSV 按怪物 id 引用；`Name` 只被 HUD 直接显示（`UnitInstanceView.BuildUnitTitle`）。
- **允许不同型号同名**：不同型号（外观 / 职能不同）可以用同一个 `Name`，靠 **`Id` + 外观**区分；文档里写的"型号代号"（如 主讲 / 督学 / 蚀刻 / 束缚）**只存在于文档，不写进 CSV**。
- **代价（必须记住）**：同名时**玩家侧没有任何文字提示**，所以**型号差异必须由外观承担**；而外观的**实现方式是配置侧的活**（用户 2026-10-02 口径：**后续在 CSV 里配置不同的美术资源** —— 现状 `Monster.csv` / `Character.csv` **都没有美术列**）→ 设计侧只写"同名必须外观可区分"，**不要求美术出规格**。并且**排障、查表、配表一律引用 `Id`**，不要用名字定位。
- **现状**：`Monster.csv`（**33 行** = 表头 + 32 个模板）的 `id` 与 `Name` 目前都是零重复，且 `3127 / 3128 / 3129` 尚未写入；加载器**不校验重复**（既不报错也不告警）—— 同名可用，但"同一 id 写两次"这类真错误也不会被拦，属已知留白（见[核心区法师怪设计 §8.4](../../玩法说明文档/怪物设计/核心区法师怪设计.md)）。
- **英文名**：Godot 的 CSV 翻译按单元格内容建 key（`Monster.en.translation` 目前为空）；同名行会共享同一条翻译 —— 将来要给型号单独英文名时需要另加一列，或由代码拼后缀。
