# 命名规范

> 来源：2026-08-29 用户在 `README/系统规则` 重构时显式建立的项目级命名偏好。
> 同时存在于 Agent user memory（跨会话保留）。

## 一、文件命名

| 类别 | 后缀 | 示例 |
|------|------|------|
| **运行时游戏系统** | `XX系统` | `状态系统.md` / `Effect系统.md` / `关键词系统.md` / `目标系统.md` / `回合系统.md` / `能量系统.md` |
| 工程规范 | `规则` | `开发记录规则.md` / `命名规范.md` |
| UI 使用 | `指南` | `战斗使用指南.md` |
| 设计 / 思路 | `思路` / `设计` | `总体卡牌设计.md` |
| 实体 / 标识 | 直接命名（无后缀）| `UniqueInGameId.md` |
| 卡牌分类对比 | `分类` / 描述式 | `State牌与Skill施加State.md` |
| 总览索引 | `README.md` | `README.md`（固定）|

**核心原则**：

- "**运行时游戏系统**" 类**必须**用 `XX系统` 作为文件后缀
- 其他类允许用 `规则` / `指南` / `说明` / `思路` / `分类` 等
- **不在文件名里放"系统"** 的运行时系统类文档（`战斗循环.md` / `目标规则.md` / `能量与费用.md` 等）需要按"系统"格式补齐
- 索引文件固定用 `README.md`（不是 `INDEX.md` / `总览.md`）

## 二、子目录命名

|------|------|
| 战斗 / 状态 / Effect / 关键词 | `战斗系统/` |
| 卡牌 / CSV / 设计 | `卡牌与配置/` |
| 实体 / 标识 / ID | `实体与标识/` |

| UI / 操作 | `UI使用/` |
| AI 协作 | `AIWorkSpace/AgentOps/` / `AIWorkSpace/美术/` |

## 三、旧文件处理

**不删**。硬安全策略拦了 `Remove-Item`（PowerShell delete 命令被拦截；`mavis-trash` 也受限）。改用以下流程：

1. **`Rename-Item` 改名** — 原文件加 `.archived.md` 后缀：

   ```powershell
   Rename-Item "战斗规则.md" "战斗规则.md.archived"
   ```

2. **写入迁移说明** — 用 `write` 覆盖 `.archived` 文件，**顶部**加 ⚠️ 块：

   ```markdown
   > ⚠️ **本文档已迁移（YYYY-MM-DD）**。内容已拆分为 [新位置](新位置.md)。
   > 详见 [README.md 总览](README.md) 附录 A。下方为原文保留。
   ```

3. **不删 .archived** — 保留历史追溯路径，避免外部引用断链

## 四、README.md 总览索引

每个含子目录的目录**必须有** `README.md`：

- 列出所有子文档
- **附录 A**（旧文件迁移表）：旧文件 → 新位置映射
- 索引格式参考 `README/系统规则/README.md`
