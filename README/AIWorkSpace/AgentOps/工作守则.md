# 工作守则

> AI Agent 维护本项目（卡牌模拟器 / Godot 4.6 + C#）时**必须**遵守的工程边界与踩坑总结。

---

## 一、PowerShell 不是 Bash

环境是 **Windows PowerShell**（不是 WSL / Git Bash）。`bash` 工具实际调用 `powershell.exe` 执行。

### 禁用 / 替换

| ❌ Bash 写法 | ✅ PowerShell 替换 |
|-------------|------------------|
| `&&` | `;` |
| `\|\|` | `if ($x) { ... }` |
| `ls -la` | `Get-ChildItem` |
| `head` / `tail` | `Select-Object -First N` / `-Last N` |
| `grep` | `Select-String` |
| `wc -l` | `(Get-Content ...).Count` |
| `cat` | `Get-Content` |
| `sed -i` | `(Get-Content) -replace ... \| Set-Content`（注意 UTF-8 编码） |
| `find` | `Get-ChildItem -Recurse -Filter` |
| `\"` 转义 | PowerShell 字符串规则：单引号 literal / 双引号插值 |

### 多语句脚本开头

```powershell
$ErrorActionPreference = 'Stop'
```

正则 / 搜索模式用**单引号**包裹（避免 `$` / `(` 等被 PowerShell 解释为变量或子表达式）。

### 输出乱码 / WSL 输出

- 如果 `bash` 工具返回乱码或 WSL 输出，**立即切换**到 `node` / `python`，最多 2 次重试后换工具
- 不要硬扛 3 次 PowerShell bash 调用

### 批量文本替换：用 `edit`，脚本只做只读统计

- ❌ **不要**用「哈希表 + 嵌套数组」循环替换：

  ```powershell
  $plan = @{ 'a.md' = @(@('x','y')) }              # 单元素数组会被展平成字符串
  foreach ($pair in $plan['a.md']) { $t.Replace($pair[0], $pair[1]) }   # $pair[0] 取到的是「首字符」
  ```

  后果：实际执行的是**字符级**替换——2026-09-21 这样把 5 个 `.md` 里所有的 `]` 换成了 `(`（`](x)` → `((x)`），只有靠 diff 抽查才发现。
- ✅ 必须用脚本时改**扁平函数、一对一行调用**：

  ```powershell
  function Rep([string]$f,[string]$from,[string]$to){ $t=[IO.File]::ReadAllText($f); if(-not $t.Contains($from)){ '未命中: '+$f; return }; [IO.File]::WriteAllText($f,$t.Replace($from,$to),(New-Object System.Text.UTF8Encoding($false))) }
  Rep 'a.md' '旧文本' '新文本'
  ```

- ✅ 改内容优先用 `edit`（精确匹配、命中失败会报错，不会静默乱改）；脚本只用于读文件、检索、校验（链接体检、行数统计）。

### 改文件前先建可回滚点

- 批量改动前跑 `git status --short`：只有**干净（= HEAD 状态）**的文件才适合脚本处理，出事可 `git checkout -- <file>` 一键还原；未跟踪的新文件先留副本。
- 改完必须 `git diff --numstat` 抽查：改动行数与预期同量级（若出现几十行噪声 = 静默污染，**整体回滚重做，不要就地修补**）。
- 收尾用**可执行体检**代替"看起来没问题"：链接可解析性、行数/行尾统计、编译与测试命令。

### 控制台编码与超长命令

- 读中文输出前先设 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`，否则 `dotnet test` 等输出乱码、`Select-String` 过滤失效。
- 单条命令过长会被截断/拼接（曾出现 `逻辑cd: 无法将...识别为 cmdlet`）→ 拆成多条短命令，不要用 `;` 串成 2000+ 字符的一行。

### 行尾（CRLF / LF）

- 仓库 `.md` 混用 CRLF / LF；`edit` 的**多行** `old_text` 在 CRLF 文件上可能匹配失败 → 优先用**单行** `old_text`，或用行号 `insert_line` 插入。
- 不要用脚本拼大段正文（容易同时踩行尾 + 编码两个坑）；`edit` 写入时会沿用目标文件既有行尾。

## 二、硬安全策略（不能做的操作）

### 完全拦截

| 操作 | 替代 |
|------|------|
| `Remove-Item`（删文件 / 删目录）| `Rename-Item` 改 `.archived.md` 后缀 + 顶部加 ⚠️ 块 |
| `mavis-trash` 不可用 | 同上 |
| Bash 的 `rm -rf` / `rm -f` | 同上 |
| 直接 `del` / `erase` | 同上 |

**例外**：临时文件（`.bak` / `.tmp` / `.log` / `.cache`）可以用 `Move-Item` 移到 `_tmp/` 或 `Rename-Item` 加 `.discard` 后缀。

### 保留 / 不动

| 路径 | 原因 |
|------|------|
| `.godot/` | Godot 编辑器自动生成，删了 IDE 重新生成会污染主项目构建 |
| `.godot/mono/temp/` | Godot SDK 中间产物，不能动 |
| `obj/` | dotnet build 中间产物，dotnet clean 会自己清 |
| `bin/` | dotnet build 输出，自己覆盖 |

## 三、Godot / C# 工程边界

### 3.1 Card / Character 等 Godot.Resource 派生类

`Card` 继承 `Godot.Resource` → **纯 .NET xUnit 单测无法 `new Card()`**，会触发 `AccessViolationException`（Godot Native interop 在无引擎运行时崩溃）。

**处理**：

- 单测覆盖**纯逻辑部分**（如 `Card.GetCurrentEnergyCost` 的工厂/override 注册）
- 集成测试需 Godot scene 框架（GodotTestRunner / GdUnit4）
- 不要试图在测试项目里引用 `GodotSharp.dll` 来 `new Card()`，跑测试会崩

### 3.2 多人战斗 / Scene 状态

`CardBattleScene.cs` / `BattleSytem.cs` 等依赖 Godot Scene 树，单测无法覆盖。

### 3.3 CSV 配置语义

- CSV 修改后必须**重启 Godot 编辑器**才能生效（运行时缓存）
- CSV 文件名变更需要同步 `FilePathRegistry.csv` 或保证路径扫描能找到（`LoadingSystem.LoadAllCardsFromFolder` 递归扫描 `DataBase/Card/`，新角色 CSV 放进去自动加载）
- CSV 头里字段名改了，需要同步改 `LoadCardCsv.cs` / `LoadStateCsv.cs` 等解析器

### 3.4 `CallDeferred` 自旋必须有重试上限

- "等内容提供子节点后再接管 UI"这类用 `CallDeferred(nameof(X))` 自我重排的等待逻辑，**必须设重试上限**：无限自旋会在退出游戏时留下挂起的 deferred 调用，落到正在拆除的实例上 → Godot 原生崩溃（`0xC0000005` 访问违例）。
- 换内容 / 退出前先**断开对旧节点的引用**（如 `activeBattle = null`），避免常驻按钮打到已释放节点。
- GUI 输入类烟测的环境要求（必须有显示窗口、鼠标同帧注入）见 [Godot运行环境.md](../Godot运行环境.md)。

### 3.5 UI 层级：只认 `CanvasLayer.Layer`，层号查 `RunUiLayers`

- `CanvasLayer.Layer` 是**视口级全局排序**，同一 CanvasLayer 内部的 `ZIndex` 只在层内生效 → 想把某个 UI 提到"压过所有层"，必须新建更高层的 `CanvasLayer`，不是调 `ZIndex`。
- 运行局层号统一登记在 `Scripts/Run/RunUiLayers.cs`：内容 10 / 世界地图 30 / 模态 40 / 常驻按钮 50 / 暂停 60。新增跨子树 UI 先在那里加常量，不要在场景里写魔法数字。
- 需要在 `GetTree().Paused = true` 期间可点的面板，其节点（含祖先）要设 `ProcessMode = Always`，否则"继续"之类按钮收不到输入。

### 3.6 烟测进程：只结束自己启动的那个进程（2026-09-22）

- **禁止** `Get-Process -Name 'Godot*' | Stop-Process`（或任何按名字批量结束 Godot 的写法）：用户的**编辑器/运行中的项目**同样是 `Godot_v4.6.2-stable_mono_win64*.exe`，会被一起杀掉。2026-09-22 已因此误关过用户的测试窗口。
- 正确做法：烟测用 `Start-Process -PassThru` 拿到**自己那一个** PID，等待其自我退出（烟测末尾应自己 `GetTree().Quit()`）；确实需要强杀时只 `Stop-Process -Id <该 PID>`。
- 图形版烟测若长时间不退出，先看日志判断是卡在渲染还是卡在断言，**不要**用按名字批量结束的办法"清理"。
- 运行窗口用 `--position 3000,3000` 挪到屏幕外，避免打断用户操作。

## 四、csproj 边界

### 4.1 主项目 (`卡牌模拟器.csproj`)

```xml
<PropertyGroup>
  <GenerateAssemblyInfo>false</GenerateAssemblyInfo>
</PropertyGroup>
<ItemGroup>
  <Compile Remove="Tests\**\*.cs" />
  <Compile Remove="卡牌模拟器.Tests\**\*.cs" />
</ItemGroup>
```

**为什么**：

- `<GenerateAssemblyInfo>false</GenerateAssemblyInfo>` — 解决 `Godot.NET.Sdk/4.6.2` 在 `.godot/mono/temp/obj/Debug/卡牌模拟器.AssemblyInfo.cs` 重复生成导致的 **CS0579 重复 attribute** 错误
- `<Compile Remove>` — 防止测试项目文件被主项目吸收（`Tests/BattleStatsTrackerTests.cs` 不能编译进主项目 dll）

### 4.2 测试项目 (`Tests/卡牌模拟器.Tests.csproj`)

```xml
<Reference Include="卡牌模拟器">
  <HintPath>..\.godot\mono\temp\bin\Debug\卡牌模拟器.dll</HintPath>
  <Private>true</Private>
</Reference>
```

**为什么用 `<Reference>` 不用 `<ProjectReference>`**：

- `<ProjectReference>` 会触发主项目重编
- Godot.NET.Sdk 中间产物（`.godot/mono/temp/`）与测试项目 SDK 冲突
- `<Reference>` 引用**已构建好的 dll**，不重编主项目

**测试运行前的必要步骤**：

```powershell
# 1. 写占位避免 Godot SDK 重复生成 AssemblyInfo 冲突
Set-Content ".godot\mono\temp\obj\Debug\卡牌模拟器.AssemblyInfo.cs" "// 占位"

# 2. 构建主项目
dotnet build 卡牌模拟器.csproj

# 3. 跑测试
dotnet test Tests\卡牌模拟器.Tests.csproj

# 4. 测试会重新生成 AssemblyInfo，再写占位避免下次 build 出错
Set-Content ".godot\mono\temp\obj\Debug\卡牌模拟器.AssemblyInfo.cs" "// 占位"
```

### 4.3 编译 / 测试命令

```powershell
# 编译主项目
dotnet build 卡牌模拟器.csproj -c Debug

# 跑测试
dotnet test Tests\卡牌模拟器.Tests.csproj -c Debug
```

如果遇到 `error CS0579: "X" 特性重复` → 99% 是 `.godot/mono/temp/obj/Debug/卡牌模拟器.AssemblyInfo.cs` 重新生成了 attribute 副本，**写占位覆盖**即可（不要用 `Move-Item` 删——硬安全策略拦）。

## 五、文件编辑规范

### 5.1 .tscn 场景文件

- 编辑前用 `read` 读最新内容，**不要凭记忆 edit**（read tool 限制了字节数时按 offset/limit 滚动读）
- 修改节点名 / 引用 / 字段用 `edit`（old_string 精确匹配）
- 关键改动后**重启 Godot 编辑器**再编译

### 5.2 CSV 头修改

- 头字段名改了必须同步 `LoadXxxCsv.cs` 解析器
- 加新列后 `StateDefinition` / `Card` 字段也要加
- 用 `Select-String` 验证所有 `field[N]` 引用都更新

### 5.3 跨文件依赖

- 改 `Scripts/System/BattleSytem.cs` / `StateSystem.cs` / `EffectSystem.cs` / `Card.cs` 之一，必须 grep 看其他文件是否引用该方法
- 新加枚举值要同时改枚举定义 + 解析器（`Enum.Parse`）+ CSV 文档

## 九、敏感信息处理

### 9.1 禁止在对话 / 输出中暴露

**绝对禁止**在以下场景中明文显示任何敏感凭证：

- 对话响应（包括摘要 / 表格 / "这是 XXX 开头..." 任何形式）
- 工具调用参数（除非用户明确要求明文传递）
- 日志 / 文档字符串 / Markdown
- Memory 写入（user memory / agent memory）
- Git 提交 / 注释
- 复述"前 N 位"或"后 N 位" — **整段都不能回显**

**敏感凭证清单**：

- API Key / API Token（Notion / OpenAI / Claude / 任何第三方）
- 数据库连接字符串（含密码）
- OAuth 客户端密钥 / Refresh Token
- 私钥（.pem / .key / SSH）
- Cookie / Session Token
- 用户密码 / 邮箱密码
- 加密密钥 / 盐
- 任何标记为 `secret:` / `private:` / `token:` 的环境变量值

### 9.2 文件位置约定

凭证放在 `README/AIWorkSpace/APIKey/` 下，文件名按服务名：

- `NotionAPIKey.md` — Notion 集成 Token
- 未来其他服务同理（`OpenAIAPIKey.md` / `GitHubToken.md` / `DBConnectionString.md` 等）

**只放凭证本身**（一行），不混入玩法 / 业务说明。**业务 / 玩法内容**放 `README/AIWorkSpace/` 下的对应主题目录（如 `AgentOps/` / `美术/`），**不要**和 API Key 混在同一文件。

### 9.3 读取流程

当用户问"读 API Key 文件"时：

1. 用 `read` 工具读出文件内容
2. **不**在响应中复述 Key 字符串
3. **不**在工具调用参数中带 Key 字符串
4. **如**文件只含 Key（无业务内容）→ 直接告知用户"文件只含 Key，请提供业务内容位置"
5. **如**文件含 Key + 业务内容 → 只复述业务部分，**省略** Key 行

### 9.4 使用 Key 调外部 API

当任务需要**使用** API Key（如拉 Notion 页面、查数据库）：

1. **不要**在响应里 show Key
2. 使用 Key 时优先用 `read` 工具读取文件后传入工具调用参数（**不**通过对话明文）
3. 如果是 mcp__notion__* 这类 MCP 工具，Key 应该已经配在 MCP server 配置里，**不需要**从文件读
4. **不要**把 Key 硬编码到任何脚本 / 代码 / 测试用例里

### 9.5 误暴露补救

如果发现 Key 在响应中暴露：

1. **立即**告诉用户"我刚才不小心暴露了 Key，建议立即在 Notion 后台 revoke 这个 token 并新建"
2. 让用户决定是否继续（不要默默掩盖）
3. 在该 key 文件旁加 `README/AIWorkSpace/APIKey/<name>.REVOKED.md` 标记已废弃
