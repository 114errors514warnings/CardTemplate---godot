## 1.4 已实现功能（8月之前基线）

### 战斗系统

- 玩家回合 / 怪物回合交替循环
- 多角色战斗：最多 3 名玩家同时参战，共享行动窗口，可自由切换操控
- 回合开始：状态结算 → 护盾清零 → 抽牌 → 能量重置
- 回合结束：弃置非保留手牌
- 怪物回合：逐只异步执行意图，结束 0.5s 后进入下一只
- 胜负判定：所有怪物死亡 = 胜利；所有玩家死亡 = 失败
- 怪物意图系统：含随机单目标 / 共享随机目标两种多段模式

### 牌堆体系

- 抽牌堆 / 弃牌堆 / 消耗牌堆 三套独立牌堆
- 抽牌堆为空时自动将弃牌堆洗回
- 状态牌独立牌堆机制：状态牌进入目标 `StatePile`，状态结束回收时根据关键词决定去 `DiscardPile` 或 `ExhaustPile`

### 效果系统（EffectType）

`None / Damage / Shield / AddState / ClearState / Heal / DrawCard / AddCost / ClearAllStates / ClearFirstNormalDebuff / ShieldSlam / UpgradeBattleCard / UpgradePermanentCard / DamageByBattleLostHp / AddKeyword / MirrorShieldToAllies` — 共 16 个效果类型。

### 状态系统（StateType）

`Vulnerable / Weak / Ignite / CounterAttack / WhirlwindSlash / AddAttack / ExtraEnergy(已废弃) / Void / CourageArmor / TurnStartEffect / GainAttackOnHpLoss / CounterAttackWhenAttacking / ShieldGuard / ShieldCapEqualsHP / ForcedTaunt / RetainAllBattleCards / HpLossPerCardPlayed / BattleCardBlocked / DrawLock / NextBattleCardFree` — 共 20 个状态类型。

### 关键词体系（CardKeyWord）

`None / Retain / Exhaust / InfiniteUpgrade / Crit` + 运行时关键词生命周期 `KeywordFlag`（RemoveAfterActivate / RemoveAtTurnEnd）。

### 升级系统

- 最小闭环已实现：战斗内升级 + 永久升级
- 卡牌目标选择挂起流程：手牌定向 / 手牌随机 / 默认卡组随机
- 无限升级伤害公式：`基础额外伤害 * 1.2^总级数`，向下取整
- 卡牌 `PermanentUpgradeLevel / BattleUpgradeLevel / TotalUpgradeLevel` 三级记录

### 卡牌配置

- 重剑手 CSV：`DataBase/Card/重剑手Card.csv` 共 27 张
- 通用 CSV：`DataBase/Card/通用/通用Card.csv`
- 状态配置：`DataBase/State/通用State.csv`（含 `IsDebuff / IsElite` 等扩展字段）

## 3.5 关键修复：CS0579 重复 attribute

**问题**：第一次 `dotnet build` 报 7 个 CS0579 错误——

```
error CS0579: "System.Reflection.AssemblyCompanyAttribute" 特性重复
error CS0579: "System.Reflection.AssemblyConfigurationAttribute" 特性重复
error CS0579: "System.Reflection.AssemblyFileVersionAttribute" 特性重复
error CS0579: "System.Reflection.AssemblyInformationalVersionAttribute" 特性重复
error CS0579: "System.Reflection.AssemblyProductAttribute" 特性重复
error CS0579: "System.Reflection.AssemblyTitleAttribute" 特性重复
error CS0579: "System.Reflection.AssemblyVersionAttribute" 特性重复
```

**根因**：`Godot.NET.Sdk 4.6.2` 通过 Implicit ItemGroup 把 `.godot/mono/temp/obj/Debug/卡牌模拟器.AssemblyInfo.cs` 引入 **2 次**（SDK 自动生成 + 默认 Compile ItemGroup），导致同一程序集内 attribute 出现 2 份。

**修复**：`卡牌模拟器.csproj` 加

```xml
<PropertyGroup>
  <GenerateAssemblyInfo>false</GenerateAssemblyInfo>
</PropertyGroup>
```

**为什么这样修**：

- 项目本身**没有** `Properties/AssemblyInfo.cs`（已 grep 确认），所以关闭 SDK 自动生成不会丢失 attribute
- `<Compile Remove=".godot\mono\temp\obj\**\*.cs" />` **不生效**（`Compile Remove` 在 Implicit ItemGroup 之后跑）
- `<Target Name="RemoveDefaultAssemblyInfo" />` 自定义 Target 会破坏其他 Godot SDK 行为
- `<GenerateAssemblyInfo>false</GenerateAssemblyInfo>` 是最干净的解，由 Godot SDK 文档推荐的方案

## 3.6 为什么 5 张新卡不能纯 .NET 单测

| 卡 | 限制 |
|----|------|
| 阵地 | `BattleSytem` 依赖 Godot Scene 树 |
| 城墙 | `MonsterIntentionService` 依赖 `BattleSytem`（单例）+ `RandomGenerator` |
| 到我身后 | `Card.ApplyRearrangeMonsterTargetsEffect` 依赖 `BattleSytem.Current.Monsters` |
| 死亡之舞 | `Card.GetCurrentEnergyCost` **可单测**（已写 `SwordmasterCardCostTests.cs` 测过工厂注册 + override 优先级），但真实计费需 `BattleStatsTracker.GetBattleHpLossEventCount`（需要 `CharacterInstance`） |
| 蓄势待发 | `EffectSystem.TryTriggerRetainAllBattleCardsCounter` 依赖 `BattleSytem.Current.PlayHandCard` |

**根本原因**：`Card` 继承 `Godot.Resource`，纯 .NET `new Card()` 会触发 `AccessViolationException`（Godot Native interop 在无引擎运行时崩溃）。5 张卡的集成验证需 **Godot scene 测试框架**（如 GodotTestRunner / GdUnit4 / 自建 `_Ready` mock）。
