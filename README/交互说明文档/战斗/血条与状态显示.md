## 一、显示对象

| 对象 | 血条 | 说明 |
|---|---|---|
| 玩家角色 | 显示 | `BattlefieldRole.Player`；参与选中、移动预览与目标选择 |
| 敌方单位 | 显示 | `BattlefieldRole.Enemy`；含爪牙、精英与带逃跑意图的单位 |
| 保护目标 | 显示 | `BattlefieldRole.Protected`；按同一规则显示，不单独设计样式 |
| 已离场单位 | 不显示 | `Presence != Active`（死亡、逃跑离场）时血条随单位一起消失，格点上不留残条 |

血条**常驻**显示，不依赖悬停或选中：玩家应当在不打开额外窗口的情况下读出双方生命与护盾（[六边形战场交互](六边形战场交互.md) §一）。格点悬停详情继续给出精确数值（当前/最大、护盾、攻击、防御），血条不替代详情。

## 二、形态

**单条 + 一段滞后 + 左端护盾徽标**。血条只表达生命，护盾不占条宽：

```text
     ╭──╮
     │7 │  ← 护盾徽标：银色纯色盾形，数值写在徽标内（宽度与护盾值无关）
  ┌──┴──┴──────────────────────┐
  │ 生命填充                   │  ← 宽 = Clamp(Hp / Max_HP, 0, 1)
  └────────────────────────────┘
     滞后条                      ← 受击时由旧值滑到新值，绘制在生命填充之下
```

| 元素 | 取值 | 默认颜色 | 何时出现 |
|---|---|---|---|
| 底条 | — | `#141c24`（与战场底色 `#151f28` 区分） | 常驻 |
| 生命填充 | `Clamp(Hp / Max_HP, 0, 1)` | 玩家 `#6ee59c`、敌人 `#e0574f` | 常驻 |
| 滞后条 | 受击前值 → 当前值 | `#ffffff`（半透明） | **生命**受到伤害后，时长 = `AttackPresentationSeconds`（`BattlefieldView.cs:20`，当前 0.55s），**自冲击帧起算** |
| 生命数值文本 | `当前/上限`（**玩家与怪物同格式**，如 `12/40`） | 字形**纯黑 `#000000`** + 细描边 `#e8f2f5`（描边宽 = `max(1, scale)`） | 常驻（随底条一起） |
| 护盾徽标 | 徽标内数值 = `Shield` | 填充 `#c7d0d8`（银）、描边 `#5f6f7d`、数字 `#16202a` | `Shield > 0` |

- **护盾不参与比例**：徽标是固定尺寸图标，宽度不随 `Shield / Max_HP` 变化；`Shield > 已损失生命`、`Shield > Max_HP` 都不再有专门分支 —— 这正是废除"护盾段"的原因（段宽在护盾大于血量时既读不出数值，又和生命填充叠在同一段宽度上）。
- 结算口径不变（先扣护盾再扣生命），表现在血条上就是：**护盾吸收时生命填充与滞后条完全不动**，只有徽标内数字变小；徽标数值归零 → 整枚徽标消失，血条位置不跳动。护盾增加同理：只有徽标数字变大，条不动。
- 治疗、最大生命变化、护盾增减**直接跳变**，不留滞后条 —— 滞后条只表达"被打掉的量"，且**只由生命伤害产生**（被护盾全额吸收的攻击不产生滞后条）。
- `Max_HP ≤ 0` 时不绘制血条，也不绘制徽标（异常数据不画出反向条）。
- 徽标压住条左端约 9%（§三）；生命数值文本始终完整，不被徽标遮挡。

## 三、尺寸与位置

单位绘制以格心为原点、单位圆半径 16、圆心在 `(0, -7)`（`BattlefieldView.cs:407`）。血条插在单位圆与状态缩略行之间，状态行下移一档：

| 元素 | 当前 y 偏移 | 本文取值 | 出处 |
|---|---:|---:|---|
| 敌方意图图标 | -66 | 不变 | `BattlefieldView.cs:419-423` |
| 敌方意图文本 | -46 | 不变 | `:413` |
| 单位名 | -27 | 不变 | `:408` |
| 单位圆（圆心 / 半径） | -7 / 16 | 不变 | `:407` |
| **血条** | 无 | **+16 ~ +24（高 8）** | 新增 `:586-609` |
| **护盾徽标** | 无 | **宽 11 × 高 12；垂直居中于血条；右缘压住条左端 4** | 新增 `:612-628` |
| 生命数值 | +15（`HP n`） | 移到血条内居中（基线 = 条底 − `1 × scale`）；**2026-10-01 起玩家与怪物同为 `当前/上限`** | `DrawUnitHealthBar` |
| 状态缩略（**图标行顶边**） | +42（文本基线） | **+48**（图标 15×15 + 间距 2，横排居中） | `:452` → `DrawUnitStateIcons` |

- 血条宽 = `CellRadius × 1.10`；当前 `CellRadius = 42`（`BattleMapDefinition.cs:52`），即宽 ≈ 46，以格心水平居中，不参与格边框（`r = 42`）的绘制。
- 缩放：`scale = CellRadius / 42`（常量 `BaseCellRadius`，`BattlefieldView.cs:36`），血条、徽标与单位圆同步缩放；地图 JSON 允许 16–120（`BattleMapDefinition.cs:95`），避免小格上溢出到邻格。
- 徽标几何（`scale = 1`）：中心在格心 `(-24, +20)`，盾形占 x ∈ [-29.5, -18.5]、y ∈ [+14, +26]，全部落在六边形边界内（正六边形左右竖边在 ±36.4，`|y| > 21` 后按斜边收窄）；随 `CellRadius` 等比缩放时不越界。
- 缩放到 `scale < 0.70`（即 `CellRadius < 30`）时徽标**只画盾形、不写数字**（数值仍可在格点悬停详情读到），避免小格上数字糊出图标。
- 徽标与单位圆（下沿 +9）、状态缩略行（+48）互不重叠。
- 绘制顺序：单位与血条在格点层之上；拖拽预览（黄色候选 / 红色弹道 / 移动路径）、敌方意图预览格与攻击表现在 `_Draw()` 中**晚于**单位循环绘制（`:428-431`），预览不被血条遮断。

## 四、文本

| 项 | 默认文案 | 出现条件 |
|---|---|---|
| 生命 | **`当前/上限`（玩家与怪物同格式）** | 常驻（2026-10-01 用户口径：怪物也公开上限，见 §七 第 1 条） |
| 护盾 | 徽标内 `N`（纯数字） | `Shield > 0` 且 `scale ≥ 0.70` |

- 生命文本画在血条内、以条中线为视觉中心：基线 = 条底 − `1 × scale`，字号 = `Max(8, Round(11 × scale))`；条高 8 小于字号，文本允许略微压出条外（§二 的"优先保留数字"）。
- 生命文本**颜色固定为纯黑**（不取单位圆配色）：先用 `#e8f2f5` 在上下左右各偏移 `max(1, scale)` px 铺一遍，再把纯黑字压在上面（`CenterTextOutlined`）。**只有纯黑、不铺描边**会在两种取值下读不出：血条被消耗后数字右半跨在 `#141c24` 底条上、受击滞后条（半透明白）正压在数字下时。
- 文本永远以**整个条宽**居中（不跟着填充走），因此 `当前/上限` 在低血量时从左到右跨「填充 + 底条」两段底色 —— 这正是需要描边的原因，也保证数字位置不随血量跳动。
- 护盾数字写在盾形内：基线 = 徽标中心 + `0.3 × 徽标高`，字号 = `Clamp(Round(10 × scale) − (位数 ≥ 3 ? 1 : 0), 7, 10)`，颜色 `#16202a`（银底深字）。
- 六边形战场**不再使用** `▦N` 符号（旧战斗 `UnitInstanceView.cs:66` 保留不动）：护盾值由盾形与盾内数字共同表达，`▦` 在 11×12 的盾形里放不下。
- 护盾数值由 `presentationStats` 提供，与生命文本同源；表现播放期间两者都停在受击前取值。
- 若玩法要求隐藏敌人生命上限，只删上限文案不够 —— 血条按上限比例这件事本身会暴露上限，见 §七 第 1 条。

## 五、与其它表现的关系

- **敌方意图**：位置不变（单位上方）；意图预览格（`DrawKnownEnemyIntentPreview`，:342）与血条互不影响。
- **攻击表现**：血条不参与位移与形变（突进、扇形/环形摆动、击退）。表现期间血条跟随 `visualUnitPositions` 的单位中心（:296），右键拖图时随单位一起平移（与 :239 的坐标平移口径一致）。
- **状态缩略图标**：只下移位置（§三）并改图标形态（方底 + 首字 + 层数，资源优先 / 代码绘制兜底，见 9 月施工文档 §48.1）；图标数量上限 `Take(3)`、悬停详情与格点详情规则不变。
- **护盾类状态与玩法护盾**：徽标只表达单位自身 `Shield` 这一个数值，与"护盾"状态、城墙、阵地等玩法对象无关 —— 那些仍走状态缩略行与格点详情，不合并进徽标。
- **战后操作态**（[战后战场操作交互](战后战场操作交互.md)、代码需求清单 P2-13）：血条继续显示，角色生命在战后仍可读；战后移动与拾取不改变血条行为。
- **按快照重建的战场**（P2-13 收尾）：血条取还原后的 `Hp`，**不重放**受击滞后条 —— 重建是"落档态"而不是"新受击"。
- **关卡类型**：生存关、保护目标关与歼灭关血条口径完全一致，不做分支。
- **悬停详情**：数值必须与血条同源（同一 `presentationStats` 延迟源），不允许出现"血条已扣、详情未扣"。

## 八、验收

1. 出牌造成伤害后，滞后条与生命文本**同帧**开始变化（同在冲击帧）：生命文本与填充跳到当前值，滞后条从**受击前值**开始滑，`AttackPresentationSeconds` 内收敛到当前值 —— 表现结束（0.55s）后滞后条**继续走完**，不冻结在中间、不残留；不出现"数字先跳、血条后跳"。
2. 护盾吸收一次攻击时，**生命填充与滞后条完全不动**，只有徽标内数值下降；徽标归零后整枚消失，条与其它元素位置不跳动。
3. `Shield > 已损失生命` 与 `Shield > Max_HP` 两种取值下，血条宽度与生命填充比例**与该护盾值无关**（与"这场战斗没有护盾"时的血条逐像素一致）—— 废除"护盾段"要守的就是这条。
4. 治疗、最大生命变化、护盾直接增减**直接跳变**，不产生滞后条（纯护盾吸收的攻击也不产生滞后条）。
5. 单位被击败或逃跑离场后血条与徽标立即消失，格点上无残条。
6. 格点悬停详情的生命 / 护盾与血条、徽标数值严格一致（含攻击表现播放期间）。
7. 徽标不遮住生命数值文本，压条宽度 ≤ 条宽 10%；`CellRadius = 16` 与 `= 120` 两端下血条与徽标不溢到邻格、不盖住状态缩略；名字与敌方意图文本位置不被挤动。
8. 战后操作态与按快照重建的战场上血条按当前 `Hp` 显示，且不重放受击变化。
9. `dotnet build 卡牌模拟器.csproj` + `dotnet test Tests\卡牌模拟器.Tests.csproj`（当前 **262 例**）与无界面 `--battlefield-smoke` 不回归（血条属表现层，不新增**单测**；文本口径由烟测 `BATTLEFIELD_HEALTH_TEXT_PASS` 断言，像素级样例走 `--battlefield-health-capture` 出图 `Tests/battlefield-health-bars.png` 人工看）。
10. 血条内生命数值**玩家与怪物同为 `当前/上限`**（如 `12/40`，含满血与 0 血），字形填充为**纯黑 `#000000`** —— 文本仍取单位圆配色（青色 / 粉色）即判不合格；数字不随血量改变横向位置（始终按整条宽居中）。
