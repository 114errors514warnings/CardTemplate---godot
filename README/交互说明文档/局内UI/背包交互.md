# 背包交互

> 规定运行局内**队伍共享背包**的入口、界面结构、拖动规则与**负荷**口径。物品分类与来源以[装备、材料、道具系统](../../玩法说明文档/系统规则/物品系统/装备、材料、道具系统.md)与[食物系统](../../玩法说明文档/系统规则/物品系统/食物系统.md)为准；战斗内随身道具与手位的槽位口径以[六边形战场玩法](../../玩法说明文档/系统规则/战斗系统/六边形战场玩法.md) §五 / §6.1 为准。

## 一、定位与入口

- 背包是**队伍共享**的：本局是单一钱袋模型（`Gold` 与 `StolenGoldFromMonsters` 都不归属角色），不做每角色独立背包。
- 入口（**2026-10-02 用户口径改判**）：运行局常驻顶部按钮栏（`RunUiLayers.GlobalButton = 50`）**时间点行**新增 `背包` 按钮，排在**时间点文案的右边**、「结束当天」之前（`RunFlowScene.BuildGlobalTopBar` 的 `AddTopButton`）。原口径「通用行排在 `地图` 之后」作废；`RunUiLayout` 的右组容量仍按「现有 4 + 预留 2」保留（`装备` 尚未落，容量断言不动）。
- 层级：界面挂 `RunUiLayers.Modal = 40`（与结算面板、调试面板同层）。单实例，重复点击只重新聚焦；`背包` 与[装备界面](../../施工文档/2026/2026.09/交互/装备系统交互案.md)互斥（打开一个自动关闭另一个）。
- 关闭：界面内 `关闭` 按钮或 `Esc`。关闭不改变任何状态；**每次拖动成功立刻写档**（`RunSession.Save()`），不做"关闭时统一提交"的草稿态 —— 与营地篝火的草稿态是两套模型（[篝火休息交互案](营地交互.md) §添加食物）。
- 地图关系：世界地图（`RunUiLayers.WorldMap = 30`）打开时可叠开背包（40 > 30），关闭背包后地图状态原样保留。
- 战斗 / 事件进行中、结算未关闭时打开 = **落点受限**（能拿起物品、不能放进道具栏 / 装备栏，顶部横幅给原因），规则见 §三。

## 二、界面结构

```text
┌ 背包 ─────────────────────────────────────────────────────────────┐
│ 背包                              负荷 12.4 / 30        〔关闭〕    │ ← 标题行 + 负荷条
│ ▍战斗中不可整理背包：物品可以拿起查看，但不能放进道具栏 / 装备栏。 │ ← 横幅（内容进行中 / 落点被拒时显示）
│ 〔全部〕〔材料〕〔道具〕〔装备〕〔食物〕                             │ ← 页签行
├───────────────────────────────────┬─────────────────────────────┤
│ 背包（页签只过滤显示，负荷是整包口径）│  〔重剑手〕〔精灵〕〔法师〕    │ ← 角色 Tab
│ ┌────┐┌────┐┌────┐┌────┐┌────┐    │  道具栏（随身 3 格）          │
│ │物品 ││物品 ││空  ││空  ││空  │    │  ┌──┐┌──┐┌──┐              │
│ └────┘└────┘└────┘└────┘└────┘    │  └──┘└──┘└──┘              │
│ ┌────┐┌────┐┌────┐┌────┐┌────┐    │  装备栏（左手 / 右手）        │
│ │空  ││空  ││空  ││空  ││空  │    │  ┌──┐┌──┐                  │
│ └────┘└────┘└────┘└────┘└────┘    │  左手位 右手位               │
│ …（共 5 行 × 5 列 = 25 格，不滚动）  │                             │
│ 〔上一页〕      第 1 / 3 页      〔下一页〕                          │ ← 页数 + 翻页
├───────────────────────────────────┴─────────────────────────────┤
│ 拖动整理：道具 / 材料 / 食物 → 道具栏；装备 → 左手 / 右手位；拖回背包即卸下。│ ← 提示行
└──────────────────────────────────────────────────────────────────┘
```

- 左侧 = 背包格（每格一件；可叠加物品显示数量角标）；右侧 = **可拖放目标**：随身道具 3 格 + 左右手位 —— 与战斗内槽位数量、语义完全一致，不引入第二套心理模型。
- **格区是固定 5 × 5 = 25 格的均匀网格**（2026-10-02 用户口径第 2 条）：每格是 **96 × 96 的正方形**，**空位也画格子**（只留暗底、**不写「空」**），因此**不滚动**；超过 25 件的部分靠**分页**看。效果图见[背包 UI 效果示意图](../../美术说明文档/UI/背包UI效果示意图.png)（[第 2 页](../../美术说明文档/UI/背包UI效果示意图-第2页.png)）。
- 格内文案：主行 = `名字 ×数量`（可叠加时带数量），副行 = `类别 · 负荷`（食物再带剩余天数）；正方形格较窄，副行允许折行，主行超出按省略号裁切。
- **网格下方一行是页数 + 翻页**：`上一页` / `第 x / y 页` / `下一页`，只有一页时两组按钮都禁用；换页签回到第 1 页；条目减少（拖走 / 消耗）时当前页自动夹取到合法页。分页算术在纯逻辑 `BagPageMath`（单测覆盖空表 / 整页 / 末页余数 / 越界夹取）。
- 每格显示：物品名、数量（可叠加时）、单件负荷（悬停给出 `单件 × 数量` 明细、效果、稀有度与来源）。
- 页签只过滤**显示**，不改变负荷统计（负荷是整包口径，见 §四）。
- 背包格数不设硬上限（由负荷约束）；叠加物品合并到同一格。

## 三、拖动规则

拖动只在**「无内容进行中」**放行：运行局处于 `RunGameModes.OnMap`，且没有不可让位的进行中内容（地图可选态、事件已结算、结算面板已关闭、不在营地）。
**2026-10-02 用户口径改判**：闸门拦的是**落点**，不是**拿起** —— 战斗、事件进行中、结算未关闭、营地与休息期间打开界面时，物品**照样能拖起来**（拖动预览正常、格与槽位可点可看），但**放进道具栏 / 装备栏会被拒绝**，并由顶部横幅给出原因（`BagArrangeGate.DescribeRestriction`：「<原因>：物品可以拿起查看，但不能放进道具栏 / 装备栏。」）；落点被规则拒绝时横幅显示「落点被拒：<原因>」，闸门状态一变旧的拒绝横幅即过期清除。提示行同步为 `拖动受限 · <原因>`。
实现上「能拿起」是必须的：Godot 在 `_CanDropData` 返回 false 时**不会**调用 `_DropData`，若在拿起点就禁掉拖动，就没有任何地方能显示横幅。

| 来源 → 目标 | 允许 | 条件与结果 |
|---|---|---|
| 背包 → 随身道具格 | 允许 | 道具 / 材料 / 食物；该格已有物品则**交换**（原物回背包），不做满栏替换面板 |
| 背包 → 左手位 / 右手位 | 允许 | 仅武器 / 防具；按 `HandsRequired` 校验，双手装备需两槽同时可让位 |
| 随身道具格 → 背包 | 允许 | 收入背包（局外不落地） |
| 手位 → 背包 | 允许 | 卸下；装备进背包的「装备」分类，**局外不落地丢弃** |
| 手位 → 另一手位 | 允许 | 交换；按[六边形战场玩法](../../玩法说明文档/系统规则/战斗系统/六边形战场玩法.md) §5.2 合法组合表校验（双手装备排斥其它手位装备），非法则拒绝并给原因 |
| 手位 → 随身道具格 | **默认非法（预留许可通道）** | 默认拒绝，提示「该装备不可放入道具栏（需装备效果开放许可）」；当该装备的 `AllowsWeaponInItemSlots` 为真时合法，落点行为与「背包 → 随身道具格」一致 |
| 装备格（头/身/脚/饰品） | 不接 | 部件装备的拖动在[装备界面](../../施工文档/2026/2026.09/交互/装备系统交互案.md)内完成；两个界面不叠开，不跨界面拖动 |

- **「武器 / 护具进道具栏」的预留通道**：落点判定与提示本轮就做，许可标志来自装备效果（玩法 §5.2 末尾的"预留由装备效果开放武器放入道具栏的许可接口"），默认全部为 false。通道存在的意义是：许可一旦开放，武器/护具可以像道具一样放进随身 3 格并随战斗携带，不需要再改交互。
- 非法落点一律**弱化 + 原因文本**，不弹窗；拖动经过的合法目标高亮（沿用战斗内黄色悬浮框口径）。
- 拖动不消耗时间点、不消耗金币、不改角色生命与卡组。
- 战斗内既有口径不变：战斗中「当前格道具 ↔ 随身槽」「拾取装备到手位（含战后拾取 `TryPostBattlePickup`）」仍按 `HexBattleScene` 现有实现。

## 四、负荷

- 每个物品有**单件负荷**（配置列 `Load`，浮点；空 = 0；叠加物品按 `Load × 数量` 计入）。
- 背包承载上限是**队伍共用上限**，来自新配置表（建议 `DataBase/Inventory/InventoryConfig.csv`，表头 `Scope,CharacterId,Capacity`；`Global` 行 = 队伍上限，`Character` 行预留不启用；经 `DataBase/FilePathRegistry.csv` 注册为 `Data.Inventory.Config`）。
- 统计口径：**只统计背包内物品**。已穿戴（左右手位 + 头部/身体/脚部 + 饰品）与战斗内临时携带**不占背包负荷** —— 穿在身上、拿在手里的不算包内。
- 校验在**拖入 / 拾取前试算**：`当前负荷 + 新物品负荷 > 上限` 即拒绝，显示 `负荷不足：12.4 + 2.0 > 14.0`。
- 结算与事件的**奖励入账不受负荷限制**（材料、金币、卡牌直接入账）：超限时负荷条转超载色并在悬停提示"超载"、同时阻止新的拖入，直到玩家自行整理（放上手位或消耗）。理由：奖励是流程产物，不应因背包满而在流程中丢失或被静默丢弃。
- 默认单件负荷（**待玩法侧配数**；下表为占位默认值，用来先跑通界面与校验链路）：

| 类别 | 默认单件负荷 | 依据 |
|---|---:|---|
| 材料 | 0.1 | 来源最广的基础物资 |
| 食物 | 0.5 | 独立实例（[食物系统](../../玩法说明文档/系统规则/物品系统/食物系统.md) §一） |
| 道具 | 1.0 | 消耗品 |
| 单手武器 / 单手防具 | 2.0 | `HandsRequired = 1` |
| 双手武器 / 双手防具 | 4.0 | `HandsRequired = 2` |
| 头部 / 身体 / 脚部 | 2.0 | 穿戴部位 |
| 饰品 | 0.5 | 最多 3 件 |
| 队伍上限 | 30.0 | 约"一件双手装备 + 全套部位装备 + 若干道具"的余量 |

- 负荷显示保留 1 位小数（0.1 与本项目已有的最小计量粒度量级一致，时间点同样按 0.1 计）。

## 六、数据模型与存档

- 背包条目 = **实例**：`InstanceId`（局内唯一；沿用 7 位数字前缀规则，见 [UniqueInGameId](../../功能说明文档/实体系统/UniqueInGameId.md)）+ `DefinitionId` + `Count`（可叠加物品 > 1；食物、装备、带独立效果的物品恒为 1）+ `Category` + 实例字段（食物有效期、稀有度等）。
- 兼容既有字段：`RunSaveData.Materials` / `Items` / `Equipment` 三个计数字典保留为**汇总视图**（材料等叠加型物品继续用它），带实例字段的物品进新列表 `RunSaveData.BagEntries`；迁移把现有字典内容按"多件同定义物品"展开，不丢数据。
- 新增字段（`RunSaveData`，与[装备系统交互案](../../施工文档/2026/2026.09/交互/装备系统交互案.md) §五同批迁移 `SchemaVersion 2 → 3`，见[代码需求清单](../../施工文档/2026/2026.09/玩法/代码需求清单.md) P0-3；**2026-10-02 起再迁 `3 → 4`**，随食物系统加入下表最后两行并以 `RUN_SESSION_SMOKE_PASS` 验证 v3 旧档迁移，见[10 月施工文档 §9](../../施工文档/2026/2026.10/10月施工文档.md)）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `BagEntries` | `List<RunBagEntrySave>` | 背包实例条目（§六 第一段）；**食物实例**的剩余有效期（`ExpireDays`）、稀有度与效果就落在这里（2026-10-02） |
| `CarryItemSlots` | `List<string>`（长度 3） | 局外随身 3 格（空串 = 空位）；默认不写入战斗开场（§九 第 1 条） |
| 装备字段 | 见[装备系统交互案](../../施工文档/2026/2026.09/交互/装备系统交互案.md) §五 | 左右手 + 头部/身体/脚部 + 饰品列表 |
| `ActiveFoodEffects` | `List<RunFoodEffectSave>` | **已吃下、仍在寿命轴上**的食物效果（`EffectType` + `Params` + `DurationKind` + `Remaining` + `SourceFoodId`）；跨天休息 / 时间点消耗 / 战斗结束各自扣对应寿命轴，用尽即移除（2026-10-02 批 B / C） |
| `CookedThisRest` | `int` | 本次休息已烹饪次数（上限 2）；休息结算后归零（2026-10-02 批 C） |

- 写档时机：每次拖动成功、每次奖励入账后立刻 `RunSession.Save()`（与战后拾取"每次成功后再落一次"的既有口径一致，见 9 月施工文档 §39）。
- **营地食物草稿不落档（2026-10-02）**：`CampScene` 的篝火草稿（`RunFoodSystem.CampFirePlan`）只活在场景里，点「休息」才由 `RunSession.ApplyRest(plan)` 一次性消耗并落档 —— 途中离开营地等于放弃草稿，背包不受影响。

## 八、验收

1. 顶部按钮栏出现 `背包`，单实例开关；`背包` 与 `装备` 互斥；`Esc` 与 `关闭` 都能退出且不留状态。
2. 分类页签过滤正确（材料 / 道具 / 装备 / 食物），`全部` 页签含全部条目；每格显示数量与单件负荷。
3. 负荷条 = `Σ(单件负荷 × 数量)`，只统计背包内物品：把装备装到左右手位后负荷**下降**，卸下后**回升**。
4. 拖入使 `当前负荷 + 新负荷 > 上限` 时被拒绝并给出带具体数字的原因；奖励入账在超限时仍入账，负荷条显示超载并阻止新的拖入。
5. 背包 → 随身格：目标格已有物品时**交换**（原物回背包），不做满栏替换面板；随身格 → 背包收入而不落地。
6. 背包 → 手位：双手装备要求两槽同时可让位；非法组合（如已有双手装备再装单手）被拒绝并给出原因。
7. 手位 → 随身道具格默认被拒绝并提示许可原因；把该装备的 `AllowsWeaponInItemSlots` 置 true 后同一拖动合法（许可通道可用）。
8. 战斗 / 事件进行中、结算未关闭时打开界面为**落点受限**：物品能拿起（拖动预览正常），放进道具栏 / 装备栏被拒绝，顶部横幅与提示行都给出原因；闸门解除后横幅消失。
9. 每次拖动成功立刻写档（退出重进状态一致）；旧档迁移后物品数量不丢。
10. `dotnet build` / `dotnet test`（238 例）/ `--battlefield-smoke` / `--run-flow-ui-smoke` 不回归；界面自身如需断言，按既有做法在烟测里加"打开 → 拖动 → 数值变化"的检查。
