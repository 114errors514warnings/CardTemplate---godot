# 精灵

> 2026-10-03 用户口径：按「通过卡牌强化的作战方向」给精灵加 3 张专有牌（B / A / S），优先复用现有机制；**精灵的增益不只是移除友方的负面状态，也作用于消耗友方的卡牌**（本轮补记）。旧三张设计牌（净化 / 水源 / 通灵）见[卡牌表格/精灵.csv](卡牌表格/精灵.csv)，新版空间适配见[六边形战场卡牌设计 §六](六边形战场卡牌设计.md)。本页为**文档设计**，2026-10-03 已落 `DataBase/Card/精灵Card.csv`（`11003001` 穿林箭 / `21003002` 林间抚慰 / `21003003` 古树哨卫，另含 `21003001` 敏捷闪躲；空间列已写、**生效受 P2-29 / P2-30 阻塞**，见 §三 末注）；等级与费用按[卡牌数值平衡标准](../系统规则/数值平衡/卡牌数值平衡标准.md) §4.2 / §4.3 / §4.4 定级。

## 一、角色定位

**一句话**：不吃盾的远程直线穿透输出 + 用「手牌 / 生命」互换资源的支援位。

| 作战方向（用户口径）| 语义 | 机制侧现状（2026-10-03 查证）|
|---|---|---|
| 消耗友方的卡牌（**增益的一环**）| 消耗一张友军手牌换取收益（原「净化」方向）| B 级设计牌「净化」在册未落表，已落表的 A 卡「林间抚慰」同缺口；**缺**「消耗 1 张手牌」的 `EffectType`（`CardOperationTargetType.SelectHandCards` 选牌通道已在，但目前只服务升级类效果）|
| 移除友方的负面状态 | 清除友军身上的普通弱化 | `EffectType.ClearFirstNormalDebuff`（筛选 `IsDebuff && !IsElite`）已实现；目标类型只有 `Self(1)` 与 `AllAllies(5)`（不含自身），没有单体友军目标 |
| 恢复友方生命 | 治疗友军 | `EffectType.Heal` 已实现；目标类型同样只有 `Self(1)` / `AllAllies(5)` |
| 召唤物 | 召唤友方单位 / 区域物 | **未实现**：无 `EffectType.Summon`；`Monster.IsMinion` 只服务怪物折损分流，玩家侧没有单位生成通道。格上区域物（`Trap` + `TrapId`）落物与「每次进入触发」已接入，**触发内容未接入** |
| 远程直线穿透攻击 | 弓的六方向直线，穿透途中单位与障碍 | **已接入**：`SpatialShape=Line` + `SpatialArgs` 里的 `Pierce`（`CardSpatialSpec.Penetrates` → 候选格、受影响格、直线求解三处都按它走）|

- 开局装备弓箭（双手；`BlocksDefenseShield=true` → 带护盾效果的防御牌会被拒，不消耗卡牌或能量），属性修正攻击 +2 → **当前攻击 4**（`Character.csv` 基础 2 + 弓箭 `DamageBonus 2`），默认攻击 = 5 格远程直线（[职业基础配置](职业基础配置.md)）。
- 定位推论：精灵**吃不到「叠盾」**，收益只能压在「射程与穿透面」和「手牌 / 生命互换」上 —— 本批 3 张按此取向；「消耗友方卡牌」与「移除友方负面」同属增益，由 A 卡一张承载。

## 二、定级口径（2026-10-03）

- 应有点数取[卡牌数值平衡标准](../系统规则/数值平衡/卡牌数值平衡标准.md) 速查表 §4.4（= 费用点数基准 §4.2 × 等级系数 §4.3）；判定用 §4.5：`|偏差| ≤ 2` 记平衡。
- **只按固定值计**（[数值设计规范](../../AIWorkSpace/AgentOps/数值设计规范.md) §一.2 / §一.4）：伤害、治疗、护盾、状态一律按**单个标准单位**计值，**不按人数或覆盖格数乘算**；直线穿透、群体覆盖、区域物触发次数、持续伤害（DoT）一律列为**未评定项**，按 §一.8 不宣告整卡平衡，但**参与等级定位**（未评定收益越重，等级越高、费用越保守）。
- 攻击类点数 = 单位当前攻击（精灵 **4**）＋ 卡牌额外伤害；其余点数见该标准 §二资源表（治疗 1 / 伤害 1 / 1 层虚弱 2 / 1 层易伤 2 / 1 层攻击力 3 / 抽 1 张 2 / 1 点能量 3 / 保留 +1 / 消耗 −1）。
- 两条未登记资源：**消耗 1 张友方手牌**（成本，建议与「抽 1 张牌 = 2」对称记 −2）、**区域物每次触发**（需先定「一局预期触发次数」）→ 见 §五 待拍板。

**空间牌状态（2026-10-04 起）**：穿林箭 `Line+Pierce` **已按设计生效**（空间配置仓库改为读全部「声明空间列」的卡表，见 [10 月施工文档 §24](../../施工文档/2026/2026.10/10月施工文档.md)），烟测实测「沿直线穿过首个敌人」；古树哨卫**只做到落物**，**「敌人每次进入该格时」仍不结算**（`OnEntered` 进入触发改表驱动 = T3 / [P2-30](../../施工文档/2026/2026.09/玩法/代码需求清单.md) 后半，待拍板）。林间抚慰的「消耗任意友军1张手牌」同样未落地（无对应 `EffectType`）—— 该卡现为「1 费治疗 6 + 清 1 个普通弱化、无代价」。

### 3.1 穿林箭（B，1 费）—— 远程直线穿透

- **设计意图**：精灵的「基础输出形状」—— 直线穿透，站得越远、敌人排得越整齐，收益越大；不叠盾、不靠反击。
- **空间字段（沿用 `勇士Card.csv` 的扩展列）**：`SpatialShape=Line`，`SpatialArgs=Range=5;Length=5;Pierce`（5 = 弓的武器距离；换武器时按武器距离，卡牌不另加距离）。
- **`Params` 草案**：`EffectType = Damage`，`Params = 2;1`（选定目标 + 额外伤害 1；受影响集合由空间层给出 —— 与「横扫」同形）。
- **定级**：已评定 = 攻击 4 + 额外伤害 1 = **5** vs 1 费 B **4.3** → 偏差 **+0.7 ✓ 平衡**；直线穿透的多目标覆盖列未评定（§六 空间）。
- **已验证复用**：`GetCandidates` 的 `Line` 分支对 `blocked && !spec.Penetrates` 才截断；`GetAffectedCells` 返回整条线；`TryCastCard` 把线上每个格上的单位作为受影响目标 → 一次出牌命中线上所有敌人。
- **注意**：`AttackMode=Thrust` 会在解析时强制关掉穿透（`spec.Penetrates = false`），本卡**不要**同时写 `Thrust`。

### 3.2 林间抚慰（A，1 费）—— 消耗友方卡牌 + 移除友方负面

- **设计意图**：一张牌同时承载精灵的**两条增益方向**（用户 2026-10-03 口径）—— ① 消耗友方的卡牌换资源（把队友手里的废牌变成续命）；② 移除友方的负面状态。费用给 1 费，落在 A 档的低位。
- **`Params` 草案**：`EffectType = Heal|ClearFirstNormalDebuff`，`Params = 1|1;1`（自身治疗 6；自身清 1 个普通弱化）；「消耗任意友军 1 张手牌」是**前置成本动作**，当前没有对应 `EffectType`（见缺口）。
- **定级**：已评定 = 治疗 6 = **6** vs 1 费 A **5.2** → 偏差 **+0.8 ✓ 平衡**；若把「消耗 1 张友方手牌」按对称口径记 −2 → **4** → 偏差 **−1.2 ✓** —— 两种口径都落在 §4.5 区间，结论稳健。清除普通弱化列未评定（§五 清单，正向）。
- **已验证复用**：`Heal` 走 `Card.ApplyHealEffect`；`ClearFirstNormalDebuff` 走 `StateSystem.TryRemoveFirstNormalDebuffs`（筛选 `IsDebuff && !IsElite`，与「奋力一击」同一链路），参数 `[1] count` 给 1。
- **缺口（一处）**：**消耗选定手牌**。`CardOperationTargetType.SelectHandCards(1)` 的选牌通道已在（升级类效果在用），缺的是把选中的牌**消耗掉**的动作 → 需新增 `EffectType`（或扩展复用该目标类型）；「任意友军的手牌」还需要选人（现无单体友军目标类型）→ **简单版**：消耗**自己**一张手牌；**完整版**：消耗任意友军一张手牌，且由该友军受益。
- **口径**：受益者写「自身」是因为运行时目标类型里没有单体友军（只有 `Self(1)` / `AllAllies(5)`）；模板侧已有「单友 / 邻友」（[六边形战场卡牌设计](六边形战场卡牌设计.md) §二）。要收窄或改成友军受益时，与「通灵」一起改。

### 3.3 古树哨卫（S，2 费）—— 召唤物（简单版 = 格上区域物）

- **设计意图**：覆盖用户口径里的「召唤物」，同时是精灵唯一的「控场」牌 —— 把一格变成敌人不愿意踩的地形。
- **空间字段**：`SpatialShape=Trap`，`SpatialArgs=Range=1`，`TrapId=vine_sentinel`（新定义名，待登记）。
- **已验证复用**：`TryCastCard` 的 `Trap` 分支已经能落地 `GroundObjectKind.Trap` + `EntryTriggerMode.EveryEntry`（每次进入都触发），`BattleMovementService` 会返回踩到的 `Trigger`；落物前会检查射程、可通行、目标格无单位与物品。
- **定级**：已评定 = 每次触发 `伤害 2 + 虚弱 1 层(2) = 4 点`，卡牌**消耗 −1** → 需要 ≈ **4 次触发**（4 × 4 − 1 = 15）才对上 2 费 S 的 **14.5**（偏差 +0.5）→ **触发次数属未评定地形收益**，要先拍板「一局预期触发次数」才能给定级结论；3 次触发（11 点）只相当于 2 费 C / B 档。
- **费用与等级依据**：原草案 3 费 S（22.8）需要 ≈ 7.6 次触发，不现实（4 能量回合里也过贵）→ 降为 **2 费 S**；若只算 2 次触发（7 点）则只值 1 费档，故「S」表达的是**上限承诺**（可反复触发、收益随战斗长度递增），与 1 费 S 的「城墙 / 旋风斩 / 盾牌冲撞」同属结构型。
- **缺口（两处，逐级落地）**：
  1. **区域物效果本体**：当前触发只到「踩到了」这一层（提示「效果待接入」）→ 需要一份区域物定义（新表或扩展现有表）给出 `vine_sentinel` 的触发内容：进入 → `Damage 2` + `AddState(Weak, 1)`，两者都是现成 `EffectType`。
  2. **完整版「召唤友方单位」**：需要 `EffectType.Summon` + 玩家侧单位生成（站位、行动序、折损分流都要接），**当前零实现**；完整版落地前本卡按简单版验收。
- **简单版验收**：2 费打出 → 目标格出现 `vine_sentinel` 区域物；敌人进入该格 → 受 2 点伤害 + 1 层虚弱；再进入再触发（`EveryEntry`）；卡牌消耗。

## 四、数值一览（固定值口径）

应有点数取 §4.4 速查表（= §4.2 费用基准 × §4.3 等级系数），判定用 §4.5（`|偏差| ≤ 2` 记平衡）；攻击类已含精灵当前攻击 **4**：

| 卡 | 等级 · 费 | 应有点数 | 已评定部分（单目标）| 偏差 | 未评定项 | 结论 |
|---|---|---|---|---|---|---|
| 穿林箭 | B · 1 | 4.3 | 攻击 4 + 额外伤害 1 = **5** | **+0.7 ✓** | 直线穿透覆盖 | 平衡 |
| 林间抚慰 | A · 1 | 5.2 | 治疗 6 = **6**（消耗手牌不估值；按 −2 → 4）| **+0.8 ✓ / −1.2 ✓** | 清除普通弱化（正向）、消耗手牌的估值 | 两种口径都平衡 |
| 古树哨卫 | S · 2 | 14.5 | 每次触发 4，卡牌消耗 −1 → 每触发 **3** | 需 ≈ **4 次触发**（4×4−1 = 15 → +0.5）| 区域物触发内容、触发次数 | **待定**（依赖触发次数口径）|

> 与上一版（2026-10-03 早前草案）的差别：不再用「治疗 ×N 人」「伤害 ×N 人」的乘算写法（违反[数值设计规范](../../AIWorkSpace/AgentOps/数值设计规范.md) §一.4），全部改为**固定值 + 未评定项清单**；林间抚慰由 2 费改 1 费、古树哨卫由 3 费改 2 费，均为对齐 §4.4 档位。
