# 单位数值平衡标准

> 角色 / 怪物属性价值评定的前提与标准。卡牌侧见「卡牌数值平衡标准.md」（同目录）。

## 一、生命跨战斗继承机制（前提）

- 角色生命在一连串战斗（关卡流程）中继承
- **单场战斗损失的生命 = 永久损失**，跨场累积
- 只有通过**特殊休息节点**才能回复基于自身生命上限的一部分生命

## 二、单位属性价值口径（三种口径，不可混用）

| 口径 | 含义 | 计入方式 | 用途 |
|------|------|----------|------|
| 价值点 | 处理该单位需投入的输出 | 怪物 = 面板 HP（全额）；护盾意图折算为额外拦截 | [关卡档位表](关卡档位表.md)的「总 HP」轴、清场轮数 |
| 威胁点 | 该单位整场对我方造成的等效伤害 | 每轮期望伤害 × 存活轮数 | 承伤校验（关卡档位表 §三）|
| 综合价值点数 | 该单位的战斗价值总量 = 清场成本 + 回合产出 | **面板 HP + K × 意图加权价值**（§2.4）| **通关奖励折损比例**（[六边形战场玩法 §7.4](../战斗系统/六边形战场玩法.md)）|

### 2.1 属性 → 点数

| 属性 | 点数 | 来源 / 理由 |
|------|------|-------------|
| 1 点生命 | 1 点 | 能承受 1 点伤害，与卡牌锚点「1 伤害 = 1 点」对齐；怪物全额、角色折扣见 §一 |
| 攻击 | 不计线性点 | 攻击只经「攻击牌 / 攻击意图」转化伤害 → 按回合产出流折算（§三 / §四）|
| 防御 | 不计线性点 | 防御只经「护盾段」转化拦截 → 按回合产出流折算（§三 / §四）|

### 2.2 回合产出公式

- 角色每轮伤害 = **实配攻击** × 每轮打出的攻击牌数。**两条口径，不可混用**（2026-10-07 统一）：
  - **上限口径 = 4 张 / 人**（每人 4 能量 → 至多 4 张 1 费攻击牌）→ 队伍 **40**/轮，用于[关卡档位表](关卡档位表.md)第五列「纯攻清场轮数」；
  - **期望口径 = 3 张 / 人**（初始牌组 8 张 = 攻击 ×5 + 护盾 ×3、每回合抽 5 → 手牌攻击牌 3.1 张，再扣移动与技能）→ 队伍 **30**/轮，用于 §三 承伤校验。
  - 实配攻击 = `Character.csv` 裸值 + 开局武器 `Weapon.csv` 的 `DamageBonus`（重剑手 2+1 = 3 / 精灵 2+2 = 4 / 法师 2+1 = 3），见[职业基础配置](../../角色设计/职业基础配置.md)。
- 怪物每轮期望伤害 = 攻击 × 单意图攻击段数 × 攻击意图占比
- 怪物每轮期望护盾 = 防御 × 单意图护盾段数 × 防御意图占比
- 攻击意图占比 = 含攻击段的意图条数 ÷ 意图总条数；护盾意图占比同理

### 2.3 意图价值与意图加权平均

**意图价值** = 该意图的全部效果按[行为与属性价值估算](行为与属性价值估算.md)折算的点数之和；不乘范围内实际命中人数（该文 §一 / §六）。

| 效果段（`Monster.csv` 的 `EffectType`）| 点数 | 依据 |
|------|------|------|
| `1` 伤害段 | 怪物攻击力 + 额外参数 | 1 伤害 = 1 点 |
| `2` 护盾段 | 怪物防御力 + 额外参数 | 1 护盾 = 1 点 |
| `3` 状态段 | 层数 × 单层值（易伤 / 虚弱 2、加攻 3、反击 4）| 行为与属性价值估算 §三 / §四 |
| `0` 无效果（如逃跑）| 0 | 不产出价值，但**计入意图条数** |

- 同一意图内的多个效果段以 `|` 分隔，价值求和；编码规则见[怪物配置](../../../功能说明文档/数据系统/数据配置/怪物.md)。
- **额外参数写法**：`1;<修正值>` / `2;<修正值>`（两元素，如 `1;-1` = 攻击力 − 1、`2;1` = 防御力 + 1）；带目标模式时写 `1;<MonsterDamageTargetMode>;<修正值>`（三元素，模式 `1` = 每次随机、`2` = 同意图共用目标）。**本节按配置语义取值**，即伤害段与护盾段一律「攻击力 / 防御力 + 额外参数」。六边形战场的取参**已统一**（2026-09-28：两元素取第 2 位、三元素起取第 3 位，执行与预览同一口径），见 §六与[代码需求清单 P2-10.4](../../../施工文档/2026/2026.09/玩法/代码需求清单.md)。
- **意图加权价值 = Σ(意图价值 × 权重) ÷ Σ权重**，权重默认 1（各意图等概率选择）；与 §2.2 的「攻击意图占比」同口径——分母是**意图总条数**，含非攻击意图。
- 数据可算性：素材只取自 `DataBase/Unit/Monster.csv`（属性 + 意图效果）与 `DataBase/Battlefield/EnemyIntent.csv`（`Behavior=Flee` 等空间规则），**不需要新增列或新表**。
- 例（近战劫匪 3115，35 HP / 攻 5 / 防 1）：意图 0 低攻 `1;-1` = 5 − 1 = 4；意图 1 高攻 `1;1` = 5 + 1 = 6；意图 2 逃跑 `0` = 0 → 意图加权价值 = (4 + 6 + 0) ÷ 3 = **3.33**。

### 2.4 综合价值点数（奖励折损口径）

**综合价值点数 = 面板 HP + K × 意图加权价值**（K = 意图折算系数，**1.0 已定稿**，2026-09-27）

> **实现（2026-09-28）**：意图价值表落 `DataBase/Balance/MonsterValue.csv`（列 `MonsterId,IntentValues,Note`，顺序同 `Monster.csv` 的 `IntentionN`），计算与档位在 `Scripts/Run/MonsterValuePoints.cs`（面板 HP 仍取 `Monster.csv`），落档 `SettlementLossTier / SettlementValueRatio`，展示为结算面板折损行（见 [9 月施工文档 §33](../../../施工文档/2026/2026.09/9月施工文档.md)）。**本节表内数值即实现值**；**折损分流同日落地**：生存关豁免（`IsSurvivalLevelType`）已有；爪牙不计入的**分流逻辑与标记载体均已落地**（`Monster.csv` 的 `IsMinion`（是否为爪牙）列 → `Monster.IsMinion` → `EnemyValueSample(..., IsMinion)`，爪牙既不在分子也不在分母；**当前无怪物置 1**），见该文 §34.1 / **§35**。

- 只看 HP 会把等量生命的「高威胁 / 低威胁」单位等同看待：双刃猎手 3007 的意图价值占其综合价值 **28.0%**，而近战劫匪 3115 只占 **8.7%**。逃跑一个高威胁单位比逃跑一个低威胁单位更该扣奖励，所以折损口径必须含意图加权。
- 折损比例 = 实际击败者的综合价值点数 ÷ 本场应击败者的综合价值点数（分子分母同口径）。
- **与「价值点（面板 HP）」不可混用**：关卡档位表的清场成本轴（总 HP）与清场轮数仍用面板 HP；本口径只用于[六边形战场玩法 §7.4](../战斗系统/六边形战场玩法.md)的通关奖励折损。

## 五、初始关卡怪物价值目标（草案）

> 本节为旧池（3001–3007）时期的历史草案，保留作价值目标推导的参考；**现役关卡已改用 3101+ 怪物**（F1-001 起），当前投放数值以[关卡档位表](关卡档位表.md)为准。

**前提设定（⚠️ 已过期，仅作历史推导参考 —— 现行口径见下）**：
- 当时的队伍是「勇士 + 重剑手 + 重剑手」（1001 + 1002 + 1002）：队伍总 HP = 40 + 30 + 30 = **100**、我方每轮输出 **27** → 3 轮总输出 81
- **现行队伍（2026-10-07 统一口径）**：重剑手 / 精灵 / 法师（**1002 / 1003 / 1004**）、总 HP = 30 × 3 = **90**、实配攻击 3 / 4 / 3 → 每轮输出 **40（上限）/ 30（期望）**；掉血永久 → 整波可接受承伤按[关卡档位表 §三](关卡档位表.md)（高等档上限 60 = 队伍 HP 的 2/3）

**推导**：
| 目标 | 约束 | 推导结果 |
|------|------|----------|
| 清场速度 | 3 轮清场，扣护盾拦截约 15% | 怪面板总 HP（价值点）≈ **60~70** |
| 承伤上限 | 3 轮怪总威胁 ≤ 30 | 每轮期望总威胁 ≤ **10** |

**结论：初始关卡一波怪的目标 = 面板总 HP 60~70（价值点），每轮期望总威胁 ≤ 10。**

**达标参考组合**（原提案）：堕魔守卫 3003 + 诅咒弓手 3004 + 狂热祭司 3005
- 面板总 HP = 30 + 16 + 20 = **66**（价值点 66，在 60~70 内）✅
- 每轮期望威胁 = 4.5 + 3 + 1 = **8.5**（≤ 10）✅ —— 2026-09-27 曾按「`1;2` = 伤害 +2」重算为 11.5 而失格；2026-09-28 把 `3003` 改写为 `1;2;0`（意图① 回到 9 点）后，该组合**恢复达标**。
