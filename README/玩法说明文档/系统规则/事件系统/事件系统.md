# 事件系统

> 事件节点的玩法规则、事件货币价格表与选项配平标准。节点类型定位见[地图玩法](../地图玩法/地图玩法.md) §四；事件 JSON 配置见[剧情事件](../../../功能说明文档/数据系统/数据配置/剧情事件.md)；选项 UI 见[事件剧情 UI 交互](../../../交互说明文档/剧情UI/事件剧情UI交互.md)。

## 一、事件节点规则

- 玩家到达事件节点后**不能放弃该节点**，必须从事件选项中选择一项。
- 事件至少提供 2 个可执行选项，不提供「离开 / 放弃节点」选项。
- 普通事件：不进入战斗；选项以增益、减益或交易为主。
- 危险事件：**不一定进入战斗**，选项可以是纯减益（通行费形态），也可以包含进入战斗的选项。
- 每个选项的公开影响（`effectPreview`）必须与执行结果一致，且不允许留空。
- 正式事件中，`effects` 只能使用执行器已支持的效果类型（见 §五）。

## 二、事件货币与价格表

### 2.1 既有锚点

| 项 | 点数 | 来源 |

| 抽 1 张牌 / 1 点能量 | 2 / 3 | 同上 §二 |
| 平衡容差 | ±2 | 同上 §4.5 |

### 2.2 时间点

时间点是本项目的第五种事件货币，其价格是**常数**（不随游戏进程变化）：

| 关系 | 值 |
|---|---|
| 1 天 | **4 时间点**（固定）|
| 1 时间点 | 10 战斗回合 |
| 最小计量单位 | **0.1 时间点 = 1 战斗回合** |
| 移动一格 | 0.3 时间点 |
| 1 天 | 1 个 Debuff（固定，可叠加）|

- 1 时间点 = 1/4 天 = 1/4 个 Debuff，因此只要有 Debuff 强度数值，时间点价格即为固定常数。
- **定 1 时间点 = 4 点（草案）**，待 §5.4 Debuff 加成数值落地后校准。
- 等价三角：**1 时间点 = 4 点 = 全队 4 点生命 = 40 金币**；**0.1 时间点 = 0.4 点**。
  - 该等价**只在代价方向成立**：用于衡量"花掉时间"值多少；不可反向把已获得的时间兑换成资源。
- 时间点当代价的约束：
  1. 单个事件的时间点代价建议 ≤ 1.0（≤1/4 天），超出应改用「今天到此为止」这类离散档；
  2. 代价不得超出当天剩余时间点，不足的选项保持可见但禁用并显示原因；
  3. 界面显示为「0.5 时间点（5 回合）」这类可换算写法；
  4. **时间点只能消耗、不能回复**：事件选项中禁止出现负的时间点变化。"节省时间"一律表达为「本选项不消耗时间」（代价为 0），不能写成 −X。理由：时间点是单调递增的运行时钟，回退会把跨天边界往回推，并使篝火回复公式（`剩余时间点 ÷ 4`）失效。

### 2.3 事件价格表（草案）

| 收益 / 代价项 | 点数 |
|---|---|
| **每名角色失去 5% 最大生命（向上取整）** | **1** |
| 治疗：每名角色回复 5% 最大生命（向上取整）| 1 |
| 10 金币 | 1 |
| 1 时间点（0.1 精度）| 4 |
| 永久移出 1 张牌 | −1 |
| 加入 1 张状态牌 | −2 × 本层剩余战斗场次 |
| 随机普通 / 罕见 / 稀有牌 | 3.6 / 5.2 / 11 |
| 常见 / 罕见 / 稀有材料 | 1 / 3 / 6 |
| 随机药剂 | 5 |

**生命一律以"最大生命百分比（向上取整）"作为计量与表达单位**，不写绝对点数：

| 占比 | 30 HP 角色 | 40 HP 角色（勇士）| 全队 3 人点数 |
|---|---|---|---|
| 5%（轻）| 2 点生命 | 2 点生命 | 3 |
| 10%（中）| 3 点生命 | 4 点生命 | 6 |
| 15%（重）| 5 点生命 | 6 点生命 | 9 |
| 20%（极限）| 6 点生命 | 8 点生命 | 12 |

- 等价三角（**仅在代价方向**）：**全队各失去 5% 最大生命 = 3 点 = 30 金币 = 0.75 时间点**。
- 单价定为"每角色 5% 最大生命 = 1 点"（30 HP 角色即 1 点生命 ≈ 0.5 点）的依据：按旧口径（1 点生命 = 1 点），一场低等档战斗净伤害 21 点 → 21 点，而该场掉落仅 ≈8.6 点，战斗永远巨亏；按新口径为 10.5 点 vs 8.6 点，接近持平，符合"战斗靠成长回本"的手感。
- 生命代价上限：**单个事件累计 ≤ 15% 最大生命**（见 §三 律 5）。

## 三、选项配平律

1. **无可放弃基准**：事件节点不可放弃，因此同一事件内所有选项的净价值极差必须 ≤ 2 点。任何"明显更差"的选项都会退化为死选项。
2. **纯减益只能全套等价**：只有当事件内所有选项都是等价纯减益（币种不同，净价值相同）时，才允许出现纯减益选项。一旦某选项是净正收益，其余纯减益选项即为死选项。
3. **单币种**：一个选项 = 一个收益 + 一种代价，禁止同一选项叠加两种代价（尤其禁止"扣血 + 推进时间"这类同向叠加）。
4. **禁止支配**：不允许"代价更大而收益相同或更小"的选项。
5. **预算隔离**：事件配平只在事件预算内进行（金币 / 时间点 / 卡组 / 材料 / 药剂 / 生命），**单个事件累计生命代价 ≤ 15% 最大生命**；不与正式战斗的承伤预算（见[关卡档位表](../数值平衡/关卡档位表.md) §三）混算。
6. **档位一致**：同一事件内所有选项走同一档位；档位随节点在设计路线中的位置提升，与「普通事件每格 C+1」的既有节奏一致。
7. **代价与收益不得同币种**：同一选项的代价币种与收益币种必须不同。同币种时账目直接合并（付 30 金币拿 100 金币＝纯 +70 金币），选项退化为纯收益，失去设计意义。
8. **生命一律用百分比表达**：事件的扣血 / 回复必须以"最大生命百分比（向上取整）"书写（例：失去最大生命的 15%，30 HP 角色为 5 点生命），不使用绝对点数；执行器接入 `HpPercentDelta` 后配置同步改为百分比。

## 五、登记与执行器现状

- 事件池登记：`DataBase/WorldMap/EventPool.csv`（按 `NodeType` 选择 `EventId`，`ConditionId` 必须留空）。
- 事件索引：`DataBase/Story/EventIndex.csv`；事件本体：`DataBase/Story/Events/<EventId>.json`。
- 已接入：
  - `effects`：`HpDelta / SelectedPlayer`、`GoldDelta / Run`；其他类型会提示「剧情效果暂未支持」且不生效。
  - 选项跳转 `next.type`：`Close` / `Battle`（`Battle` 需带 `referenceId` 指向 `LevelId`；2026-09-21 接入）。
  - `autoComplete`：纯推进剧情的事件直接显示「前往地图」，不播放选项。
  - 选项结算后行为：锁定已选项并显示唯一「前往地图」按钮，不自动关闭剧情 UI。
- 待接入：`HpDelta / AllPlayers`、`TimePointDelta`（0.1 精度、非负）、材料 / 道具 / 药剂、卡组增删与永久升级、状态牌入库、按掉落表发奖。详见[代码需求清单](../../../施工文档/2026/2026.09/玩法/代码需求清单.md) P0-2 / P1-4。

### 6.1 诊断

- `EVT-F1-011 / 012 / 013` 共 8 个选项：收益全是金币、代价全是单角色生命 → 三个事件读起来是同一个事件，**币种重复度过高**。
