### 1.1 命名口径：型号同名、编号不同（2026-10-02 第二版）

用户口径：**不同型号的学徒 / 教授用同一个名字，只用编号（与外观）区分型号**。核实结论：**当前工程完全支持，不需要任何代码**。

| 结论 | 依据 |
|---|---|
| 主键是 `id`，不是名字 | `LoadingSystem.MonsterDictionary` 是 `Dictionary<int, Monster>`（`Scripts/System/LoadingSystem.cs:120`）；建场按 `Level/Config/*.csv` 的 `DefinitionId`（怪物 id）取模板（`Scripts/Battlefield/Runtime/BattlefieldSession.cs:324` 起）|

| 全库没有"按名字查 / 按名字去重"的代码 | 本轮用 `Select-String` 扫 `Scripts/**/*.cs`：`Dictionary<…Name` / `FirstOrDefault(…Name` / `Where(…Name ==` / `GroupBy(…Name` **0 命中** |

**代价与三条硬约束**（设计侧必须自己背）：

2. **排障、查表、写文档一律用 id**（同名时名字定位不到具体型号）。
3. 将来做英文名时再确认：Godot 的 CSV 翻译按列生成 `*.translation`（本仓库 `DataBase/Unit/Monster.en.translation` 目前为空）；同名行会**共享同一条翻译 key** —— 若将来要给型号单独英文名，需要另加一列或由代码拼后缀。

## 二、失控伴侣法师（F1-008）

### 2.1 男方「失控男法师」3123 —— 纯输出（**第三版：数值补足整关缺口**）

用户口径：**两种攻击意图** —— 远程投掷攻击，或者近战高伤害攻击（**能够移动**）；第二版追加「**伴侣法师的数值变高一点**」，且本关**不再有散兵**（见 §2.4）；**第三版澄清：不改成精英关** —— 加强这两只是为了**补足被移除散兵的关卡怪物价值**（v1 全关 **210.0** → v3 两人合计 **219.25**，见 §5.1），档位四项指标只是顺带贴住。

| 意图 | 名称 | 几何（`EnemyIntent.csv`）| 效果段（`Monster.csv`）| 伤害 | 价值 |
|---:|---|---|---|---:|---:|
| 0 | 符能投掷 | `ThrowSingle` / 射程 4 / 移动 1 / `Nearest` | `1;6\|3;2;1;6` | **18**（攻 12 + 6）+ **6 层易伤** | 30 |
| 1 | 暴走突进 | `MeleeLine` / 射程 2 / 移动 **3** / `Nearest` | `1;10\|3;2;1;6` | **22**（攻 12 + 10）+ **6 层易伤** | 34 |

- **面板：88 HP / 12 攻 / 2 防**（v1 = 32 / 9 / 2）。散兵全删后，被移除的那部分**关卡怪物价值（137.5）**必须由这两人自己顶上 → 面板提到 **88 + 80 = 168**（正好等于档位总 HP），**每轮伤害 22（男 20 + 女 2）、状态 11、护盾 4** 也一并由两人包干（完整价值账见 §5.1）。
- **两条意图都挂 6 层易伤**（第三版改动：v2 是"投掷挂 3 层、近战白板"）：只有 2 只单位时，状态轴必须在**每次出手**上产生，否则 11 层/轮凑不出来。层数 = 持续回合数（易伤强度固定 ×1.5），不是叠层伤害（见 §5.1 的口径说明）。
- 远程那条是**投掷**（`ThrowSingle`，与 3121 大型史莱姆同一种几何），不是直线：投掷只看距离、不吃障碍截断 → 躲柱子对"投掷"无效，只有**拉开距离**有效。
- 近战那条**带移动 3**：他可以先贴上来再打 **22** 点，逼玩家把脆皮后撤或让前排顶住。⚠️ 22 单发落到带易伤的角色身上 = **33 > 角色满血 30** → 这是"把散兵的伤害预算并进 2 只"的必然结果，处理路径是**清易伤 / 预铺护盾 / 拉出近战距离**；设计侧另留**低峰值旋转钮**（默认不启用，见 §5.1）。

### 2.2 女方「失控女法师」3124 —— 支援（**第三版：护幕与虚弱同步补足**）

用户口径：**给双方增加力量**、**添加护盾**、或者**投掷敌方目标为其施加虚弱**。

| 意图 | 名称 | 几何 | 效果段 | 数值 | 价值 |
|---:|---|---|---|---|---:|
| 0 | 缠绕投掷 | `ThrowSingle` / 射程 4 / 移动 1 / `Nearest` | `1\|3;2;2;5` | **6 伤**（攻 6）+ **5 层虚弱**（伤害段 + `SelectedTarget` 状态段）| 16 |
| 1 | 抽能护幕 | `AdjacentSingle` / 射程 0 / 移动 0 / `AllyRange` 半径 3 | `2;9\|3;0;2;5` | 半径 3 内**友方各 12 点护盾**（防 3 + 9）+ **随机一名角色 5 层虚弱** | 22 |
| 2 | 伴侣共鸣 | `AdjacentSingle` / 射程 0 / 移动 0 / `AllyRange` 半径 3 | `3;1;6;1\|3;5;6;1\|3;0;2;5` | **自身 +1 层力量**（`Self`）+ **半径内友方各 +1 层力量**（`AllAllies`）+ **随机一名角色 5 层虚弱**（`Auto`）| 16 |

- **面板：80 HP / 6 攻 / 3 防**（v1 = 28 / 5 / 3）。
- **三条意图都挂 5 层虚弱**（第三版改动：v2 只有缠绕挂 4 层）：设计上她**所有动作的本质都是"抽取对手符能"** —— 抽来的力气用在哪儿，决定了这一轮她出哪条意图（打人 / 撑盾 / 回充伴侣）。这样 2 只单位才能凑出 11 层/轮的状态轴。
- **护幕从 8 涨到 12**（`2;9` = 防 3 + 9）：护盾支援轴的档位目标是 4/轮，12 ÷ 3 条意图 = **4.0** 正好命中；同时 12 点护盾 = 直接吃掉一次三人队集火的三分之一。
- 纯护盾意图**没有伤害段**，所以状态段必须用 `0`（`Auto` = 随机一名角色）—— 按[怪物配置](../../功能说明文档/数据系统/数据配置/怪物.md)"纯状态意图不能用 `2`"的规则（没有伤害段就解析不出 `SelectedTarget`）。
- 「给**双方**加力量」= 两段 `AddState`：`Self` 管她自己、`AllAllies` 管伴侣 —— 与护幕走同一条"半径 3 友方"的思路，读表即懂。
- ⚠️ **意图 2 的两段力量依赖 §八 P2-25**：当前六边形战场的 `AddState` 段**忽略目标类型**、一律施加到"本意图的索敌目标（= 角色）"，所以现在写这两段会**给玩家 +1 攻击**（反向增益）。P2-25 落地前**只写 `3;0;2;5` 那一段**（虚弱可正常落地）。
- 女方**移动预算 1**：她不是纯站桩辅助，会小步调整以保持罩住伴侣；但只有 1 格，玩家用位移很容易把她与伴侣拉开。

### 2.3 女方阵亡后：男方的「狂暴」

用户口径：女方死后，**男方意图的伤害值增加**；**或者**做额外的两个新攻击意图，攻击方式与原本两条对应，但变成**单次伤害较低、总伤害更高的多次伤害**。

| 口径 | 触发后的表现 | 优点 | 代价 |
|---|---|---|---|
| **B 换意图（推荐）** | 新增意图 2 / 3：**符能连掷** `1;-5\|1;-5\|1;-5\|3;2;1;6`（投掷，**7×3 = 21** 伤 + 6 层易伤）、**连续突进** `1;-4\|1;-4\|1;-4\|3;2;1;6`（近战，**8×3 = 24** 伤 + 6 层易伤）| 单次伤害**下降**（18→7、22→8）、总额**上升**（18→21、22→24）；HUD 直接读成 `7×3` / `8×3`，玩家一眼看出「他疯了」；不依赖状态叠加，无失控曲线 | 需要 4 条意图列 + 1 条规则（P2-24）|
| A 数值提升 | 仍是 2 条意图，伤害整体上调（如 18→21、22→26）| 数据最薄（只要改修正值），HUD 数字变化也看得见 | 仍需"同伴退场"规则；只有"更疼"、没有"形态变了"的表现力 |
| C 加攻状态 | 女方退场瞬间给男方挂 2 层 `AddAttack` | 复用现成状态 | 加攻会**随回合累积**（无上限）→ 长局伤害失控；同样需要"退场时施加"的钩子 |

**推荐 B**，理由：① 完全命中用户原话「攻击方式对应、单次更低、总额更高」；② 表现最直白（意图数字从 `18` / `22` 变成 `7×3` / `8×3`）；③ 三种口径都依赖**同一条规则**（判定同伴是否退场 + 收窄候选意图列），所以选表现力最好的 B 不会有额外成本。

> 期望值：常态 (18 + 22) ÷ 2 = **20.0 / 轮**；狂暴 (21 + 24) ÷ 2 = **22.5 / 轮**（**+12.5%**）—— 这正是"女方是男方的安全阀"这条关系的数值形态，也让本关的伤害轴变成**前半段在档位内、后半段略高于档位**（22.0 → 22.5，档位 22）；同时女方消失会一并带走 **5.0 状态 + 4.0 护盾**，所以"先斩女方"仍然是**有得有失**的选择。

### 2.4 本关**没有散兵**（2026-10-02 第二版指令 + 第三版补足口径）

用户指令：**F1-008 不要散兵**。第一版的编组（2 只学徒 / 2 只装置 / 1 只黏液 / 1 只石卫 / 1 只小史莱姆）**整组取消**，本关只剩伴侣二人（3123 ×1 + 3124 ×1）。

- 直接后果：① 玩家的"清杂兵缓冲轮"消失，从第一回合起就只在处理两个高血目标；② 档位的「总 HP 168」必须由两人分摊 → **88 + 80 = 168**；③ 其余三条轴也只能由这两只承担 → **意图数值整体上调**。
- **第三版的做法（用户澄清：不是把本关改成"精英关"）**：散兵原先分摊的四条轴**整条补进这两只** —— 每轮伤害 **22.0**（男 20 + 女 2）、状态 **11.0**（男 6 层易伤 + 女 5 层虚弱）、护盾 **4.0**（护幕 12 ÷ 3 条意图）、清场 **4.7 轮**，**档位四项指标全中**（§5.1）。
- **为什么状态轴能补齐**（第二版"贴不住 → 改精英编组口径"的结论**作废**）：易伤 / 虚弱的**强度与层数无关**（`StateSystem.ModifyIncomingDamage`：`stacks > 0` 就 ×1.5 / ×0.75，各只算一次），**层数 = 持续回合数**；而清状态牌是**整条移除**（`TryRemoveFirstNormalDebuff` → `RemoveState`）。因此"每人每次 5–6 层"只是"更持久、但可被一张牌整条拆掉"的压力，**不是**"单发 5 层易伤 = 死刑"。
- **代价（设计侧必须背）**：伤害集中到 2 只之后，**单发峰值**从 v1 的"9 只分摊（最高 9）"变成 **22 点**；对带易伤的角色是 `22 × 1.5 = 33 > 角色满血 30` → 需要**清易伤 / 预铺护盾 / 拉距离**（这是"把散兵的伤害预算并进 2 只"的必然代价，不是设计失误）。§5.1 另留**低峰值旋转钮**：**默认不启用**，只在实机反馈"过于惩罚"时才切（总额与档位四项指标一分不动）。

## 三、教授与学徒群（F1-009）

### 3.1 学徒三分：三个型号同名「学徒法师」（**第二版口径**）

用户口径（第一版）：学徒分两种，**一种施加虚弱，一种施加易伤**，且名字上要能看出设计区别；学徒的意图 = **施加弱化效果的攻击** 与 **伤害更高但不施加弱化的攻击**。
用户口径（第二版）：**不同型号名字相同、编号不同**（型号差异由外观区分）→ 三个型号**都叫「学徒法师」**，靠型号代号（通识 / 蚀刻 / 束缚）与外观分辨。

| 型号 id | `Name`（同名）| 型号代号 | 状态课 | 意图 ①（低伤 + 挂状态）| 意图 ②（高伤、不挂状态）|
|---:|---|---|---|---|---|
| 3126 | **学徒法师** | 通识 | **易伤** | **符文侵蚀** `3;0;1;3`：距离 4、对随机一名角色 **3 层易伤**（0 伤害）= 6 价值 | **学徒箭** `1`：距离 4 远程直线 **7 伤** = 7 价值 |
| 3128 | **学徒法师** | **蚀刻** | **易伤** | **蚀刻咒** `1;-4\|3;2;1;3`：距离 4 远程直线 **2 伤 + 3 层易伤** = 8 价值 | **学徒箭** `1`：距离 4 远程直线 **6 伤** = 6 价值 |
| 3129 | **学徒法师** | **束缚** | **虚弱** | **束缚咒** `1;-4\|3;2;2;3`：距离 4 远程直线 **2 伤 + 3 层虚弱** = 8 价值 | **学徒箭** `1`：距离 4 远程直线 **6 伤** = 6 价值 |

- **面板（第二版裁定：6 攻）**：3128 / 3129 = **18 HP / 6 攻 / 1 防**。理由：7 攻时 F1-009 的累计净伤害 **66 > 档位上限 60**；降到 6 攻后每轮伤害刚好 **22.0**（= 档位目标）、净伤害 **59** ≤ 60（见 §5.2）。3126 是备用型号（F1-008 已无散兵），**本轮不动它**（保持 v1 的 18 / 7 / 1）。
- **型号之间的区别只由外观承担**（见 §1.1 外观列）：蚀刻 = 赤红蚀刻纹 + 蚀刻笔；束缚 = 青灰锁链纹 + 符环。玩家的判断依据从"名字"变成"**看起来像哪一种**"。
- **两条意图都造成伤害**（这是与 v1 最大的差别）：v1 的 3126 是「0 伤害挂 3 层易伤 / 7 点普攻」，玩家总能靠"这次它只挂状态"省下伤害预算；现在**挂状态的那一击本身也是伤害**，压力与痛苦绑定。
- 状态段用**附带写法**（`1;<修正>\|3;2;<状态>;<层数>`）：有伤害段时目标类型 `2`（`SelectedTarget`）合法且精确，v1 那条「纯状态意图不能写 `2`」的警告**不适用于 3128 / 3129**（3126 是纯状态意图，仍只能写 `0` / `3`）。

### 3.2 教授法师的定位分析

#### 3.2.1 教授能承担的四类职能（先划清可选范围）

| 职能象限 | 表现 | 数据载体 | 现状 |
|---|---|---|---|
| **支援核心**（群体增益）| 护幕（护盾）/ 强化学徒（力量）| `2;1` + `AllyRange`（**今天就能用**）；`3;…;6;n` + `AllAllies`（**需 P2-25**）| 护幕已可用；力量增益不可用 |
| **弱化核心**（群体弱化）| 全体易伤 / 全体虚弱 | `3;3;…`（`AllEnemies` = 全体角色）**需 P2-25** | ⚠️ 当前**退化为单体**（已写的 3125「导师威压」实际只打到 1 名角色）|
| **单体惩教**（输出 + 状态）| 戒尺 / 教鞭：伤害 + 虚弱 | `1;<修正>\|3;2;<state>;<n>` | **今天就能用**（链路已被 3119 / 3124 验证）|
| **指挥**（改学徒节奏）| 学徒意图偏向、强化层数、教授死则学徒溃散 | `BattleRule`（P2-24 族）| 未实现 |

结论：**"教授"这个身份的可选职能里，只有「护幕」和「伤害 + 状态」今天能真落地**，其余两类卡在 P2-25（目标类型）与 P2-24（联动规则）上。所以教授的设计必须**以这两条为骨架**，把群体弱化 / 强化学徒作为"P2-25 落地后的增强"。

#### 3.2.2 推荐：两位教授、两条链（用户要求"额外多一个教授法师"）

> **第二版口径**：两位教授**同名**（都叫「教授法师」），靠**型号代号（主讲 / 督学）+ 外观**区分（见 §1.1）。名字不再承担辨识职责，因此两只**必须分工**，否则玩家连文字提示都没有、只能看到两个同名单位在刷盾。

| 教授 | 定位 | 意图 | 站位 |
|---|---|---|---|
| **3125 教授法师（主讲）** | **支援核心**：把整间讲堂变成"叠层训练场" | ① 导师威压：距离 4，对**全体角色** 3 层易伤（0 伤害，需 P2-25）② 护罩矩阵：**半径 4 友方各 4 点护盾** | 讲台最后排 `(-5,0)`，**移动 0** |
| **3127 教授法师（督学，新模板）** | **惩教 / 压线**：把玩家从掩体和后排里逼出来 | ① 戒尺惩戒：距离 4 远程直线 **3 伤 + 2 层虚弱** `1;-3\|3;2;2;2`（价值 7）② 教鞭抽击：距离 4 远程直线 **6 伤**（不挂状态）`1`（价值 6）| 讲台侧翼 `(-5,-1)`，**移动 0** |

- **为什么不是"两个一样的教授"**：两只 3125 会让「全体 3 层易伤」与「半径 4 护幕」直接翻倍成 **6 层 / 8 盾**——数值更肉更疼，但**决策不变**（反正都得先打教授）。分工之后出现两条不同的拆解理由：**先斩主讲 = 拆掉护罩与叠层**；**先斩督学 = 换回自己的输出（虚弱）与移动节奏**。
- 督学法师**与主讲同面板（34 / 6 / 3）**、同样移动 0：两只都够不到玩家出生区，是"区域压制"而不是"追击威胁"；玩家要花回合把射程够过去。
- 督学站主讲旁边 → **主讲半径 4 的护幕同样罩住督学**（距离 1），"先拆护罩还是先拆人"的选择被保留下来。

#### 3.2.3 教授的数值定位（不该承担每轮伤害）

- 主讲 **0 伤害**、督学 **4 伤/轮**（(3+6)÷2），两人合计只占本关 23.5 点/轮的 **约 17%**；它们真正的价值在**放大别人的伤害、压低玩家的输出**（全体易伤 + 虚弱 + 护幕）。
- **34 HP × 2** 的量级：三人队一次集火就能带走一只 → "**能不能在 2 回合内把射程/位移铺到讲台**"就是本关的核心提问。
- 移动预算 0（与 3118 失控哨戒装置同口径）：教授不追击，"讲台"的空间直觉才成立；也正是移动 0 让玩家可以**用撤退换回合**。
- 如果把教授做成高伤单位，本关会立刻退化成"先秒教授否则死"的单解 —— 状态关的乐趣来自"叠层与拆链"，不来自单点爆发。

#### 3.2.4 反例清单（不要这样设计）

- ❌ **两位教授都给护幕**：护盾叠到 8 点/轮，玩家输出被吃光，战斗变成"磨"。
- ❌ **教授带"召唤学徒"**：会与 P2-22（召唤段 + 爪牙波次）耦合，且人数会失控。
- ❌ **教授会追击**（`MoveBudget > 0`）："讲台支援"的直觉消失，F1-009 与 F1-008 的差异也跟着消失。
- ❌ **两只教授用同一条意图表**：决策退化（见 §3.2.2 第一点）。

2. **状态轴靠"少次数、每次 5–6 层"补齐，机制上成立**：易伤 / 虚弱的强度与层数无关（`StateSystem.ModifyIncomingDamage`：`stacks > 0` → ×1.5 / ×0.75 各算一次），**层数 = 持续回合数**（每回合开始掉 1 层），清状态牌**整条移除**（`TryRemoveFirstNormalDebuff`）→ 5–6 层 = "更持久、但一张牌就能整条拆掉"的压力。第二版据此得出的"状态轴贴不住 → 改精英编组口径"的结论**作废**。

### 8.2 代码走读发现的**现役偏差**（不是本轮设计引入的，但会直接影响配表）

`BattlefieldSession.ExecuteEnemyIntentionEffect` 的 `AddState` 分支：

```csharp
else if (type == EffectType.AddState && effect.Length > 2 && Enum.IsDefined(typeof(StateType), effect[2]))
{
    int stacks = effect.Length > 3 ? effect[3] : 1;
    StateSystem.AddOrUpdateState(target.Unit, (StateType)effect[2], stacks, ownerUnit: enemy.Unit);
}
```

它**完全忽略 `effect[1]`（`EffectTargetType`）**，一律把状态加在 `target.Unit` = 本意图的**索敌目标（永远是角色）**上。连带后果（**均为代码走读结论，当前没有断言覆盖**，建议随 P2-25 一并补断言）：

| 现役写法 | 设计意图 | 当前实际 | 影响 |
|---|---|---|---|
| `3123 = 3;1;6;1`（伴侣共鸣）| 自身加攻 1 层 | **给最近的玩家 +1 攻击** | 反向增益（v1 表里这条"价值 3"实际是给玩家的收益）|
| `3102 = 3;1;6;1`、`3113 = 3;1;6;2`（碎片蓄能 / 号令）| 自身加攻 | 同上 | 同上 |
| `3125 = 3;3;1;3`（导师威压）| **全体角色** 3 层易伤 | 只给**单体** 3 层 | F1-009 的状态轴实际低于文档口径 |
| `3118 = 3;0;2;2`、`3101 = 3;0;1;1` 等 | 对随机一名角色 | 加在最近角色 ✓（恰好吃对）| 与 `BATTLEFIELD_MONSTER_STATE_TARGET_PASS` 口径一致 |

- 因此 §2.2 女方「伴侣共鸣」、§3.2.2 主讲「导师威压（全体）」**都必须等 P2-25**；在此之前配表不要写 `3;1;…`（`Self`）与 `3;3;…`（`AllEnemies`）两种目标类型。
