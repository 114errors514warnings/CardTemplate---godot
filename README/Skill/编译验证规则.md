# 编译与验证规则

> **2026-10-01 调整**：验证按**改动类型分级**——只有改 **C# 代码**才跑 `dotnet build` + `dotnet test`；改**配置**按需跑定向检查；改**文档**不检测。

## 一、总原则（2026-10-01：验证按改动类型分级）

| 改动类型 | `dotnet build` | `dotnet test` |
|---|---|---|
| **C# 代码**：`Scripts/**`、`Tests/**` | ✅ 必须 | ✅ 必须（全量）|
| **配置 / 数据**：`DataBase/**`（CSV / JSON）| ❌ 不需要 | ⚠️ 仅「结构性改动」跑**定向**过滤测试 |
| **文档**：`README/**`、`*.md` | ❌ | ❌ |
| **场景 / 资源**：`Scenes/**`、`Resources/**`、`*.tscn` | ❌ | ❌（`.tscn` 编辑另见 [tscn_no_bom.md](tscn_no_bom.md) / [tscn_utf8_safe_edit.md](tscn_utf8_safe_edit.md)）|

**依据**：配置与文档**不参与编译**，跑 build 得不到任何信息；测试工程的 dll 是构建产物，只有**代码**改动才会让它过期。

## 二、改代码时（必须，顺序不可颠倒）

`Tests/卡牌模拟器.Tests.csproj` 引用的是主项目**已构建的 dll**（`<Reference>` 指向 `.godot/mono/temp/bin/Debug/卡牌模拟器.dll`，而非 `ProjectReference`）——先跑 `dotnet test` 会测到**旧 dll**，所以 build 必须在前：

```powershell
dotnet build 卡牌模拟器.csproj -v q --nologo        # 期望 0 个警告 / 0 个错误
dotnet test Tests\卡牌模拟器.Tests.csproj --nologo  # 期望 失败: 0
```

## 三、改配置时（按需，不必 build）

**结构性改动** = 新增 / 删除 **Id、行、列**，改**枚举取值**、改**跨表引用**、改**地图几何**。有既有测试覆盖时，跑**定向过滤**测试就够（不跑 build、不跑全量）：

```powershell
dotnet test Tests\卡牌模拟器.Tests.csproj --filter "FullyQualifiedName~Monster"
```

| 配置 | 覆盖它的测试 / 断言 |
|---|---|
| `Unit/Monster.csv`、`Battlefield/EnemyIntent.csv` | `MonsterCsvSchemaTests`、`EnemyIntentDamageArgsTests`；整表接线由烟测 `VerifyMonsterTableColumns()` 覆盖 |
| `Balance/MonsterValue.csv` | `MonsterValuePointsTests` |
| `Level/Config/*.csv`、`Level/LevelIndex.csv`、`WorldMap/LevelPool.csv`、`NormalCombatRule.csv` | `StageEncounterPickerTests`、`NormalEncounterCountPerActTests`；端到端由烟测 `VerifyLevelConfigs()` / `VerifyNormalCombatPool()` 覆盖 |
| `BattleMap/Maps/*.json` | `MapGeometryTests`、`MapLayoutTests` |
| `State/*.csv` | `UnitInitialStateConfigTests`、`StateTypeNamesTests` |
| 其余（奖励 / 掉落 / 卡牌数值等） | 暂无覆盖 → **人工核对 + 同步设计文档数值表** |

- **纯数值 / 文案改动**（只改既有单元格的数值与文本，不动结构与引用）→ **不检测**，但必须把同一数值同步到对应设计文档的表格（口径冲突时以《关卡档位表》《怪物总表》等平衡文档为准）。
- **值得额外跑一次烟测**（仍**不**跑 build）的情况：改的是"决定能否进场"的配置——新增关卡 / 新增怪被流程实际加载、池行解析、初始状态解析。命令见 [Godot 运行环境](../AIWorkSpace/Godot运行环境.md) 的 `--battlefield-smoke`（末行须为 `BATTLEFIELD_SMOKE_PASS`）。
- 新增关卡 CSV 后，由 Godot 编辑器或 `--headless --import` 生成 `.import` / `.translation` 边车（与现役关卡一致；运行期 `LoadCsv` 直读文件，不依赖边车）。

## 四、预期结果口径

- build：`0 个警告 / 0 个错误`（出错先修复再继续）
- test：`失败: 0`
- 烟测：末行 `BATTLEFIELD_SMOKE_PASS`
- 以上三项**仅在改代码时要求**；配置改动按 §三 按需检查，文档改动不检测（见 §一 分级表）

（旧口径「每次改完都跑一遍 dotnet」已废止）

## 六、改界面 / 运行局时：定向 API 验证（2026-10-02 起，推荐）

改完**只能在真场景里验证**的东西（背包界面、营地 / 夜间 UI、时间点、战斗表现、地图交互），
**不必**默认陪跑整条 UI 烟测。分层：

| 层 | 命令 | 什么时候 |
|---|---|---|
| ① 纯逻辑 | `dotnet build` + `dotnet test` | 改 `Scripts/**`、`Tests/**` 一律（见 §二） |
| ② **定向 API 点打** | 起一次游戏 + 本机 AI 接口点打**改动模块** | 每一次改完界面 / 运行局相关内容 |
| ③ 全量烟测 | `--run-flow-ui-smoke` + `--battlefield-smoke` | **一批改动收尾 / 提交前**跑一次（当门，不退化成每次都跑） |

- 接口与用法：[跑测使用说明](../功能说明文档/AI接口/跑测使用说明.md)（含各模块配方与 PowerShell 脚手架）；
  越权指令清单：[调试API.md](../功能说明文档/AI接口/调试API.md)。
- **通道红线**：`debug.` 前缀 = 越权（只用于**摆场景**）；判断仍走玩家通道（`battle.*` / `run.*`）。
  新增指令时按这条分文件、分表，`Tests/ApiCommandCatalogTests.cs` 会断死边界。
- 跑测要能还原环境：先备份 `user://run_save_v1.json`，收尾用 `debug.game.quit` 退出并还原备份。
