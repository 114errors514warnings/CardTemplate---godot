# 开发记录规则

> 摘录自 `README/系统规则/开发记录规则.md`（2026-08-29 迁移）

## 月度完成事项记录

进行代码或配置更改后，必须将**主要修改内容**记录到当月施工文档：`README/施工文档/2026/<年.月>/<月>月施工文档.md`。

### 记录原则

1. 记录内容应**完整而简洁**，覆盖本次改动的主要结果与规则变化
2. 在当月文档**顶部新增 `## §N` 小节**（编号沿用该月已有最大编号 +1），小节内写清结果、规则变化与验证方式
3. 若该次改动对应某个设计案 / 需求案，除了在案文件内写「完成情况」，**还必须在月度施工文档中记录同一份实现情况**（两处都要有）
4. 历史月份（5 月、6 月）沿用了 `已完成事项_<年.月>.md`；8 月起统一写进 `<月>月施工文档.md`

### 示例

- 2026-09-21 完成「事件 / 关卡结束后的地图表现」修复 → 在 `README/施工文档/2026/2026.09/9月施工文档.md` 顶部新增 `## §18`，并在对应的案文件里同步「完成情况」

### 适用范围

- 代码逻辑修改
- 配置表结构或语义修改
- UI/交互行为修改
- 重要规则实现或规则调整
- 影响后续开发的关键修复

### 备注

- 记录重点是"**本次完成了什么**"，不是逐文件变更清单
- 若一次改动覆盖多个点，可合并为 1~3 条高信息密度描述
- 默认按当前自然月对应文件记录，例如 `2026.5.md`、`2026.6.md`

## 配套目录结构

完整目录结构与分类口径见 [施工文档目录规范](../../施工文档/README.md)：月份目录下按 `玩法 / 交互 / 战斗` 分类，跨类或无法归类的直接放月份根目录；每个案/待做文件自身带「完成情况」小节。
