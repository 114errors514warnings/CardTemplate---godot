# AI API 跑测使用说明（按模块点打）

> **2026-10-02 流程调整（用户指令）**：改完功能**不再**默认陪跑整条 UI 烟测。
> 现在分三层：**纯逻辑单测 → 定向 API 点打（主力）→ 全量烟测（只在提交门跑一次）**。
> 「点打」= 启动一次游戏，用[本机 AI 接口](README.md)把世界摆成要验证的样子，只执行**被改动模块**的那几步，读响应断言。

## 一、三层验证（用哪层按改动类型定）

| 层 | 做什么 | 什么时候 | 耗时量级 |
|---|---|---|---|
| ① 纯逻辑单测 | `dotnet build` + `dotnet test`（可加 `--filter`） | 改 `Scripts/**`、`Tests/**` 一律跑（见[编译验证规则](../../Skill/编译验证规则.md)） | 秒级 |
| ② **定向 API 点打** | 起一次游戏 → HTTP 点打**改动模块** → 读响应断言 → `debug.game.quit` | 改了界面 / 运行局 / 背包 / 营地 / 战斗表现等**只能在真场景里验证**的东西 | 1–3 分钟 |
| ③ 全量烟测 | `--run-flow-ui-smoke`（图形版）+ `--battlefield-smoke`（headless） | **一批改动收尾 / 提交前**跑一次，作为最后的整体回归 | 整套 ≈ 15 s（2026-10-03 图形版实测；只改一段时用 `--run-flow-ui-smoke=<段名>` ≈ 6 s） |

**省在哪儿**：以前每改一处都要跑到「①③」；现在日常是「①②」，只有准备提交时才补 ③。
②把「进入要测的那一步」的前置全部交给调试通道（选关 / 跳关 / 塞物品 / 改时间点），
所以断言只覆盖真正改动的那几条规则，失败时也不需要翻整条流程的日志。

**改单段就只跑那一段（2026-10-03 补，省时口径）**：整套 UI 烟测把背包 / 地图 / 结算 / 战斗 / 事件 / 营地 / 读档
七段串在一个方法里（含 15 张截图与大量等帧，**图形版实测整套 ≈ 15 s、单段 ≈ 6 s**）；改动只落在其中一段时，用

```powershell
'--','--run-flow-ui-smoke=event-battle'   # 段名见 RunFlowScene.RunUiSmokeSegment 的 switch
```

只跑那一段（≈ 6 s）。建档 / 存档备份 / 收尾与整套走同一条路径，**断言口径不缩水**。
它真正的价值是**隔离失败**：无关段挂 / 前段残留污染不会被算进本段的结论（本轮就吃过一次「前段留下待处理
内容 → 后段 `IsOnMap` 断言挂」的亏）。
末尾打印 `RUN_FLOW_UI_SMOKE_SEGMENT_PASS: <段名>`（失败打 `..._FAIL: <段名>: <原因>` 并退出码 1）。
当前可用段名：`event-battle`（危险事件战斗选项点下即进战）、`time-point-camp`（时间点闸门 / 营地 / 食物烹饪 / 休息结算）。
裸 `--run-flow-ui-smoke` 仍是**整套**回归（提交门）。

## 二、启动与收尾

```powershell
$exe = 'D:\MY\Godot\Godot_v4.6.2-stable_mono_win64\Godot_v4.6.2-stable_mono_win64_console.exe'
$proj = 'D:\MY\My Game\卡牌模拟器'

# 开跑前备份本局存档（API 会写档，收尾要还原）
$save = Join-Path $env:APPDATA 'Godot\app_userdata\卡牌模拟器\run_save_v1.json'
if (Test-Path $save) { Copy-Item -LiteralPath $save -Destination ($save + '.apibak') -Force }

# 起游戏（图形版；GUI / 截图类验证必须图形版，窗口挪到屏幕外）
$p = Start-Process -FilePath $exe -PassThru -ArgumentList @(
  '--path', '"' + $proj + '"', '--position', '3000,3000') `
  -RedirectStandardOutput 'Tests\api-smoke-out.txt' -RedirectStandardError 'Tests\api-smoke-err.txt'
$p.Id    # 只记自己的 PID；不要用 Get-Process 批量杀 Godot
```

- 服务**随游戏启动**就监听 `http://127.0.0.1:17880/api/game/`（autoload，`EnableDebugApi` 可关）。
- `--headless` 下接口照常可用，但**截图**与 GUI 命中类断言仍要图形版。
- 收尾：`POST {"type":"debug.game.quit"}`（比外部杀进程干净）；然后还原存档备份。

## 三、PowerShell 脚手架（复制即用）

```powershell
$u = 'http://127.0.0.1:17880/api/game/'
function Api($json) {
  try   { Invoke-RestMethod -Uri $u -Method Post -Body ([Text.Encoding]::UTF8.GetBytes($json)) `
            -ContentType 'application/json; charset=utf-8' -TimeoutSec 20 }
  catch { $s = (New-Object IO.StreamReader($_.Exception.Response.GetResponseStream())).ReadToEnd()
          $s | ConvertFrom-Json }   # 400 也返回 JSON：errorCode + 原因 + 当刻状态
}
```

要点：

- `-Body` 传 **UTF8 字节数组**，避免 PowerShell 5.1 的原生参数引号坑（用 `curl.exe` 时中文 JSON 会被吃引号）。
- 被规则拒绝时 HTTP 400，但响应体仍是 JSON（`ok=false` + `errorCode` + `data`），所以 `catch` 里也要解析。
- 每条响应都有 `permission`（`玩家` / `调试`）—— 断言时顺手确认自己没跑到越权通道上。
- 更早的示例（纯战斗玩法）见本文 §六 与[战斗指令API](../运行测试说明/战斗指令API.md)。
- **请求用 `curl + 文件 body`（2026-10-05 实测）**：PS 5.1 的 `Invoke-RestMethod` 在 **400 分支**里读响应流会**静默失败**（断言拿到 `$null`，看起来像「API 没回话」，`smithy_craft` / `restaurant_cook` 因此被误判过一次）。稳定写法：body 写 UTF-8 无 BOM 文件 → `curl.exe -s --max-time 60 -X POST -H 'Content-Type: application/json; charset=utf-8' --data-binary '@body.json' $u` → `ConvertFrom-Json`。

## 四、按模块的配方

### 4.1 背包（P0-17 界面半）

```powershell
Api '{"type":"debug.game.new_run"}'                                  # 开局（任意场景都能调）
Api '{"type":"debug.run.back_to_map"}'                               # 回到可选地图
Api '{"type":"debug.run.add_bag_item","category":"equipment","definitionKey":10001,"count":1}'
Api '{"type":"debug.run.add_bag_item","category":"item","definitionKey":301,"count":1}'
$b = Api '{"type":"run.bag.open"}'                                   # 网格 25 格 / 96×96 / 页码文案 / 负荷
$s = Api '{"type":"run.bag.state"}'                                  # 每格格名 + 拖动载荷（链式拖动不用猜下标）
Api '{"type":"run.bag.drag","fromCell":"BagCell_1","toCell":"BagHand_0_0"}'   # 规则拒绝（含原因）
Api '{"type":"run.bag.tab","tab":"equipment"}'                       # 页签（换页签回第 1 页）
Api '{"type":"run.bag.character_tab","slotIndex":1}'                 # 装备栏归属角色
Api '{"type":"run.bag.close"}'
```

「内容进行中」闸门想绕过（只验拖动规则本身）：`debug.run.force_bag_gate`（`reason` 留空 = 强制放行）。

### 4.2 时间点 / 夜间（营地）

```powershell
Api '{"type":"debug.run.back_to_map"}'
Api '{"type":"run.end_day"}'                       # 进营地（= 顶栏「结束当天」）
Api '{"type":"run.camp.state"}'                    # 守夜模式 / 饱食度 / 面板 / 按钮 / 预览文案
Api '{"type":"run.camp.toggle_food"}'
Api '{"type":"run.camp.add_food","instanceId":"bag-100301-001"}'   # 实例键来自 run.bag.state
Api '{"type":"run.camp.cook","recipeId":1}'
Api '{"type":"run.camp.set_watch","mode":"single","watcherSlot":1}'
Api '{"type":"run.camp.rest"}'                     # 回复 → 新一天 → 淡出回地图（约 0.35s 后收）
Start-Sleep -Seconds 2; Api '{"type":"run.state"}' # 断言 day+1、remaining=4.0、campOpen=false
```

- 强制把当天耗光（触发营地转场）：`debug.run.set_time_points` 传 `0`（允许负向）。
- 内容进行中想直接到地图：`debug.run.back_to_map`（放弃当前内容，不结算）。

### 4.3 战斗

```powershell
Api '{"type":"debug.run.select_level","levelId":"F1-001"}'   # 选关（调试通道）
Api '{"type":"battle.state"}'                                # 玩家通道读状态
Api '{"type":"battle.legal_actions"}'
Api '{"type":"battle.move","path":[{"q":-1,"r":0}]}'
Api '{"type":"battle.end_turn"}'
Api '{"type":"battle.wait_idle"}'                            # 轮询到 idle=true
Api '{"type":"battle.events","afterEventId":0,"limit":50}'
Api '{"type":"debug.battle.spawn_enemy","q":3,"r":0,"unitId":3101}'   # 摆怪（越权）
Api '{"type":"debug.battle.clear_enemies"}'                           # 一键判胜
```

### 4.4 地图 / 选关 / 跳关

```powershell
Api '{"type":"debug.run.map_state"}'            # 全图节点（类型 / 已访问 / 可达 / 当前）
Api '{"type":"run.map.state"}'                  # 玩家口径（可达格列表）
Api '{"type":"run.map.enter_next"}'             # 点第一个可达格（玩家入口）
Api '{"type":"debug.run.next_combat"}'          # 一键跳到最近的未访问战斗格
Api '{"type":"debug.run.select_level","levelId":"F1-H-001"}'
```

### 4.5 截图与出图核对

```powershell
Api '{"type":"debug.game.capture","name":"bag","captureMode":"compressed"}'  # 任意场景
Api '{"type":"debug.capture","name":"battle"}'                               # 战斗内
```

产物统一在 `Tests/ApiCaptures/`（不进库）。

### 4.6 结算：领取 / 关闭（P3-18 收口）

```powershell
Api '{"type":"debug.run.next_combat"}'          # 摆场景：跳到最近的未访问战斗格
Start-Sleep -Seconds 2
Api '{"type":"debug.run.complete_level"}'       # 一键判胜 → 走正常结算（面板 / 选卡）
Start-Sleep -Seconds 3
$s = Api '{"type":"run.settlement.state"}'      # items[].claimKey；cardPools[].{slotIndex,candidateCardIds}
foreach ($i in $s.data.items)   { Api ('{"type":"run.settlement.claim","claimKey":"'      + $i.claimKey + '"}') }
foreach ($p in $s.data.cardPools) { Api ('{"type":"run.settlement.claim_card","slotIndex":' + $p.slotIndex + ',"cardId":' + $p.candidateCardIds[0] + '}') }
$s2 = Api '{"type":"run.settlement.state"}'     # unclaimedCount 应为 0
Api '{"type":"run.settlement.close_panel"}'     # 领完 → 回地图；没领完 → 待领取态 + 浮窗
Start-Sleep -Seconds 2; Api '{"type":"run.state"}'   # 断言 ui.settlementOpen=false、ui.mapSelectable=true
```

### 4.7 村庄（地点场景）

```powershell
Api '{"type":"debug.game.new_run"}'
Start-Sleep -Seconds 2
Api '{"type":"debug.run.back_to_map"}'          # 放弃起始事件（否则后面进不去任何节点）
Api '{"type":"run.end_day"}'; Start-Sleep -Seconds 1; Api '{"type":"run.camp.rest"}'   # 休息一天 → 清 PendingRestDay
Start-Sleep -Seconds 3
Api '{"type":"debug.run.set_gold","amount":500}'
Api '{"type":"debug.run.set_time_points","value":4}'
Api '{"type":"debug.run.add_bag_item","category":"material","definitionKey":202,"count":2}'   # 打造要 铁矿石 ×2
Api '{"type":"debug.run.add_bag_item","category":"material","definitionKey":101,"count":2}'   # 现做要 药草 ×2
Api '{"type":"debug.run.add_bag_item","category":"material","definitionKey":102,"count":1}'   # 现做要 苔藓 ×1
$m = Api '{"type":"debug.run.map_state"}'
$node = ($m.data.nodes | Where-Object { $_.type -eq 'Village' } | Select-Object -First 1).nodeId
Api ('{"type":"debug.run.enter_node","nodeId":' + $node + '}')     # 摆场景：直接进村庄（越权）
Start-Sleep -Seconds 2
$v = Api '{"type":"run.village.state"}'                            # 19 可走格 / 7 版图行 / plots[].{kind,entranceNodeId}
$entrance = @{}; foreach ($p in $v.data.plots) { $entrance[$p.kind] = $p.entranceNodeId }
Api ('{"type":"run.village.walk_to","nodeId":' + $entrance['Forest'] + '}')   # 走到树林门口 → 弹 tips
Api '{"type":"run.village.tips_accept"}'                            # 搜寻一次（扣树林专属 1.0）
Api ('{"type":"run.village.walk_to","nodeId":' + $entrance['Smithy'] + '}')
$s = Api '{"type":"run.village.smithy_state"}'                      # craftsLeft / recipeDefinitionIds / craftDisabled
Api ('{"type":"run.village.smithy_select","definitionId":"' + $s.data.recipeDefinitionIds[0] + '"}')
Api '{"type":"run.village.smithy_craft"}'                           # 次数 −1、时间点 −0.1、装备进背包
Api '{"type":"run.village.close"}'
Api ('{"type":"run.village.walk_to","nodeId":' + $entrance['Restaurant'] + '}')
Api '{"type":"run.village.restaurant_state"}'                       # shelf / cooksLeft / cookableRecipeIds
Api '{"type":"run.village.restaurant_cook","recipeId":1}'           # 现做一次（扣 0.1 + 材料、产物打「现做」标）
Api '{"type":"run.village.restaurant_order","index":0}'             # 点菜（扣 0.1 + 菜价）
Api '{"type":"run.village.restaurant_sell","instanceId":"<run.bag.state 里的食物实例>"}'
Api '{"type":"run.village.exit"}'                                   # 走到离开格 → 回地图 + 节点已访问
```

- **摆场景顺序不能颠倒**：新局会先跑**起始事件**，事件跨过日界后 `pendingRestDay=true`，此时**任何节点都进不去**（`EnterNode` 的时间点闸门会转营地，而「内容进行中」又不许进营地）→ 必须先 `back_to_map`，再 `end_day` + `camp.rest`。
- 已有 headless 实跑的完整验收脚本（一条会话跑完村庄 + 结算两条链，69 条断言全绿，含存档哈希核对）：按上面 4.6 / 4.7 两段照跑即可复现。

## 五、发现 API 缺口怎么办

**新功能做完就补 API**（用户口径）：

- 玩家在界面上能做的 → 加到**玩家通道**（`PlayerApi*`），并在 `RunFlowScene` / UI 类上开一个
  「等同点一下」的窄口；
- 只有测试才需要的摆场景能力 → 加到**调试通道**（`DebugApi*` + `RunSession.Debug.cs` / `BattlefieldSession.Debug.cs`）。

两处都要：① 表里加一条 `ApiCommandInfo`；② 绑上处理器。`dotnet test` 里 `Tests/ApiCommandCatalogTests.cs`
会检查类型名唯一、通道前缀一致、处理器与元数据齐；运行时 `api.catalog` 的 `integrity` 会报同一批问题。

## 六、已实测覆盖（2026-10-02，图形版实跑）

- 进程启动即监听；`GET` = 全局摘要；`api.catalog` 的 `integrity.ok=true`。
- `debug.game.new_run` → 切场景进本局；`run.state` 读回天数 / 剩余时间点 / 角色槽 / 界面形态。
- 背包：`add_bag_item` ×2 → `run.bag.open`（25 格、全部 `96×96`、`第 1 / 1 页`、负荷 `2.3 / 30.0`）→
  `run.bag.drag` 被**规则**拒绝（`DROP_REJECTED`「双手装备不能与其它手位装备互换（先卸下）」+ 横幅）→
  道具入随身格成功（`carry|0`、负荷降到 `2.0`）→ `tab` / `character_tab` / `close` 均生效。
- 时间点 / 夜间：`run.end_day` 进营地 → `run.camp.state` → `toggle_food` → `set_watch single/slot1`
  （预览文案含「单人守夜（精灵 不回复）」）→ `toggle_watch` → `run.camp.rest` → 次日 `day=2 remaining=4.0`、
  营地已销毁、回到可选地图。
- 地图：`debug.run.map_state` 读出 127 个节点；`debug.run.next_combat` 跳到战斗格 7。
- 越权拦截：不在营地时 `run.camp.set_watch` 返回 `NO_CAMP`（玩家通道的守卫照常生效）。
- 截图：`debug.game.capture` 落 `Tests/ApiCaptures/apibag-*.png`；`debug.game.quit` 干净退出（退出码 0）。

> 更早的一批实测（2026-09-15，纯战斗玩法）见 9 月文档：状态 / 合法操作 / 事件 / 空闲 / 截图、角色切换与移动、
> 治疗药剂拾取与使用、五把武器的拾取装备卸装、投掷类道具、结束回合与怪物行动。

## 七、仍需跑全量烟测的情况

- 一批改动收尾 / 提交前（把 ③ 当门）。
- 改动**跨段**（例如结算 → 战后 → 地图 → 营地整条链）：`--run-flow-ui-smoke=<段名>` 只管一段，跨段要跑整套。
- 改动涉及 `DataBase/**` 的「能否进场」类配置（新增关卡 / 新怪）→ 见[编译验证规则](../../Skill/编译验证规则.md) §三。

启动命令与进程管理注意事项见 [Godot 运行环境](../../AIWorkSpace/Godot运行环境.md)。
