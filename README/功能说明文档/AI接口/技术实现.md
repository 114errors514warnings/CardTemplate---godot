# AI API 技术实现

> 2026-10-02 重构：从「战斗场景自带一个 HTTP 服务」改成 **autoload 单服务 + 域注册 + 两条通道**。
> 目的：一个端口同时服务战斗与运行局，且「玩家范围」与「越权」在代码结构上就分开。

## 架构

```text
HTTP 线程（HttpListener）
  → ApiHttpServer            只解析 JSON 与拼响应
  → ApiService.pending       线程安全队列
  → ApiService._Process      Godot 主线程泵
  → 域注册表（battle / run / debug.*）
     ├─ PlayerApiBattle / PlayerApiRun   通道 = 玩家（battle.* / run.*）
     └─ DebugApiBootstrap / DebugApiRun / DebugApiBattle   通道 = 调试（debug.*）
  → 会话 / 场景的公开入口（BattlefieldSession、RunSession、RunFlowScene 的 API 访问面）
```

实现文件（`Scripts/Api/`）：

| 文件 | 职责 |
|---|---|
| `ApiContracts.cs` | 请求 / 响应 / `ApiLane` / 通道判据 `ApiLanes` / 指令元数据 / 场景句柄（**不引用 Godot 之外的逻辑**） |
| `ApiHttpServer.cs` | 本地 HTTP（唯一 socket；`GET` → `api.read`） |
| `ApiService.cs` | autoload 单例：懒启动监听、域注册（按 owner 记账）、主线程泵、`api.*` 元指令与自检 |
| `ApiEventJournal.cs` | 只读事件日志（消息 / 入格 / 攻击 / 胜负） |
| `ApiBattleSnapshot.cs` | 战斗只读投影（状态 / 手牌 / 装备 / 地图 / 合法操作） |
| `ApiRunSnapshot.cs` | 运行局只读投影（本局 / 背包 / 营地 / 地图 / 结算） |
| `PlayerApiBattle.cs` · `DebugApiBattle.cs` | 战斗域两条通道 |
| `PlayerApiRun.cs` · `DebugApiRun.cs` | 运行局域两条通道 |
| `DebugApiBootstrap.cs` | 服务级引导域（开局 / 切场景 / 截图 / 退出） |
| `Scenes/Api/ApiService.tscn` | autoload 场景（`project.godot` 已登记） |

## 关键决定

1. **单一端口**：`ApiService` 是唯一持有 `HttpListener` 的地方。原先 `HexBattleScene` 自带服务，
   运行局（地图 / 营地 / 背包）根本没有接口可用；现在战斗场景只**登记**自己的域。
2. **懒启动**：`EnsureStarted` 在第一次有域登记时监听；服务级引导域在进程启动时就登记，因此
   **任何场景都能用 `debug.game.*` 开局**（不必先从主菜单手点）。
3. **按 owner 记账**：换场景时旧场景是延迟释放的，`_ExitTree` 会晚于新场景的 `_Ready`。
   登记项带 `owner`（场景实例），注销只摘自己那份，避免「新场景刚登记就被旧场景摘掉」。
4. **通道由前缀判**：`ApiLanes.LaneOf(type)` 是唯一判据；`ApiService.Catalog()` 的 `integrity` 会报
   「类型名重复 / 前缀与声明通道不符 / 处理器缺元数据」，`Tests/ApiCommandCatalogTests.cs` 在纯 .NET 下断死同一批不变量。
5. **场景只给「访问面」**：`RunFlowScene` 暴露 `Bag` / `Camp` / `Map` / `Settlement` 与
   `ToggleBagUi` / `TryEndDay` / `TryEnterReachableNode` 等**等同于点一下**的方法；带 `Debug` 前缀的方法
   （`DebugSelectLevel` / `DebugNextCombat` / `ApiBackToMap`）只由调试域调用。
6. **拖动通路唯一**：`run.bag.drag` → `BagUi.DragCell` → `ApplyDrop` → `RunSession` 整理 API，
   与鼠标拖放是同一条路（所以 API 能覆盖到的规则 = 玩家真能动到的规则）。

## 状态与响应

- `api.read`（GET）= `{ port, domains, battle 摘要, run 摘要 }`。
- `api.catalog` / `api.lanes` = 全部指令 + 通道 + 用途 + 字段提示 + `integrity` 自检结果。
- `api.events` = 事件日志（`afterEventId` + `limit` 增量拉取，环形缓冲 500 条）。
- 失败响应带 `errorCode`（`DROP_REJECTED` / `NO_CAMP` / `NO_BAG` / `PLAYER_PERMISSION` …）与原因文案；
  规则拒绝时 `data` 仍带当刻状态，调用方一次就能拿到「为什么 + 现在什么样」。
- `responseMode`：`none` / `summary`（默认）/ `full` 控制写指令回包体量。
- 截图产物统一落 `Tests/ApiCaptures/<name>-<yyyyMMdd-HHmmss>.png`（名称过滤为字母数字，防任意路径写入）。
