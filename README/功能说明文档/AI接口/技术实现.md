# AI API 技术实现

## 架构

```text
HTTP 请求线程
  → BattleApiHttpServer
  → BattleApiHost.pending
  → HexBattleScene._Process（Godot 主线程）
  → BattleApiRouter
  → BattlefieldSession 正式规则入口
  → JSON 响应 / 状态快照 / 事件
```

实现文件：

- `Scripts/Battlefield/Api/BattleApiHost.cs`：主线程队列与 API 生命周期
- `Scripts/Battlefield/Api/BattleApiHttpServer.cs`：HTTP 监听与 JSON 收发
- `Scripts/Battlefield/Api/BattleApiRouter.cs`：玩家指令到正式规则入口的映射
- `Scripts/Battlefield/Api/BattleApiSnapshot.cs`：状态与合法操作快照
- `Scripts/Battlefield/Api/BattleApiContracts.cs`：请求、响应与坐标 DTO
- `Scripts/Battlefield/Api/BattleApiEventJournal.cs`：只读战斗事件日志
- `Scripts/Battlefield/Presentation/HexBattleScene.cs`
- `Scripts/Battlefield/Runtime/BattlefieldSession.cs`

`HttpListener` 仅接收和解析请求；不得从网络线程直接修改 Godot 节点或战斗数据。请求被放入线程安全队列，由场景 `_Process` 在主线程调用现有 `BattlefieldSession` 方法。

## 状态快照

`battle.state` 返回：

- 战斗阶段、回合、当前角色；
- 全部单位的 ID、阵营、HP、护盾、能量、坐标、Presence；
- 怪物意图展示数据；
- 三名角色的手牌实例 ID、CardId、名称和费用；
- 当前角色的左右手、随身栏；
- 全图地面物品、触发物件及其实例 ID、空间规格和数值。

实例 ID 是道具拾取、装备和地面道具使用 API 的唯一操作标识。

## 合法操作

`battle.legal_actions` 只从当前规则状态推导结果，不授予额外能力：

- 每个可达终点及其合法路径；
- 当前手牌每张卡的实际费用、是否需要目标、可执行状态、不可执行原因与可选目标格；
- 当前格物件。

调用方必须从该结果中选择坐标和卡牌；服务端仍会在执行时二次校验费用、回合、目标、路径、占位和物件状态。

## 事件与表现

`BattleApiEventJournal` 订阅战斗消息、单位入格、攻击结算和胜负事件；每条记录分配连续 ID，`battle.events` 只读返回当前事件队列。

`battle.wait_idle` 返回当前怪物回合和表现队列是否结束；调用方应轮询至 `idle=true` 后读取状态或截图。

`battle.capture` 在 Godot 主线程读取当前视口并保存 PNG 至：

```text
Tests/ApiCaptures/<name>-<timestamp>.png
```

名称会过滤为字母数字，避免 API 任意写入项目外路径。
