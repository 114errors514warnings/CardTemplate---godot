# 战斗数据配表规范

> 本文是其他 Agent 配置正式战斗数据的唯一操作规范。配置使用 UTF-8 CSV；首行为英文表头；枚举大小写必须与本文一致；ID 不得有空格。

## 目录与总表

| 数据 | 总表 | 分文件 |
|---|---|---|
| 正式地图 | `DataBase/BattleMap/MapIndex.csv` | `DataBase/BattleMap/Maps/<MapId>.json` |
| 正式关卡 | `DataBase/Level/LevelIndex.csv` | `DataBase/Level/Config/<LevelId>.csv` |
| 掉落表 | `DataBase/Reward/DropTableIndex.csv` | `DataBase/Reward/Config/<DropTableId>.csv` |
| 地图节点内容 | `DataBase/WorldMap/*.csv` | 普通战斗规则、关卡池、事件池、固定节点绑定 |
| 交互点定义 | `DataBase/Level/InteractPoint.csv`（默认落点，待确认） | 无分文件：一行一个交互点（设施 / 商人 / 入口格 / 离开格），见「交互点定义表」 |

所有总表都严格使用两列：

```csv
<IdColumn>,ConfigPath
```

- `<IdColumn>` 分别为 `MapId`、`LevelId`、`DropTableId`。
- ID 在本表中必须唯一。
- `ConfigPath` 必须是项目内的 `res://` 路径，且文件必须存在。
- 正式内容只能通过 `MapIndex.csv` 的 `MapId` 引用地图；不得写入已移除的测试地图路径。

## 地图节点内容配置

文件均位于 `DataBase/WorldMap/`：

| 文件 | 固定表头 | 当前作用 |
|---|---|---|
| `NormalCombatRule.csv` | `Act,MinCombatCount,MaxCombatCount,Difficulty` | 普通战斗次数映射到难度 |
| `LevelPool.csv` | `PoolId,Act,NodeType,Difficulty,LevelId,Weight` | 普通/高危等随机战斗节点从关卡池加权选取 `LevelId` |
| `EventPool.csv` | `Act,NodeType,ConditionId,EventId,Weight` | 随机事件节点加权选取 JSON 事件 |
| `FixedNode.csv` | `Act,NodeKey,NodeType,ContentType,ContentId,Weight` | 村庄、三个精英位置、Boss 固定位置的直接或池化内容 |

`ConditionId` 当前必须留空；不得自行填入枚举。`FixedNode.csv` 中同一个 `Boss` 节点键允许多条 `Level` 行，运行时按 `Weight` 随机选择三种 Boss 关卡之一。

## 全局变量

文件：`DataBase/GameVariables.csv`；路径由 `DataBase/FilePathRegistry.csv` 的 `Data.Game.Variables` 注册。

固定表头：

```csv
Scope,CharacterId,DefaultEnergyPerTurn,DefaultDrawCardsPerTurn,MovesPerTurn,MoveTimePointCost,VillageOperationTimePointCost,ForestForageTimePointCost
```

必须包含且只能包含一行全局行：

```csv
Global,,4,5,,0.3,0.1,1.0
```

| `Scope` | `CharacterId` | 能量/抽牌列 | `MovesPerTurn` | 作用 |
|---|---:|---|---:|---|
| `Global` | 留空 | 必填非负整数 | 留空 | 全角色每回合基础能量、基础抽牌数 |
| `Character` | 必填，且存在于 `Character.csv` | 留空 | 必填非负整数 | 覆盖该角色的基础移动次数 |

示例：

```csv
Character,1002,,,3,,,
Character,1003,,,3,,,
Character,1004,,,3,,,
```

第 6–8 列（时间点进程 / 代价；三列都可留空；2026-10-05 起启用，第 7 / 8 列为 2026-10-05 第四轮新增）：

| 项 | 口径 |
|---|---|
| 语义 | 世界地图「**节点 → 相邻节点**」移动一次消耗的时间点进程（[地图玩法 §5.1](../../../玩法说明文档/系统规则/地图玩法/地图玩法.md)） |
| 填哪一行 | **只填 `Global` 行**；`Character` 行留空 |
| 取值 | 必须 **&gt; 0** 的有限数，且与时间点的最小计量单位 **0.1** 对齐（恒为 0.1 的整数倍） |
| 留空 | 等于「不改数值」：消费方回落到默认 **0.3**（`RunTimePoints.MoveCost`） |
| 消费点 | `MapScene.EnterNode` 的移动闸门与支付（点数不足 → 转营地休息）；改表即生效，无需改代码 |
| 坏表 | 填了非数字 / ≤ 0 → `FormatException`（不静默降级） |
| 文件级校验 | `Tests/GameVariablesTableTests.cs`（表头列序 / 全局行取值 / 角色行留空） |
| 第 7 列 `VillageOperationTimePointCost` | **村庄设施「每次操作」**的时间点代价（锻造 / 烹饪 / **点菜（餐厅买入）**；2026-10-05 第四轮用户口径 = **`0.1`**，即 1 个战斗回合）。语义 / 填哪一行 / 取值 / 坏表 / 文件级校验与第 6 列同一口径（只填 `Global` 行、> 0 且对齐 0.1、填坏值 → `FormatException`） |
| ↳ 留空 / 消费点（第 7 列） | 留空 = 回落默认 **0.1**（`RunFacilityCosts.DefaultOperationCost`）；消费链 = `GameVariables.ApplyFacilityCosts()`（**2026-10-06 起在「世界地图开启」时调** = `MapScene._Ready`；原调用点 `VillageScene._Ready` 随村庄专用场景撤除，见 [10 月施工文档 §34](../../../施工文档/2026/2026.10/10月施工文档.md)）→ `RunFacilityCosts.OperationCost` → `SmithyCrafting.CraftTimePointCost` / `RestaurantTrade.CookTimePointCost` / `RestaurantTrade.OrderTimePointCost`；扣费在 `RunSession.Place` 的四处操作结算（搜寻之外）与 `SmithyUi` / `RestaurantUi` 的按钮态 |
| 第 8 列 `ForestForageTimePointCost` | **树林「单次搜寻」**的时间点代价 —— 与第 7 列**分开配**（用户口径「树林里搜索的耗时与村庄其他操作不同」），当前 = `1.0`。其余口径同上 |
| ↳ 留空 / 消费点（第 8 列） | 留空 = 回落默认 **1.0**（`RunFacilityCosts.DefaultForestForageCost`）；消费链同上 → `VillageForage.TimePointCost` / `VillageForage.CanSearch`；扣费在 `RunSession.TryForageMaterials` |
| 文件级校验（第 7 / 8 列） | `Tests/GameVariablesTableTests.cs`（表头 8 列列序 / 三项取值可解析、对齐 0.1、等于代码兜底、两项互不相等 / 角色行三列留空）+ `Tests/RunFacilityCostsTests.cs`（表值灌入运行期取值与复位） |

- 地点**局内**（村庄，将来的商人）的移动**不**消耗时间点，与第 6 列无关（[村庄地图交互案](../../../施工文档/2026/2026.10/交互/村庄地图交互案.md) §四）。**2026-10-06 起村庄专用地点场景已撤除**（[10 月施工文档 §34](../../../施工文档/2026/2026.10/10月施工文档.md)）—— 本条是给「统一关卡通道落地后的地点关」留的口径。
- **进入设施本身不是操作**：第 7 / 8 列只在「执行一次操作」时收（旅馆的 1 金币是过夜费、民宿免费，都不看这两列）；出售食物等纯交易也不计。

读取入口为 `GameVariables.Load()`。基础能量写入 `CharacterInstance.Max_costs`，基础抽牌数写入角色模板，移动次数写入 `Character.MovesPerTurn`；装备移动修正会在此基础上叠加。不得为同一角色配置两行 `Character`；未配置角色当前会得到 0 次基础移动。

## 正式地图 JSON

文件：`DataBase/BattleMap/Maps/<MapId>.json`。

正式地图只保存永久地形。必须满足：

```json
{
  "MapId": "M-F1-001",
  "Version": 1,
  "Seed": 1001,
  "CellRadius": 42,
  "Shape": "Hexagon",
  "Radius": 6,
  "PlayerSpawnCoords": [{ "Q": 0, "R": 0 }, { "Q": 1, "R": 0 }, { "Q": 0, "R": 1 }],
  "PlayerCharacterIds": [1002, 1003, 1004],
  "MonsterIds": [3101],
  "CellOverrides": [],
  "GenerationExcludedCoords": [{ "Q": 0, "R": 0 }, { "Q": 1, "R": 0 }, { "Q": 0, "R": 1 }],
  "RandomObstacleCount": 0,
  "RandomItemCount": 0,
  "RandomItemDefinitions": [],
  "MinEnemyDistance": 0,
  "MaxGenerationAttempts": 1,
  "ObjectPlacements": []
}
```

`PlayerCharacterIds`、`MonsterIds` 是当前 JSON 解析器要求的占位字段；正式运行局会用运行局角色和关卡 CSV 的怪物覆盖它们。

正式地图约束：

- `ObjectPlacements` 必须为 `[]`。
- `RandomItemCount` 必须为 `0`，`RandomItemDefinitions` 必须为 `[]`。
- `CellOverrides` 仅允许永久 `Obstacle`、`Ground`、`Pit` 及永久 `BlocksSight`。
- 不可在地图 JSON 配置怪物、道具、装备、陷阱、机关、保护目标、可变地形或可摧毁障碍。
- 三个 `PlayerSpawnCoords` 必须两两相邻、可通行且不重叠。

## 单关卡 CSV

文件：`DataBase/Level/Config/<LevelId>.csv`。

固定表头：

```csv
MapId,DropTableId,LevelType,Difficulty,InstanceId,ObjectType,DefinitionId,Q,R,Facing,InitialValue,Extra
```

示例：

```csv
M-F1-001,2001,NormalCombat,Low,F1-001-M01,Monster,3101,-1,-4,,,
M-F1-001,2001,NormalCombat,Low,F1-001-M02,Monster,3102,-3,-1,,State=1:2|HP=12,
M-F1-001,2001,NormalCombat,Low,F1-001-T01,Trap,毒雾陷阱,0,-2,,,EveryEntry
M-F1-001,2001,NormalCombat,Low,F1-001-G01,ProtectedTarget,商队马车,1,-3,,HP=18,
```

前四列是该关卡的固定绑定，文件内每一行必须完全一致：

| 字段 | 允许值/格式 |
|---|---|
| `MapId` | 必须存在于 `MapIndex.csv` |
| `DropTableId` | 必须存在于 `DropTableIndex.csv` |
| `LevelType` | `NormalCombat`、`HighRiskCombat`、`EliteCombat`、`Boss`、`Event`、`Village`、`Merchant`、`Survival` |
| `Difficulty` | `Low`、`Mid`、`High` |
| `InstanceId` | 本关卡唯一；建议 `<LevelId>-<类型缩写><序号>`。除做对象标识外，也作为"**按实例记账**"的稳定键（如怪物窃取金币的 `StolenGoldEntry.InstanceId`，见[状态系统 §2.4](../../战斗系统/状态系统.md)） |
| `ObjectType` | `Monster`、`Item`、`Equipment`、`Trap`、`Mechanism`、`VariableTerrain`、`DestructibleObstacle`、`ProtectedTarget`、**`InteractPoint`**（交互点；2026-10-06 新增：地点内一切可交互单位 —— 设施 / 商人 / 入口格 / 离开格**共用这一个类型**，见本文「交互点定义表」） |
| `DefinitionId` | 对应对象模板 ID；怪物必须引用 `Monster.csv` 的数字 ID；`InteractPoint` 引用 `InteractPoint.csv` 的 `DefinitionId`（如 `Inn` / `Grove` / `Merchant` / `Entrance` / `Exit`）—— **区分靠 `DefinitionId`，不靠新增 `ObjectType`** |
| `Q,R` | 已存在、可用的轴向格坐标 |
| `Facing` | 可空；使用 `Q;R` 方向，如 `1;0`（合法值即六邻格偏移之一：`1;0`、`1;-1`、`0;-1`、`-1;0`、`-1;1`、`0;1`）。**当前未实装**：解析层不读该列（`BattleLevelCatalog.Parse` 只读 `f[0..8]`、`f[10]`、`f[12]`），运行时与表现层也都没有朝向；填任何值（含非法值）都不生效、也不报错，已填值仅作设计意图留档。见[9月施工文档 §40](../../../施工文档/2026/2026.09/9月施工文档.md) |
| `InitialValue` | 可空；对象初始值，`\|` 分隔的 `Key=Value` 列表，在**战斗开始时**写入该对象。当前机制消费 `HP=<正整数>`（初始生命，超过模板上限时按上限截断）与 `State=<StateType>[:<层数>]`（初始状态，可重复并按序叠加；层数省略按 1 层；不可叠加状态只落 1 层）。`StateType` 可写枚举名（`Steal`）或 `通用State.csv` 编号（`21`）。**未定义的键原样保留、不报错也不丢弃**；已知键的值非法（`HP=0`、层数 ≤0、StateType 不存在）或条目缺少 `=` 会在战斗开始时报错并带出原始文本。完整语法、示例与生效链路见[对象初始值](对象初始值.md)。 |
| `Extra` | 可空；触发方式或对象扩展参数，例如 `EveryEntry`。**2026-10-07 起解析层已读该列**（`BattleLevelCatalog.Parse` → `BattleLevelObject.Extra`）：`InteractPoint` 行写 `Door` = 该行是**可通行、踏入即触发该交互点**的门口格，留空 = 本体格（不可通行、不触发）。见 [10 月施工文档 §35](../../../施工文档/2026/2026.10/10月施工文档.md) |
| `BattleRule` | **关卡级变量**，可空；第 13 列，值 = `BattleRuleKind` 枚举名（如 `BanditEscalation`），多个用 `\|` 分隔；留空/缺列 = 无额外规则。**同一关卡内所有行必须一致**，写未知规则名报错。规则不绑地图：换关卡填上即可复用；机制见[战斗规则](../../战斗系统/战斗规则.md)。 |

- **`LevelType` 是字符串列，由统一关卡流程分流**：战斗关（`NormalCombat` / `HighRiskCombat` / `EliteCombat` / `Boss`）、生存关（`Survival`，`MonsterValuePoints.IsSurvivalLevelType` 消费；**通关总是全额折损**）、事件关（`Event`）、**非战斗地点关（`Village` / `Merchant`）** —— 2026-10-06 用户强制规定：村庄 / 商人一律走关卡统一流程配置、不做专用场景，见 [10 月施工文档 §33](../../../施工文档/2026/2026.10/10月施工文档.md)。

- **空值必须留空，不要写 `None`**：`None` 是表格导出时空单元格留下的**字面量**，会被当成真实内容读入（`InitialValue=None` 会在战斗开始时报错，实例见[9月施工文档 §40](../../../施工文档/2026/2026.09/9月施工文档.md)）。`--battlefield-smoke` 的 `VerifyLevelConfigs()` 会对 `LevelIndex.csv` 的每个关卡查这条 + 按运行局路径建场自检。
- **`Facing` 是预留列**：目前**没有任何代码消费**（`Scripts/` 全库检索 `facing` 零命中，详见上表）。数据现状（观察，非文档规定）：西侧怪填 `1;0`、东侧怪填 `-1;0`，即"面向战场中央/玩家出生侧"；`F1-B-00*`、`F1-E-00*`、`F1-H-001` 这 7 个关卡留空。

对象占位规则：

- `Monster`、`VariableTerrain`、`DestructibleObstacle`、`ProtectedTarget` 占据单位层；同一格最多一个。
- `Item`、`Equipment`、`Trap`、`Mechanism` 使用物件层；具体叠放/排他规则以战斗物件系统为准。
- 同一 `InstanceId` 不得重复；同一单位层坐标不得重复。
- 第一阶段正式运行局已接入 `Monster` 固定出生；其余 `ObjectType` 的模板和运行时生成将在相同 CSV 结构上继续接入，Agent 可按本规范预配，但不能把它们写进地图 JSON。
- **`InteractPoint`（交互点，2026-10-06）占单位层**，同一格最多一个（与 `Monster` 同层）。一行一格：一个交互点占几格就写几行，多行共享同一个 `DefinitionId`；本体格默认不可通行，标记为门的行（`Extra = Door`）可通行且踏入即触发该交互点。见下节。

## 交互点定义表（新增，2026-10-06）

文件（默认落点，待用户确认）：`DataBase/Level/InteractPoint.csv`。

固定表头（草案，待用户确认）：

```csv
DefinitionId,Name,Trigger,Ui,TimePointCost,GoldCost,Params
```

| 字段 | 规则 |
|---|---|
| `DefinitionId` | 交互点定义 ID，本篇内唯一；关卡 CSV 第 7 列填它。取值为 ASCII 单词（如 `Inn` / `Merchant` / `Exit`），**不得**有空格 |
| `Name` | 显示名（名称牌 / 标题行） |
| `Trigger` | 触发形态：`Door`（踏入门口格触发）/ `Adjacent`（走到相邻格自动触发，商人口径）/ `None`（无可交互内容，如入口格） |
| `Ui` | 触发的界面 / tips 标识；`None` = 不开界面（入口格 / 离开格） |
| ↳ 关于 `None` | 这里的 `None` 是**枚举值**（表示「没有」），与「空单元格禁止写字面量 `None`」的数据纪律**不是一回事**：枚举列要表达「无」时写 `None`，**空单元格仍必须留空**（见本节上方「空值必须留空，不要写 `None`」） |
| `TimePointCost` / `GoldCost` | **进入 / 操作**代价（可空 = 0）；「每次操作」的时间点代价仍读 `GameVariables.csv` 第 7 列，本表不重复承载 |
| `Params` | 行内扩展参数（`\|` 分隔 `Key=Value`），与关卡 CSV 的 `InitialValue` 同一语法 |

- **一个 `ObjectType`，不细分**：设施 / 商人 / 入口格 / 离开格**都是 `InteractPoint`**，区别只在 `DefinitionId` 指向本表的哪一行 —— 与「不同的怪都是 `Monster`、靠 `DefinitionId` 指向 `Monster.csv` 不同行」完全同构。⛔ 不得为它们各开一个 `ObjectType`（`Facility` / `Merchant` / `Entrance` / `Exit` / `Door`…）。
- 本表**只放交互点的行内参数**；具体机制（旅馆过夜、锻造配方、货架、搜寻权重）仍由各自的系统表与交互案承载，不往本表堆机制。
- 首个落地版的建议取值（村庄 / 商人）：`Entrance`（世界地图进入点）/ `Exit`（离开格）/ `Inn` / `Guesthouse` / `Smithy` / `Restaurant` / `Forest`（村庄 5 设施）/ `Merchant`（商人）。
- 落地状态：**已实装（2026-10-07）**：首版表 `DataBase/Level/InteractPoint.csv`（8 行：`Entrance` / `Exit` / `Inn` / `Guesthouse` / `Smithy` / `Restaurant` / `Forest` / `Merchant`）+ 解析层 `InteractPointCatalog` + **统一非战斗地点视图** `PlaceLevelView`（村庄关 `F1-V-001` / 商人关 `F1-M-001`）；表头与落点按本节草案落，待拍板项（B19 落点 / B20 门口格标记法）见 [10 月施工文档 §35](../../../施工文档/2026/2026.10/10月施工文档.md)。

## 掉落表 CSV

文件：`DataBase/Reward/Config/<DropTableId>.csv`。

固定表头：

```csv
RewardGroup,RewardType,ReferenceId,MinAmount,MaxAmount,Probability
```

示例：

```csv
Gold,Gold,,35,50,1
Card,Card,Common,1,1,0.70
Card,Card,Uncommon,1,1,0.25
Card,Card,Rare,1,1,0.05
```

| 字段 | 规则 |
|---|---|
| `RewardGroup` | 同组奖励共用一次抽取逻辑；`Gold`、`Card`、`Material` 等 |
| `RewardType` | `Gold`、`Card`、`Material`、`Item`、`Equipment`、`Key` |
| `ReferenceId` | `Card` 填 `Common`、`Uncommon`、`Rare`；材料/道具/装备填其定义 ID；金币留空 |
| `MinAmount` / `MaxAmount` | 非负整数，且 `MinAmount <= MaxAmount` |
| `Probability` | `0`–`1` 小数；同一 `DropTableId + RewardGroup` 的互斥条目概率总和必须为 `1` |

金币使用闭区间随机数；卡牌默认按全队角色相同的稀有度概率抽取，再从有效角色卡池中选择具体卡牌。

## 状态 CSV

文件：`DataBase/State/通用State.csv`；路径由 `DataBase/FilePathRegistry.csv` 的 `Data.State.Common` 注册。

固定表头：

```csv
StateType,Name,IsStackable,IsDebuff,IsElite,DecayTiming,DecayMode,StacksToRemove,EffectDescription,EnumName
```

| 字段 | 规则 |
|---|---|
| `StateType` | `StateType` 枚举的数字值（`Scripts/DataUnit/Card/CardEnum.cs`）；必须是已定义成员，否则整行被丢弃并报错 |
| `Name` | 中文显示名 |
| `IsStackable` / `IsDebuff` / `IsElite` | `TRUE` / `FALSE`；不可叠加状态无论施加几层都只按 1 层落地 |
| `DecayTiming` | `Never`、`OnTurnStart`、`OnTurnEnd` |
| `DecayMode` | `None`、`Flat`、`ClearAll` |
| `StacksToRemove` | 非负整数；`DecayMode=Flat` 时每回合移除的层数 |
| `EffectDescription` | 说明文本（供 UI/文档） |
| `EnumName` | **该行对应的枚举名**（如 `Steal`）；可空，留空时按 `StateType` 自动取 `枚举名`。填写时必须与 `StateType` 列一致（`StateTypeNames.Matches`），不一致或写了未定义名会整行报错跳过 |

- 新增状态必须三处同步：`StateType` 枚举加成员、本表加行、说明文档补表项。
- 该 CSV 由 Godot 的 `csv_translation` 导入器处理，新增列后由**编辑器**在下次导入时生成对应 `.translation`（勿手改 `.import` 与 `.translation`）；运行时不走 translation，直接解析 CSV。

## 物品表（材料 / 道具 / 食物 / 篝火配方）

文件在 `DataBase/Item/`；路径由 `DataBase/FilePathRegistry.csv` 的 `Data.Item.Material` / `Data.Item.Item` / `Data.Item.Food` / `Data.Item.FoodRecipe` 注册，加载与字段校验走 `LoadingSystem` 的 `ItemCsvSchema` / `ItemEffectSpecParser`（纯逻辑，单测可直接调用）。

| 表 | 表头 | 当前数据行 |
|---|---|---|
| `Material.csv` | `MaterialId,DefinitionId,Category,SubType,Rarity,Load,Description` | 16（`Category` 取 `合成材料` / `打造材料`；`SubType` 取 `植物` / `动物整体` / `身体部位` / `矿物`） |
| `Item.csv` | `ItemId,DefinitionId,Rarity,UseScope,Effect1,Effect2,Load,Description` | 8（301–308；`UseScope` 取 `使用后立即` / `战斗内` / `持续`） |
| `Food.csv` | `FoodId,DefinitionId,Rarity,Satiety,ExpireDays,Effect1,Effect1Duration,Effect2,Effect2Duration,Load,Description` | 8（401–408） |
| `FoodRecipe.csv` | `RecipeId,ResultFoodId,ResultCount,Input1Kind,Input1Id,Input1Count,Input2Kind,Input2Id,Input2Count,Enabled,Description` | 12（7 条材料配方 `Enabled=FALSE` + 5 条食物升级 `TRUE`） |

- **ID**：`MaterialId` / `ItemId` / `FoodId` 为正整数，仅在本表内唯一；掉落表以 `Category,Id` 引用（类别取 `Material` / `Item` / `Food`），引用不存在的 ID 会被 `Tests/ItemTableFileTests.DropTable_References_ResolveAgainstItemTables` 与烟测拦下。
- **效果列**：`Effect1` / `Effect2` 写 `类型[:参数[:…]]`，类型必须是 `EffectType` 枚举名；`AddState` 的状态参数写 `StateType` 枚举名（如 `AddState:AddAttack:2`）。**尚未实现的机制写 `Pending:说明`** —— 解析器把它记进 notes 并返回 null（**不静默丢弃**）；当前 3 条：`303` / `304` / `308`（等 `StateType` / `TurnStartResourceType` 扩词汇后再替换）。
- **寿命轴（食物专用）**：`Effect1Duration` / `Effect2Duration` 取 `BattleCount` / `TimePoint` / `DayCount`，可带 `:值`；**留空 = `BattleCount:1`（下一场战斗）**，`值` 必须 ≥ 1。
- **配方**：`Input1Kind` / `Input2Kind` 取 `Food` 或 `Material`，留空 = 该输入位不用；`Enabled=FALSE` 的行保留在表内但**不参与烹饪**（营地「烹饪」面板不显示、`RunFoodSystem.CanCook` 直接拒绝）。当前口径「**材料暂不参与烹饪**」→ 7 条材料配方全部禁用，烟测据此断言「放行配方只允许 `Food` 输入」。
- **实例与落档**：食物入包按**实例**记录剩余有效期与稀有度（`RunSaveData.BagEntries`）；吃下的效果进 `ActiveFoodEffects`（`DurationKind` + `Remaining` + `SourceFoodId`），分别由跨天休息 / 时间点消耗 / 战斗结束扣对应寿命轴；字段与迁移见[背包交互 §六](../../../交互说明文档/局内UI/背包交互.md)。
- **验证**：`dotnet test` 的 `ItemTableFileTests`（表头稳定 / ID 唯一 / 效果与寿命轴解析 / 掉落表引用 / 文案兜底）+ `--battlefield-smoke` 的 `BATTLEFIELD_ITEM_TABLES_PASS` 段（四表**真实加载**的接线：8 食物 / 12 配方 / 5 放行 / 每条效果带寿命轴）。


## 装备表与背包配置（2026-10-02）

| 表 | 表头 | 注册 key | 加载器 |
|---|---|---|---|
| `DataBase/Equipment/Weapon.csv` | `WeaponId,DefinitionId,HandsRequired,AttackMode,AttackRange,DefenseValue,DamageBonus,MoveBonus,ResourceCost,BlocksDefenseShield,EquipmentType` | `Data.Equipment.Weapon` | 战斗侧 `BattleWeaponCatalog`（攻击方式 / 射程 / 类型）；**局外侧** `LoadWeaponCsv`（名字 / 手数 / 类型 / 负荷） |
| `DataBase/Equipment/Armor.csv`（**新增**） | `ArmorId,DefinitionId,Slot,HandsRequired,DefenseValue,DamageBonus,MoveBonus,ResourceCost,Load` | `Data.Equipment.Armor` | `LoadArmorCsv`（部位装备：头 / 身 / 脚 / 饰品） |
| `DataBase/Equipment/EquipmentConfig.csv`（**新增**） | `Scope,CharacterId,AccessorySlots` | `Data.Equipment.Config` | `LoadEquipmentConfigCsv`（饰品格数） |
| `DataBase/Inventory/InventoryConfig.csv`（**新增**） | `Scope,CharacterId,Capacity` | `Data.Inventory.Config` | `LoadInventoryCsv` |

- **`Weapon.csv` 两个视图、一张表**：战斗侧只认与攻击有关的列，局外侧（背包 / 装备界面）只认 `WeaponId` / `DefinitionId` / `HandsRequired` / `EquipmentType` 与**可选**的 `Load`。`LoadWeaponCsv` 的校验口径是「前 3 列列名必须匹配 + 允许表尾追加列」：`EquipmentType` 在第 11 列、`Load` 在第 12 列，缺列时按默认推导。
- **装备负荷**：`Load` 列留空 = 按手数推导（`HandsRequired = 1` → 2.0、`= 2` → 4.0，见[背包交互 §四](../../../交互说明文档/局内UI/背包交互.md) 的默认表）；填了就以表里的值为准。局外侧读数口是 `ItemNameResolver.LoadOf(BagCategory.Equipment, WeaponId)`。
- **`InventoryConfig.csv`**：`Scope` 取 `Global` / `Character`；`Global` 行 = **队伍共用负荷上限**（必须恰好一条，`CharacterId` 留空、`Capacity > 0`），`Character` 行 = 按角色的**额外**额度（预留，当前不启用）。读数口 `ItemNameResolver.InventoryCapacity`（表缺失时用兜底 30）。
- **`Armor.csv`（部位装备，2026-10-02 装备界面批）**：表头固定 9 列（顺序不可换），`Slot` 只能 `Head` / `Body` / `Feet` / `Accessory`（未知部位**报错**，不静默丢进头部）；与武器表**不同**的是 `Load` **必填**（部位装备没有「按手数推导」的兜底，留空 / 0 / 负数一律 `FormatException`）。`HandsRequired` 只允许 0 / 1 / 2，部位装备恒 0（不占手位；手位防具走 `Weapon.csv` 的 `EquipmentType = Armor`）。加载期还会做**跨表名字去重**：两张装备表共用一个「装备」命名空间（`ItemNameResolver.EquipmentKeysByName`），重名直接报错。
- **`EquipmentConfig.csv`（饰品格数，2026-10-02 装备界面批）**：`Scope` 取 `Global` / `Character`；`Global` 行 = 全队饰品格数（必须恰好一条、`CharacterId` 留空、`AccessorySlots > 0`），`Character` 行 = 按角色的额外格数（预留，当前不启用）。读数口 `ItemNameResolver.AccessorySlotCount`（表缺失 / 非正数时回落 3）；装备界面按它铺格，改值即加减格位（案例 §二 / §九 第 5 条）。
- **验证**：`dotnet test` 的 `RunBagArrangeTests`（手数 / 负荷推导、手位合法组合、随身格归属、`v4 → v5` 迁移）+ `RunEquipmentSlotTests`（部位校验 / 替换 / 饰品满 / 互换 / 手位拒收 / 格数配置 / `v5 → v6` 迁移 / 读档清洗 / 卸下超载）+ `ItemTableFileTests` 的装备表文件级校验（`Armor.csv` / `EquipmentConfig.csv` 表头与解析）+ `--run-flow-ui-smoke` 的 `RUN_FLOW_UI_SMOKE_BAG` / `RUN_FLOW_UI_SMOKE_EQUIP` 两段（入口位置 / 打开 / 拖动落档 / 只读原因 / 关闭 / 互斥）。


## 怪物与意图

- `DataBase/Unit/Monster.csv`：怪物模板属性和意图效果。`IntentionN` 里段首的 `EffectType` 可以是 `0`（`None`）：该意图没有任何效果，用于"非攻击意图"（例如逃跑）占位。
- `DataBase/Battlefield/EnemyIntent.csv`：同一怪物每个意图的空间攻击、移动和索敌；第 12 列 `Behavior` 取 `Attack`（默认，缺列/留空同此）或 `Flee`（不索敌、不攻击、朝最近边界移动）。`Behavior=Flee` 时该行的 `AttackMode` **不参与校验**（逃跑不属于攻击方式）。
- `Monster.csv` 的 `Intention1` 对应 `EnemyIntent.csv` 的 `IntentionIndex=0`，依此类推。
- 每一个非空意图都必须有一条对应 `EnemyIntent.csv` 行；同一 `(MonsterId, IntentionIndex)` 不得重复。
