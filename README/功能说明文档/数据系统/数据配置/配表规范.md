# 战斗数据配表规范

> 本文是其他 Agent 配置正式战斗数据的唯一操作规范。配置使用 UTF-8 CSV；首行为英文表头；枚举大小写必须与本文一致；ID 不得有空格。

## 目录与总表

| 数据 | 总表 | 分文件 |
|---|---|---|
| 正式地图 | `DataBase/BattleMap/MapIndex.csv` | `DataBase/BattleMap/Maps/<MapId>.json` |
| 正式关卡 | `DataBase/Level/LevelIndex.csv` | `DataBase/Level/Config/<LevelId>.csv` |
| 掉落表 | `DataBase/Reward/DropTableIndex.csv` | `DataBase/Reward/Config/<DropTableId>.csv` |
| 地图节点内容 | `DataBase/WorldMap/*.csv` | 普通战斗规则、关卡池、事件池、固定节点绑定 |

所有总表都严格使用两列：

```csv
<IdColumn>,ConfigPath
```

- `<IdColumn>` 分别为 `MapId`、`LevelId`、`DropTableId`。
- ID 在本表中必须唯一。
- `ConfigPath` 必须是项目内的 `res://` 路径，且文件必须存在。
- 正式内容只能通过 `MapIndex.csv` 的 `MapId` 引用地图；不得写入已移除的测试地图路径。

## 地图节点内容配置

文件均位于 `DataBase/WorldMap/`：

| 文件 | 固定表头 | 当前作用 |
|---|---|---|
| `NormalCombatRule.csv` | `Act,MinCombatCount,MaxCombatCount,Difficulty` | 普通战斗次数映射到难度 |
| `LevelPool.csv` | `PoolId,Act,NodeType,Difficulty,LevelId,Weight` | 普通/高危等随机战斗节点从关卡池加权选取 `LevelId` |
| `EventPool.csv` | `Act,NodeType,ConditionId,EventId,Weight` | 随机事件节点加权选取 JSON 事件 |
| `FixedNode.csv` | `Act,NodeKey,NodeType,ContentType,ContentId,Weight` | 村庄、三个精英位置、Boss 固定位置的直接或池化内容 |

`ConditionId` 当前必须留空；不得自行填入枚举。`FixedNode.csv` 中同一个 `Boss` 节点键允许多条 `Level` 行，运行时按 `Weight` 随机选择三种 Boss 关卡之一。

## 全局变量

文件：`DataBase/GameVariables.csv`；路径由 `DataBase/FilePathRegistry.csv` 的 `Data.Game.Variables` 注册。

固定表头：

```csv
Scope,CharacterId,DefaultEnergyPerTurn,DefaultDrawCardsPerTurn,MovesPerTurn
```

必须包含且只能包含一行全局行：

```csv
Global,,4,5,
```

| `Scope` | `CharacterId` | 能量/抽牌列 | `MovesPerTurn` | 作用 |
|---|---:|---|---:|---|
| `Global` | 留空 | 必填非负整数 | 留空 | 全角色每回合基础能量、基础抽牌数 |
| `Character` | 必填，且存在于 `Character.csv` | 留空 | 必填非负整数 | 覆盖该角色的基础移动次数 |

示例：

```csv
Character,1002,,,3
Character,1003,,,3
Character,1004,,,3
```

读取入口为 `GameVariables.Load()`。基础能量写入 `CharacterInstance.Max_costs`，基础抽牌数写入角色模板，移动次数写入 `Character.MovesPerTurn`；装备移动修正会在此基础上叠加。不得为同一角色配置两行 `Character`；未配置角色当前会得到 0 次基础移动。

## 正式地图 JSON

文件：`DataBase/BattleMap/Maps/<MapId>.json`。

正式地图只保存永久地形。必须满足：

```json
{
  "MapId": "M-F1-001",
  "Version": 1,
  "Seed": 1001,
  "CellRadius": 42,
  "Shape": "Hexagon",
  "Radius": 6,
  "PlayerSpawnCoords": [{ "Q": 0, "R": 0 }, { "Q": 1, "R": 0 }, { "Q": 0, "R": 1 }],
  "PlayerCharacterIds": [1002, 1003, 1004],
  "MonsterIds": [3101],
  "CellOverrides": [],
  "GenerationExcludedCoords": [{ "Q": 0, "R": 0 }, { "Q": 1, "R": 0 }, { "Q": 0, "R": 1 }],
  "RandomObstacleCount": 0,
  "RandomItemCount": 0,
  "RandomItemDefinitions": [],
  "MinEnemyDistance": 0,
  "MaxGenerationAttempts": 1,
  "ObjectPlacements": []
}
```

`PlayerCharacterIds`、`MonsterIds` 是当前 JSON 解析器要求的占位字段；正式运行局会用运行局角色和关卡 CSV 的怪物覆盖它们。

正式地图约束：

- `ObjectPlacements` 必须为 `[]`。
- `RandomItemCount` 必须为 `0`，`RandomItemDefinitions` 必须为 `[]`。
- `CellOverrides` 仅允许永久 `Obstacle`、`Ground`、`Pit` 及永久 `BlocksSight`。
- 不可在地图 JSON 配置怪物、道具、装备、陷阱、机关、保护目标、可变地形或可摧毁障碍。
- 三个 `PlayerSpawnCoords` 必须两两相邻、可通行且不重叠。

## 单关卡 CSV

文件：`DataBase/Level/Config/<LevelId>.csv`。

固定表头：

```csv
MapId,DropTableId,LevelType,Difficulty,InstanceId,ObjectType,DefinitionId,Q,R,Facing,InitialValue,Extra
```

示例：

```csv
M-F1-001,2001,NormalCombat,Low,F1-001-M01,Monster,3101,-1,-4,,,
M-F1-001,2001,NormalCombat,Low,F1-001-M02,Monster,3102,-3,-1,,State=1:2|HP=12,
M-F1-001,2001,NormalCombat,Low,F1-001-T01,Trap,毒雾陷阱,0,-2,,,EveryEntry
M-F1-001,2001,NormalCombat,Low,F1-001-G01,ProtectedTarget,商队马车,1,-3,,HP=18,
```

前四列是该关卡的固定绑定，文件内每一行必须完全一致：

| 字段 | 允许值/格式 |
|---|---|
| `MapId` | 必须存在于 `MapIndex.csv` |
| `DropTableId` | 必须存在于 `DropTableIndex.csv` |
| `LevelType` | `NormalCombat`、`HighRiskCombat`、`EliteCombat`、`Boss`、`Event`、`Village` |
| `Difficulty` | `Low`、`Mid`、`High` |
| `InstanceId` | 本关卡唯一；建议 `<LevelId>-<类型缩写><序号>`。除做对象标识外，也作为"**按实例记账**"的稳定键（如怪物窃取金币的 `StolenGoldEntry.InstanceId`，见[状态系统 §2.4](../../战斗系统/状态系统.md)） |
| `ObjectType` | `Monster`、`Item`、`Equipment`、`Trap`、`Mechanism`、`VariableTerrain`、`DestructibleObstacle`、`ProtectedTarget` |
| `DefinitionId` | 对应对象模板 ID；怪物必须引用 `Monster.csv` 的数字 ID |
| `Q,R` | 已存在、可用的轴向格坐标 |
| `Facing` | 可空；使用 `Q;R` 方向，如 `1;0` |
| `InitialValue` | 可空；对象初始值，`\|` 分隔的 `Key=Value` 列表，在**战斗开始时**写入该对象。当前机制消费 `HP=<正整数>`（初始生命，超过模板上限时按上限截断）与 `State=<StateType>[:<层数>]`（初始状态，可重复并按序叠加；层数省略按 1 层；不可叠加状态只落 1 层）。`StateType` 可写枚举名（`Steal`）或 `通用State.csv` 编号（`21`）。**未定义的键原样保留、不报错也不丢弃**；已知键的值非法（`HP=0`、层数 ≤0、StateType 不存在）或条目缺少 `=` 会在战斗开始时报错并带出原始文本。完整语法、示例与生效链路见[对象初始值](对象初始值.md)。 |
| `Extra` | 可空；触发方式或对象扩展参数，例如 `EveryEntry` |
| `BattleRule` | **关卡级变量**，可空；第 13 列，值 = `BattleRuleKind` 枚举名（如 `BanditEscalation`），多个用 `\|` 分隔；留空/缺列 = 无额外规则。**同一关卡内所有行必须一致**，写未知规则名报错。规则不绑地图：换关卡填上即可复用；机制见[战斗规则](../../战斗系统/战斗规则.md)。 |

对象占位规则：

- `Monster`、`VariableTerrain`、`DestructibleObstacle`、`ProtectedTarget` 占据单位层；同一格最多一个。
- `Item`、`Equipment`、`Trap`、`Mechanism` 使用物件层；具体叠放/排他规则以战斗物件系统为准。
- 同一 `InstanceId` 不得重复；同一单位层坐标不得重复。
- 第一阶段正式运行局已接入 `Monster` 固定出生；其余 `ObjectType` 的模板和运行时生成将在相同 CSV 结构上继续接入，Agent 可按本规范预配，但不能把它们写进地图 JSON。

## 掉落表 CSV

文件：`DataBase/Reward/Config/<DropTableId>.csv`。

固定表头：

```csv
RewardGroup,RewardType,ReferenceId,MinAmount,MaxAmount,Probability
```

示例：

```csv
Gold,Gold,,35,50,1
Card,Card,Common,1,1,0.70
Card,Card,Uncommon,1,1,0.25
Card,Card,Rare,1,1,0.05
```

| 字段 | 规则 |
|---|---|
| `RewardGroup` | 同组奖励共用一次抽取逻辑；`Gold`、`Card`、`Material` 等 |
| `RewardType` | `Gold`、`Card`、`Material`、`Item`、`Equipment`、`Key` |
| `ReferenceId` | `Card` 填 `Common`、`Uncommon`、`Rare`；材料/道具/装备填其定义 ID；金币留空 |
| `MinAmount` / `MaxAmount` | 非负整数，且 `MinAmount <= MaxAmount` |
| `Probability` | `0`–`1` 小数；同一 `DropTableId + RewardGroup` 的互斥条目概率总和必须为 `1` |

金币使用闭区间随机数；卡牌默认按全队角色相同的稀有度概率抽取，再从有效角色卡池中选择具体卡牌。

## 状态 CSV

文件：`DataBase/State/通用State.csv`；路径由 `DataBase/FilePathRegistry.csv` 的 `Data.State.Common` 注册。

固定表头：

```csv
StateType,Name,IsStackable,IsDebuff,IsElite,DecayTiming,DecayMode,StacksToRemove,EffectDescription,EnumName
```

| 字段 | 规则 |
|---|---|
| `StateType` | `StateType` 枚举的数字值（`Scripts/DataUnit/Card/CardEnum.cs`）；必须是已定义成员，否则整行被丢弃并报错 |
| `Name` | 中文显示名 |
| `IsStackable` / `IsDebuff` / `IsElite` | `TRUE` / `FALSE`；不可叠加状态无论施加几层都只按 1 层落地 |
| `DecayTiming` | `Never`、`OnTurnStart`、`OnTurnEnd` |
| `DecayMode` | `None`、`Flat`、`ClearAll` |
| `StacksToRemove` | 非负整数；`DecayMode=Flat` 时每回合移除的层数 |
| `EffectDescription` | 说明文本（供 UI/文档） |
| `EnumName` | **该行对应的枚举名**（如 `Steal`）；可空，留空时按 `StateType` 自动取 `枚举名`。填写时必须与 `StateType` 列一致（`StateTypeNames.Matches`），不一致或写了未定义名会整行报错跳过 |

- 新增状态必须三处同步：`StateType` 枚举加成员、本表加行、说明文档补表项。
- 该 CSV 由 Godot 的 `csv_translation` 导入器处理，新增列后由**编辑器**在下次导入时生成对应 `.translation`（勿手改 `.import` 与 `.translation`）；运行时不走 translation，直接解析 CSV。

## 怪物与意图

- `DataBase/Unit/Monster.csv`：怪物模板属性和意图效果。`IntentionN` 里段首的 `EffectType` 可以是 `0`（`None`）：该意图没有任何效果，用于"非攻击意图"（例如逃跑）占位。
- `DataBase/Battlefield/EnemyIntent.csv`：同一怪物每个意图的空间攻击、移动和索敌；第 12 列 `Behavior` 取 `Attack`（默认，缺列/留空同此）或 `Flee`（不索敌、不攻击、朝最近边界移动）。`Behavior=Flee` 时该行的 `AttackMode` **不参与校验**（逃跑不属于攻击方式）。
- `Monster.csv` 的 `Intention1` 对应 `EnemyIntent.csv` 的 `IntentionIndex=0`，依此类推。
- 每一个非空意图都必须有一条对应 `EnemyIntent.csv` 行；同一 `(MonsterId, IntentionIndex)` 不得重复。

详见[怪物配置](怪物.md)、[关卡配置](关卡.md)、[地图配置](地图.md)。
