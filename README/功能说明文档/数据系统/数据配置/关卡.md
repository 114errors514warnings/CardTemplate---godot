# 关卡与遭遇配置

## 一、配置路径（正式）

| 配置 | 路径 | 用途 |
|---|---|---|
| 关卡索引 | `DataBase/Level/LevelIndex.csv` | `LevelId` → `ConfigPath` 映射 |
| 单关卡配置 | `DataBase/Level/Config/<LevelId>.csv` | 每行一个对象（怪物 / 陷阱 / 机关 / 保护目标 / 交互点）与坐标 |
| 已归档关卡 | `DataBase/Level/Archive/<LevelId>.csv` | 历史配置，不参与运行 |
| 正式地图 | `DataBase/BattleMap/MapIndex.csv` + `Maps/<MapId>.json` | 关卡引用的地形模板 |
| 掉落表 | `DataBase/Reward/DropTableIndex.csv` + `Config/<DropTableId>.csv` | 遭遇奖励 |

字段定义与约束见 [配表规范](配表规范.md)。
- **非战斗地点关（村庄 / 商人）与战斗关同级、同一套载体（2026-10-06 用户强制规定）**：`Level/LevelIndex.csv` 登记 `LevelId` → `Level/Config/<LevelId>.csv` 放对象（设施 / 商人 / 入口格 / 离开格）→ 该行 `MapId` 指到 `BattleMap/MapIndex.csv` + `Maps/<MapId>.json`（地形与格子）；节点侧 `FixedNode.csv` 用 `ContentType = Level` 绑定，`LevelType = Village` / `Merchant` 区分表现。**不做地点专用场景、不做专用版图表**。地点内一切可交互单位（设施 / 商人 / 入口格 / 离开格）**共用同一个 `ObjectType = InteractPoint`**（交互点），靠 `DefinitionId` 区分、**不得再细分成多个对象类型**（见 §33.2.1）。详见 [10 月施工文档 §33](../../../施工文档/2026/2026.10/10月施工文档.md)。

对象的**初始值**（第 11 列 `InitialValue`）用于在**战斗开始时**写入该对象的初始生命与初始状态，例如 `HP=12`、`State=1:2`（易伤 2 层）、`State=Steal:1`（窃取 1 层）；
逐行独立配置，解析与应用由 `UnitInitialStateConfig` 完成：完整语法、容错规则、示例与生效链路见[对象初始值](对象初始值.md)。

第 13 列 `BattleRule` 是**关卡级变量**（全行一致，可空）：填写战斗规则枚举名即可让该关卡挂上对应规则（如 `BanditEscalation`），机制见[战斗规则](../../战斗系统/战斗规则.md)。

## 三、档位规则

- **分档计数只统计由普通敌袭节点（节点类型 `NormalCombat`）发起的战斗**：第 1–3 场 `Low`、第 4–5 场 `Mid`、第 6 场起 `High`。
- **计数按层独立**：`NormalCombatRule.csv` 以 `Act` 分档，进入新的一层后普通敌袭场次**从第 1 场重新计**（第一层的第 4 场与第二层的第 4 场同为 `Mid`）。计数已按此口径落地（`RunMapStateSave.NormalEncounterCounts` 按 `Act` 独立记；旧档遗留的全局值在读取时按当前层归入），落地记录见 [9 月施工文档 §45](../../../施工文档/2026/2026.09/9月施工文档.md)（需求 [代码需求清单](../../../施工文档/2026/2026.09/玩法/代码需求清单.md) P2-11）。
- 每层的普通敌袭总场数**尚未确定**，不是固定 5 场：它取决于该层地图的格点数量与节点类型占比。**高等档普通敌袭已于 2026-10-01 补齐**：`F1-007` / `F1-008` / `F1-009` 三关 + 池行 `P-F1-NORMAL-HIGH`（在此之前第 6 场起解析不到任何关卡）；**同日按用户指令整组重制**为「1 关生存关典型（`F1-007` 黏液培育槽，`LevelType = Survival`）+ 2 关符文之地核心区（`F1-008` 失控伴侣法师 / `F1-009` 教授与学徒群）」，三关共用新建地图 `M-F1-003`「符文法师研究圈」；旧三关配置归档到 `DataBase/Level/Archive/`（**`LevelId` 复用**，池行与 `LevelIndex` 行不变）。设计文档见[第一层普通敌袭](../../../玩法说明文档/关卡设计/普通敌袭/第一层/README.md)。
- 其他节点类型（普通事件 / 危险事件等）发起的战斗**不计入该计数**，属于额外节点遭遇，按关卡自身配置的 `Difficulty` 执行。此处区分的是**节点类型**，不是战斗本身的类型。
- 战斗失败是否结束本局，由**关卡自身声明的关卡类型**（歼灭 / 生存 / 保护目标）决定，与是否由事件进入无关；规则见[六边形战场玩法 §七](../../../玩法说明文档/系统规则/战斗系统/六边形战场玩法.md)。

各档位的强度目标（总 HP、每轮直接伤害、状态 / 强化压力、护盾支援）见 [关卡档位表](../../../玩法说明文档/系统规则/数值平衡/关卡档位表.md)。

## 四、已废弃配置

- `DataBase/Stage/<层>/<节点类型>.csv` 及其选择逻辑（`StageEncounterPicker`、`LoadStageEncounterCsv`）为旧体系，**已废弃**：**2026-09-30 已整体归档到 `_archive/DataBase-Stage-2026-09-30/`**（工程卫生 C5，见 [9 月施工文档 §46](../../../施工文档/2026/2026.09/9月施工文档.md)），仅作历史存档，不再新增或修改。
- 新关卡一律写入 `DataBase/Level/Config/`，并在 `LevelIndex.csv` 登记。
- **退休关卡**归档到 `DataBase/Level/Archive/`（命名 `<LevelId>-<关卡名>-<归档日期>.csv`，另有 `废弃说明.md` 记录原因）：归档后在 `LevelIndex.csv` 与 `LevelPool.csv` 里都不再引用，运行时不会加载；若 `LevelId` 被复用给新关（先例：`F1-005`、`F1-007/008/009`），旧配置只作历史留档。
