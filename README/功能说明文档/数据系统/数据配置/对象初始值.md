# 对象初始值（InitialValue）

> 单关卡 CSV 第 11 列 `InitialValue`：**战斗开始时**给该行对象写入初始生命与初始状态。
> 本文只写**已实现**行为（`UnitInitialStateConfig`）；字段约束另见[配表规范](配表规范.md)。

## 一、配置位置与作用范围

| 项 | 内容 |
|---|---|
| 文件 | `DataBase/Level/Config/<LevelId>.csv` |
| 列 | 第 11 列 `InitialValue`（表头位置见[配表规范 §单关卡 CSV](配表规范.md)） |
| 粒度 | **每行（每个对象实例）独立配置**，同一关卡可只给部分对象配，留空 = 用模板默认值 |
| 生效时点 | 战斗开始、实例化该单位的那一刻（不是读表时） |
| 代码入口 | `UnitInitialStateConfig.Parse` / `Apply`；调用点在 `BattlefieldSession` 建怪处 |

- 当前**只有 `ObjectType=Monster` 会被消费**：`BattleLevelCatalog.ApplyMonstersTo` 只把怪物行的初始值写进 `BattleMapDefinition.MonsterInitialValues`。
- 其它对象类型（`Trap`、`ProtectedTarget`、`Mechanism` 等）的 `InitialValue` **会原样读入但不生效**，也不报错——等对应运行时机制接入后再消费。
- 玩家角色不走这里：他们的生命与牌组由运行局存档（`RunSaveData.CharacterSlots`）恢复。

## 二、语法

```csv
MapId,DropTableId,LevelType,Difficulty,InstanceId,ObjectType,DefinitionId,Q,R,Facing,InitialValue,Extra
M-F1-001,2001,NormalCombat,Low,F1-001-M02,Monster,3102,-3,-1,,HP=12|State=1:2,
```

- 多个条目用 `|` 分隔，条目形如 `Key=Value`；两侧空白会被去掉，空条目直接跳过。
- 键名**大小写不敏感**（`HP` / `hp` 等价）；`State` 的值也大小写不敏感（枚举名）。

## 三、当前消费的键

### 3.1 `HP=<正整数>`：初始生命

- 开局把该单位生命设为配置值，并**按模板上限截断**：实际生命 = `clamp(配置值, 1, 模板 MAX_HP)`。
  - 例（模板 `3115 近战劫匪` 20 HP）：`HP=12` → 12；`HP=999` → 20。
- 非法值报错：`HP=0`、`HP=-3`、`HP=abc`。
- 同一行重复写 `HP=` → **以最后一个为准**。

### 3.2 `State=<StateType>[:<层数>]`：初始状态

- `StateType` 可写**枚举名**（`Ignite`、`vulnerable`，忽略大小写）或 **`通用State.csv` 的编号**（`3`）；编号必须是已定义枚举成员，名字必须能解析且不能是 `None`。
- 层数**省略按 1 层**；层数必须是正整数。
- 可重复出现，**按书写顺序**依次施加（`StateSystem.AddOrUpdateState`）：
  - 可叠加状态 → 层数**累加**：`State=Vulnerable:1|State=Vulnerable:2` → 3 层易伤。
  - **不可叠加状态**（`通用State.csv` 的 `IsStackable=FALSE`，如 `3 燃烧`）→ 无论写几层都只落 **1 层**。
- 挂载初始状态本身不消耗能量/行动、不触发额外结算；带 `DecayTiming=OnTurnStart` 的状态会在第一个玩家回合开始后按规则衰减（语义见[状态系统](../../战斗系统/状态系统.md)）。

### 3.3 未定义的键 → `Extras`

- 引擎**不认识的键不报错、也不丢弃**，原样保留在 `UnitInitialState.Extras`（键名大小写不敏感），供后续机制读取。
- 例：`SpawnTag=elite|HP=8` 中的 `SpawnTag` 会被保留，当前没有任何机制消费它。
- 历史注：`F1-006` 早期草案写的 `窃取=1` 就属于这种未定义键；现已改为正式状态写法 `State=Steal:1`（规则见[状态系统 §2.4](../../战斗系统/状态系统.md)）。

## 四、容错与报错

| 配置 | 结果 |
|---|---|
| 整列留空 | 什么都不做（沿用模板生命、不带初始状态） |
| 未知键 `Foo=bar` | 保留进 `Extras`，不报错 |
| 条目缺少 `=`（`HP`）/ 缺少键名（`=1`） | **报错** |
| `HP=0` / `HP=-3` / `HP=abc` | **报错** |
| `State=999:1`（编号不存在）/ `State=None:1` / `State=3:0` / `State=3:2:5` / `State=` | **报错** |

报错形态为 `ArgumentException`，消息带上下文与原始文本，例如：

```
单位初始值无效（小型符文史莱姆（M-F1-001 第 1 只怪物））：HP 必须是正整数：HP=0；原始文本 = "HP=0"
```

**报错时点 = 战斗开始时**：`BattleLevelCatalog.Parse` 只把该列文本原样带到关卡对象上，真正的解析发生在 `BattlefieldSession` 实例化怪物的那一刻；因此配错不会在加载阶段静默通过，而是进战斗时报“战场初始化失败：…”。这让配置错误在开局就暴露，而不是打到一半才发现。

## 五、生效链路（代码）

```
DataBase/Level/Config/<LevelId>.csv 第 11 列 InitialValue
  → BattleLevelCatalog.Parse            读列、按行保存（纯函数，不校验值）
  → BattleLevelCatalog.ApplyMonstersTo  把怪物行的初始值写进 definition.MonsterInitialValues（与 MonsterIds 一一对应）
  → BattlefieldSession 建怪时            UnitInitialStateConfig.Apply(monster, raw, context)（在 Register 之前）
  → UnitInitialStateConfig.Apply        先按上限截断生命，再按书写顺序 AddOrUpdateState
```

- 相关文件：`Scripts/Battlefield/Core/UnitInitialStateConfig.cs`（解析与应用）、`Scripts/Battlefield/Core/BattleLevelCatalog.cs`、`Scripts/Battlefield/Core/BattleMapDefinition.cs`（`MonsterInitialValues` 数量非空时必须与 `MonsterIds` 一致）、`Scripts/Battlefield/Runtime/BattlefieldSession.cs`。
- 关卡里的怪物携带初始状态时，窃取等状态只管**状态本身**；依赖它的机制（例如窃取金币的记账与结算返还）在[状态系统 §2.4](../../战斗系统/状态系统.md) 里描述。

## 六、示例

以模板 `3101 小型符文史莱姆`（9 HP / 3 攻 / 1 防）为例：

| `InitialValue` | 结果 |
|---|---|
| `HP=5` | 生命 5/9 |
| `HP=999` | 生命 9/9（按模板上限截断） |
| `State=1:2` | 易伤 2 层（编号写法） |
| `State=Vulnerable:2` | 易伤 2 层（枚举名写法，等价） |
| `State=3:2` | 燃烧 **1** 层（不可叠加状态只按 1 层落地） |
| `State=Steal:1` | 窃取 1 层（每次命中偷 1 金币；被击杀实例在结算时返还） |
| `HP=6\|State=1:1\|State=1:2` | 生命 6/9 + 易伤 3 层（同状态累加） |
| `窃取=1` | 无任何效果；`Extras["窃取"]="1"`（未定义键，仅保留） |

正式关卡用法：`F1-006` 的 4 只 `3115 近战劫匪` 配 `State=Steal:1`（见[关卡配置 §二](关卡.md)）。

## 七、验证入口

- 单测 `Tests/UnitInitialStateConfigTests.cs`：解析顺序、枚举名与编号等价、未知键保留、非法值报错、`ApplyMonstersTo` 逐只携带初始值。
- 无界面自检 `BattlefieldSceneSmoke.VerifyMonsterInitialStates()`：断言 `State=1:2`（易伤 2 层）、`State=3:2` 只落 1 层、`HP=5`（截断为 5/9）、`State=Steal:1` 生效 → 输出 `BATTLEFIELD_INITIAL_STATE_PASS`。
