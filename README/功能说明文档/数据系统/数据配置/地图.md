# 六边形战斗地图配置

## 当前文件与加载方式

正式地图由 `DataBase/BattleMap/MapIndex.csv` 的 `MapId → ConfigPath` 映射加载。主菜单不再提供独立测试关，正式运行局按关卡 `MapId` 读取对应地图。

解析入口是 `BattleMapDefinition.Parse()`，生成入口是 `BattleDeploymentService.Generate()`，场景入口是 `HexBattleScene`。

## JSON 字段

| 字段 | 说明 |
|---|---|
| `MapId` | 地图唯一 ID |
| `Version` | 配置版本，至少为 1 |
| `Seed` | 随机障碍/物品的确定性种子 |
| `CellRadius` | 六边形显示半径，16–120 |
| `Shape` | `Hexagon`（规则六边形）或 `Explicit`（逐格定义） |
| `Radius` | `Hexagon` 的地图半径 |
| `Cells` | `Explicit` 地图的格点列表 |
| `CellOverrides` | 覆盖格点的 `Kind`、`Surface`、`BlocksSight` |
| `PlayerSpawnCoords` | 三个玩家出生格；必须两两相邻 |
| `ExitAnchors` | `Explicit` 地图必须提供的出口锚点 |
| `GenerationExcludedCoords` | 不参与随机障碍/物品生成的保护格 |
| `ObjectPlacements` | 固定道具、装备、陷阱或机关 |
| `RandomObstacleCount` | 随机障碍数量 |
| `RandomItemCount` / `RandomItemDefinitions` | 随机物品数量与定义池 |
| `MinEnemyDistance` | 怪物出生与任一玩家出生点的最短距离 |
| `MaxGenerationAttempts` | 地图随机生成失败时的最大重试次数 |
| `PlayerCharacterIds` / `MonsterIds` | 测试关的玩家与怪物；正式运行局会覆盖这两项 |

固定物件格式：

```json
{ "Q": 2, "R": 0, "DefinitionId": "弓", "Kind": "Equipment", "HandsRequired": 2, "AttackRange": 5 }
```

`Kind` 使用 `Item`、`Equipment`、`Trap` 或 `Mechanism`。投掷道具另可配置 `SpatialShape`、`ItemMaxRange`、`ItemRadius`、`ItemLength` 与 `DamageAmount`。

## 待实现的正式地图目录

地图生成完成后统一放入：

```text
DataBase/Battlefield/Maps/
└─ M-F1-001.json
```

这些编号将由关卡 CSV 的 `BattleMapId` 指定。接入时需要同步修改 `StageEncounterRow`、`LoadStageEncounterCsv`、`RunSaveData`/`RunSession` 和 `HexBattleScene`，以实现“选中遭遇 → 加载对应地图 → 续战仍加载同一地图”。地图设计约束和推荐编号见[关卡配置](关卡.md)。

相关代码：`Scripts/Battlefield/Core/BattleMapDefinition.cs`、`Scripts/Battlefield/Core/BattleDeploymentService.cs`、`Scripts/Battlefield/Presentation/HexBattleScene.cs`。
