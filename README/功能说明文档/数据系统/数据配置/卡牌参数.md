# 卡牌参数

CSV 字段说明、EffectType / EffectTargetType / StateType 完整枚举、卡牌操作目标类型、关键词、状态分类。

## 一、CardId 编号规则

所有 CardId 均为 **8 位数字**，由「5 位前缀」+「3 位后缀」组成。

### 1.1 通用牌前缀

| 卡牌类型 | CardType | 前缀 |
|----------|----------|------|
| 攻击牌 | Attack | `10000` |
| 技能牌 | Skill | `20000` |
| 状态牌 | State | `30000` |

### 1.2 角色专有牌前缀

格式：`<类型数字(1位)><CharacterID(4位)>`

- 攻击专有牌：`1XXXX`
- 技能专有牌：`2XXXX`
- 状态专有牌：`3XXXX`

### 1.3 后缀规则（3 位）

- 同前缀下，已有 ID 的最大后缀 + 1，补零至 3 位
- 若该前缀下尚无 ID，后缀从 `001` 开始
- 示例：前缀 `10000` 下已有 `10000001`、`10000002`，新卡 ID 为 `10000003`

## 二、CSV 排列顺序

CSV 文件中的卡牌行必须按 **CardId 从小到大**升序排列。新增卡牌应插入到对应数值位置，而非追加到文件末尾。

## 三、通用 Card.csv 字段

表头：`CardId,CardName,CardType,EnergyCost,EffectType,EffectDesc,Params,CardKeyWord,ConditionParams`

| 字段 | 说明 |
|------|------|
| `CardId` | 8 位卡牌模板 ID |
| `CardName` | 卡牌显示名称 |
| `CardType` | 卡牌类别：`Attack` / `Skill` / `State` |
| `EnergyCost` | 出牌消耗的能量点数 |
| `EffectType` | 效果类型，多效果用 `\|` 分隔，**顺序即执行顺序** |
| `EffectDesc` | 效果描述（展示用文本） |
| `Params` | 各效果参数，多效果用 `\|` 分隔，同一效果内各参数用 `;` 分隔 |
| `CardKeyWord` | 卡牌关键词，多关键词用 `\|` 分隔 |
| `ConditionParams` | 可选；卡牌出牌条件参数，填写 `CardConditionType` 枚举名 |

> **`EffectType` 与 `Params` 按索引一一对应**，第 i 个效果使用第 i 组参数。

## 四、Params 参数格式

`Params[i][0]` 固定为该效果的目标类型（`EffectTargetType`），后续参数为效果自身参数。

### 4.1 EffectTargetType（目标类型）

| 值 | 枚举名 | 说明 |
|----|--------|------|
| 0 | Auto | 自动（有选中目标用选中，否则自身）|
| 1 | Self | 自身 |
| 2 | SelectedTarget | 选定目标（卡牌自动标记 `NeedTarget=true`）|
| 3 | AllEnemies | 全体敌人 |
| 4 | AllUnits | 场上所有单位 |
| 5 | AllAllies | 全体友方（不含自身）|

### 4.2 EffectType 完整表

| 值 | 枚举名 | 效果参数（`Params[i][1]` 起）| 说明 |
|----|--------|------------------------------|------|
| 1 | Damage | `[1] extraDamage`，`[最后] hitCount`（默认 1）| 对目标造成伤害（受易伤等状态修正）|
| 2 | Shield | `[1] extraShield`，`[最后] shieldCount`（默认 1）| 为目标增加护盾 |
| 3 | AddState | `[1] stateType`，`[2] stacks`（默认 1）| 为目标附加状态 |
| 4 | ClearState | `[1] stateType` | 清除目标指定状态 |
| 5 | Heal | — | 治疗 |
| 6 | DrawCard | — | 抽卡 |
| 7 | AddCost | `[1] amount` | 增加来源单位能量 |
| 8 | ClearAllStates | — | 清除目标全部状态 |
| 9 | ShieldSlam | `[1] extraDamage` | 造成"来源攻击力 + 来源护盾值 + 额外值"的伤害 |
| 10 | ClearFirstNormalDebuff | `[1] count`（默认 1）| 清除目标状态栏中的前 count 个**普通弱化**状态（`IsDebuff && !IsElite`）|
| 11 | UpgradeBattleCard | `[0] cardTargetType`，`[1] count`，`[2] requireKilledTarget` | 升级战斗中的卡牌 |
| 12 | UpgradePermanentCard | 同上 | 升级角色默认卡组中的卡牌 |
| 13 | DamageByBattleLostHp | `[1] baseExtraDamage` | 额外造成自身本局失去生命值的伤害 |
| 14 | AddKeyword | `[0] cardTargetType`，`[1] keyword`，`[2] keywordFlag`，`[3] count` | 为指定卡牌运行时添加关键词 |
| 15 | MirrorShieldToAllies | `[1] extraShield` | 将前续 Shield 效果累积的护盾复制到全体友方 |
| 16 | RearrangeMonsterTargets | — | 「到我身后」：把所有怪物单攻目标重定向到施法者，每改一个目标获得 1 点护盾（**2026-08 新增**）|
| 17 | HpLoss | `[1] extraHp` | 纯扣血（**不**叠加来源攻击力）；燃血、强撑等用（2026-10-02）|
| 18 | ShieldOnFirstHit | `[1] shield` | 本场战斗首次受到伤害时额外获得护盾（在护盾抵扣**之前**生效）；食物「烤蟾蜍」用 |
| 19 | SurviveFatalOnce | `[1] percent` | 本场战斗首次生命降至 0 时按最大生命百分比回复（本场一次）；食物「凤凰羽羹」用 |
| 20 | ShieldByAttack | `[1] extraShield` | 获得「**来源当前攻击力** + extraShield」的格挡（不叠加 `Defend`，也不吃「持盾防守」的 +3）；法师「法术护盾」用（**2026-10-03 新增**）|
| 21 | ConsumeSelectedHandCard | `[1] count`（默认 1）| **消耗选定手牌**成本：走既有选牌通道（`SelectHandCards`），被选中的牌从手牌移出并进入**消耗堆**；口径 = **只作用于施法者自己的手牌**，候选排除本牌自身，没有别的牌可选时**跳过成本**、不阻塞回合。精灵「林间抚慰」「净化」用（**2026-10-04 新增，T6**）|

### 4.3 CardOperationTargetType（卡牌操作目标）

`Params[i][0]` = `CardOperationTargetType`：

| 值 | 枚举名 | 说明 |
|----|--------|------|
| 0 | None | 无效目标 |
| 1 | SelectHandCards | 玩家手动选择手牌中的指定数量 |
| 2 | RandomHandCards | 随机手牌指定数量 |
| 3 | RandomDefaultDeckCards | 随机默认卡组指定数量 |

`Params[i][1]` = 目标数量（默认 1）
`Params[i][2]` = `requireKilledTarget`（可省；>0 时要求本次先击杀目标才触发）

示例：

```csv
11002004,淬炼,Attack,2,Damage|UpgradePermanentCard,攻击，造成6点额外伤害，如果击杀目标，随机永久升级卡组中的一张牌，消耗,2;6|3;1;1,Exhaust
```

## 五、关键词与条件

### 5.1 CardKeyWord（卡牌固有关键词）

| 枚举名 | 说明 |
|--------|------|
| Retain | 保留：回合结束时不弃置 |
| Exhaust | 消耗：打出后进入消耗牌堆 |
| InfiniteUpgrade | 无限升级：允许记录并显示累计升级级数 |
| Crit | 暴击：造成双倍伤害（实现中）|

详见 [关键词系统](../../../玩法说明文档/系统规则/战斗系统/关键词系统.md)。

### 5.2 KeywordFlag（运行时关键词生命周期）

| 枚举名 | 说明 |
|--------|------|
| None | 不移除 |
| RemoveAfterActivate | 关键词生效一次后移除 |
| RemoveAtTurnEnd | 回合结束时移除 |

### 5.3 CardConditionType（出牌条件）

| 枚举名 | 条件 |
|--------|------|
| None | 无 |
| NoBattleCardPlayedThisTurn | 本回合内该角色尚未打出过战斗牌（Attack / Skill）|

## 七、CSV 文件组织

```
DataBase/Card/
├── 通用/
│   └── 通用Card.csv        ← 通用牌（不属于任何角色，所有角色都可用）
├── 勇士Card.csv            ← 角色专有牌
├── 重剑手Card.csv
├── 精灵Card.csv            ← 2026-10-03 新建（敏捷闪躲）；同日扩为 12 列（含空间三列）并补到 4 行
└── 法师Card.csv            ← 2026-10-03 新建（法术护盾）；同日同上 → 4 行
```

- 通用牌：放 `通用/通用Card.csv`
- 角色专属牌：以 `<角色名>Card.csv` 命名，直接放 `DataBase/Card/` 下
- **归属与掉落**（[总体卡牌设计](../../../玩法说明文档/系统规则/卡牌系统/总体卡牌设计.md)「卡牌归属与掉落」，2026-10-03 用户口径）：归属由**所在表**决定；战斗中掉落的牌**必须是该角色的专有牌、不含通用牌**，通用来源默认被 `LoadingSystem.GetCharacterRewardCardIds` 过滤，只有特殊装备效果（`CardRewardOwnership.IncludeGenericSources`，未实现）可放行。
- `CharacterRewardPool.csv` 只登记**候选来源**（含通用行），不表达归属结论。
- **等级列 `CardTier`（2026-10-04 已实现最小版）**：卡表可在**表头**任意位置声明 `CardTier` 列，值取 `D / C / B / A / S`（`CardTier` 枚举，次序有意义）；`LoadCardCsv` 按**表头定位**该列（缺列 / 越界 / 空值 = `None`，老表零影响、不抛异常）；`CardRewardOwnership.IsTierEligibleForReward` 只服务「战斗结算候选只含该角色 B–S 级专属牌」（`C` / `D` 拦截、`B/A/S` 放行、`None` 不拦截并打一次告警），落点在 `LoadingSystem.GetCharacterRewardCardIds` 一处。已落列：`精灵Card.csv` / `法师Card.csv` / `重剑手Card.csv`；**`勇士Card.csv` 无设计等级数据源 → 仍缺列**（待设计侧补表，见施工文档 T12）。口径与验证见 [10 月施工文档 §26](../../../施工文档/2026/2026.10/10月施工文档.md)。
- **空间列（可选，目前只有角色卡表在用）**：表头可带 `SpatialShape,SpatialArgs,TrapId` 三列（形态见 `DataBase/Card/勇士Card.csv`），语义见[六边形战场卡牌设计](../../../玩法说明文档/角色设计/六边形战场卡牌设计.md)。**准入条件（2026-10-04，P2-29 已修）**：`BattleCardSpatialRepository.LoadAll` 递归扫描 `DataBase/Card/**.csv`，**只有「表头首列 `CardId` 且含 `SpatialShape` 列」的表才进空间规格字典**（`通用/通用Card.csv`、`重剑手Card.csv` 不声明空间列 → 不进字典，其卡保持「`Attack` / `NeedTarget` → 回落 `Single`」的旧语义；若误当空间表，攻击牌会拿到 `Shape=None` 而失去目标）。同 `CardId` 重复时**先到者胜**（文件路径按序号排序，保证可复现），后到者跳过 + 告警；一张都读不到时打告警（防空字典静默退化）。纯逻辑解析在 `Scripts/Battlefield/Core/CardSpatialSpecCatalog.cs`。⚠️ 判表要用 `LoadCsv.LoadCSVLines`（含表头）—— `LoadCSVDataLines` **会跳过表头**，拿它判表会把所有卡表判成非卡表。

**自动加载**：`LoadingSystem` 启动时递归扫描 `DataBase/Card/` 下全部 `.csv`，合并加载到字典。新增角色 CSV 无需改代码或路径表。

- 多个 CSV 有相同 `CardId`：先加载的保留，后续重复打印警告并跳过

- **区域物 / 格点效果表（2026-10-04 新增，T3 + T8）**：`DataBase/Battlefield/AreaObject.csv`（已登记 `FilePathRegistry`），表头 `TrapId,Name,TriggerTiming,SideFilter,MaxTriggers,DecayTiming,EffectType,Params` ——
  `TriggerTiming` 取 `OnEnter` / `OnTurnEnd`（可组合，缺省 `OnEnter`，`OnEnter` 由格上物件本体承载、`OnTurnEnd` 由格点地形状态承载）；`SideFilter` 取 `Triggerer / Enemy / Ally / All`（相对来源单位）；`MaxTriggers` 正整数 = 触发几次后消失（`0` = 无限）；`DecayTiming` 取 `Never` / `OnTurnEnd`（回合末结算后层数 −1）；`EffectType` / `Params` 与卡表同一套语法（当前结算支持 `Damage` / `HpLoss` / `Heal` / `Shield` / `AddState`）。进入触发 = 查表结算（未登记 `TrapId` 保留 3 点伤害兜底）；回合末结算在玩家结束回合时**一回合一次**。现役行：`test_trap` / `vine_sentinel` / `frost_field` / `blessed_ground`（T8 增益通道演示行）。
