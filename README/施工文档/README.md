## 分类口径

| 目录 | 收什么 |
|---|---|
| `玩法/` | 关卡、怪物、数值、配表相关的需求与设计案 |
| `交互/` | UI、局内流程、覆盖层、场景转场相关的执行案与需求案 |
| `战斗/` | 战斗系统、状态、空间规则、战斗动效相关的方案 |
| 月份根目录 | 月度施工文档、跨类需求清单、策划须知、待做/待测/扩展总览等无法单一归类的内容 |
| 规划/ | **跨层的阶段规划与功能清单**：现状快照 + 代码 / 玩法 / 交互 / 美术 / 音效五层方向 + 执行批次；`功能现状` 粗粒度版只列已实现的程序系统、**明细版把待做项一并按模块归类并以「（待做）」标注**、`功能规划` 列待做方向，两份共用同一套 `一、层 → 1、模块 → 1.系统` 三级格式；`待做项实施计划` 只做估时与排期（AI 协作工时 + 20% 缓冲 + 批次截止日，含复算命令）；文件名与标题都带日期，用于标注时效性 |

## 记录要求

- 每个案 / 待做 / 打磨文件都要有**完成情况**小节：已实现 / 部分实现 / 未实现 + 日期，并指向月度施工文档对应章节。
- 完成一个案时**两处都要写**：案文件内写「完成情况」，当月施工文档（如 `2026/2026.09/9月施工文档.md`）里新增 `## §N` 记录同一份实现情况。
- **已实现的交互案 / 执行案要迁出施工文档**（2026-10-02 用户指令）：案对应的功能**落地后**，把案迁到 `README/交互说明文档/<分类>/`（去掉文件名里的「案」、改用说明语气）；说明文档里**已有对应文档就合并进那一份**（不另开重复文件），未实现项在说明文档里**就地标注**并指向施工文档（待做清单或仍未落地的案）。施工文档侧只保留**完成情况**：案文件的迁出记录 + 当月施工文档的 `## §N` + 本文件「在办案索引」里该行标「**已迁出**」。

- 月度施工文档是当月唯一的完成事项入口（5、6 月历史文件仍为 `已完成事项_<年.月>.md`），记录规则见[开发记录规则](../功能说明文档/工程规范/开发记录.md)。
