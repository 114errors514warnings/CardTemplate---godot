## §三 当前阶段应集中的方向（结论）

**结论：集中「交互层」，并把「代码层」的配置前置与存档迁移作为同一批做完（血条 → 物品表 → 装备 → 背包）。**

### 3.1 判据对照

| 判据 | 交互层 | 代码层 | 玩法层 | 美术层 | 音效层 |
|---|---|---|---|---|---|
| 设计是否已定稿（可直接开工） | 是（[血条](../2026/2026.09/交互/角色与怪物血条交互案.md) / [背包](../2026/2026.09/交互/背包系统交互案.md) / [装备](../2026/2026.09/交互/装备系统交互案.md) 三案已落，含待拍板清单） | 是（P0-3 / P1-4 / P2-11 验收已写死） | 否（P2-8 等玩法输入；G4 需先拍板模板字段） | 部分（骨骼案自述待实机观感验收） | 否（无规格案） |
| 是否直接阻塞玩家体验 | **是**（内容已在库、界面入口没有） | 间接（前置） | 部分（规则收口） | 否（像素序列帧可回退） | 否 |
| 是否被其它层依赖 | 被美术层依赖（血条与角色表现同层） | 被交互层 / 玩法层依赖 | 被工程侧依赖 | 被音效层依赖（音画同步） | 无（末端） |

### 3.2 结论依据

1. **内容已铺、出口缺失**：15 张关卡 / 23 只怪物 / 6 张地图 / 7 个事件 / 3 张掉落表 / 23 条状态 / 9 类武器已在库并通过烟测；但玩家侧血条（P0-16）、背包（P0-17）、局外装备（P0-18）三项全缺 —— 材料（`Material,101`）只以原始编号出现在结算文案里，防具 / 饰品表根本不存在。交互层是当前唯一"做完就能把已有内容立刻变成可玩量"的方向。
2. **设计密度最高、实现为 0**：三案是仓库当前唯一"含逐条验收 + 待拍板清单 + 默认值"的可用工件（§41 记录），其余方向的需求都还停在方向级（P2-8、G4 4.1/4.2/4.3）。
3. **依赖链不允许拆开做**：血条零依赖可立即开工；但装备与背包被"物品表 + 存档迁移"卡住，所以代码层必须与交互层同批推进，而不是先做一层再做另一层。

```text
I1 血条 ────────────────→（零依赖，随时开工）
Armor.csv ──┐
C2 存档迁移 ┼─→ I2 装备界面 ─┐
（P0-3 float）+（装备/背包字段，SchemaVersion 2→3）│
C1 材料/道具表 ─────────────────┴─→ I3 背包 ─→ I4 摘要入口
C4 分档计数 ────────────→（零依赖，修正类）
```

4. **玩法层当前是"等输入"而非"可推进"**：P2-8 需玩法侧先给影响清单；P2-9 等 C2；P2-7 需拍板字段名；G4 的 4.1 / 4.2 / 4.3 需先定模板与索敌字段。这些项要么依赖交互侧的存档迁移，要么依赖玩法侧先出清单，单独强推会返工。
5. **美术层与音效层应排在交互层之后**：骨骼案自述"仍需继续接受实际游戏观感验收"，观感验收需要稳定的局内界面（血条 / 战后操作态）作参照；且血条与角色表现落在同一文件层（`BattlefieldView` / `HexBattleScene`），分两批改 = 两次回归面。音效层零实现且被现有文档明确排除在方向外，需先批准范围。

### 3.3 若目标变化时的反向选择

| 若当前目标是 | 则先做 | 原因 |
|---|---|---|
| 对外演示"内容量" | C1 → I3 最小版（只读背包 + 物品名称） | 让 15 关的掉落结果能被看见 |
| 验证战斗空间价值 | C4 + G4.3 攻击模板统一 + G5 数值校准 | 空间规则未稳时数值校准会反复 |

| 对外试玩 | 交互层之后补 S1 → S2 | 无声可玩，但试玩体验缺口最大项是音效 |
