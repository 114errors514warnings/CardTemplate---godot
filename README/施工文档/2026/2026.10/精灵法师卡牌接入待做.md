### T1 —— 空间配置仓库不再只读 `勇士Card.csv`（D1 / P2-29）

**现状（证据）**

- `Scripts/Battlefield/Runtime/BattleCardSpatialRepository.cs:10`：`public const string WarriorCardCsvPath = "res://DataBase/Card/勇士Card.csv";`
- `:22`：`LoadCsv.LoadCSVDataLines(WarriorCardCsvPath)` —— 只读这一个文件；`:30` 逐行 `CardSpatialSpec.ParseFields(LoadCsv.ParseCSVFields(line))`。
- 运行时**唯一消费点**：`Scripts/Battlefield/Runtime/BattlefieldSession.cs:117`（`GetSpatialSpec`）；查不到时的回落分支 `:119-128`（`Shape = Single`（Attack / NeedTarget）或 `None`，`MaxRange = 1`）。
- 后果：其他卡表（精灵 / 法师 / 重剑手 / 通用）的 `SpatialShape / SpatialArgs / TrapId`（第 10/11/12 列）被**完全忽略**，无告警。

**改法**

1. **枚举全部卡表**：`Scripts/System/LoadingSystem.cs:402-427` 已有递归收集器 `private static void CollectCsvFiles(string folderPath, List<string> result)`（Godot `DirAccess`，只收 `.csv`，子目录也进）→ 提为可复用（`public static`，或抽独立 helper），或在本仓库内自带同样的递归（不建议复制一份）。
2. `LoadAll` 遍历收集结果 → 合并进同一个 `Dictionary<int, CardSpatialSpec>`。
3. **重名策略**：同 `CardId` 后到的**跳过 + 告警**（对齐 `LoadingSystem.MergeCardsFromCsvIntoCache` 的既有 `GD.PrintErr` 口径）。
   ⚠️ **必须先对文件路径排序再合并**：`DirAccess.GetNext()` 的顺序不保证稳定，否则「哪个文件赢」变成偶发不确定行为。
4. `useCache` 语义与 `ForCard` 对外签名不变。`WarriorCardCsvPath` 常量改后若无引用即可删（删前 grep 全库）。
5. **留出可测缝（重要）**：

   ```csharp
   // 纯逻辑：方法体内不得出现 LoadCsv / DirAccess / FileAccess / GD.*
   public static void MergeSpatialFields(IEnumerable<string[]> fieldRows,
       Dictionary<int, CardSpatialSpec> target, string sourceLabel = null)
   ```

   Godot 侧只做「读文件 → `LoadCsv.ParseCSVFields(line)` → 交给纯方法」；`LoadAll` 里组装。

**边界（不要破坏）**

- `勇士Card.csv` 的 3 张空间卡行为**必须不变**：`11001002` 横扫（`Fan Range=1`）、`11001003` 烈闪突（`Line Range=2;Length=2;AttackMode=Thrust`）、`21001005` 埋设陷阱（`Trap Range=1 / test_trap`）。

**改法（拍板后）**
