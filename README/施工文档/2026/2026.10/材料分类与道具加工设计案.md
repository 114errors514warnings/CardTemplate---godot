## 四.2 待拍板 7（最高优先级）：餐厅「烹饪」的输入口径

**冲突事实**（2026-10-07 走读）：用户口径「烹饪 = 食物 → 更高级食物」，而餐厅当前烹饪吃的是**材料**（§一 第 7 / 8 条）—— 这条通道既不是烹饪、也不是合成。

| 方案 | 做什么 | 影响面 |
|---|---|---|
| **A 餐厅也做「食物升级」** | `RestaurantUi.CookableRecipes()` 判据改「输入全为 `Food` 且 `Enabled=TRUE`」（= 与营地同 5 条）；`RestaurantRequirements` 的扣减从 `BagCategory.Material` 计数改为**食物实例**（复用 `RunFoodSystem.TryConsumeFoodInstances`）；`FoodRecipe.csv` 的 7 条材料行**转废案**（`Enabled` 维持 `FALSE`，其中 104 / 106 / 109 / 110 转交「合成」通道） | 动 3 处（`RestaurantUi` / `RunSession.Place.cs` / 提示文案）+ 补单测；**副作用：餐厅钱路变弱**（买 2 × 普通食物 40 金币 → 升罕见 → 现做卖 24，是亏的；现版本材料来自掉落、现做卖 24 是净赚）→ 需同时定「时间点 / 次数」是否仍足以节流 |
| **B 餐厅只保留购买 / 出售**（去掉烹饪页） | 烹饪只在营地做；餐厅职责 = 买 / 卖（「现做 ×1.5」失去来源 → 一并去掉） | 动 `RestaurantUi` 删页签 + `RestaurantTrade` 的现做标记链路（按实例集合）+ 烟测 / 单测断言；`RunSession.Place.cs` 的餐厅烹饪三段（时间点 / 次数 / 材料）删或留作「合成」复用 |
| **C 保留现状（餐厅 = 材料 → 食物「现做」）** | 把这条通道**定义成第四类加工**（「现做」：材料 → 食物，卖价 ×1.5），与合成 / 锻造 / 烹饪并列写进系统规则文档 | **与 2026-10-07 用户口径直接冲突** —— 仅在用户明确把「餐厅现做」区别于「烹饪」时成立；此时 7 行必须维持 `Enabled=FALSE`（否则会漏进营地） |
