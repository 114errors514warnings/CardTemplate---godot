# 餐厅交互案

> 规定村庄**餐厅**的进入代价、**三页签界面**（购买 / 烹饪 / 出售）、价格与出售价（现做食物卖价更高）与拒绝原因。共用口径（地图形态、移动、时间点、界面分层）见[村庄地图交互案](村庄地图交互案.md)，本文只写餐厅自己的规则。

## 一、代价与次数

| 项 | 值 | 说明 |
|---|---|---|
| 进入代价 | **无**（进入本身不是操作） | 2026-10-05 口径：进入不看、不扣时间点（村庄案 §四） |
| 每次烹饪 | **0.1 时间点** | 点一次 `烹饪` 扣一次操作的时间点 = 全局数据表第 7 列 `VillageOperationTimePointCost`（默认 `0.1`，＝ 1 个战斗回合）；时间点不足时按钮转 `时间点不足` 禁用 + 一行去处指引 |
| 每次点菜（购买页「买入」） | **0.1 时间点 + 菜价金币** | 2026-10-05 第四轮：点菜也算一次「操作」（原先按纯交易 0 点，本轮改判）；先校验时间点 → 金币 → 背包负荷，通过后扣时间点 → 扣金币 → 入包 |
| 烹饪次数 | **每次进入 2 次** | 与营地「每次休息 ≤ 2 次」同档；用完出去再进刷新（进入不消耗 → **限次才是主要节流**，见村庄案 §十二 第 11 条） |
| 出售 | **0 时间点** | 纯交易不计（用户口径「出售食物不算」）；只受金币与背包约束 |
| 购买 / 出售次数 | 不限 | 只受金币与背包约束 |
| 占用 | 3 格（南边横 3）+ 入口格 1 | 见[村庄地图交互案](村庄地图交互案.md) §2.2 |
| 界面 | 模态层 `RunUiLayers.Modal = 40` | 单实例、与背包 / 装备 / 商人 / 锻铁铺互斥 |

## 二、界面结构

```text
┌ 餐厅 · 金币 168 · 本次还可烹饪 2 次 · 时间点 2.4                       [关闭] ┐
│ [ 购买 ] [ 烹饪 ] [ 出售 ]        ← 页签，默认「购买」                      │
├───────────────────────────────────────────────────────────────────────────┤
│ 购买页：4 格食物货架（图标 + 名称 + 稀有度 + 价格条），点击即买即入背包      │
│ 烹饪页：配方列表（材料 → 食物）+ 选中配方的材料需求 / 剩余次数 + [ 烹饪 ]    │
│ 出售页：背包食物按实例一行（名称 / 稀有度 / 剩余有效期 / 售价 + 「现做」标） │
├───────────────────────────────────────────────────────────────────────────┤
│ 提示行：<成功 / 失败原因，见 §六>                                           │
└───────────────────────────────────────────────────────────────────────────┘
```

- 面板几何、单实例与互斥口径与[商人交互案](商人交互案.md) §三 一致；食物格沿用商人 §4.3 的「132 × 132 + 价格条」尺寸。
- 三个页签**各自独立滚动**，共用同一条底部提示行；切页签不重置任何已选状态（烹饪页的选中配方在本次进入内保留）。

## 三、购买页

- 货源与生成口径与[商人交互案](商人交互案.md) §4.3 完全一致（`Food.csv` 按稀有度权重抽 4 格、一格一件、已售出不补位），价格用同一张表。
- 买入 → 食物**按实例**入背包（各自记有效期与效果）；价格见 §五。
- 与商人的分工：商人卖「材料 + 食物 + 装备 + 道具」，餐厅卖**只有食物**（且能买 / 能卖 / 能现做）。

## 四、烹饪页

- 配方来源：`DataBase/Item/FoodRecipe.csv` —— 现实现为餐厅**只放行 7 条「材料 → 食物」配方**（判据不看 `Enabled`）；「食物 + 食物 → 更高级食物」的 5 条 `Enabled=TRUE` 行**留营地**，餐厅不列（分工见 §六）。
  - ⛔ **2026-10-07 用户口径冲突**：用户定义「烹饪 = 食物 → 更高级食物」，则餐厅这条「材料 → 食物」通道既不属于烹饪、也不属于合成 → **去留待拍板**（见[材料分类与道具加工设计案 §四.2](../材料分类与道具加工设计案.md)）；未拍板前本文不改实现。
- 每行显示：产物（名称 + 稀有度 + 饱食度 / 有效期 / 篝火效果）+ 材料需求（逐条 `名称 ×N（持有 M）`）+ 是否可做。
- `烹饪` 按钮：本次次数已满 / **时间点不足** / 材料不足 / 背包超载时禁用并给具体原因；成功后产物**进背包**并立刻打上「现做」标（§五）。
- 烹饪**消耗一次操作的时间点（表值，默认 0.1）**（2026-10-05 第四轮口径：进入本身不是操作、每次操作收表值），与营地「合成不消耗额外时间点」不同 —— 营地不另收，餐厅按次收。
- **点菜（购买）同样算一次操作**（第四轮新增）：每次收 0.1 时间点 + 菜价；出售仍是纯交易（0 时间点）。

## 五、价格表与「现做」

| 稀有度 | 购买价 | 出售价（普通） | 出售价（**现做**） |
|---|---:|---:|---:|
| 普通 | 20 | 8 | 12 |
| 罕见 | 40 | 16 | 24 |
| 稀有 | 80 | 32 | 48 |

- 出售价 = 购买价 × **40%**（取整）；**现做**再加 ×1.5。
- 防套利硬口径：**现做卖价（60%）仍低于购买价（100%）** —— 买进来再卖掉一定亏，出售只对「战斗 / 事件 / 树林拿到的食物」和「自己烹饪的产物」有意义。
- **「现做」的定义**：本次进入餐厅中**通过烹饪产出**的食物实例（进入时建立实例集合；用它自己的 `InstanceId` 标记，不写在物品表上）。
- **存活期**：**离开餐厅即失效**（本批默认；待拍板第 3 条）—— 已售出 / 未售出的现做食物都掉标，之后按普通食物卖。
- 出售只收**食物**：材料不在此出售（材料变现归[商人交互案](商人交互案.md) §十 第 2 条的「卖出区」，未开）。

## 六、与营地烹饪的分工

| 项 | 营地（篝火） | 餐厅 |
|---|---|---|
| 入口代价 | 结束当天 / 时间点耗尽进营地 | 0（进入本身不是操作） |
| 配方 | 「食物 + 食物 → 更高级食物」5 条（`Enabled=TRUE`） | 「材料 → 食物」7 条（`Enabled=FALSE`；**与 2026-10-07 口径冲突，待拍板 → 设计案 §四.2**） |

| 额外代价 | 不消耗时间点 | **每次烹饪 0.1 时间点、每次点菜 0.1 时间点 + 菜价**（出售不收） |

| 输入限制 | **草稿里的食物不能当原料**（防一物两吃） | 现为只吃材料、不涉及草稿（**若改「食物升级」口径，则同样要防草稿食物**，见设计案 §四.2） |

## 九、验收

1. 踏入入口格 → 直接开界面（**不扣时间点**，时间点只剩 0.4 也能进）；标题行显示 `金币 … · 时间点 X.X`。
2. 购买页：4 格食物，买得起 → 点击即扣 **0.1 时间点 + 金币** + 食物实例入背包；每行显示 `时间点 0.1`；买不起 / 已售出 / **时间点不足**各给原因。
3. 烹饪页：列出 7 条材料配方；材料够时烹饪成功 → 产物入背包 + 打「现做」标 + 次数 −1；次数用尽后按钮禁用并给文案。⛔ **2026-10-07 口径冲突，本条待拍板后重写**（若改「食物升级」：应列出 5 条食物升级配方、扣食物**实例**）。
4. 出售页：列出背包内食物实例（含有效期）；点卖 → 食物移除 + 金币按 §五 增加；**现做的**食物按 ×1.5 结算且行上有「现做」标；出售**不**收时间点。
5. 防套利：买入一件再立刻卖出 → 金币净减少（普通食物 20 买 / 8 或 12 卖），**再叠加点菜的时间点 0.1**（亏得更多，不会因点菜收点而产生套利路径）。
6. 离开餐厅后重新进入 → 上一次的「现做」标全部失效（按普通价卖）；次数刷新为 2/2（进入不消耗 → 刷新本身无代价）。
7. **烹饪与点菜各扣一次操作的时间点（表值，默认 0.1）**；时间点不足时 `烹饪` / `买入` 按钮转 `时间点不足` 禁用并给去处指引（点不动、不扣材料 / 金币）；去旅馆 / 民宿过夜后补满 4.0 可继续。出售**不**扣时间点。
8. 营地侧的烹饪行为不变（仍只吃食物、仍 ≤ 2 次 / 次休息、仍不额外收时间点）。
9. `dotnet build` / `dotnet test` / `--run-flow-ui-smoke`（新增餐厅段）不回归。
