# 餐厅交互案

> 规定村庄**餐厅**的进入代价、**三页签界面**（购买 / 烹饪 / 出售）、价格与出售价（现做食物卖价更高）与拒绝原因。共用口径（地图形态、移动、时间点、界面分层）见[村庄地图交互案](村庄地图交互案.md)，本文只写餐厅自己的规则。

## 一、代价与次数

| 项 | 值 | 说明 |
|---|---|---|
| 进入代价 | **1 时间点 / 次进入** | 时间点不足 → 不触发、不弹、不开界面（村庄案 §五） |
| 烹饪次数 | **每次进入 2 次** | 与营地「每次休息 ≤ 2 次」同档；用完再踏入入口格（再花 1 时间点）刷新 |
| 购买 / 出售次数 | 不限 | 只受金币与背包约束 |
| 占用 | 3 格（南边横 3）+ 入口格 1 | 见[村庄地图交互案](村庄地图交互案.md) §2.2 |
| 界面 | 模态层 `RunUiLayers.Modal = 40` | 单实例、与背包 / 装备 / 商人 / 锻铁铺互斥 |

## 二、界面结构

```text
┌ 餐厅 · 金币 168 · 本次还可烹饪 2 次                                  [关闭] ┐
│ [ 购买 ] [ 烹饪 ] [ 出售 ]        ← 页签，默认「购买」                      │
├───────────────────────────────────────────────────────────────────────────┤
│ 购买页：4 格食物货架（图标 + 名称 + 稀有度 + 价格条），点击即买即入背包      │
│ 烹饪页：配方列表（材料 → 食物）+ 选中配方的材料需求 / 剩余次数 + [ 烹饪 ]    │
│ 出售页：背包食物按实例一行（名称 / 稀有度 / 剩余有效期 / 售价 + 「现做」标） │
├───────────────────────────────────────────────────────────────────────────┤
│ 提示行：<成功 / 失败原因，见 §六>                                           │
└───────────────────────────────────────────────────────────────────────────┘
```

- 面板几何、单实例与互斥口径与[商人交互案](商人交互案.md) §三 一致；食物格沿用商人 §4.3 的「132 × 132 + 价格条」尺寸。
- 三个页签**各自独立滚动**，共用同一条底部提示行；切页签不重置任何已选状态（烹饪页的选中配方在本次进入内保留）。

## 三、购买页

- 货源与生成口径与[商人交互案](商人交互案.md) §4.3 完全一致（`Food.csv` 按稀有度权重抽 4 格、一格一件、已售出不补位），价格用同一张表。
- 买入 → 食物**按实例**入背包（各自记有效期与效果）；价格见 §五。
- 与商人的分工：商人卖「材料 + 食物 + 装备 + 道具」，餐厅卖**只有食物**（且能买 / 能卖 / 能现做）。

## 四、烹饪页

- 配方来源：`DataBase/Item/FoodRecipe.csv` —— 餐厅**只放行 7 条「材料 → 食物」配方**（现 `Enabled=FALSE`）；「食物 + 食物 → 更高级食物」的 5 条放行配方**留营地**，餐厅不列（分工见 §六）。
- 每行显示：产物（名称 + 稀有度 + 饱食度 / 有效期 / 篝火效果）+ 材料需求（逐条 `名称 ×N（持有 M）`）+ 是否可做。
- `烹饪` 按钮：本次次数已满 / 材料不足 / 背包超载时禁用并给具体原因；成功后产物**进背包**并立刻打上「现做」标（§五）。
- 烹饪**不消耗时间点**（进门已经花了 1 点），与营地「合成不消耗额外时间点」同口径。

## 五、价格表与「现做」

| 稀有度 | 购买价 | 出售价（普通） | 出售价（**现做**） |
|---|---:|---:|---:|
| 普通 | 20 | 8 | 12 |
| 罕见 | 40 | 16 | 24 |
| 稀有 | 80 | 32 | 48 |

- 出售价 = 购买价 × **40%**（取整）；**现做**再加 ×1.5。
- 防套利硬口径：**现做卖价（60%）仍低于购买价（100%）** —— 买进来再卖掉一定亏，出售只对「战斗 / 事件 / 树林拿到的食物」和「自己烹饪的产物」有意义。
- **「现做」的定义**：本次进入餐厅中**通过烹饪产出**的食物实例（进入时建立实例集合；用它自己的 `InstanceId` 标记，不写在物品表上）。
- **存活期**：**离开餐厅即失效**（本批默认；待拍板第 3 条）—— 已售出 / 未售出的现做食物都掉标，之后按普通食物卖。
- 出售只收**食物**：材料不在此出售（材料变现归[商人交互案](商人交互案.md) §十 第 2 条的「卖出区」，未开）。

## 六、与营地烹饪的分工

| 项 | 营地（篝火） | 餐厅 |
|---|---|---|
| 入口代价 | 结束当天 / 时间点耗尽进营地 | 1 时间点 |
| 配方 | 「食物 + 食物 → 更高级食物」5 条（`Enabled=TRUE`） | 「材料 → 食物」7 条（现 `Enabled=FALSE`） |
| 次数 | 每次休息 2 次 | 每次进入 2 次 |
| 额外代价 | 不消耗时间点 | 不消耗时间点（进门已花） |
| 产物去向 | 进背包，可立刻放进本次篝火 | 进背包，带「现做」标（可卖高价） |
| 输入限制 | **草稿里的食物不能当原料**（防一物两吃） | 只吃材料，不涉及草稿 |

- 两处**共用** `RunFoodSystem` 的烹饪实现与 `FoodRecipe.csv`；差别只在「放行哪些配方」与「输入允许哪些类别」。营地口径不变（仍是 Food-only），餐厅需要**额外放行 Material 输入**。

## 九、验收

1. 时间点 ≥ 1.0 踏入入口格 → 直接开界面并扣 1.0；不足时不开界面、给原因。
2. 购买页：4 格食物，买得起 → 点击即扣金币 + 食物实例入背包；买不起 / 已售出各给原因。
3. 烹饪页：列出 7 条材料配方；材料够时烹饪成功 → 产物入背包 + 打「现做」标 + 次数 −1；次数用尽后按钮禁用并给文案。
4. 出售页：列出背包内食物实例（含有效期）；点卖 → 食物移除 + 金币按 §五 增加；**现做的**食物按 ×1.5 结算且行上有「现做」标。
5. 防套利：买入一件再立刻卖出 → 金币净减少（普通食物 20 买 / 8 或 12 卖）。
6. 离开餐厅后重新进入 → 上一次的「现做」标全部失效（按普通价卖）；次数刷新为 2/2。
7. 营地侧的烹饪行为不变（仍只吃食物、仍 ≤ 2 次 / 次休息）。
8. `dotnet build` / `dotnet test` / `--run-flow-ui-smoke`（新增餐厅段）不回归。

## 十、待拍板（当前默认值）

| # | 问题 | 默认值 | 回改方式 |
|---|---|---|---|
| 1 | 购买价与商人是否一致 | **一致**（共用 `Category=Food` 的价格行） | 餐厅单独上浮（如 ×1.1）：只改价格表的查询口径 |
| 2 | 出售比例与现做加成 | 40% / ×1.5 | 改两个全局配置（`SellRatio` / `FreshBonus`） |
| 3 | 「现做」标的存活期 | **离开餐厅即失效** | 改为当日有效：把标记的清除时机从「离开场景」换成「跨天」（`AdvanceToNextDay`） |
| 4 | 道具合成台（物品系统 §2.3）的落点 | **本批不承接** | 挂餐厅第 4 页签（复用同一套「配方 + 材料 + 金币」界面）或挂锻铁铺 |
| 5 | 出售是否也收材料 | **不收**（只收食物） | 收材料：按[商人交互案](商人交互案.md) §五 的材料价 ×40% 结算 |
| 6 | 每次进入的烹饪次数 | **2 次** | 改常量 / 配表值 |
| 7 | 购买页货架格数 | **4 格** | 与商人食物栏同步调（两边共用一个格数配置） |
