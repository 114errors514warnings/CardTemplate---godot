## 一、代价与次数

| 项 | 值 | 说明 |
|---|---|---|
| 进入代价 | **无**（进入本身不是操作） | 2026-10-05 口径：进入不看、不扣时间点（村庄案 §四） |
| 每次打造 | **0.1 时间点 + 配方金币** | 点一次 `打造` 扣一次操作的时间点 = 全局数据表第 7 列 `VillageOperationTimePointCost`（默认 `0.1`，＝ 1 个战斗回合），另扣配方金币（村庄 ×1）；时间点不足时按钮转 `时间点不足` 禁用，费用行给「去旅馆 / 民宿过夜」的指引 |
| 打造次数 | **每次进入 2 次** | 用完可出去再进刷新次数（进入不消耗 → 刷新本身无代价；**限次才是主要节流**，见村庄案 §十二 第 11 条） |

| 产出 | 装备**进背包** | 不自动装上；要装上走[装备系统交互案](../../2026.09/交互/装备系统交互案.md) |

## 二、界面结构

```text
┌ 锻铁铺 · 本次可打造 2 / 2 · 金币 168 · 时间点 2.4                   [关闭] ┐
│ ┌ 左列（40%）：配方列表 ─────────────┐ ┌ 右列（60%）：选中配方 ──────────┐ │
│ │ 行军短剑  单手 · 距离 1 · 防御 1  │ │ 行军短剑（单手武器）             │ │
│ │ 长刀      单手 · 距离 2 · 防御 1  │ │ 属性：攻击距离 1 / 防御 1 / 移动 1│ │
│ │ 长枪      双手 · 距离 3 · 防御 1  │ │ 材料：铁矿石 ×2（持有 1）        │ │
│ │ …（现役 14 件，竖排一行一格）     │ │ 费用：20 金币（当前 168）        │ │
│ └───────────────────────────────────┘ │ [ 打造 ]                        │ │
│                                        └─────────────────────────────────┘ │
│ 提示行：<成功 / 失败原因，见 §五>                                          │
└───────────────────────────────────────────────────────────────────────────┘
```

- 面板几何、层级（`RunUiLayers.Modal = 40`）、单实例与互斥口径与[商人交互案](商人交互案.md) §三 一致（同时只开一个设施界面）。
- 左列配方列表：一行一配方（图标 + 名称 + 部位 / 手数 + 攻击距离 / 防御），**材料不足或金币不足的配方仍可选中**（详情里给红字），只有点 `打造` 时才校验（与背包界面的「先拿起、再拦落点」同一手感）。
- 右列详情：属性行 → 材料需求（逐条 `名称 ×N`，`（持有 M）`，不足标红）→ 费用行（不足标红）→ `打造` 按钮（次数用尽 / 背包超载时禁用并给一行说明）。
- 成功 / 失败都在**底部提示行**给一行文案（成功同时角色 / 界面内一次浮字）。

### 2.1 复用接口：界面与内容分离（商人锻造炉共用）

- 本界面**一份实现、两处调用**：村庄锻铁铺与[商人交互案](商人交互案.md) §4.9 的**锻造炉**共用同一份 `SmithyUi`；两处差异全部收敛进一个注入对象（`SmithyContext`），界面代码里**不出现**「在村庄 / 在商人」这类分支。
- 注入项（必须全部走参数，不得写死在界面内）：

| 字段 | 村庄锻铁铺 | 商人锻造炉 | 说明 |
|---|---|---|---|
| `Title` | `锻铁铺` | `锻造炉` | 标题行左侧文案 |
| `MaxCrafts` | 2（§九 待拍板第 2 条） | 1（[商人交互案](商人交互案.md) §十 第 13 条） | 本次可打造次数 |
| `RecipeSource` | `EquipmentRecipe.csv` 全表 | 同表（本批不筛） | 预留「只出部分配方」的口子 |
| `GoldMultiplier` | 1.0 | 1.5（[商人交互案](商人交互案.md) §十 第 14 条） | 费用行金币系数，向上取整到 5 的倍数 |
| `CurrencyNote` | `费用：材料 + 金币` | `费用：材料 + 金币（商人工匠费 ×1.5）` | 右列费用说明文案 |
| `TimePointRestHint` | `请前往旅馆或民宿过夜，或回营地结束当天。` | `请回营地结束当天。` | 时间点不足时的去处指引（接在费用行后；界面内不出现场景分支） |
| `OnClose` | 回村庄场景 | 回商人界面 | 关闭后的上层界面由调用方给回调 |
| `OnCrafted` | 产出进背包 | 产出进背包 | 本批两处相同；留回调便于以后分叉 |

- 次数上限、金币系数、费用文案**只从 `SmithyContext` 读**；界面内不得出现村庄专属常量（否则「复用」会退化成两套实现、改一处漏一处）。
- 落地形式（拟）：`SmithyUi` 构造函数收 `SmithyContext`；两个预设 `SmithyContext.VillageSmithy` / `SmithyContext.MerchantForge` 放同文件或 `SmithyContexts.cs`；次数 / 材料 / 金币的**纯逻辑校验仍落 `SmithyCrafting`**，两处共用同一份单测。

## 四、打造流程与反馈

1. 选配方（左列）→ 右列显示属性 / 需求 / 费用。
2. 点 `打造` → 依次校验：**时间点够（当天剩余 ≥ 一次操作的代价 `VillageOperationTimePointCost`，默认 0.1）** → 本次次数未用尽 → 材料够 → 金币够 → 背包可入账。
3. 通过 → 扣一次操作的时间点（默认 0.1）→ 扣材料（按材料实例数扣，不足即拒）→ 扣金币（配方金币 ×系数）→ 装备进背包 → 本次次数 −1 → `Save()` → 提示行 `打造完成：行军短剑`，标题行（次数与时间点）刷新。
4. 不通过 → 不改任何状态，提示行给原因（§五），并高亮缺的那一条需求。

## 五、失败原因表

| 情形 | 时机 | 文案 |
|---|---|---|
| 时间点不足 | 界面内（按钮转 `时间点不足` 禁用 + 费用行给指引） | `时间点不足：需要 1.0，当前剩余 0.4。请前往旅馆或民宿过夜，或回营地结束当天。` |
| 本次次数用尽 | 界面内点 `打造` | `本次进入的打造次数已用尽，离开锻铁铺再进即可刷新次数。` |
| 材料不足 | 界面内点 `打造` | `材料不足：铁矿石 需要 2，持有 1。` |
| 金币不足 | 界面内点 `打造` | `金币不足：需要 20，当前 5。` |
| 背包超载 | 界面内点 `打造` | `背包已超载，请先整理。` |

- 材料 / 金币不足时 `打造` 按钮**保持可点**（点了才知道缺什么，与背包界面「先拿起、再拦落点」同一手感）；次数用尽 / 背包超载时按钮**直接禁用**并附一行说明。

## 八、验收

1. 踏入入口格 → 直接开界面（**不扣时间点**，时间点只剩 0.0 也能进）；标题行显示 `金币 … · 时间点 X.X`。
2. 界面配方列表 = 现役装备 14 件；选中任一件，右列的需求 / 费用与 §三 表一致。
3. 材料与金币都够 → 打造成功：材料按数量扣、金币扣、装备出现在背包、次数 −1、立刻落档。
4. 次数用尽后再点 `打造` → 不给扣材料 / 金币，提示行给对应文案。
5. 材料不足 / 金币不足 → 按钮可点但被拒，提示行点名缺的材料与数量。
6. 离开界面再踏入入口格 → **不再扣时间点**，次数刷新为 2/2；每次点 `打造` 各扣 0.1 时间点 + 配方金币（两项数值都读表，见[配表规范](../../../../功能说明文档/数据系统/数据配置/配表规范.md)）；时间点不足时按钮转 `时间点不足` 且费用行给去处指引（点不动、不扣料）。
7. 背包超载时 `打造` 按钮禁用 + 一行说明。
8. `dotnet build` / `dotnet test` / `--run-flow-ui-smoke`（新增锻铁铺段）不回归。
