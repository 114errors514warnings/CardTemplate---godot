# 已到达地点进局内地图需求案

> **用户口述需求（2026-10-06）**：「已经到达过的地点点击后不会在地图上停留，而是来到局内地图中，但是是和商人、村庄一样的非战斗状态，其中的物品也会得到保留。」
> 本页是**需求案**（写「要做什么」），与 [10 月施工文档 §33](../10月施工文档.md) 的「地点一律走关卡统一流程」配套；落地后按 [文档编写规则 §九](../../../../AIWorkSpace/AgentOps/文档编写规则.md) 迁出为交互说明文档。

## 一、现状（本需求要改掉什么）

| 场景 | 现状 | 出处 |
|---|---|---|
| 点一个**已到达过**的节点 | 角色**停在原地**：`MarkCurrentNodeVisitedAndAdvanceEncounter()` + 提示「已访问格：可再次经过，不重复触发。」除落盘外什么都不发生 | `MapScene.EnterNode` 的 `node.Visited` 分支 |
| 首次到达但解析不出配置 | `Visited = true` + 「已到达（无配置遭遇），停留地图。」 | 同文件的「无配置」分支（村庄行 2026-10-06 起暂落这里） |
| 地点（村庄 / 商人） | 原为专用场景（`VillageScene`）→ **2026-10-06 已撤除**，村庄暂不可达 | [10 月施工文档 §33](../10月施工文档.md) / §34 |

- 一句话现状：**「再去一次已经到过的地方」这条路现在不存在** —— 已到达 = 一次性，之后那格只是能通行的空地。

## 二、需求（改成什么）

1. 点一个**已到达过**的地点节点 → **不留在世界地图**，而是**进入该地点的局内地图**。
2. 该局内地图是**非战斗状态** —— 与商人 / 村庄同一类：能走动、能与里面的单位交互、能离开；**不是**战斗关的战斗态（不摆阵、不抽卡、不进战斗结算）。
3. **其中的物品保留** —— 再次进入时，该地点里上次留下、未取走的东西还在（不是每次进去重新生成一份）。
4. 蕴含的推论：这类地点**可重复进入**（不再是「一次性节点」）；「首次到达」与「再次到达」的差别只落在**进入时的初始状态**上。

## 三、与统一关卡流程的关系（§33）

- §33 规定地点与战斗**同一条关卡流程 + 同一套载体**：`Level/LevelIndex.csv` + `Level/Config/<LevelId>.csv` + `BattleMap/MapIndex.csv` / `Maps/<MapId>.json`；节点绑定写 `FixedNode.csv` 的 `ContentType = Level`，`LevelType` 决定表现。
- 本需求是那条流程上**多一条入口条件**：同一个节点，**首次进入**按 `LevelType` 表现（战斗 / 地点），**再次进入**一律走「非战斗的局内地图」表现。
- 因此本需求**不新增内容类型** —— 运行时仍只有 `Level` / `Event` 两条通道（§33.2 的自查判据不变），差别落在关卡流程内部的「初访 / 复访」状态上。

## 四、判定口径（待用户裁定）

| # | 问题 | 未裁定前的默认写法（照此写测试） |
|---|---|---|
| 1 | 哪些节点算「会复访进局内地图的地点」 | `LevelType` 属非战斗类的关卡（§33.2 取值表里的 `Village` / `Merchant`）；**纯战斗关复访是否也这样**（复访不进战斗）待定 |
| 2 | 「已到达过」怎么判 | 存档 `MapState.VisitedNodeIds`（现有字段，与版图上的「已访问」标记同源） |
| 3 | 复访要不要花时间点 | 建议**要**：仍走世界地图「节点 → 相邻节点」那一跳的移动消耗（与首访一致）；局内走动不消耗 |
| 4 | 「物品保留」保到什么程度 | 建议：该地点的容器 / 货架 / 掉落残留按**地点维度持久化**（键用 `LevelId`，复用 `RunSaveData` 现有地点状态字段的思路）；**已取走的不再生成**，未取走的原样留着 |
| 5 | 能不能空进空出 | 建议：可以 —— 非战斗态没有战斗结算，离开条件由关卡自身给（离开格 / 界面关闭） |
| 6 | 与结算面板的关系 | 建议：非战斗复访**不发卡、不弹结算面板**（结算只属战斗关） |
| 7 | 「已到达」要不要分两种语义 | 待定：若战斗关也允许复访进非战斗态，则需把「本关已通过」与「该地点已到达」分开记（影响存档字段与地图标记） |

## 五、实现要点（初判，不含数值）

- `MapScene.EnterNode`：`node.Visited` 分支由「停留地图」改为「请求进入该节点的关卡（非战斗态）」；`content == null` 的兜底保持现状（真没配置才停留）。
- 关卡流程侧：进入时要带上**「初访 / 复访」**这一个事实（来源 = 进入前的 `Visited` 判定），由关卡场景据此选表现（战斗态 / 非战斗态）。
- 存档：地点状态要有**按 `LevelId` 索引**的落点（是否需要从旧 `VillageState` 迁移，取决于「物品保留」的裁定 —— 见 §四 第 4 / 7 条）。
- API：待批 B 定下形态后按 [AI 接口说明](../../../../功能说明文档/AI接口/README.md) 的口径补指令（只补「玩家在界面上真能点的那一下」），**不照搬已撤除的 `run.village.*`**。

## 六、验收判据（可执行）

1. 点一个已到达过的地点节点 → `RunFlowScene.ContentKind` 是**非战斗**态（不是 `battle`），世界地图转只读，能在局内走动，能离开并回到可选地图。
2. 同一地点连进两次：第一次取走的东西，第二次进去**仍然不在**；没取的**仍在**（按地点存档持久化）。
3. **首次到达的表现不变**（战斗关照打、地点关照进）—— 初访 / 复访两条路互不影响。
4. `Scripts/` 全库检索 `run.village` 零命中（§33 的自查判据保持）。
