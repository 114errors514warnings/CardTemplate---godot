# 已到达地点进局内地图需求案

> **用户口述需求（2026-10-06）**：「已经到达过的地点点击后不会在地图上停留，而是来到局内地图中，但是是和商人、村庄一样的非战斗状态，其中的物品也会得到保留。」
> 本页是**需求案**（写「要做什么」），与 [10 月施工文档 §33](../10月施工文档.md) 的「地点一律走关卡统一流程」配套；落地后按 [文档编写规则 §九](../../../../AIWorkSpace/AgentOps/文档编写规则.md) 迁出为交互说明文档。

## 一、现状（本需求要改掉什么）

| 场景 | 现状 | 出处 |
|---|---|---|
| 点一个**已到达过**的节点 | 角色**停在原地**：`MarkCurrentNodeVisitedAndAdvanceEncounter()` + 提示「已访问格：可再次经过，不重复触发。」除落盘外什么都不发生 | `MapScene.EnterNode` 的 `node.Visited` 分支 |
| 首次到达但解析不出配置 | `Visited = true` + 「已到达（无配置遭遇），停留地图。」 | 同文件的「无配置」分支（村庄行 2026-10-06 起暂落这里） |
| 地点（村庄 / 商人） | 原为专用场景（`VillageScene`）→ **2026-10-06 撤除专用场景**，**2026-10-07 已按 §33 落地为关卡**（村庄关 `F1-V-001` / 商人关 `F1-M-001`，走统一关卡通道） | [10 月施工文档 §33](../10月施工文档.md) / §34 |

- 一句话现状：**「再去一次已经到过的地方」这条路现在不存在** —— 已到达 = 一次性，之后那格只是能通行的空地。

## 二、需求（改成什么）

1. 点一个**已到达过**的节点 → **不留在世界地图**，而是**进入该节点的局内地图**。
2. 该局内地图是**非战斗状态** —— 与商人 / 村庄同一类：能走动、能与里面的单位交互、能离开；**不是**战斗关的战斗态（不摆阵、不抽卡、不进战斗结算）。
3. **进入时只做三件事**（用户 2026-10-06 口径：「全都可以，只要加载地图和地图上的交互点、物品、障碍物就行」）：加载该节点的**地图** + 地图上的**交互点 / 物品 / 障碍物**。
4. **交互点、物品、障碍物保留** —— 再次进入时，上次留下、未取走的东西还在（不是每次进去重新生成一份）；**已取走的不再生成**（持久化键 = 格点位置 id，见 §四）。
5. **所有节点一视同仁**（用户 2026-10-06 口径）：任何节点**重复进入都进非战斗态**，与它是什么 `LevelType` 无关（纯战斗关同样如此）；**例外**只有「特殊情况」（如一次性事件选项、剧情强制节点 —— 逐个出现时单独裁定）。
6. **判定只用「到达过」**（用户 2026-10-06 口径）：只要**到达过**该地点就算 —— **不要求通过关卡**；一个非游戏结束性的关卡即使没打过，该格点之后再到达也**仍是非战斗态**（无需区分「本关已通过」与「该地点已到达」）。
7. 蕴含的推论：这类节点**可重复进入**（不再是「一次性节点」）；「首次到达」与「再次到达」的差别只落在**进入时的初始状态**上。

## 三、与统一关卡流程的关系（§33）

- §33 规定地点与战斗**同一条关卡流程 + 同一套载体**：`Level/LevelIndex.csv` + `Level/Config/<LevelId>.csv` + `BattleMap/MapIndex.csv` / `Maps/<MapId>.json`；节点绑定写 `FixedNode.csv` 的 `ContentType = Level`，`LevelType` 决定表现。
- 本需求是那条流程上**多一条入口条件**：同一个节点，**首次进入**按 `LevelType` 表现（战斗 / 地点），**再次进入**一律走「非战斗的局内地图」表现 —— **与 `LevelType` 无关，含纯战斗关**（用户 2026-10-06 裁定）。
- 因此本需求**不新增内容类型** —— 运行时仍只有 `Level` / `Event` 两条通道（§33.2 的自查判据不变），差别落在关卡流程内部的「初访 / 复访」状态上。

## 四、判定口径

### 4.1 已裁定（用户 2026-10-06）

| # | 问题 | 裁定 |
|---|---|---|
| 1 | 哪些节点复访进非战斗态 | **所有节点** —— 重复进入都进非战斗态，`LevelType` 不参与判断（`Village` / `Merchant` / 纯战斗关一致） |
| 2 | 「已到达过」怎么判 | 存档 `MapState.VisitedNodeIds`（现有字段，与版图「已访问」标记同源）；**只要到达过即可，不要求通过关卡**（非游戏结束性的关卡没打过也算到达） |
| 3 | 「物品保留」用什么键 | **格点位置 id**（**不是** `LevelId`）—— 与 `MapState.VisitedNodeIds` / `CurrentNodeId` 同一套 id；**已取走的不再生成**，未取走的原样留着 |
| 4 | 保留哪些东西 | **交互点 / 物品 / 障碍物**（用户口径原话三件）；「特殊情况」逐个裁定 |
| 5 | 允许哪些 `LevelType` 复访 | **全部** —— 只要求「能加载出地图 + 地图上的交互点 / 物品 / 障碍物」 |

## 五、实现要点（初判，不含数值）

- `MapScene.EnterNode`：`node.Visited` 分支由「停留地图」改为「请求进入该节点的关卡（**非战斗态**）」；`content == null` 的兜底保持现状（真没配置才停留）。`ContentType = Village / Merchant` 的旧行**不再需要专用分流**（§33 规定 + §34 已撤除专用场景）。
- 关卡流程侧：进入时要带上**「初访 / 复访」**这一个事实（来源 = 进入前的 `Visited` 判定），由关卡场景据此选表现（战斗态 / 非战斗态）；复访时**不摆阵、不抽卡、不进结算**，只加载地图 + 交互点 / 物品 / 障碍物。
- 存档：地点状态按**格点位置 id**索引（与 `MapState.VisitedNodeIds` / `CurrentNodeId` 同源，由 `MapGeometry.RecordFixedNodeIds` 记录）；版图按 act 重建 → 键建议取 **`(Act, 格点 id)`**，避免跨 act 串号。
- 旧 `VillageState` **不需要迁移**（村庄专用场景与专用版图表已撤除，见 §34）。
- API：待批 B 定下形态后按 [AI 接口说明](../../../../功能说明文档/AI接口/README.md) 的口径补指令（只补「玩家在界面上真能点的那一下」），**不照搬已撤除的 `run.village.*`**。

## 六、验收判据（可执行）

1. 点一个**已到达过**的节点 → `RunFlowScene.ContentKind` 是**非战斗**态（不是 `battle`），世界地图转只读，能看到该节点的地图与交互点 / 物品 / 障碍物，能走动能离开并回到可选地图。
2. **纯战斗关复访同样是非战斗态**（`LevelType` 不参与该判断）。
3. 同一地点连进两次：第一次取走的东西，第二次进去**仍然不在**；没取的**仍在**（按 `(Act, 格点 id)` 持久化）；**没打过的非游戏结束性关卡**之后再到达，同样是**非战斗态**。
4. **首次到达的表现不变**（战斗关照打、地点关照进）—— 初访 / 复访两条路互不影响。
5. `Scripts/` 全库检索 `run.village` 零命中（§33 的自查判据保持）。
