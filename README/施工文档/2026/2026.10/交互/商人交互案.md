## 一、商人节点在世界地图上的位置

- 商人节点是**常规节点**（`MapNodeType.Merchant`），每层**仅刷新 1 个**（地图玩法 §4.2），由 `EventPool.csv` 的 `Merchant` 行解析；本批把它从「随机选一个事件」改为「进入商人场景」。
- 节点**只能进入一次**：与其它节点同一口径（已访问节点可经过、不重复触发，见[地图交互](../../../../交互说明文档/地图/地图交互.md)）。
- 商人**不消耗时间点**：进入与购买都只花金币（待拍板第 1 条）。

## 二、场景形态（用户口径：一片空白的地图上出现一个商人节点）

- 进入商人节点 → 淡出世界地图、切换到**商人场景**：底图为**空白地图**（无地形、无其它设施；美术未定前用纯色 + 网格线占位）。
- 场景内只有三个元素：

| 元素 | 占格 | 说明 |
|---|---|---|
| 商人单位 | 3 格（横向三格） | 不可通行；整体一个单位，点任一格即选中 |
| 角色（队伍） | 1 格 | 从世界地图进入时落在**入口格**（商人左侧 3 格外） |
| 离开格 | 1 格 | 商人对侧（右侧）；踏入即离开商人场景 |

- 网格、移动与「离开格」复用[村庄地图交互案](村庄地图交互案.md) §二 / §三 的同一套口径（六边形格、`RunTimePoints.MoveCost = 0.3`/格）；两案差异只有一条：

| 项 | 村庄 | 商人 |
|---|---|---|
| 场景内容 | 5 个设施单位 + 空地 | 商人单位 3 格 |
| 走到单位附近是否自动开界面 | 否（踏入入口格才触发） | **是**（走到商人相邻格即自动打开） |

### 2.1 点击 → 走近 → 自动打开

1. 左键点商人单位的任一格。
2. 角色沿**可达路径**（复用地图的可达性判定）移动到商人**最近的可站格**（商人四周且路径可达的格）；移动途中加**局部输入锁**（不可再点、不可开背包）——当前仓库只有营地有转场锁，本批按局部锁实现，落点见 §八。
3. 到达那一刻**自动打开**商人界面，不需要再点一次。
4. 若点击时角色**已经在可站格上**（例如刚进入场景就贴着商人），跳过第 2 步，直接打开界面。
5. 再次点商人单位 = 再次打开界面（不重复扣费、不重放走近演出）。
6. 退出界面：界面内 `关闭` / `Esc` → 回到商人场景（角色原地）；要离开商人场景必须走到**离开格**。

## 四、货架

### 4.1 通用格规则

- 每格显示：图标 + 名称 + 稀有度底色 + 格下价格条。
- 三种状态：**可购买**（金币够）、**买不起**（灰显，点击给原因）、**已售出**（原位显示 `已售出` 并变暗，**不补位、不重排**）。
- **一格一件**，不做数量堆叠（待拍板第 5 条）。
- 悬停显示明细（材料：类别 / 稀有度 / 负荷；食物：饱食度 / 有效期 / 效果；装备：属性；道具：效果 / 生效范围），口径与[背包交互](../../../../交互说明文档/局内UI/背包交互.md)一致。

### 4.2 卡包（上部 5 格）

- 5 个卡位**各是一个卡包**（不是单张牌）：格上显示包背 + 包名 + 剩余可买数 `余 N / 5`；左键点格 → 打开该包的**卡包详细**（§4.3）。
- 每包固定 **5 张卡**，5 个包的分工：

| # | 卡包 | 候选卡来源 | 买下后进入哪个卡组 |
|---:|---|---|---|
| 1 | 角色 1 专属包 | 槽位 0 角色的卡池（`DataBase/Card/CharacterRewardPool.csv` 该角色行指向的 CSV） | **固定 = 槽位 0** |
| 2 | 角色 2 专属包 | 槽位 1 角色的卡池 | **固定 = 槽位 1** |
| 3 | 角色 3 专属包 | 槽位 2 角色的卡池 | **固定 = 槽位 2** |
| 4 | 混合包 | 三个槽位角色的卡池**混合**抽 5 张 | **买时选**：三个槽位任选一个（§4.3） |
| 5 | 通用牌包（通用卡池） | 通用卡池 `DataBase/Card/通用/通用Card.csv` | **买时选**：三个槽位任选一个（§4.3） |

- **第 5 包的构成硬口径（用户指定）**：**3 张 A 级 + 2 张 S 级**，全部取自**通用卡池**（通用牌）。⚠️ 依赖：现役通用表**只有 D / C 级行**，且两张表都**没有等级列** → 见 §十 第 9 / 10 条（先落 `CardTier` 列 + 通用表补 5 行 A / S 通用牌）。
- 第 1–4 包的候选卡按**等级权重**抽（权重落新表，缺省 D 40 / C 30 / B 18 / A 9 / S 3），包内不重复，且**不出现状态牌**（`CardType = State`）。
- 卡包**按槽位生成**（不是按角色 Id）：队伍可出现同名角色，同名两个槽位各有自己的专属包，包名带槽位编号（口径同[战斗结算交互 §3.1](../../../../交互说明文档/战斗/战斗结算交互.md)）。**卡包不刷新、不补位**：本局首次进入本商人生成快照后固定（§七）；买走一张 → 该卡位 `已售出`，5 张全买完 → 包格显示 `已售罄`（仍可点开，只读）。
- 卡包**不整包出售**（只能逐张买；见 §十 第 12 条）。

### 4.3 卡包详细（子界面）

- 打开方式：左键点 §4.2 任一卡包格 → 在商人界面之上打开**卡包详细**（同层遮罩，`Esc` / `关闭` 回到商人界面；商人界面的金币、其它货架状态不变）。
- 结构：标题行（左 `包名`、中右 `金币 × N`、最右 `关闭`）→ 一行 **5 张卡**（卡牌 prefab，与结算三选一同款）→ **每张卡下方一行价格**（金币图标 + 数字）→ 底部提示行。
- 每张卡三态：

| 状态 | 表现 | 点击 |
|---|---|---|
| 可购买 | 正常 | 按 §6.2 结算 |
| 买不起 | 卡片灰显 + 价格标红 | 不改状态，提示行 `金币不足：需要 N，当前 M。` |
| 已售出 | 卡面变暗 + 覆盖 `已售出` | 不改状态，提示行 `该商品已售出。` |

- **可买多张**：同一卡包内**逐张**购买，**每张限买 1 次**（买走的那张不再上架）；不设「每包只能买 1 张」的上限，金币够就能继续买（用户口径）。
- **归属选择（第 4 / 5 包）**：这两包的卡不属于固定角色 → 点可购买的卡时**先弹归属选择**（一行三个按钮 = 三个槽位的角色显示名）→ 选完才结算；直接关闭 = 取消，**不扣金币**。
  - 口径同[战斗结算交互 §5.7](../../../../交互说明文档/战斗/战斗结算交互.md)：**入组槽位 = 玩家点选的槽位**，不靠卡 Id 反查；显示名统一取 `RunSession.GetSlotDisplayName(slot)`，界面**不得自行拼编号**。
  - 第 1–3 包**不弹**归属选择（包本身已绑定槽位）。
- 入组落点：`RunSession.AddCardToSlotDeck(槽位, 卡 Id, 0)`（新卡永久升级级数 0，与结算领卡同一入口）。
- 卡面元素：卡名 / 费用 / 效果描述 + **右下角等级字母**（D / C / B / A / S，取自卡牌等级列）；不发散显示卡池名等元信息。

### 4.4 材料（3 格，上排）

- 位置：左下，**与右侧装备 / 道具同款栏位样式**（一行 3 格、96 × 96、格下价格条），食物在其正下方。
- 来源 `DataBase/Item/Material.csv`（16 行，含 `Rarity`；打造材料 / 合成材料两类别）。
- 生成：**本层首次进入商人场景时**按稀有度权重抽 3 件（同物品不重复占两格；不足 3 件留空位），快照落档后不再重抽（§七）。

### 4.5 食物（3 格，下排）

- 来源 `DataBase/Item/Food.csv`（8 行，含 `Rarity` / `Satiety` / `ExpireDays`）。
- 生成口径同 §4.4；**买入的食物按实例入背包**（各自记有效期与效果，[食物系统](../../../../玩法说明文档/系统规则/物品系统/食物系统.md) §二）。
- 数量口径：3 格（第二轮批注把原「5 格」改为「3 格」）；留空不补位。

### 4.6 装备（3 格）

- 装备来源：`DataBase/Equipment/Weapon.csv`（8 行）+ `Armor.csv`（6 行）；**两张现役表没有稀有度列**（待拍板第 4 条）。
- 买入后进背包，**不自动装上**（装上走[装备系统交互案](../../2026.09/交互/装备系统交互案.md)）。

### 4.8 卡牌相关操作（右下，真按钮）

- 位置与大小照参考图（右下角大按钮），与 §4.9 的 `锻造炉` 横向并列。
- 点击 → 打开**卡组操作界面**（子界面，同层遮罩）；可用操作 = **删除卡牌 / 变化卡牌 / 转移卡牌 / 升级卡牌**四种（清单与取舍分析见 §6.3.1）。
- 界面结构（三列）：

```text
┌ 卡牌操作 · 金币 168                                   [关闭] ┐
│ ┌ 操作列（26%）─┐ ┌ 角色列（20%）┐ ┌ 卡组列（54%）───────────┐ │
│ │ 删除卡牌  75  │ │ 重剑手  (5)  │ │ 盾牌冲撞  1费 · B · +1  │ │
│ │ 变化卡牌 100  │ │ 精灵    (8)  │ │ 奋力一击  2费 · C       │ │
│ │ 转移卡牌  60  │ │ 法师    (8)  │ │ …（该槽位全部卡，一卡一行）│ │
│ │ 升级卡牌 80×N │ │              │ │                         │ │
│ └───────────────┘ └──────────────┘ └─────────────────────────┘ │
│ 选中卡：盾牌冲撞 · 费用 75 金币 · [ 确认 ]                      │
│ 提示行：<成功 / 失败原因，见 §6.3>                              │
└────────────────────────────────────────────────────────────────┘
```

- 操作列：四个操作各一行（名称 + 价格）；**次数已用尽的操作灰显**并在行尾标 `本商人已用`；不可用的组合（如目标槽位卡组为空）仍可点，点了在提示行给原因（与背包「先拿起、再拦落点」同一手感）。
- 角色列：三个槽位，行内 = **角色显示名 + `(卡组张数)`**；**转移操作的目标槽位**在这里点选（源槽位 = 卡组列当前所属槽位）。
- 卡组列：一行一张卡（卡名 + 费用 + 等级字母 + 永久升级 `+N`）；**一卡一行、不合并同名**（卡组是实例列表，两张同名卡可分别删 / 升）。
- 全部操作**只用金币计价**，成功即扣金币 + 改卡组 + `Save()`（§6.3）；失败不改任何状态。

### 4.9 锻造炉（右下，新增）

- 位置：`卡牌相关操作` 按钮**旁边**（同直径、同行并列），图标用铁砧 / 炉火占位。
- 点击 → 打开**锻造炉界面**：**复用村庄[锻铁铺交互案](锻铁铺交互案.md) 的打造界面（同一份 `SmithyUi`）**，只替换「界面内容」部分（标题、次数、配方集、费用说明、退出文案），布局与交互**逐项一致**；内容注入接口见[锻铁铺交互案](锻铁铺交互案.md) §2.1。
- 与村庄锻铁铺的差异（其余全同）：

| 项 | 村庄锻铁铺 | 商人锻造炉 |
|---|---|---|
| 进入代价 | 1 时间点（踏入入口格） | **0**（商人不消耗时间点） |
| 次数 | 每次进入 2 次 | **每次打开 1 次**（§十 第 13 条） |
| 单件费用 | 配方材料 + 配方金币 | 同配方材料 + **配方金币 ×1.5**（商人工匠费，向上取整到 5 的倍数；§十 第 14 条） |
| 产出 | 装备进背包 | 同 |
| 内容注入 | `SmithyContext.VillageSmithy` | `SmithyContext.MerchantForge`（标题 `锻造炉`、次数 1、金币系数 1.5） |

- 依据：[装备、材料、道具系统](../../../../玩法说明文档/系统规则/物品系统/装备、材料、道具系统.md) §3.2「商人处可花费金币使用锻造台」与 §四 联动表 —— 本批把它落成界面。
- 打开锻造炉**不影响**货架与卡包状态；关闭后回商人界面（不回到地图）。

## 五、价格表（草案）

> 锚点：[事件系统 §2.3](../../../../玩法说明文档/系统规则/事件系统/事件系统.md) —— 10 金币 = 1 点；1 时间点 = 4 点 = 40 金币；常见 / 罕见 / 稀有材料 = 1 / 3 / 6 点；随机药剂 = 5 点。

| 货架 | 普通 | 罕见 | 稀有 |
|---|---:|---:|---:|
| 材料 | 10 | 30 | 60 |
| 食物 | 20 | 40 | 80 |
| 装备 | 40 | 80 | 160 |
| 道具 | 50 | 90 | 160 |
| 钥匙 | 80（库存 1 把） | — | — |

- 材料价直接取事件表锚点；道具「普通 50」对齐「随机药剂 = 5 点」；装备「普通 40」对齐「1 费 C 级牌 3.6 点 ≈ 36」取整。
- 食物 / 装备两行为**新定价**（无既有锚点），随[关卡档位表](../../../../玩法说明文档/系统规则/数值平衡/关卡档位表.md)的金币收入校准。
- 只用金币计价：商人不收时间点、不收材料。

### 5.1 卡牌价格（买卡，按等级）

| 等级 | D | C | B | A | S |
|---|---:|---:|---:|---:|---:|
| 单张价（金币） | 60 | 70 | 85 | 105 | 125 |

- 推导（可复核）：**1 费牌的应有点数** × **10 金币/点** × **商店系数 2** → 取整到 5 的倍数。
  - 点值取[卡牌数值平衡标准 §4.4](../../../../玩法说明文档/系统规则/数值平衡/卡牌数值平衡标准.md)：D 3.0 / C 3.6 / B 4.3 / A 5.2 / S 6.2（1 费行）；金币口径取本页 §五 锚点（10 金币 = 1 点）。
  - 系数 2 的依据：卡牌是**永久入组**（不消耗、每场都能抽到），与装备同量级（装备档 40 / 80 / 160）。
- 按**卡牌等级列**（`CardTier`）取值；等级列落地前本表无法实现（§十 第 9 条）。
- **整包买空**（第 5 包 = 3 张 A + 2 张 S）= 105 × 3 + 125 × 2 = **565 金币** —— 与[关卡档位表](../../../../玩法说明文档/系统规则/数值平衡/关卡档位表.md)的层级金币收入核对（§十 第 11 条）。

### 5.2 卡牌操作价格（§6.3）

| 操作 | 价格（金币） | 每次商人的次数上限 |
|---|---:|---|
| 删除卡牌 | 75 | **1 次** |
| 变化卡牌 | 100 | 不限（受金币约束） |
| 转移卡牌 | 60 | **1 次** |
| 升级卡牌（永久 +1） | **80 × （当前永久级数 + 1）** → 80 / 160 / 240 | 不限（受金币与级数上限约束） |

- 锚点：删牌 75 对齐同类商店的「移除服务」价；变化 / 转移 / 升级为**新定价**（无既有锚点），随关卡档位表的金币收入校准。
- 次数按**进入的商人**记，**不因开关界面重置**；商人场景本局只进一次（§一）→ 等于「每个商人 1 次」。

### 5.3 锻造炉价格（§6.4）

- 沿用[锻铁铺交互案](锻铁铺交互案.md) §三 的 14 条配方（材料 + 20–80 金币），商人处**金币 ×1.5** 并向上取整到 5 的倍数：20→30、30→45、40→60、60→90、80→120。

## 六、购买流程

### 6.1 通用格（材料 / 食物 / 装备 / 道具 / 钥匙）

1. 左键点可购买格 → 立即结算（**不弹二次确认**，与结算界面「点击即领取」同一手感）。
2. 依次校验：该格未售出 → 金币够 → 背包可入账（负荷未超限）。
3. 通过 → 扣 `RunSaveData.Gold` → 物品入背包（`RunSession.TryAddBagItem`）→ 该格转「已售出」→ `Save()` → 标题行金币刷新（带一次浮字）。
4. 不通过 → 不改任何状态，界面**底部横幅**给原因：

| 原因 | 文案 |
|---|---|
| 金币不足 | `金币不足：需要 N，当前 M。` |
| 已售出 | `该商品已售出。` |
| 背包超载 | `背包已超载，请先整理。` |

5. 界面内**不提供卖出**（待拍板第 2 条）。

### 6.2 卡包内买卡（§4.3）

1. 在卡包详细里左键点一张**可购买**的卡 → （第 4 / 5 包）先弹**归属选择**（点一个槽位）→ 立即结算（**不弹二次确认**，与通用格同一手感）。
2. 依次校验：该卡未售出 → 金币够 → 该槽位卡组可写入（槽位合法）。
3. 通过 → 扣 `RunSaveData.Gold` → `RunSession.AddCardToSlotDeck(槽位, 卡 Id, 0)` → 该卡位转「已售出」→ `Save()` → 卡包格的 `余 N / 5` 与标题行金币刷新。
4. 不通过 → 不改任何状态，提示行给原因：

| 原因 | 文案 |
|---|---|
| 金币不足 | `金币不足：需要 N，当前 M。` |
| 该卡已售出 | `该商品已售出。` |
| 槽位不可写入（读档损坏 / 越界） | `该角色的卡组当前不可写入。` |

5. 买下的卡**直接进永久卡组**，不再走结算界面 —— 本页是**购买**（花金币），不是发卡奖励；发卡奖励「只有一个界面形态」的口径仍以[战斗结算交互 §5.7](../../../../交互说明文档/战斗/战斗结算交互.md) 为准。
6. 卡包内**买走不补位**；5 张全售出后包格显示 `已售罄`（点开只读）。

### 6.3 卡牌操作（§4.8）

1. 点 `卡牌相关操作` → 打开卡组操作界面（默认选中槽位 0 + 该槽位卡组第一张）。
2. 选操作 → 选槽位 → 选卡（转移还要选**目标槽位**）→ 底部行显示费用与 `确认`。
3. 点 `确认` → 依次校验：该操作的次数未用尽 → 金币够 → 操作合法（逐条限制见 §6.3.1）。
4. 通过 → 扣金币 → 改卡组 → 该操作次数 +1 → `Save()` → 卡组列与金币刷新，提示行给成功文案（例：`已删除卡牌：盾牌冲撞`）。
5. 不通过 → 不改任何状态，提示行给原因：

| 原因 | 文案 |
|---|---|
| 次数用尽 | `本次进入的该操作次数已用尽。` |
| 金币不足 | `金币不足：需要 N，当前 M。` |
| 卡组只剩 1 张（删除 / 转移） | `卡组至少保留 1 张卡。` |
| 目标卡组为空（转移） | `目标卡组为空，无法接收。` |
| 已到升级上限 | `该卡已达永久升级上限（+3）。` |
| 无同等级可替换卡（变化） | `没有可替换的同等级卡牌。` |

6. 次数按**操作类型**记（删牌 1 / 转移 1），只在进入一个新商人时重置；关掉界面再打开**不重置**（同一商人）。

#### 6.3.1 可用操作的清单与取舍（分析）

| 操作 | 用户口径 | 本批 | 做什么 | 依赖的代码能力 | 风险 / 备注 |
|---|---|---|---|---|---|
| 删除卡牌 | **必须包含** | ✅ | 从该槽位永久卡组移除 1 张 | 新增 `RunSession.RemoveCardFromSlotDeck(slot, index)` | 现状只有 `AddCardToSlotDeck`；这是唯一能把「状态牌 / 弱卡」清出卡组的手段 → 必做 |
| 变化卡牌 | 允许包含 | ✅ | 删 1 张 + **同等级**随机换 1 张（该槽位角色卡池） | 删 + 加两个 API | 「同等级」依赖卡牌等级列（§十 第 9 条）；无等级列时退化为「同 `CardType` 随机」 |
| 转移卡牌 | 允许包含 | ✅ | 源槽位删 1 张 → 目标槽位加同一张（**保留永久升级级数**） | 删 + 加 + 目标槽位校验 | 角色专属牌能否进别人的卡组：默认**允许**（卡组是实例列表，无卡池校验）→ §十 第 17 条 |
| 升级卡牌 | 允许包含 | ✅ | 该卡 `PermanentUpgradeLevel + 1` | 新增 `RunSession.UpgradeSlotDeckCard(slot, index)` | 字段已有（`RunDeckEntry.PermanentUpgradeLevel`），结算领卡固定写 0；「升级的数值变化」本身仍在未评定行为清单（[卡牌数值平衡标准 §五](../../../../玩法说明文档/系统规则/数值平衡/卡牌数值平衡标准.md)） |
| 复制卡牌 | 未提 | ❌ | 卡组 +1 张同名卡 | 加 API（已有）+ 计费 | 与「买卡」重叠（买卡就是加卡）；再开一项会让卡组膨胀失控 |
| 清除状态牌 | 未提 | ❌ | 批量移除 `CardType = State` 的卡 | 删 API + 筛选 | 与删牌重叠；批量消状态牌会抹掉「状态牌」这条压力轴的设计价值 |
| 分解为材料 | 未提 | ❌ | 删 1 张换材料 | 删 + 材料入账 | 属「出售 / 回收」体系（§6.1 第 5 条已定界面内不提供卖出），别混进卡牌操作 |
| 指定买牌 / 重抽卡包 | 未提 | ❌ | 指定卡池抽卡 / 刷新卡包 | 卡包快照改写 | 会破坏「卡包快照固定、不刷新」的口径（§4.2） |

→ 结论：**删除 / 变化 / 转移 / 升级**四项共用同一个「选操作 + 选槽位 + 选卡 + 确认」界面与同一套卡组 API 面（删 / 改 / 移 / 加），本轮不做第 5 项。

### 6.4 锻造炉打造（§4.9）

1. 点 `锻造炉` → 打开锻造炉界面（复用锻铁铺界面，注入 `SmithyContext.MerchantForge`）。
2. 选配方 → 右列显示属性 / 需求 / 费用（费用 = 配方金币 ×1.5）。
3. 点 `打造` → 依次校验：本次次数未用尽（**1 次**）→ 材料够 → 金币够 → 背包可入账。
4. 通过 → 扣材料 → 扣金币 → 装备进背包 → 次数 −1 → `Save()` → 标题行次数与提示行刷新（`打造完成：行军短剑`）。
5. 不通过 → 不改任何状态，提示行给原因（文案与[锻铁铺交互案](锻铁铺交互案.md) §五 同款，金额按商人口径）。
6. 关掉锻造炉 → 回商人界面；同一商人**不刷新**次数（节点一次性）。

## 九、验收

1. 走到商人节点 → 切到空白地图场景，角色落入口格，商人单位占 3 格。
2. 点商人单位 → 沿可达路径走到最近可站格 → **到达即自动打开**界面；重复点击不重放演出。
3. 界面结构与 §三 表逐项一致：**卡包 5 格**、材料 3 格、食物 3 格、装备 3 格、道具 3 格、右下 `卡牌相关操作` 与 `锻造炉` 两个按钮，标题行金币与顶栏时间点行并存。
4. 通用格买得起 → 点击即扣金币 + 入背包 + 该格已售出 + 立刻落档（退出重进一致）。
5. 通用格的金币不足 / 已售出 / 背包超载三种情形各给对应原因，状态不变。
6. 点任一卡包格 → 卡包详细一行 5 张卡、**每张卡下方有价格**；同一卡包内**连买 2 张都成功**（不限制只买 1 张）；买过的卡显示 `已售出`。
7. 第 4 / 5 包买卡时弹**归属选择**：选槽位 N → 卡进槽位 N 的卡组；改选另一槽位再买 → 进另一卡组（卡下的角色名与入组槽位一致）。
8. 点 `卡牌相关操作` → **删除 / 变化 / 转移 / 升级**各跑一次：金币按 §5.2 扣、卡组按预期变化、立刻落档（退出重进一致）；次数用尽 / 金币不足 / 卡组只剩 1 张 / 已达升级上限各给对应原因。
9. 点 `锻造炉` → 界面与村庄锻铁铺**逐项一致**，只有标题、次数（1 次）、金币（×1.5）不同；打造成功扣材料 + 金币 + 装备进背包。
10. 材料 / 食物各 3 格且与装备 / 道具**同款栏位样式**；材料与食物各自独立生成、不互相占位。
11. 走到离开格 → 返回世界地图，商人节点标记已访问；再次经过不重复触发。
12. `dotnet build` / `dotnet test` / `--run-flow-ui-smoke`（新增商人段）不回归。
