# 民宿交互案

> 规定村庄**民宿**的进入条件（默认开放，遇特定 Debuff 或事件选项后封门）、免费休息效果（回复、晚上更好、弱于旅馆）、每天的可进入次数与和旅馆的互斥。共用口径（地图形态、移动、时间点、确认 tips 组件、昼夜判定）见[村庄地图交互案](村庄地图交互案.md)，本文只写民宿自己的规则。

## 完成情况（2026-10-03）

- 状态：**未实现**（本批只出案）。用户指令：「民宿（特定情况下能够进入（默认能够进入，获得特定 debuff 或者选择事件特定选项后不能进入），不花费金币，回复生命值，晚上效果更好，效果差于旅馆，且和旅馆之间只能选择一个）」。
- 无独立界面：按用户口径只做**跟随角色的确认进入 tips**（村庄案 §六 的共用组件）。
- 本批带来的**两个新需求**（§七）：`通用State.csv` 新增 `BlocksGuesthouse` 列；事件效果新增 `RunFlag` 类型。
- **2026-10-05 落地批 1（规则层已落，界面未落）**：§四 的效果表与 §六 的结算顺序已落成 `Scripts/Run/VillageLodging.cs`（白天 25% / 晚上 40%、免费、推进新一天、`GuesthouseUsedDay` 记日）；§五 的四类拒绝原因各有独立文案常量，Debuff 封门走 `RunVillageStateSave.GuesthouseDebuffBlockName`（P2-20 落地前恒空 —— §七 的降级口径），事件选项封门走 `GuesthouseLockedByEvent`（`RunFlag` 效果未接入，暂由调试 / API 置位）。单测覆盖「免费 / 一天一次 / 已选旅馆被拒 / 两类封门各给不同文案」。§八 的确认 tips 随村庄场景一起落 → [10 月施工文档 §28](../10月施工文档.md)。


## 一、代价与次数

| 项 | 值 | 说明 |
|---|---|---|
| 进入代价 | **免费**（不花金币、不花时间点） | 用户口径「不花费金币」 |
| 进入次数 | **每天 1 次** | 待拍板第 1 条 |
| 占用 | 3 格（西南边竖 3）+ 入口格 1 | 见[村庄地图交互案](村庄地图交互案.md) §2.2 |
| 进入 = 过夜 | **推进到新一天** | 与旅馆同口径（村庄案 §八）；不触发篝火休息 |

## 二、进入条件

- **默认开放**：没有任何封门标记时，走到入口格即弹确认 tips。
- 两类来源都会置位**同一个本局标记** `VillageStateSave.GuesthouseLocked`：

| 来源 | 载体 | 现状 |
|---|---|---|
| ① 持有特定 Debuff | `DataBase/State/通用State.csv` 新增列 `BlocksGuesthouse`（`TRUE` 的状态视为「村民不愿收留」） | **该列不存在**，且现役 `通用State.csv` 的 `IsDebuff` 中具体哪几种算「恶名」需内容侧指定（待拍板第 2 条） |
| ② 选择事件的特定选项 | 事件 `effects` 新增类型 `RunFlag`（`target = Run`、`value` = 旗标名，本批用 `guesthouse_locked`） | 执行器现只支持 `HpDelta / SelectedPlayer`、`GoldDelta / Run`、`CardAdd / Slot`（[代码需求清单 P0-2](../../2026.09/玩法/代码需求清单.md)）→ `RunFlag` 属**新增需求** |

- 标记**本局一旦置位不可清除**（不给玩家任何恢复途径）；读档保留（§八）。
- 判定时机：**踏入入口格时**（不是进村时）——进村后拿到 Debuff 也会立刻生效。

## 三、确认 tips 内容

沿用村庄案 §六 的 4 行气泡（示例：白天、角色最大生命 48）：

| 行 | 内容 |
|---|---|
| 1 | `民宿` |
| 2 | `过夜：回复 12 生命`（数值按 §四 现场计算） |
| 3 | `代价：无` |
| 4 | `进入` / `稍后` |

- 被锁时不弹 tips，只给一行原因（§五）。

## 四、效果表（草案）与旅馆对比

| 时段 | 回复 | 清除每日 Debuff | 推进新一天 |
|---|---|---|---|
| 白天（当天剩余 > 1.0） | 最大生命的 **25%**（向上取整） | **不清** | 是 |
| 晚上（当天剩余 ≤ 1.0） | 最大生命的 **40%** | **不清** | 是 |

| 对比项 | [旅馆](旅馆交互案.md) | 民宿 |
|---|---|---|
| 代价 | 1 金币 | 免费 |
| 回复（白天 / 晚上） | 50% / 100% | 25% / 40% |
| 清除每日 Debuff | 全部层 | 不清 |
| 次数 | 本局 1 次 | 每天 1 次 |
| 进入条件 | 无（只受金币与次数限制） | 可能被 Debuff / 事件选项封门 |
| 互斥 | 本局二选一 | 同 |

## 五、拒绝原因表

| 情形 | 时机 | 文案 |
|---|---|---|
| 已被 Debuff 封门 | 踏入入口格时（**不弹 tips**） | `民宿因你们的恶名（<Debuff 显示名>）拒绝收留。` |
| 已被事件选项封门 | 踏入入口格时（**不弹 tips**） | `民宿不再欢迎你们。` |
| 当天已住过 | 踏入入口格时（不弹 tips） | `今天已经借住过了，明天再来吧。` |
| 已选旅馆过夜（本局） | 踏入入口格时 | `你已经在这家旅店住下了。` |

- 封门（Debuff / 事件）与「当天已住」「已选旅馆」三类原因**必须给不同文案**：前者本局不会再开，后两者是可恢复 / 已作别的选择。

## 六、结算顺序（点「进入」后）

1. 校验：本局未选旅馆 → 未被封门 → 当天未住过。
2. 回复：按 §四 的比例逐槽回复（`RunTimePoints.HealAmount`，超出上限无效）。
3. 推进到新一天（当天剩余作废；食物有效期 −1）。
4. 记录 `VillageStateSave.GuesthouseUsedDay = 当前天数` → `Save()`。
5. 反馈：角色上方浮字 + 一行提示；角色留在入口格。**不扣金币、不清 Debuff、不触发篝火**。

## 九、验收

1. 无任何标记时走到入口格 → 弹 tips（`过夜：回复 12 生命` / `代价：无`）；点 `进入` → 免费回复、当天推进到新一天。
2. 晚上（剩余 ≤ 1.0）进入 → tips 按 40% 计算且结算值与之一致。
3. 同一村庄内第二次踏入入口格（同一天）→ 给 `今天已经借住过了，明天再来吧。`；过一天后再来可以再住。
4. 持有 `BlocksGuesthouse = TRUE` 的状态后踏入 → 不弹 tips，给带该状态名的原因；该状态移除后仍**不给进**（本局标记不可清除）。
5. 事件选项置位 `guesthouse_locked` 后踏入 → 给 `民宿不再欢迎你们。`。
6. 先住旅馆 → 民宿入口给 `你已经在这家旅店住下了。`；反之旅馆给对应原因（[旅馆交互案](旅馆交互案.md) §五）。
7. 全程**不扣金币**（结算前后 `Gold` 不变）、**不清 Debuff**、**不触发篝火**（食物不被消耗）。
8. `dotnet build` / `dotnet test` / `--run-flow-ui-smoke`（新增民宿段）不回归。
