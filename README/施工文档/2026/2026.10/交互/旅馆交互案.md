# 旅馆交互案

> 规定村庄**旅馆**的进入确认 tips、休息效果（回复 + 清除每日 Debuff）、一次性与与民宿的互斥。共用口径（地图形态、移动、时间点、确认 tips 组件、昼夜判定）见[村庄地图交互案](村庄地图交互案.md)，本文只写旅馆自己的规则。

## 一、代价与次数

| 项 | 值 | 说明 |
|---|---|---|
| 进入代价 | **1 金币** | 不消耗时间点（待拍板第 1 条） |
| 进入次数 | **本局 1 次** | 用过之后 tips 不再弹，直接给一行原因（§五） |
| 占用 | 4 格（北边横 4）+ 入口格 1 | 见[村庄地图交互案](村庄地图交互案.md) §2.2 |
| 进入 = 过夜 | **推进到新一天** | 不触发篝火休息（§七） |
| 过夜与每日 Debuff | **不新增** | 在村庄过完的这一天**不发放**每日 Debuff（[村庄地图交互案](村庄地图交互案.md) §八）；旅馆的「清除」清的是**既往**层，不是「免得当天这一层」 |

## 二、确认 tips 内容

沿用村庄案 §六 的 4 行气泡（跟随角色、宽 260、`进入` / `稍后`）：

| 行 | 内容（示例：剩余 2.4 时间点、2 层每日 Debuff） |
|---|---|
| 1 | `旅馆` |
| 2 | `过夜：回复 15 生命；清除每日 Debuff 2 层`（白天口径；数值按 §三 现场计算） |
| 3 | `代价：1 金币`（金币不足 → 按钮转 `金币不足` 禁用 + 该行追加 `（需要 1，当前 0）`） |
| 4 | `进入` / `稍后` |

- 第 2 行**必须与结算结果逐字一致**（效果预览是公开契约，口径同[事件系统](../../../../玩法说明文档/系统规则/事件系统/事件系统.md) §一）。
- 每日 Debuff 未落地（P2-20）时，第 2 行只写回复，不写「清除 N 层」。

## 三、效果表（草案）

| 时段 | 回复 | 清除每日 Debuff | 推进新一天 |
|---|---|---|---|
| 白天（当天剩余 > 1.0） | 最大生命的 **50%**（向上取整） | **全部层** | 是 |
| 晚上（当天剩余 ≤ 1.0） | **100%（回满）** | **全部层** | 是 |

- 数值锚点：营地满配休息 = `10% + 20% × 1 + 2% × 10 = 50%`（[篝火休息与食物](../../../../玩法说明文档/系统规则/营地系统/篝火休息与食物.md) §二）→ 旅馆白天 = 营地满配水平；晚上回满，作为**本局只能用一次**的强效果。
- 「晚上」判据由[村庄地图交互案](村庄地图交互案.md) §八 定义（`剩余时间点 ≤ 1.0`）。
- 回复只补到最大生命，超出部分无效；逐角色分别结算（3 人都回）。

## 四、结算顺序（点「进入」后）

1. 校验：本局未用过旅馆 → 金币 ≥ 1。
2. 扣 1 金币。
3. 逐槽回复（`Math.Min(最大生命 − 当前生命, RunTimePoints.HealAmount(最大生命, 比例))`，口径同营地）。
4. 清除每日 Debuff 全部层（`P2-20` 未落地前跳过）。
5. 推进到新一天（`RunMapStateSave.AdvanceToNextDay`，当天剩余作废；食物有效期照常 −1）。
6. 标记本局已住（`VillageStateSave.InnUsed = true`、`ChosenLodging = Inn`）→ `Save()`。
7. 反馈：角色上方浮字（`回复 15 / 18 / 12`）+ 一行提示；角色**留在入口格**，名称牌转「已住过」灰态。

## 五、拒绝原因表

| 情形 | 时机 | 文案 |
|---|---|---|
| 本局已住过 | 踏入入口格时（不弹 tips） | `旅馆本局只能进一次。` |
| 金币不足 | tips 内（按钮禁用） | `金币不足：需要 1，当前 0。` |
| 已选民宿过夜（本局） | 踏入入口格时 | `你已经答应在民宿过夜了。` |

## 六、与民宿的互斥

- 本局**只能选一家住宿**（用户口径「和旅馆之间只能选择一个」）：
  - 用过旅馆 → [民宿](民宿交互案.md) 入口拒绝，文案见该案 §五；
  - 用过民宿 → 本设施入口拒绝（`你已经答应在民宿过夜了。`）。
- 互斥按**本局**计，不按天重置。

## 七、不触发的东西（边界）

- **不触发篝火休息**：不吃食物、不选守夜、不触发夜袭与「睡眠不佳」（[篝火休息与食物](../../../../玩法说明文档/系统规则/营地系统/篝火休息与食物.md) §一：村庄的回复独立于篝火休息）。
- 不消耗 / 不回复时间点（唯一例外是「推进新一天」这一跨天边界：当天剩余作废 → 新一天 4.0）。
- 不清除其它状态：营地的「睡眠不佳」、战场遗留状态、食物腐败照常按跨天结算（有效期 −1，到 0 腐坏）。

## 十、验收

1. 白天进村走到旅馆入口格 → tips 第 2 行显示按 50% 算出的回复量；点 `进入` → 扣 1 金币、3 名角色各回该值（不超过上限）、当天推进到新一天。
2. 晚上（当天剩余 ≤ 1.0）进入 → tips 显示「回满」，结算后 3 人满血。
3. 每日 Debuff 已落地时：持有 2 层 → tips 显示「清除每日 Debuff 2 层」，结算后清 0；未落地时 tips 不显示该行且不报错。
4. 第二次踏入入口格 → 不弹 tips，给 `旅馆本局只能进一次。`。
5. 金币为 0 时进入 → tips 内按钮为 `金币不足` 禁用 + 原因行；点它不改状态。
6. 用过民宿后再来旅馆 → 给 `你已经答应在民宿过夜了。`，且不扣金币。
7. 结算后立刻落档：退出重进（仍在村庄）→ 无法再进旅馆。
8. `dotnet build` / `dotnet test` / `--run-flow-ui-smoke`（新增旅馆段）不回归。
