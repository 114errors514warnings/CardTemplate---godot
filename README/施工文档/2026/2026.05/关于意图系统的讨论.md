为了把设计落到数据层，我再看一下怪物 CSV 的读取入口，确认后面应该把哪些字段加到 Monster.csv。

先看现状，当前代码离“可配置意图系统”还差三层能力。

Monster.cs:4 里的 Monster 模板目前只有基础属性，没有意图表。
BattleSytem.cs:992 里的怪物回合是硬编码流程：每只怪固定先攻击一次，再加一次护盾。
Monster.csv 和 LoadMonsterCsv.cs:10 也只支持 6 列基础字段，还没有意图配置的入口。
而你在 施工文档.md:6 里希望的，其实已经不是“动作脚本写死”，而是“怪物模板驱动的规则系统”。

要实现你提到的两个场景，核心不是只加一个意图表，而是把“意图”拆成 4 个独立维度：

意图内容
一项意图到底做什么。这里对应你文档里的“一个意图可由多个原子意图组成”，比如：
攻击一次
给自己加盾
先给玩家上弱化，再攻击
这部分应该是纯配置，不掺杂触发条件和次数限制。

意图触发条件
一项意图什么时候有资格被选中。这里要单独建条件层，而不是塞进原子意图参数里。
至少要支持：
生命值小于等于某阈值
生命值百分比小于等于某阈值
是否首次进入某血线
是否已经执行过某意图
是否存在某状态
是否第几回合后才能触发
你提到的“生命值降到特定数值后才会执行且只会执行一项意图”，本质上就是：
满足血线条件时，这项意图变成可选
并且它的选择优先级/排他级别高于普通意图
再叠加“执行次数上限 = 1”

意图选择策略
当一只怪同时有多个可选意图时，怎么选。
这一层非常关键，否则以后规则一复杂就会打架。
建议直接支持三种模式：
按优先级选最高
按权重随机
命中排他条件时强制只在排他意图里选
这样“血线技只会执行一项意图”就很好实现：
血线技配置为排他意图
当它满足条件时，本回合只从排他意图里选 1 项
普通攻击、防御直接被压掉

意图次数限制
这层必须和触发条件分开。因为“能不能触发”和“还能不能再用”是两回事。
建议支持三种作用域：
单个怪物实例限制
同模板怪物在本场战斗内共享限制
全场共享限制
你提到的“相同种类的所有怪物执行特定意图的总次数有限”，就是第二种，不应记在 MonsterInstance 自己身上，而应记在 BattleSystem 的战斗期共享状态里。

我建议的数据结构这样拆。

模板层，挂在 Monster 上
MonsterIntentConfig 列表
每个 MonsterIntentConfig 包含：
IntentId
Priority
Weight
AtomicActions
Conditions
Limit
ExclusiveWhenMatched

运行时实例层，挂在 MonsterInstance 上
只存“这只怪自己用过几次哪些意图”“哪些一次性触发已经消费过”
比如：
UsedIntentCountByIntentId
TriggeredFlags

战斗层，挂在 BattleSytem 上
专门存共享次数池
比如：
BattleIntentCounter[string counterKey] = usedCount
这里的 counterKey 不建议只用 IntentId，最好是：
MonsterTemplateId + IntentId
或者允许配置自定义 SharedCounterKey
这样以后你不仅能做“同种怪共享次数”，还能做“两个不同怪共享一个 Boss 机制次数池”。

设计上最关键的一点是：血线触发不要写成“HP 到了就立刻放技能”，而要写成“HP 条件让某条意图进入候选集合”。

推荐的怪物行动流程应该是：

到怪物行动时，先收集该怪所有意图配置
逐条判断条件是否满足
再判断次数限制是否还有剩余
如果存在 ExclusiveWhenMatched 的候选，只在这些候选里选 1 个
否则在普通候选里按优先级或权重选 1 个
选中后先消费计数器
再顺序执行这条意图里的多个原子动作
这样两个目标场景都自然成立：

第一种，血线技只会执行一次
条件：当前 HP <= 50%
选择：ExclusiveWhenMatched = true
限制：InstanceScope，MaxUseCount = 1

第二种，同类怪共享 2 次群体强化
条件：常规可触发
选择：普通候选
限制：TemplateBattleScope，MaxUseCount = 2
计数 key：3002#BuffAllies
这样无论场上有几只 3002，总共只能放 2 次

还有一个你现在最好先定下来的点：是“意图预告制”还是“即时决策制”。

如果你后面想像杀戮尖塔那样，在玩家回合就看到怪物下一步要干什么，那就不能在 BattleSytem.cs:992 才临时选意图。更合理的是：

怪物回合结束时，或者玩家回合开始时，先为每只怪选好 NextIntent
把 NextIntent 显示到 UI
等到怪物真正行动时执行缓存的 NextIntent
执行完后再滚出下一回合的 NextIntent
如果不做预告，那可以每次行动前即时选择，结构更简单。

关于 CSV，我建议你不要沿用“一个字段里硬塞所有语义、层级还不清晰”的做法。你现在附件里的描述是：
意图之间用 |
意图内部字段用 #
不同原子意图参数用 ;
但你刚刚已经把全局最小一级分隔符定成了 #，所以这套写法和你新规则是冲突的。这里最好统一成固定层级。

更稳的约定建议是：

| 分隔多个完整意图
; 分隔单条意图里的各个段
分隔某一段内部的小字段
也就是一条意图可以拆成：
基础信息段 ; 条件段 ; 限制段 ; 原子动作段1 ; 原子动作段2

这样层级就统一了，不会再出现“有时 # 比 ; 大一级，有时又更小一级”的问题。

如果按这个方向落地，我建议分 3 步做，不要一次把所有功能揉进去：

先做最小可用版
支持怪物配置多个意图
支持每回合只选 1 条意图
支持原子动作 Attack、Shield、BuffSelf、DebuffTarget
支持单怪次数限制

再加条件系统
支持血量绝对值阈值
支持血量百分比阈值
支持排他意图

最后加共享限制
在 BattleSytem 上加入战斗期共享计数池
支持同模板共享次数
必要时再扩成自定义共享键
