## 已讨论的候选关键词

1. 预言成真：回合结束时在牌堆顶时自动打出
2. 奇巧：被丢弃时自动打出
3. 消耗：打出后移动到角色专属消耗牌堆，不再参与抽牌堆/状态牌堆/弃牌堆循环
4. 时计：回合结束时移动到消耗牌堆

结论：
- 以上都适合作为“关键词体系”能力，而不是普通 EffectType
- 但当前仅实现“保留”，其余暂不实现

## 关于“为什么用位标记”的结论

### 1) 位标记的核心价值

- 关键词天然可能并存（例如一张牌同时拥有“保留 + 消耗”）
- 位标记可以在单字段中表达多个关键词
- 查询与序列化成本低，适合固定集合的规则标签

### 2) 为什么不直接用普通从1开始枚举

- 普通枚举单字段只能表达“一个值”，无法表达多个关键词并存
- 要用普通枚举支持多关键词，必须改成数组/列表（会增加结构与解析复杂度）

### 3) 与 EffectType 的区别

- EffectType 是“打出时执行的效果动作”，在系统里本来就是数组结构
- 关键词更像“生命周期规则标签”（回合结束、弃置时、打出后去向等）
- 两者职责不同，不建议混用

---

## 关于“位标记是否会溢出”的结论

- 当前默认底层是 int（32位），可用位数有限
- 目前项目关键词规模下够用
- 若未来关键词非常多，可迁移到 long（64位）或改为集合模型

---

## 关键风险点与边界

仅靠“静态位标记”无法完整表达“仅本回合生效”这类时效规则。

位标记本身只能表示“有/没有关键词”，无法单独表达：
- 生效时长（本回合、直到打出等）
- 失效时机（回合结束、回合开始、打出后等）

结论：
- 只用静态位标记：不够
- 位标记 + 运行时时效数据：可行且推荐
