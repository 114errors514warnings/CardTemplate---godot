## 一、术语

| 术语 | 含义 |
|---|---|
| 结算浮窗 | 待领取态下常驻在画面上的入口浮窗（`SettlementUi.BuildBadge`），点击重新打开结算面板；层号 `RunUiLayers.SettlementBadge = 35`（高于世界地图 30、低于结算模态 40），见[战斗结算界面交互案 §二 / §6.3](战斗结算界面交互案.md) |
| 战斗来源结算 | 由**战斗胜利**进入的结算（`SourceNodeType` = 战斗节点、有实机 `HexBattleScene`）；对照组是「非战斗来源结算」（事件 / 商人发卡，§5.7） |
| 停留战场 | 关闭结算面板后**不自动打开世界地图**，画面仍是战斗场景 + 浮窗；此时 `GameMode` 仍是 `InSettlement`（待领取态），地图**可控但未打开** |
| 战后战场操作态 | 战斗来源在**本场战斗结束后**进入的**受限操作态**：只剩「切换角色」与「移动」，不能出牌 / 攻击 / 结束回合 / 触发敌人回合。**进入时机（2026-10-01 用户改判）= 结算界面一出现**，不必等关闭面板；未结束的战斗一律拒绝进入（防软锁） |
| 战后自由移动 | 战后战场操作态下的移动：**不消耗能量、不消耗移动额度**，可反复执行；一次点击 = 沿合法路径走到该格 |
| 待领取态 | 结算面板已关闭但仍有未领取项的状态（`GameMode` 仍是 `InSettlement`）；见交互案 §6.2 |

## 二、结算浮窗位置（修订交互案 §6.3）

- **现状问题**：浮窗（220 × 96）锚在「右缘内缩 24、垂直居中」（`AnchorTop = AnchorBottom = 0.5`）→ 落在屏幕**右侧中部**，与战斗 HUD 的**右侧列**重叠：上沿压住「当前格道具」（锚点 y `0.30–0.44`），下半压住「随身道具」（y `0.48–0.62`）与三个道具槽。截图即为该重叠态。
- **新位置（已实现）**：仍贴**右缘内缩 24**，高度改为**右侧上部空带** —— 上沿 = **屏幕高度的 15%**，高 **112**（`AnchorTop = AnchorBottom = 0.15`、`OffsetTop = 0`、`OffsetBottom = 112`；宽度不变 220 = `OffsetLeft -244 / OffsetRight -24`）。
- **为什么是这条带**（战斗 HUD 的既有锚点，见 `HexBattleScene` HUD 构建）：

  | 元素 | 锚点（x × y） | 与浮窗的关系 |
  |---|---|---|
  | 常驻按钮栏（`地图` / `定位当前角色` / `调试` / `暂停`） | `0.54–0.98 × 0–0.09` | 浮窗**必须**在其下方 → 上沿 ≥ 0.09（这一带自 2026-10-01 起同时是**不透明底板**的范围，左沿由 `0.64` 扩到 `0.54` 为 `背包` / `装备` 预留；见[10 月施工文档 §4.1](../../2026.10/10月施工文档.md)、`Scripts/Run/RunUiLayout.cs`） |
  | 剧情专属行（`Log` / `隐藏` / `Auto`、`跳过`） | `0.02–0.37` 与 `0.64–0.98`，y `0.09–0.145` | 与浮窗同带 → 浮窗上沿取 **0.15**，避开该行 |
  | 右侧列：当前格道具 | `0.84–0.98 × 0.30–0.44` | 浮窗下沿（0.15 + 112px）必须在其上方 → 1080p 下 0.15 × 1080 + 112 = 274 < 324 |
  | 右侧列：随身道具 / 右手装备 | `0.84–0.98 × 0.48–0.62`、`0.87–0.972 × 0.71–0.87` | 同上，不再接触 |

- **规则**：
  1. 浮窗**只占自身矩形**，不吃其余输入（现状不变）：战场照常接收左键选人 / 悬停详情、右键拖图。
  2. 不遮挡常驻按钮栏、剧情专属行、右侧三块面板与底部 HUD 区；在**世界地图**打开时也落在该带（地图节点密集区在中部，不冲突）。
  3. 尺寸与最终样式（羊皮纸 / 图标 / 描边）仍以**美术终稿**为准；位置规则（右缘内缩 24 + 上沿 15% 屏高）是**交互规则**，美术不得再移回压住右侧列的位置。
  4. 小窗口 / 非 16:9：位置按屏高比例锚定（不写死像素），高 112 固定；若屏高不足导致浮窗下沿越过「当前格道具」上沿，**以上移优先**（允许临时贴到按钮栏下方 0.09）。

## 三、关闭结算面板后的落点（修订交互案 §6.2）

- **战斗来源（有实机战场）—— 结算界面一出现即进战后态；关闭面板后停留战场（2026-10-01 改判）**：**结算界面一出现**（`RunFlowScene.OnSettlementReady` → `EnterPostBattleStateForSettlement()`）就把战斗 HUD 收起、战场转入战后操作态（§四 / §五）—— **不必等关闭面板**（面板是模态层，所以实际点战场仍要等关闭面板）。关闭面板 → ① 面板隐藏；② **世界地图不打开**（`map.Visible == false`，`MapView` 仍可见），但地图**转为可选**（`mapSelectable = true` + `map.SetReadOnly(false)`，`地图` 按钮回到「地图」文案）；③ 浮窗出现；④ 战场**保持**战后战场操作态。
  - 这样玩家可以**立刻在地图上操作**（选人 / 看范围 / 战后移动），而不是被地图覆盖层挡住。
- **前提（2026-10-01 复核补注 + 同轮改判）**：① 进战后操作态需要**本场战斗已结束**（`HexBattleScene.SetPostSettlementMode` 对 `!Session.IsFinished` 直接拒绝 —— 「战斗途中事件发卡结算」若被收掉手牌与结束回合就是软锁）；② 进战后态**不再**要求「仍有未领取项」（面板一出现就进），但**关闭面板那一刻是否仍有未领取项**决定落点：全部领完再关闭 → 视为**结算完成** → `ReturnToSelectableMap()` 直接回地图（战场随内容销毁）。要留在战场移动，就保留至少一项未领取（或点浮窗重开面板后再关闭）。判据与分支见 `RunFlowScene.OnSettlementReady` / `OnSettlementPanelClosed`。
- **非战斗来源（事件 / 商人）—— 保持现状**：关闭面板 → 世界地图以「已打开 + 可选」覆盖（`ReturnToSelectableMap()`），`顶部按钮` 文案转「返回」；这类来源没有可操作的战场，浮窗仍是唯一入口。
- **读档重进的结算界面 —— 有落档则重建战场（2026-09-28 用户改判）**：`RunBattleScene` 在 `IsInSettlement` 时读 `RunSaveData.PostBattleBattlefield`：**有本场战斗的落档**（`PendingContentType == "Level"` 且 `LevelId` 与快照一致）→ 按同一关卡重建战场、还原布局并直接进入**战后战场操作态**，此时 `HasLiveBattlefield` 为 true，因此与战斗来源一样**停留战场**；**没有落档**（事件 / 商人发卡、旧档）→ 保持原路径（没有实机战场 → 打开可选地图）。
  - 实现判据：`RunBattleScene.HasLiveBattlefield`（`battleView` 存活且已绑定 `MapView`）；还原失败（快照与待处理内容对不上、地图不一致、角色数量不符）会**销毁重建的战场**并退回原路径，不会落到空战场 / 半成品战场。
- **面板打开期间地图仍只读**（现状不变，交互案 §九）；「全部领取后关闭」仍视为结算完成、直接回地图（现状不变）。
- **进入下一个节点的路径不变**：点 `地图` → 打开可选地图 → 点节点 → 放弃确认弹窗（若有未领取项）→ 确认后才推进节点（交互案 §七）。多了一次「点地图」的动作，这是「停留战场」的代价，也是本案的取舍。

## 四、战后战场操作态（已实现：`HexBattleScene.SetPostSettlementMode`）

**进入**：战斗来源关闭结算面板且**仍有未领取项**时，战场自动进入该状态（不需要玩家再点开关）。**退出**：结算完成 / 放弃（转 `OnMap`）时随内容一起销毁；面板重新打开期间战场只读（现状）。

- **实现（2026-09-28）**：`HexBattleScene.SetPostSettlementMode(bool)` 收口全部战后表现，由 `RunFlowScene.StayOnBattlefield()` 在「关闭结算面板 → 停留战场」的落点处开启；**未结束的战斗一律不进该状态**（`Session.IsFinished` 为假时直接拒绝）—— 否则收掉手牌与「结束回合」会让战斗无法继续（例如战斗途中触发的事件发卡结算）。

| 区域 | 战后表现 | 说明 |
|---|---|---|
| 手牌区（`handPanelNode` = 角色 Tab 行 + 手牌槽） | **手牌槽隐藏**（连卡面一起）；**角色 Tab 行保留**（理由见 §七 未决 1） | 战后不能出牌；手牌数据保留在 Session 里，但不显示、不响应拖拽 |
| **底部操作区底板**（`bottomHudBackdrop`：`0–1 × 0.68–1` 的暗色底板） | **整条隐藏**（**2026-10-02 用户口径**「底板随手牌区一起消失」） | 手牌收起了就不该横着一条空底板；它原来带 `MouseFilter = Stop`、会把底部几行格点的点击吃掉，隐藏后那些格点**可直接点到**（战后点选即移动需要） |
| 能量（`energyDisplay` / `energyLabel`）与「移动 x/y · 每次 N 格」额度文本（`moveInfo`） | **隐藏** | 战后不消耗能量与额度 → 不再显示这两个数 |
| 牌堆按钮（抽牌 / 弃牌 / 消耗）与三堆弹窗 | **隐藏 / 不可打开** | 牌堆不再变化 |
| `结束回合` 按钮 | **隐藏** | 战后没有回合推进，也不会触发敌人回合 |
| `移动` 按钮 | **保留**，文案改为 **`移动`**（去掉「（1 能量）」） | 唯一可用行动；见 §五 |
| 角色 Tab（`tabs[3]`） | **保留** | 与战斗内同一套切人逻辑：点 Tab / 点自己人 = 选中 + 镜头平滑移动 |
| 左右手装备槽（`leftHandButton` / `rightHandButton`） | 保留显示；**只接受「当前格装备拖到此处」**（§五 补注） | 不接受从手位拖出：不投掷、不卸下、不换手（战后再换装备没有意义） |
| 当前格道具 / 随身道具槽 | 保留显示；**当前格道具可拖到随身槽拾取**（§五 补注） | 随身槽不能拖出：不使用、不丢弃；也不自动拾取 |
| 地图 / 定位当前角色 / 调试 / 暂停（常驻栏） | 保留（现状） | `地图` → 打开可选地图；`暂停` / `调试` 照常 |
| 单位悬停详情、右键拖图、`定位当前角色` | 保留 | 与战斗内一致 |

- **实现补注（2026-09-28）**：上表要隐藏的「能量 / 额度文本 / 牌堆按钮」与**角色名**（`resources`）在**同一个面板** `resPanel` 内（`resources` / `energyDisplay` / `moveInfo` / 三个牌堆按钮都是它的子节点），实现按**整块隐藏**收口 —— 角色名一并隐藏（§38.2 偏差 3）。该选择按「未提到的内容保留默认 = 现行实现」登记在 §39.5 附注 1；若要求严格保留角色名，按那一条的「回改方式」改（保留 `resPanelNode`、只隐藏子节点，并同步 `PostSettlementUiCollapsed` 与烟测断言）。
- **实现补注（2026-10-02）**：上表新增的「底部操作区底板」由字段 `bottomHudBackdropNode` 控制（`HexBattleScene.ApplyPostSettlementVisibility()`），并已并入 `PostSettlementUiCollapsed` 断言链（新增只读口 `IsBottomHudBackdropHidden`）与烟测断言；落地记录见[10 月施工文档 §7.1](../../2026.10/10月施工文档.md)。回改方式 = 删掉那一行与断言链上的对应条件。
- 战后**不能**：出牌 / 攻击 / 使用或投掷道具 / 丢弃地面物品 / 从手位卸装或换手 / 结束回合 / 触发敌人回合 / 改变 HP、状态、金币、奖励与折损口径。
- 战后**能**：切换选中角色、平移与缩放视角（右键拖图、定位当前角色）、查看单位与格点详情、**自由移动**（§五）、**拾取当前格的道具与装备**（§五 补注）。
- 战后布局**落档**（2026-09-28 用户改判；原口径为「不落档」→ 见 §七 4）：单位位置 / 存活 / 生命、地面物件、每个角色槽的随身与手位在**进入战后操作态**与**每次战后移动 / 拾取**后写入本局存档（`RunSaveData.PostBattleBattlefield`）；读档重进结算界面时按它**重建同一张战场**并直接进入战后操作态。结算完成 / 放弃（转 `OnMap`）后快照作废，下一个节点按关卡配置重新部署。快照只覆盖**表现层可感知**的状态（位置 / 在场 / 生命 / 地面物件 / 随身与手位）：**不含**单位状态、地形变化与牌堆顺序（战后态都不显示）。
- **收起时机（2026-10-01 用户改判）**：上表的隐藏**不再等关闭结算面板** —— 结算界面一出现就收（`RunFlowScene.EnterPostBattleStateForSettlement`，见 §三）。面板是模态层（40），所以在面板打开期间只是先把 HUD 收起、并已允许战后自由移动，实际点战场仍要等关闭面板；「战斗途中事件发卡结算」被 `HexBattleScene` 的 `IsFinished` 守卫拒绝、HUD 原样保留（战斗继续）。**2026-10-02 追加**：这份收起清单还包含**底部操作区底板**（见上表与 §四 补注）。

## 五、移动流程（已实现：`BattlefieldSession.TryPostBattleMove`）

1. **选中角色**：点战场上的自己人，或点底部角色 Tab（若角色 Tab 随手牌区一起隐藏，则此步改由点自己人 / `定位当前角色` 完成 —— 见 §七 未决 1）。
2. **点「移动」**：进入移动规划态 —— 战场高亮**所有可达格**，按钮文案转 `取消移动`，再次点击即退出规划态。
3. **点地图上的任意可前往的一点**：**立即移动**（不再弹「确定移动 / 取消移动」两步确认），角色沿**最短合法路径**走过去并播放既有移动表现；**移动不消耗能量、不消耗移动次数**。
4. **移动后仍留在规划态**，可继续点下一个格**连续移动**；按 `Esc` 或点 `取消移动` 退出规划态。
5. **可达格判定**：与战斗内同一套空间规则 —— 逐格可走（非地图外 / 障碍 / 坑洞）、逐格可进入（不被任何单位占据）、**路径不穿过障碍与单位**；距离**不限格数**（战后再没有「移动额度」这一约束），因此可达格 = 从当前格出发的**连通可达区域**。
6. **非法目标**：点非可达格 → 不移动、不退出规划态，控制台打一条原因（`战后再移动：目标不可达`，沿用 `ShowMessage` 的控制台日志口径，不弹提示框）。
7. **拖拽画路线**：战斗内的「按住左键拖连续路线 + 确定 / 取消」在战后**不再需要**（点选即移动）。保留与否不影响规则，实现时按简化优先：**战后只做点选**。

- **实现补注（2026-09-28）**：第 2 步的「高亮所有可达格」以**悬停预览最短路径**实现（`MapView.SetMovePath` + `BattleMovementService.FindPathIgnoringBudget`），可达位查询本身是 `BattleMovementService.ReachableCells`；第 7 步按「简化优先」执行 —— 战后**只做点选**，拖拽画路线与「确定 / 取消」两步确认整体停用（控件保留但不触发）。点自己人只切换选中（角色 Tab 行保留，见 §七 未决 1 的默认取值）；移动表现逐格播放期间不接收新的移动指令。

### 5.1 战后拾取（2026-09-28 新增，§七 3 改口径）

1. **能拾取什么**：**当前格**的道具与装备（判定与战斗内同一套：物件必须在该角色所在格）。道具拖到三个**随身道具槽**之一 → 收进该槽；装备拖到**左右手位** → 装到该手。
2. **交换口径沿用战斗内**（不做替换面板）：目标随身槽已有道具时**交换**，原槽道具落回当前格；装备位已满时，换下的装备按战斗内同一口径落回当前格；双手装备占据两手。
3. **不能做**：随身槽 / 手位**不能拖出** —— 不使用、不投掷、不丢弃、不换手；拖到随身槽与手位以外的任何地方一律**取消**，控制台打一条原因（不弹提示框）。战后拖拽**不显示**使用 / 投掷的目标预览与引导线。
4. **拾取即落档**：每次拾取成功都刷新战后布局快照（§四末条），因此读档重进后随身栏仍持有该道具、**地面不再出现它**；这也意味着「拾取」是战后可留下的唯一持久结果（临时道具本身仍**不能带出战斗**，结算完成后随快照一起清掉）。
5. **实现**：`HexBattleScene.TryPostBattlePickup(instanceId, slot, hand, out message)`（拖拽落点与烟测走**同一实现**）→ 复用 `BattlefieldSession.TryPickItemFromCurrentCell` / `TryEquipFromCurrentCell`；成功后触发 `PostBattleStateChanged`，由 `RunBattleScene` 落档。

## 六、离开战场与 `Esc`（已实现）

- 离开战场只有一条路：常驻栏 `地图` → 打开可选地图 → 点节点 → （有未领取项时）放弃确认弹窗 → 确认后推进节点（交互案 §七）。
- `Esc` 分层（在交互案 §九 基础上插入战后一层）：
  1. 放弃确认弹窗 → 「取消」；
  2. 卡牌三选一 → 跳过；
  3. 结算面板 → 关闭（进入待领取态）；
  4. **战后移动规划态 → 退出规划态**（不领取、不放弃、不回地图）；
  5. 待领取态的地图打开 → 关闭地图（回战场）；
  6. 暂停 → 关闭暂停。
- `Esc` **永不等于「确认」**（不代替「确认放弃并进入」，也不代替点卡领取）—— 这条总则不变。
- **实现补注（2026-09-28）**：战后第 4 层由 `HexBattleScene` 在 `IsPostSettlementMode` 下**先让宿主**逐层接管（第 1–3 层与「待领取态的地图打开」都在宿主侧），宿主没消费才退出规划态、再落回第 6 层暂停 —— 这样「结算面板打开 + 规划态同时存在」时仍是面板优先。

## 七、边界与未决项

> **实现状态（2026-09-28）**：① 角色 **Tab 行保留**（只隐藏手牌槽）、② 移动距离**不限**（连通可达区域）、③ 战后**可**拾取道具（§5.1）、④ 位置**落档**并在读档重进时重建战场 —— ③ / ④ 是用户同日**改判**（原默认值为「不拾取 / 不落档」），落地记录见 [9 月施工文档 §39](../9月施工文档.md)；① / ② **按默认值保留**（用户 2026-09-28 口径：**未在改判中提出的内容一律不改，保留默认值**），已随 [9 月施工文档 §39.5](../9月施工文档.md) 收口为定稿取值，不再挂「待拍板」。与本文的实现差异逐条登记在 [9 月施工文档 §38.2](../9月施工文档.md) 与 [§39.2](../9月施工文档.md)。

**已定口径**（2026-09-28 用户口述）：

1. 浮窗**上移**，不遮挡既有 UI（右侧列三块面板、按钮栏、剧情行）。
2. 关闭结算面板后**战场仍可点**（战斗来源不自动打开世界地图）。
3. 战后战场**只保留移动**：隐藏手牌区，并把「移动（1 能量）」的能量显示去掉（文案 `移动`）。
4. 移动交互 = **选中角色 → 点「移动」→ 点地图上任意可前往的点 → 移动到位**。

**未决项与默认取值（2026-09-28 收口）**：**以下每一条都按本轮默认值保留** —— 用户对**未在改判中提出的内容一律不改**（默认 = 现行实现）；只有第 3 / 4 条被明确改判。① / ② 若日后要改口径，按各条的「回改方式」调整即可（都是纯参数 / 表现收口）。

1. **角色 Tab 是否保留**：**取值 = 保留默认：Tab 行保留、只隐藏手牌槽**。用户口径只说「隐藏手牌区」，而角色 Tab 与手牌区在实现里是**同一个面板**（`handPanelNode` = 角色 Tab 行 + 手牌槽）；切人是战后移动的前置操作，去掉就得靠点小人也勉强可用。**回改方式**：若要求「整块隐藏」，§五 第 1 步改为「点自己人 / 定位当前角色」。
2. **移动距离是否限一次动作的射程**：**取值 = 保留默认：不限（连通可达区域即可去）**。战后没有额度概念。**回改方式**：改成「每次点击最多走 `EffectiveMoveDistancePerAction` 格」即可（纯参数，`BattleMovementService` 已有按动作分段的现成路径）。
3. **战后是否能拾取地上的道具**：**已定（2026-09-28 改判：能）** —— 战后可把**当前格**道具拖到随身槽拾取、把**当前格**装备拖到手位装备（§5.1）；仍不能使用 / 投掷 / 丢弃 / 换手，也不做满栏替换面板（沿用战斗内交换口径）。原先「不能」的理由（拾取牵涉随身栏满格替换流程）由「交换口径 + 不做替换面板」化解。
4. **位置是否落档**：**已定（2026-09-28 改判：落档）** —— 进入战后操作态与每次战后移动 / 拾取后写入 `RunSaveData.PostBattleBattlefield`（单位位置 / 存活 / 生命 + 地面物件 + 每个角色槽的随身与手位），读档重进结算界面时按它重建同一张战场（§三 / §四末条）。**边界**：快照不含单位状态、地形变化与牌堆顺序；结算完成 / 放弃后快照清空；**不写回局外装备字段**（`RunCharacterSlotSave.EquippedWeaponDefinitionId` 仍在胜利当刻写回，因此战后拾取的武器只作战后表现，不改变下一场战斗的初始武器）—— 最后这条**按默认值保留**并已收口为定稿取值（[9 月施工文档 §39.5](../9月施工文档.md) 第 3 条，附回改方式）。
5. **战后敌人残留**：歼灭关胜利时敌人已全部离场，战场通常为空；若未来出现「非爪牙全退场即胜」而场上仍有爪牙存活（爪牙未实现，见[代码需求清单 10.5](../玩法/代码需求清单.md)），战后移动**不**与存活敌人产生任何互动（不触发攻击、不索敌、不推进敌人回合），存活爪牙按放置物处理（不可穿过）。

## 九、验收

**已实现部分（本轮，`--run-flow-ui-smoke` 覆盖）**：

1. 关闭结算面板且仍有未领取项、且本场有实机战场 → `GameMode` 仍是 `InSettlement`、**世界地图未打开**、`MapView` 可见、浮窗可点、`地图` 按钮文案是「地图」。
2. 点 `地图` → 地图打开且可选（`!IsReadOnly`、`MouseFilter == Stop`）；点 `返回` → 回战场、地图关闭、浮窗仍在。
3. 点浮窗 → 结算面板重新打开、浮窗隐藏（现状不变）。
4. 读档重进的结算界面（无实机战场）关闭面板 → **仍自动打开可选地图**（不回归成空战场）。
5. 浮窗矩形与「当前格道具」（`0.30–0.44`）、「随身道具」（`0.48–0.62`）**无重叠**（右缘内缩 24；上沿 ≤ 0.16 屏高、下沿 ≤ 0.30 屏高）。

**战后战场操作态部分（P2-13 ③，已实现；第 6–10 条由 `--run-flow-ui-smoke` 端到端覆盖，实测记录见 [9 月施工文档 §38.3](../9月施工文档.md)）**：

6. ✅ 战后战场：手牌槽 / 能量 / 额度文本 / 牌堆 / `结束回合` 全部隐藏；`移动` 按钮文案**不含**「能量」（角色 Tab 行、左右手装备槽、当前格与随身道具槽保留显示；其中**当前格道具可拾取到随身槽 / 手位**，随身槽与手位不能拖出）。
7. ✅ 选中角色 → 点 `移动` → 点可达格 → 角色移动到位，且该角色 **能量与移动次数不变**、`Phase` 仍 `Victory`、回合数不变。
8. ✅ 连续点可达格可连续移动（移动表现播完仍留在规划态）；点不可达格只打日志、不移动、不退出规划态（`[战场] 战后再移动失败：目标不可达。`）。
9. ✅ 战后点（已隐藏的）`结束回合` / 卡牌 / 攻击 → 无任何反应（不触发敌人回合、不改 `Phase`）；卡牌与道具的拖拽入口整体关闭。
10. ✅ `Esc`：规划态 → 退出规划态（不清结算态、不放弃，浮窗仍在）；地图打开时 → 关地图（宿主的逐层接管**先于**规划态退出，见 §六 实现补注）。
11. ✅ 位置**落档**（2026-09-28 改判，原为「不入档」）：战后移动 / 拾取后 `RunSaveData.PostBattleBattlefield` 记录当前坐标 / 存活 / 生命、地面物件与随身手位，且**真的写进存档文件**（`RunSession.Save()`）；`--run-flow-ui-smoke` 断言落档坐标 = 实际坐标、落档能通过存档 JSON 往返、拾取结果（地面少一件 / 随身多一件）也落档。
12. ✅ **战后拾取**：战后把当前格道具放进随身槽成功（随身槽 1 持有该实例、地面不再有它），且拾取结果落档。
13. ✅ **按落档还原**：把状态改乱（角色走开 + 已拾取道具塞回地面）后按快照还原 → 角色回到落档坐标、地面不再出现该道具、随身栏仍持有它、仍是战后操作态（`Phase = Victory`）。
14. ✅ **读档重进结算界面**：内容宿主 `RunBattleScene` 的 `InSettlement` 分支按落档**重建出实机战场**（`HasLiveBattlefield` 为 true）、直接进入战后操作态、角色在落档坐标、随身道具还原、地面不含已拾取道具（烟测临时实例化一个 `RunBattleScene` 走同一条 `_Ready` 路径）。
15. 事件 / 商人发卡结算：`PostBattleBattlefield` 为空 → 不重建战场，关闭面板仍打开可选地图（`RunSession.EnterSettlement` / `CompleteSettlementToMap` 清空快照，`CanRebuildPostBattleBattlefield` 校验来源类型与关卡 ID）。
