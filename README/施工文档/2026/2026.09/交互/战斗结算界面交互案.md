## 三、条目 Tab（条状）

- **形态**：竖排、**宽度接近整个结算界面**（= 面板内容宽度，左右各留 24 内边距；不是等分横排的小按钮）。单条高度 64、条间距 10、圆角 12；距左 24 处放 24 × 24 图标，紧随其后为 24px 文案。
- **Tab 数量**：物品 Tab = 掉落表行（一行一个）；**卡牌 Tab = 本场卡牌奖励份数**（默认 **3 个**、折损后 **2 个或 1 个**，见 §5.1）。`DropTable` 内出现多行 `Card` 只作为「本次卡牌奖励」的整体配置，**不额外增加 Tab**。**领过的行 / 份会从数量里消失**（2026-10-02 口径，见下方状态表）。
- **文案**：物品沿用 `BattleRewardPresenter.FormatRewardLine`（`金币 +N` / `钥匙 +N` / `材料 <ID> ×N` / `道具 <ID> ×N` / `装备 <ID> ×N`）；卡牌 Tab 用「将一张牌添加到你的牌组。」+ `· ` + **该份的角色显示名**（例：`将一张牌添加到你的牌组。· 重剑手`、`将一张牌添加到你的牌组。· 重剑手2`），用于区分多个卡牌 Tab。**直接用角色名**（2026-09-27 第四轮口径：不再用角色头像 / 槽位序号区分）；队伍内有同名角色时按 §3.1 编号。
- **状态**（**2026-10-02 修订：领取后的条目不再留在列表里**）：

| 状态 | 表现 | 可点 |
|---|---|---|
| 未领取 | 正常底色 + 图标 + 文案 | 是 |
| 已领取（物品） | **该条从列表中消失**（不再灰显、不再打「已领取」标记） | —（不存在） |
| 已领取（卡牌） | **该份卡牌 Tab 从列表中消失**（不再显示「已获得 / 已领取：<卡名>」）；其余卡牌 Tab 不受影响 | —（不存在） |
| 已跳过（卡牌） | **与未领取相同**（跳过不改变 Tab 状态，该份可再进） | 是 |

- **输入**：仅左键单击；不支持拖动、不响应右键。已领取的条目**根本不再渲染**（原先的「已领取的 Tab 点击无任何反应」随之取消）—— 面板每次领取后重建，「还能点到的条目」恒等于「还能领的条目」，不存在点了没反应的死条目。
- **计数口径**：面板上看得见的条目数 = 未领取项数 = 浮窗的 `N 项未领取`（同源于 `SettlementClaimedRewardKeys` / `SettlementCardClaims`，不另存一份界面状态）。
- 条目多于 5 条时列表内部滚动，标题条与底部动作区固定不动。

### 3.1 同名角色的显示编号（全局规则）

> 2026-09-27 第四轮用户口径：**直接使用角色名**，转而给同名角色加「**角色名 + 数字**」的编号机制（例：`重剑手`、`重剑手2`）。

- **命名规则**：按**槽位序**（0 → 1 → 2）扫描队伍；同一个 `CharacterId` 第 k 次出现时——k = 1 显示原名（`重剑手`），k ≥ 2 显示 `原名 + k`（`重剑手2`、`重剑手3`）。
  - 编号是**同名出现次序**，**不是槽位号 + 1**：槽位 0 / 1 / 2 = 重剑手 / 伊瑟拉 / 重剑手 时，显示 `重剑手` / `伊瑟拉` / `重剑手2`（伊瑟拉虽在槽位 1，也不带数字）。
  - 数字紧贴名字末尾，**不加空格、不加括号**：写 `重剑手2`，不写 `重剑手 2` / `重剑手(2)`。
  - 队伍内没有重复角色时，所有名字与 `Character.csv` 的 `Name` **完全一致**（不额外补 `1`）。
- **适用范围（全局，不止本界面）**：凡是显示「队伍中某个角色的名字」的位置，队伍里出现同名时都必须用同一规则编号，避免同一角色在不同界面显示成两个名字：
  - 结算面板的**卡牌 Tab 文案**（§三）、卡牌三选一界面**卡下方的归属角色名**（§5.2 / §5.3）；
  - 战斗内的角色名位置（`BattleInfoPresenter` 的角色列表、队伍条 / 头像条等）；
  - 组队界面**已进入槽位的角色名**（`CharacterSelectScene` 的已选列表）；
  - 后续新增的卡组视图 / 队伍视图等任何列出队伍成员的地方。
  - **待选列表（尚未进入槽位的候选角色）不编号**：编号依赖「队伍槽位身份」，只在进入槽位之后成立。
- **性质**：**纯显示层**——不改 `Character.csv`、不改 `CharacterId`、不写进存档；同一槽位在任何界面、任何时刻都显示同一个名字。
- **实现**：新增纯逻辑静态类 `Scripts/Run/CharacterSlotNaming.cs` + 单测 `Tests/CharacterSlotNamingTests.cs`（参照 `RunGoldLedger` 的「纯逻辑 + 单测」形态），只暴露「按槽位列表出显示名」的方法（如 `BuildDisplayNames(characterIds, resolveName)` / `GetDisplayName(characterIds, slotIndex)`）；`RunSession` 增加 `GetSlotDisplayName(int slotIndex)` 作为**界面唯一取名口**（槽位不变 → 结果可缓存，`StartNewRun` / `LoadSave` 后重算）。**禁止各界面自行拼接编号**（否则同一角色会出现两种写法）。
- **兜底**：槽位越界或角色未在 `Character.csv` 中找到 → 显示 `角色 {characterId}`（沿用现状），不做编号。

## 四、物品 Tab：点击即领取

1. 左键点击物品 Tab → 立即执行 `BattleRewardPresenter.ApplyRewardEntryToRun`（金币 / 钥匙 / 材料 / 道具 / 装备入账）。
2. 同一次点击内：把去重键 `{index}:{Category}:{RewardParam}:{Amount}` 追加进 `RunSaveData.SettlementClaimedRewardKeys` → `RunSession.Save()` 落档。
3. 该 Tab **从面板列表消失**（**2026-10-02 口径**；可给一次浮字 / 高亮反馈，但不弹确认框、不遮挡面板）。
4. 读档重进或关闭后再打开：已领取的条目**不再出现**，**不重复发放**（防重仍靠去重键）。

> 材料 / 道具 / 装备当前无 ID 表，文案会直接显示编号（见[代码需求清单 P1-4](../玩法/代码需求清单.md)）；这是文案缺口，不影响本交互。

## 五、卡牌 Tab：卡牌三选一界面

### 5.1 份数、Tab 与打开

- **份数 = 卡牌 Tab 数**：默认 **3 份**（每个角色槽位一份，重复角色按槽位分开）；奖励折损后 **2 份**（击败比例 ≤ 70%）或 **1 份**（< 50%），至少保留 1 份。折损时**随机取消不同槽位的份**（见 §5.6）。
- 每一份是**独立的卡牌奖励**：点它 → 在结算面板之上打开**该份的卡牌三选一界面**（同层遮罩，遮住结算面板其余部分）；各份领取互不影响，全场最多领 3 / 2 / 1 张卡。
- 顶部为标题条「选择一张牌」（图 2）。**该份的 3 张候选**横排居中、间距 24；底部居中「跳过」按钮（约 320 × 64）。
- ⚠️ **两个「数量」不要混淆**：折损改变的是**结算面板上的卡牌 Tab 数**（3 → 2 → 1）；三选一界面里的**候选卡数恒为 3 张**，与折损无关（见 §5.2）。

### 5.2 卡牌显示（必须用卡牌 prefab）

- 每份**固定 3 张候选**（**常态值，不随折损变化**；未来可由装备调整 → 实现时写成**参数而非常量**）；候选来源卡池本身不足 3 张时按实际张数显示。每张候选**必须**用卡牌 prefab 实例化：`res://Scenes/Card/CardDisplayPrefab.tscn` + `Scripts/UI/CardDisplayPrefab.cs`，逐张 `SyncFromCard(LoadingSystem.CardDictionary[cardId])`。
- 卡面按 prefab 原生尺寸（300 × 420）显示；屏幕高度不足时整组等比缩小，缩小后仍是同一个 prefab（不另做一套卡面）。
- **不要**用六边形战场手牌的小型卡面（`HexBattleScene.MakeBattleCard`，108 × 156，代码内构建、不是 prefab）。
- **每张卡下方**显示该卡将加入的牌库所属角色：一行居中小字，**内容仅为角色显示名**（例：`重剑手`；同名第二个角色显示 `重剑手2`，见 §3.1），不显示卡池、稀有度、槽位序号等其它信息。

### 5.3 归属角色的判定

- **候选来源** = **只取该份所属槽位角色自己的卡池** `LoadingSystem.GetCharacterRewardCardIds(该份的 CharacterId)`，**不与队伍其它角色的卡池混合**（2026-09-27 第五轮口径定稿：**不做**跨角色联合池）；每份抽 **3 张**不重复候选（**常态候选数，与折损无关**），不足则按实际张数。
- **入组槽位 = 该份的槽位**（不靠 `FindOwningSlotIndex` 反查）：这样两张候选同属一个角色、或两名角色共用一张卡时，都只进入该份对应的牌库。
- **卡下方的角色名 = 该份槽位角色的显示名**（同名按 §3.1 编号），与入组目标严格一致（不允许显示一个、加入另一个）。
- `FindOwningSlotIndex` 只作**兼容兜底**（旧存档里没有份槽位的单份奖励）；正常路径（战斗结算与 §5.7 的非战斗来源发卡）都由**份自带的槽位**决定入组目标，不再反查。
- 找不到角色 / 卡池为空时：该份显示为空态（文案「该角色暂无可用卡牌」）并打日志，不静默发放到别的角色。

### 5.4 选中与领取

1. 悬停：卡片轻微上浮 / 描边高亮；点击：**立即选中并结算**，不要求二次确认。
2. 入组：`RunSession.AddCardToSlotDeck(该份的槽位, cardId, 0)`（新卡永久升级级数为 0）。
3. 落档：记录「**该份**的卡牌奖励已领取」+ 卡 Id + 槽位 → `RunSession.Save()`。
4. 关闭三选一界面回到结算面板；**该份**卡牌 Tab **从列表消失**（其余份保持未领取，**2026-10-02 口径**）。
5. **每份只能领一次、只能领一张**：已领取的份不再出现在列表里（也就没有可点的 Tab）；未领取的份照常打开各自的候选。

### 5.5 跳过

- 「跳过」→ **不做任何领取**，直接返回结算面板；**该份**卡牌 Tab 保持未领取，可再次点开重新选择。
- 「跳过」**不等于立刻丢弃**：该份卡牌奖励在**离开结算（进入下一个节点）**时才作废，见 §七。
- `Esc` 等价「跳过」（只关三选一界面，不透传成关闭结算面板）；右键不响应。
- 三选一界面打开时不显示结算面板的「关闭」按钮（避免同时存在两个退出语义）。

### 5.6 份数与奖励折损

- **卡牌 Tab 数 = 本次卡牌奖励份数**：**全额 3 份 / ≤ 70% 2 份 / < 50% 1 份**（阈值与口径见[六边形战场玩法 §7.4](../../../../玩法说明文档/系统规则/战斗系统/六边形战场玩法.md)、[单位数值平衡标准 §2.4](../../../../玩法说明文档/系统规则/数值平衡/单位数值平衡标准.md)；实现见[代码需求清单 P2-10.3](../玩法/代码需求清单.md)）。
- **份的归属**：每份绑定一个角色槽位（默认 3 份 = 槽位 0 / 1 / 2 各一份，与 §7.4「每个角色一张」一致）；折损 = **随机取消不同槽位的份**（取消 2 份时取消两个不同槽位，恰好对应 §7.4「随机取消不同角色的奖励」）。
  - ✅ **已落地（2026-09-28，施工文档 §33）**：份 = 角色槽位（默认 3 份），折损**随机取消不同槽位的整份**；每份候选**只取该份角色自己的卡池**、候选数 `SettlementRewardPresenter.DefaultCandidateCount = 3`（**参数**，未来由装备影响时改值即可）。
- **折损只减 Tab 数，不减候选数**：被取消的份**连同它的三选一界面一起消失**；保留下来的份，三选一里**仍是 3 张候选**（常态值，不随折损变化）。
- 某份的**卡池本身不足 3 张**时按实际张数显示（1 ~ 2 张也照常显示卡与「跳过」，不自动领取）——这是卡池容量问题，与折损无关。
- 折损原因与比例在结算面板显示一行（例如「卡牌奖励减少：击败 57.0%（≤ 70%）→ 卡牌奖励 2 份」）。
- 折损的**数值与展示**由 P2-10.3 落地；「折损展示与实机一致」依赖 [P2-10.4](../玩法/代码需求清单.md)（意图伤害修正值取参缺口）先修。

### 5.7 非战斗来源的发卡（事件 / 商人等）也走本界面

> 2026-09-27 第五轮用户口径：「**非战斗来源发卡也通过战斗结算界面并产生浮窗**」。

- **入口统一**：卡牌奖励只有**一个界面形态**——本文的结算界面。战斗胜利之外的**任何发卡来源**（事件选项、商人节点、后续其它途径）**都进入同一个结算界面**（同样的物品 Tab / 卡牌 Tab / 三选一 / 「跳过」/ 「关闭」/ 浮窗 / 放弃确认），**不另做简化弹窗、也不跳过浮窗**。与 `交互说明文档/战斗/六边形战场交互.md §十`「『卡牌奖励』弹窗是**全游戏统一的获取卡牌入口**」一致：**统一的是本文的界面形态**（该节描述为简版，形态以本文为准）。
- **份的归属**：非战斗来源发卡同样是「**一份 = 一个卡牌 Tab = 该来源指定的角色槽位**」；来源配了几个角色的卡就出几份（同一角色多份各占一个 Tab，按 §3.1 显示同名编号）。
- **候选**：来源指定了**具体卡**时该份候选 = 这 1 张（照常显示卡与「跳过」，**仍需玩家点击领取，不自动发放**）；来源是「该角色卡池任选」时按 §5.2 抽 3 张候选；**候选池同样只取该份角色的卡池**（§5.3）。
- **不做折损**：奖励折损只属战斗结算（按击败比例，见 §5.6）；非战斗来源的份数**不折损**。
- **关闭后同样产生浮窗**：面板关闭即进入**待领取态**（§6.2 / §6.3，`GameMode` 保持 `InSettlement`），浮窗照常出现在显眼位置；此后点任意节点进入前**同样先弹放弃确认弹窗**（§七，与节点类型无关）、放弃时**同样打印一条 `SETTLEMENT_ABANDONED` 日志**（§7.4；`{来源名}` = 事件名 / 商人节点名，`{节点类型}` = 事件 / 商人）。
- **重进表现**：按 §6.5 / §八——面板开着时退出 → 重进直接复现面板；面板已关闭 → 只显示浮窗。

> **实现（2026-09-28，[9 月施工文档 §34](../9月施工文档.md)）**：发卡由**事件效果 `CardAdd`** 触发（`target = Slot`、`value` = 槽位序（0 起）、`referenceId` 留空 = 该角色卡池任选 3 张 / 写具体卡 Id = 该份候选恒为这 1 张），执行器落档 `RunSession.EnterSettlement` 后广播 `SettlementReady`；面板 / 浮窗 / 放弃闸门全部复用 `SettlementUi`，来源名 = 事件标题、节点类型取 `RunSaveData.PendingSourceNodeType`，读档重进按 `IsInSettlement` 优先（不重播事件）。**同一槽位只出一份**（份的身份 = 槽位，见 §34.2 偏差 3）；书写范例：`DataBase/Story/Events/EVT-CARD-001.json`（不进 `EventPool.csv`）。

## 六、关闭结算与未领取浮窗

### 6.1 关闭入口

- 结算面板提供两个等价入口：右上角**关闭按钮（X）**、底部**「关闭」按钮**。
- `Esc` 等价关闭（三选一界面打开时 `Esc` 只关三选一，见 §5.5）。
- 关闭**不领取任何东西**；与现状「确认选择并返回地图」不同：现在把「关闭」和「前往下一个节点」拆成两件事。
- **关闭不附加任何确认或提示**（2026-09-27 第五轮口径）：任何情况下——包括**一项都没领取**就直接关闭、也包括本局**第一次**关闭——都**不弹二次确认、不弹「还有未领取项」提示**，直接进入待领取态；后续由**浮窗**（§6.3）与**放弃确认弹窗**（§七）承接。

### 6.2 关闭后发生什么

1. 结算面板隐藏，结算进入**待领取态**（`GameMode` 仍是 `InSettlement`，不转 `OnMap`）。
2. **落点分两种情况（2026-09-28 修订，见[战斗结算后战场操作交互案](战斗结算后战场操作交互案.md) §三）**：
   - **战斗来源（本场有实机战场，`RunBattleScene.HasLiveBattlefield`）→ 停留战场**：世界地图**不打开**（`map.Visible == false`、战场可见），只把地图**转为可选**（`mapSelectable = true` + `map.SetReadOnly(false)`，`地图` 按钮文案仍是「地图」）。玩家可以立刻在战场上操作（选人 / 悬停详情 / 战后移动），不会被地图覆盖层挡住；要离开时点 `地图`。
   - **非战斗来源（事件 / 商人）与读档重进的结算界面（无实机战场）→ 保持原行为**：世界地图以「已打开 + **可选**」覆盖到内容之上（等价现实现的 `ReturnToSelectableMap()`），顶部按钮文本转「返回」。
3. 画面内出现**结算浮窗**（§6.3）——此后无论地图是否打开都常驻。**任何来源**的结算关闭后都一律出现浮窗（战斗胜利 / 事件 / 商人等**不做例外**，2026-09-27 第五轮口径，见 §5.7）。

> 规则差异：现状是「结算未确认 → 地图只读，确认后才可选」。本设计要求**关闭结算面板后地图即可选**（否则玩家无法「未领取就进入下一个节点」）。面板**打开期间**地图仍为只读，该现状规则不变；「即可选」不等于「立刻打开」——战斗来源下地图保持关闭（本文 §6.2 第 2 条）。

### 6.3 浮窗

- **内容**：`战利品` 标题 + `N 项未领取`（N = **未领取 Tab 数** = 未领取的物品 Tab + 未领取的卡牌份）+ **本次结算的来源名**（战斗 = 关卡名，例：`劫匪团伙`；事件 / 商人等非战斗来源 = 事件名 / 商人节点名，见 §5.7）。全部领取后**浮窗消失**。
- **常驻范围**：只要处于「待领取态」，浮窗就一直在（战斗画面与地图打开两种状态下都显示；地图打开时叠在地图之上）——对应「关闭结算后在地图内以显眼位置显示浮窗」。
- **位置**（**2026-09-28 修订，已实现；细则见[战斗结算后战场操作交互案](战斗结算后战场操作交互案.md) §二**）：显眼且固定 —— 贴**右缘内缩 24**，垂直位置从「屏幕中部」**上移到屏幕高度的 15%**，高 112（宽度 220）；它必须落在**常驻按钮栏（y ≤ 0.09，2026-10-01 起该带含不透明底板）与剧情专属行（y 0.09–0.145）之下、战斗 HUD 右侧列「当前格道具」（y 0.30–0.44）/「随身道具」（y 0.48–0.62）之上**的空带里，不得遮挡这三块面板与按钮栏。小窗口 / 非 16:9 时按屏高比例锚定（上移优先）。样式仍以美术为准，位置规则不得回退成压住右侧列的中部位置。
- **层级**：新增 `RunUiLayers.SettlementBadge = 35`（世界地图 30 之上、结算模态 40 之下）→ 地图打开时可见、可点；结算面板打开时被压住，不可点。
- **点击** → 重新打开结算面板（§6.4）。
- 浮窗只占自身矩形，不吃地图其余区域的输入（平移、点节点照常）。

### 6.4 再次打开结算面板

- 重新打开时读取**内存中的结算状态**（面板未关闭期间）或**存档中的结算字段**（关过游戏 / 重进）：
  - 已领取的条目**不再列出**（**2026-10-02 口径**；原先为保持「已领取」且禁用）；
  - 各份卡牌候选**不重新随机**（沿用 `SettlementCardPools` 中该份的候选列表）；若对应数据不存在于存档，必须报错而不是重抽；
  - 折损行与比例沿用落档值（见 P2-10.3）。
- 重复开合任意次，不重复发奖、不改变候选。
- 待领取态下若点顶部 `地图` 按钮：地图打开且可选，浮窗保持可见；结算面板**不自动弹出**。

### 6.5 与读档重进的关系

- 待领取态直接退出游戏 → 主菜单「继续游戏」：按 `InSettlement` 进入 `RunBattleScene`，**不自动弹结算面板**、只显示**浮窗**（因为玩家上一次已经关闭过面板）；点浮窗才打开面板。
- 若上次是**面板开着**时退出的，重进则直接复现面板（现状已实现的行为保持）。

## 七、放弃：进入下一个节点前的确认

### 7.1 触发条件（与节点类型无关）

- 在**待领取态**下，只要要进入下一个节点（**不分节点类型**：普通敌袭 / 高危敌袭 / 精英 / Boss / 事件 / 商人 / 村庄 / 固定节点…），且本次结算**仍有未领取 Tab** → **先弹「放弃确认弹窗」**，不直接进入。
- 未领取 Tab 为 0（全部领取）→ **不弹窗**，直接进入节点并 `CompleteSettlementToMap()`。
- 本局已勾选「本局游戏内不再显示」→ **不弹窗**，直接放弃未领取项并进入。
- 结算面板**打开期间**地图仍是只读 → 不产生该弹窗（弹窗只在待领取态出现）。

### 7.2 弹窗内容与操作

| 元素 | 内容 |
|---|---|
| 标题 | 「放弃未领取的战利品？」 |
| 勾选项 | **「本局游戏内不再显示」**（单个 `CheckBox`，写法与友方伤害确认一致） |
| 按钮 | 「确认放弃并进入」（主） / 「取消」 |

- 弹窗**只有标题、勾选项与两个按钮**：**不列未领取项清单、不写后果说明**（2026-09-27 第三轮用户口径）；未领取内容与后果由玩家自己在结算面板查看。
- 勾选项**默认不勾**；勾选并在本次确认中生效后**落档**（`RunSaveData.SuppressAbandonSettlementConfirm`）：本局后续进入节点不再弹窗；**新局 / 放弃本局后重置**。
- 「取消」→ 关闭弹窗、**不进入节点、不放弃任何内容**，回到打开弹窗前的状态（地图保持打开，结算仍在待领取态）；且**不额外提示**（无二次确认、无飘字 / 音效，也不打印放弃日志，见 §7.4）——2026-09-27 第五轮口径。
- 「确认放弃并进入」→ 按 7.3 作废未领取项 → 进入节点。
- `Esc` = **「取消」**（关闭弹窗、不进入、不放弃；即 §九 的「`Esc` 逐层关闭」的一层）；**右键不响应**。`Esc` 在任何界面下都能退出当前界面，但**永不等于「确认」**——不能代替「确认放弃并进入」（「节点进入确认不能被 `Esc` 绕过」的既有约定继续成立）；暂停界面（60）仍压过它。

### 7.3 作废与推进

- **待领取态下地图可选**：确认后，**本次结算内所有未领取项（未领取的物品 Tab + 未领取的卡牌份）立即作废**。
- 作废后走 `RunSession.CompleteSettlementToMap()`：`InSettlement → OnMap`、清空 `Settlement*` 字段、浮窗消失。
- 已领取的物品与卡牌**保留**（领取当刻已入账 / 已入组并落档）。
- 未领取的卡牌**不补偿**：不折算成金币、不影响后续结算的候选。
- 若结算内所有项**都已领取**：点「关闭」即视为结算完成（直接转 `OnMap`，无浮窗）；此时点节点进入与普通流程一致（无弹窗）。
- 放弃**不会**重复触发分档计数 / 节点访问标记的额外副作用（沿用现有 `OnReturnToMap` 的推进逻辑）。

### 7.4 放弃资源记录日志

> 2026-09-27 第四轮用户口径：「**添加 放弃资源记录 的日志**」。放弃的资源不可找回，日志是唯一的追溯手段。

- **何时写**：每次**实际作废**未领取项时写一条——「确认放弃并进入」，或本局已勾选「不再显示」而直接放弃。点「取消」、未领取项为 0 直接进入 → **不写**。（**非战斗来源**的待领取态同样适用，见 §5.7。）
- **落点**：Godot 控制台（`GD.Print`，与 `HexBattleScene` 的 `[战场] …` 消息同风格），随 `Tests/*.log` 与烟测输出保留，便于事后核对「这一局放弃了什么」。**不弹提示、不写横幅、不阻断进入节点**（弹窗正文已按第三轮口径删除，日志同样只在控制台）。
- **格式**（固定关键字便于 grep 与烟测断言；**一次放弃只写一条**）：

  ```text
  [结算] SETTLEMENT_ABANDONED: {来源名}（{节点类型}）| 未领取 {N} 项 | {明细} | {放弃方式}
  ```

  - `{来源名}` / `{节点类型}` = **本次结算的来源**：战斗 = 关卡名 + 战斗节点类型（例 `劫匪团伙`（普通敌袭））；事件 / 商人等非战斗来源 = 事件名 / 商人节点名 + `事件` / `商人`（§5.7）。
  - `{明细}` 用 `；` 分隔，逐项写清按什么算：
    - 未领取物品 Tab：复用 `BattleRewardPresenter.FormatRewardLine(entry)`（如 `金币 +14`、`道具 2001 ×2`）；
    - 未领取卡牌份：`卡牌（{角色显示名}）未领`（同名角色按 §3.1 编号，如 `卡牌（重剑手2）未领`）。
  - `{放弃方式}`：`弹窗确认` / `已勾选不再提示`（用于区分玩家主动确认与本局静默放弃）。
  - 示例：`[结算] SETTLEMENT_ABANDONED: 劫匪团伙（普通敌袭）| 未领取 3 项 | 金币 +14；道具 2001 ×2；卡牌（重剑手2）未领 | 弹窗确认`
- **时机与次数**：在「作废 → 打印日志 → `CompleteSettlementToMap()`」之间执行，由转场锁保证同一次进入**只打印一次**。
- **可选扩展**（非本项必做）：若后续要做「本局回顾」，再把同样的内容落档为账本（与 `RunSaveData.StolenGoldFromMonsters` / `StolenGoldEntry` 同构，整局保留、新局重置）；现阶段**不新增存档字段**。

| 界面状态 | 可输入的层 | 说明 |

  | 当前最上层界面 | `Esc` 行为 |
  |---|---|
  | 卡牌三选一 | 跳过 → 返回结算面板（不领取，该份保持未领取） |
  | 结算面板 | 关闭 → 待领取态（地图转可选 + 出现浮窗；不领取任何东西，也不弹提示） |
  | 待领取态 + 地图打开 | 关闭地图 → 回到战斗画面（浮窗仍在，结算仍是待领取态） |
  | 放弃确认弹窗 | 「取消」（关弹窗、不进入节点、不放弃、不额外提示、不打印日志） |
  | 暂停界面 | 关闭暂停（继续游戏） |

- 领取 / 放弃**不能被 `Esc` 绕过**（与 `局内UI交互待做` P1「输入层级与转场」一致）：`Esc` 只做「关闭 / 取消 / 跳过」，既不代替「确认放弃并进入」，也不代替「点卡领取」；`Esc` 在结算面板只做「关闭 → 待领取态」，不做领取。
- 转场与防重复：开始节点内容时加统一转场锁，避免同一帧内重复触发「进入节点 + 放弃奖励」（同 P1 转场锁需求）。

## 十一、验收清单

1. 胜利后弹出结算面板：条目为**竖排、宽度接近整个结算界面**的条状 Tab；图 1 的两项（金币 + 卡牌）形态可复现。
2. 点物品 Tab → 立即入账，**该条从面板列表消失**（不显示「已领取」）；退出重进同样不再出现，**不重复发放**。
3. **卡牌 Tab 数量** = 卡牌奖励份数：全额 **3 个**；F1-006「逃 1 近战 + 1 远程」（57.0%）**2 个**；「全体离场」**1 个**（算例见 [F1-006 §4.1](../../../../玩法说明文档/关卡设计/普通敌袭/第一层/F1-006劫匪团伙.md)）。每个 Tab 归属一个角色，折损时被取消的是**不同角色**的份；被取消的份**连同其 3 张候选一起消失**，保留份的三选一里**仍是 3 张候选**（候选数不随折损变化）。

8. 点浮窗 → 结算面板重新打开：**已领取的条目不再列出**（列表里只剩还没领的）、各份候选不变、折损行一致；反复开合不重复发奖。

10. 未领取 Tab 为 0 时点节点 → **不弹窗**，直接进入。

## 十二、已定口径与待规则确认

**已定（2026-09-27 用户口述，含第二 / 三 / 四 / 五轮补充）**：

- **奖励张数口径** = **每个角色各得一张、共 3 张入组**：默认 **3 个卡牌奖励 Tab**（每个角色槽位一份），每份独立 3 选 1、独立领取；折损后降为 **2 / 1 个**（击败比例 ≤ 70% / < 50%），被取消的是**不同角色槽位**的份。「3 张候选选 1 张」的旧解读作废。
- **放弃确认弹窗**：**所有节点类型**统一——待领取态下只要还有未领取 Tab 就弹；弹窗含勾选项「本局游戏内不再显示」（本局有效、落档、新局重置）；弹窗**只显示标题**「放弃未领取的战利品？」+ 勾选项 + 两个按钮，**不列未领取清单、不写后果说明**。
- **两个「数量」必须区分（第三轮修正）**：**结算面板的卡牌 Tab 数** = 卡牌奖励份数（默认 **3**，折损后 **2 / 1**）；**三选一界面的候选卡数** = 常态 **3 张**、**不随折损变化**（未来可由装备影响该数值，实现时按**参数**预留）。折损取消的是整个 Tab（连同它的三选一），不是 Tab 内的候选张数。
- **卡牌 Tab 文案与同名角色（第四轮）**：**直接用角色名**（`Character.csv` 的 `Name`），**不用头像 / 槽位序号区分**；队伍内有同名角色时按**槽位序**在名字末尾加数字编号（`重剑手` / `重剑手2`，编号 = **同名出现次序**，不是槽位号），规则见 §3.1。编号**只作用于已进入槽位的队伍成员**（待选列表不编号）、**纯显示层**（不改数据与存档），且所有显示角色名的界面必须共用同一取名口。
- **放弃资源记录日志（第四轮）**：每次**实际作废**未领取项时打印**一条** `[结算] SETTLEMENT_ABANDONED: …` 控制台日志（来源名 + 节点类型 + 未领取项数 + 逐项明细 + 放弃方式），格式与时机见 §7.4；「取消」不打印、未领取为 0 不打印。
- **候选只取该角色自己的卡池（第五轮）**：每份三选一的候选**只从该份角色自己的卡池抽**，**不与队伍其它角色的卡池混合**（不做跨角色联合池）；不足 3 张按实际张数显示（§5.3）。
- **「取消」不额外显示（第五轮）**：放弃确认弹窗点「取消」→ 只关弹窗、不进入、不放弃；**不额外提示**（无二次确认、无飘字 / 音效），也不打印日志（§7.2）。
- **非战斗来源发卡同界面 + 同浮窗（第五轮）**：事件 / 商人等非战斗来源的发卡**也走同一个结算界面**（同一份 / 卡牌 Tab / 三选一 / 「跳过」/ 「关闭」形态），关闭后**同样产生未领取浮窗**、点节点同样先弹放弃确认弹窗、放弃同样打印日志；这类来源**不做折损**（§5.7）。
- **`Esc` 逐层关闭（第五轮）**：任何状态下 `Esc` 都能退出当前界面——三选一 → 跳过、结算面板 → 关闭（待领取态）、待领取态的地图 → 关闭地图、放弃确认弹窗 → 「取消」、暂停 → 关闭暂停；`Esc` **永不等于「确认」**（§九）。
- **关闭不附加提示（第五轮）**：允许在**一项都没领取**时点「关闭」（进入待领取态），且**不额外弹提示**、不做「首次关闭提示一次」（§6.1）。
- **领取后条目直接消失（2026-10-02 用户口径）**：结算面板里的物品 Tab 与卡牌份 Tab **领取后从列表消失**（不再灰显、不再打「已领取」标记、不留禁用死条目）；「已领取」只作为**落档判定**存在（防重 / 浮窗计数 / 放弃日志）。面板列出的即「还能领的」，数量与浮窗 `N 项未领取` 一致。落点见[10 月施工文档 §7](../../2026.10/10月施工文档.md)。
