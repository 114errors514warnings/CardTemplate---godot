# 角色与怪物血条交互案

> 规定六边形战场内**角色与怪物血条**（生命 / 护盾 / 受击滞后）的显示对象、形态、取值来源与表现时序。生命与护盾的结算规则以[六边形战场玩法](../../../../玩法说明文档/系统规则/战斗系统/六边形战场玩法.md)为准，界面分区与信息层级以[六边形战场交互](../../../../交互说明文档/战斗/六边形战场交互.md)为准。

## 完成情况（2026-09-28）

- 状态：**未实现**。六边形战场当前没有血条：单位只绘制 `HP n` 文本（`Scripts/Battlefield/Presentation/BattlefieldView.cs:320`），**护盾在战场上没有任何表现** —— 只在格点悬停详情里以文本给出（`Describe()`，:257）。
- 旧战斗（卡牌战场）的 `Scripts/UI/UnitInstanceView.cs:45-73` 有 `ProgressBar` 血条与 `▦N` 护盾标签；本范围**只覆盖六边形战场**，旧战斗不改。
- 已就位的取值载体：表现层延迟数值源 `presentationStats`（`BattlefieldView.cs:30`，`(Hp, Shield)` 元组；攻击表现播放期间保持受击前取值，写入 :62-67、读取 :319）。血条必须与它同源，否则血条会早于数字跳变。
- 实现后：定稿的交互描述迁到 `README/交互说明文档/战斗/`，并按[文档编写规则](../../../../AIWorkSpace/AgentOps/文档编写规则.md) §十在当月施工文档补一条同份实现记录。

## 一、显示对象

| 对象 | 血条 | 说明 |
|---|---|---|
| 玩家角色 | 显示 | `BattlefieldRole.Player`；参与选中、移动预览与目标选择 |
| 敌方单位 | 显示 | `BattlefieldRole.Enemy`；含爪牙、精英与带逃跑意图的单位 |
| 保护目标 | 显示 | `BattlefieldRole.Protected`；按同一规则显示，不单独设计样式 |
| 已离场单位 | 不显示 | `Presence != Active`（死亡、逃跑离场）时血条随单位一起消失，格点上不留残条 |

血条**常驻**显示，不依赖悬停或选中：玩家应当在不打开额外窗口的情况下读出双方生命与护盾（[六边形战场交互](../../../../交互说明文档/战斗/六边形战场交互.md) §一）。格点悬停详情继续给出精确数值（当前/最大、护盾、攻击、防御），血条不替代详情。

## 二、形态

单条三段 + 一段滞后：

```text
[ 底条 ]                                    ← 暗色底板，始终满宽
[ 护盾段 ][ 生命填充        ]               ← 护盾段从左端起，宽 = 护盾 / 最大生命（封顶整条）
[ 滞后条                    ]               ← 受击时由旧值滑到新值，绘制在生命填充之下
```

| 段 | 取值 | 默认颜色 | 何时出现 |
|---|---|---|---|
| 底条 | — | `#141c24`（与战场底色 `#151f28` 区分） | 常驻 |
| 生命填充 | `Clamp(Hp / Max_HP, 0, 1)` | 玩家 `#6ee59c`、敌人 `#e0574f` | 常驻 |
| 护盾段 | `Shield / Max_HP`，封顶 = 整条宽 | `#8fd6ff` | `Shield > 0` |
| 滞后条 | 受击前值 → 当前值 | `#ffffff`（半透明） | 受到伤害后，时长 = `AttackPresentationSeconds`（`BattlefieldView.cs:19`，当前 0.55s） |

- 扣减顺序：先扣护盾段，护盾归零后再动生命填充；同一次攻击两段同时变化时不排队。
- 治疗、最大生命变化、护盾增减**直接跳变**，不留滞后条 —— 滞后条只表达"被打掉的量"。
- `Max_HP ≤ 0` 时不绘制血条（异常数据不画出反向条）。

## 三、尺寸与位置

单位绘制以格心为原点、单位圆半径 16、圆心在 `(0, -7)`（`BattlefieldView.cs:315`）。血条插在单位圆与状态缩略行之间，状态行下移一档：

| 元素 | 当前 y 偏移 | 本文取值 | 出处 |
|---|---:|---:|---|
| 敌方意图图标 | -66 | 不变 | `BattlefieldView.cs:327-331` |
| 敌方意图文本 | -46 | 不变 | `:321` |
| 单位名 | -27 | 不变 | `:316` |
| 单位圆（圆心 / 半径） | -7 / 16 | 不变 | `:315` |
| **血条** | 无 | **+16 ~ +24（高 8）** | 新增 |
| 生命 / 护盾文本 | +15（`HP n`） | 移到血条内居中（基线 +22） | `:320` |
| 状态缩略 | +42 | **+48** | `:333-334` |

- 血条宽 = `CellRadius × 1.10`；当前 `CellRadius = 42`（`BattleMapDefinition.cs:52`），即宽 ≈ 46，以格心水平居中，不参与格边框（`r = 42`）的绘制。
- 血条随 `CellRadius` 缩放：地图 JSON 允许 16–120（`BattleMapDefinition.cs:95`），血条与单位圆同步按 `CellRadius / 42` 缩放，避免小格上溢出到邻格。
- 绘制顺序：单位与血条在格点层之上；拖拽预览（黄色候选 / 红色弹道 / 移动路径）、敌方意图预览格与攻击表现在 `_Draw()` 中**晚于**单位循环绘制（:336-339），预览不被血条遮断。

## 四、文本

| 项 | 默认文案 | 出现条件 |
|---|---|---|
| 生命 | 玩家 `当前/最大`；敌人 `当前` | 常驻（沿用现状：敌人不显示上限） |
| 护盾 | `▦N`（与旧战斗 `UnitInstanceView.cs:66` 同一符号） | `Shield > 0` |

- 文本绘制在血条中央，字号 12；血条高度不足时**优先保留数字**，条退化为纯底板。
- 若玩法要求隐藏敌人生命上限，只删上限文案不够 —— 血条按上限比例这件事本身会暴露上限，见 §七 第 1 条。

## 五、与其它表现的关系

- **敌方意图**：位置不变（单位上方）；意图预览格（`DrawKnownEnemyIntentPreview`，:342）与血条互不影响。
- **攻击表现**：血条不参与位移与形变（突进、扇形/环形摆动、击退）。表现期间血条跟随 `visualUnitPositions` 的单位中心（:296），右键拖图时随单位一起平移（与 :239 的坐标平移口径一致）。
- **状态缩略图标**：只下移位置（§三），图标数量、`Take(3)` 与悬停详情规则不变。
- **战后操作态**（[战斗结算后战场操作交互案](战斗结算后战场操作交互案.md)、代码需求清单 P2-13）：血条继续显示，角色生命在战后仍可读；战后移动与拾取不改变血条行为。
- **按快照重建的战场**（P2-13 收尾）：血条取还原后的 `Hp`，**不重放**受击滞后条 —— 重建是"落档态"而不是"新受击"。
- **关卡类型**：生存关、保护目标关与歼灭关血条口径完全一致，不做分支。
- **悬停详情**：数值必须与血条同源（同一 `presentationStats` 延迟源），不允许出现"血条已扣、详情未扣"。

## 八、验收

1. 出牌造成伤害后，滞后条与生命文本**同帧**开始变化，`AttackPresentationSeconds` 结束后二者一致；不出现"数字先跳、血条后跳"。
2. 护盾吸收时先扣护盾段；`Shield > Max_HP` 时护盾段封顶整条、生命填充保持满。
3. 治疗、最大生命变化、护盾直接增减**直接跳变**，不产生滞后条。
4. 单位被击败或逃跑离场后血条立即消失，格点上无残条。
5. 格点悬停详情的生命 / 护盾与血条数值严格一致（含攻击表现播放期间）。
6. `CellRadius = 16` 与 `= 120` 两端下，血条不溢到邻格、不盖住状态缩略；名字与敌方意图文本位置不被挤动。
7. 战后操作态与按快照重建的战场上血条按当前 `Hp` 显示，且不重放受击变化。
8. `dotnet build 卡牌模拟器.csproj` + `dotnet test Tests\卡牌模拟器.Tests.csproj`（当前 238 例）与无界面 `--battlefield-smoke` 不回归（血条属表现层，不新增断言；如需像素级校验另开图测）。
