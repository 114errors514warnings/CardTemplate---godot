## 一、定位与入口

- 背包是**队伍共享**的：本局是单一钱袋模型（`Gold` 与 `StolenGoldFromMonsters` 都不归属角色），不做每角色独立背包。
- 入口：运行局常驻顶部按钮栏（`RunUiLayers.GlobalButton = 50`）**通用行**新增 `背包` 按钮，排在 `地图` 之后、`调试` 之前（按钮创建点 `Scripts/Run/RunFlowScene.cs:336-340`，`AddTopButton`）。
- 层级：界面挂 `RunUiLayers.Modal = 40`（与结算面板、调试面板同层）。单实例，重复点击只重新聚焦；`背包` 与[装备界面](装备系统交互案.md)互斥（打开一个自动关闭另一个）。
- 关闭：界面内 `关闭` 按钮或 `Esc`。关闭不改变任何状态；**每次拖动成功立刻写档**（`RunSession.Save()`），不做"关闭时统一提交"的草稿态 —— 与营地篝火的草稿态是两套模型（[篝火休息交互案](篝火休息交互案.md) §添加食物）。
- 地图关系：世界地图（`RunUiLayers.WorldMap = 30`）打开时可叠开背包（40 > 30），关闭背包后地图状态原样保留。
- 战斗 / 事件进行中、结算未关闭时打开 = **只读**（可看不可拖），规则见 §三。

## 二、界面结构

```text
┌ 背包 ─────────────────────────────────────────────────────┐
│ 负荷 12.4 / 30            〔全部〕〔材料〕〔道具〕〔装备〕〔食物〕 │ ← 页签行 + 负荷条
├──────────────────────────────┬───────────────────────────┤
│ 物品格（滚动）                 │ 随身道具（3 格）             │
│  ┌────┐┌────┐┌────┐          │  ┌──┐┌──┐┌──┐              │
│  │物品 ││物品 ││物品 │   …      │  │  ││  ││  │              │
│  └────┘└────┘└────┘          │  └──┘└──┘└──┘              │
│  ┌────┐┌────┐┌────┐          │  左手位 ┌────┐              │
│  │物品 ││物品 ││物品 │          │         │    │              │
│  └────┘└────┘└────┘          │  右手位 └────┘              │
│                              │                〔关闭〕      │
└──────────────────────────────┴───────────────────────────┘
```

- 左侧 = 背包格（每格一件；可叠加物品显示数量角标）；右侧 = **可拖放目标**：随身道具 3 格 + 左右手位 —— 与战斗内槽位数量、语义完全一致，不引入第二套心理模型。
- 每格显示：物品名、数量（可叠加时）、单件负荷（悬停给出 `单件 × 数量` 明细、效果、稀有度与来源）。
- 页签只过滤**显示**，不改变负荷统计（负荷是整包口径，见 §四）。
- 背包格数不设硬上限（由负荷约束）；叠加物品合并到同一格。

## 三、拖动规则

拖动只在**「无内容进行中」**放行：运行局处于 `RunGameModes.OnMap`，且没有不可让位的进行中内容（地图可选态、事件已结算、结算面板已关闭、不在营地）。战斗、事件进行中、结算未关闭、营地与休息期间，界面打开为**只读**：格与槽位可点可看，不接拖动，悬停提示原因「战斗中不可整理背包」/「事件进行中不可整理背包」。

| 来源 → 目标 | 允许 | 条件与结果 |
|---|---|---|
| 背包 → 随身道具格 | 允许 | 道具 / 材料 / 食物；该格已有物品则**交换**（原物回背包），不做满栏替换面板 |
| 背包 → 左手位 / 右手位 | 允许 | 仅武器 / 防具；按 `HandsRequired` 校验，双手装备需两槽同时可让位 |
| 随身道具格 → 背包 | 允许 | 收入背包（局外不落地） |
| 手位 → 背包 | 允许 | 卸下；装备进背包的「装备」分类，**局外不落地丢弃** |
| 手位 → 另一手位 | 允许 | 交换；按[六边形战场玩法](../../../../玩法说明文档/系统规则/战斗系统/六边形战场玩法.md) §5.2 合法组合表校验（双手装备排斥其它手位装备），非法则拒绝并给原因 |
| 手位 → 随身道具格 | **默认非法（预留许可通道）** | 默认拒绝，提示「该装备不可放入道具栏（需装备效果开放许可）」；当该装备的 `AllowsWeaponInItemSlots` 为真时合法，落点行为与「背包 → 随身道具格」一致 |
| 装备格（头/身/脚/饰品） | 不接 | 部件装备的拖动在[装备界面](装备系统交互案.md)内完成；两个界面不叠开，不跨界面拖动 |

- **「武器 / 护具进道具栏」的预留通道**：落点判定与提示本轮就做，许可标志来自装备效果（玩法 §5.2 末尾的"预留由装备效果开放武器放入道具栏的许可接口"），默认全部为 false。通道存在的意义是：许可一旦开放，武器/护具可以像道具一样放进随身 3 格并随战斗携带，不需要再改交互。
- 非法落点一律**弱化 + 原因文本**，不弹窗；拖动经过的合法目标高亮（沿用战斗内黄色悬浮框口径）。
- 拖动不消耗时间点、不消耗金币、不改角色生命与卡组。
- 战斗内既有口径不变：战斗中「当前格道具 ↔ 随身槽」「拾取装备到手位（含战后拾取 `TryPostBattlePickup`）」仍按 `HexBattleScene` 现有实现。

## 四、负荷

- 每个物品有**单件负荷**（配置列 `Load`，浮点；空 = 0；叠加物品按 `Load × 数量` 计入）。
- 背包承载上限是**队伍共用上限**，来自新配置表（建议 `DataBase/Inventory/InventoryConfig.csv`，表头 `Scope,CharacterId,Capacity`；`Global` 行 = 队伍上限，`Character` 行预留不启用；经 `DataBase/FilePathRegistry.csv` 注册为 `Data.Inventory.Config`）。
- 统计口径：**只统计背包内物品**。已穿戴（左右手位 + 头部/身体/脚部 + 饰品）与战斗内临时携带**不占背包负荷** —— 穿在身上、拿在手里的不算包内。
- 校验在**拖入 / 拾取前试算**：`当前负荷 + 新物品负荷 > 上限` 即拒绝，显示 `负荷不足：12.4 + 2.0 > 14.0`。
- 结算与事件的**奖励入账不受负荷限制**（材料、金币、卡牌直接入账）：超限时负荷条转超载色并在悬停提示"超载"、同时阻止新的拖入，直到玩家自行整理（放上手位或消耗）。理由：奖励是流程产物，不应因背包满而在流程中丢失或被静默丢弃。
- 默认单件负荷（**待玩法侧配数**；下表为占位默认值，用来先跑通界面与校验链路）：

| 类别 | 默认单件负荷 | 依据 |
|---|---:|---|
| 材料 | 0.1 | 来源最广的基础物资 |
| 食物 | 0.5 | 独立实例（[食物系统](../../../../玩法说明文档/系统规则/物品系统/食物系统.md) §一） |
| 道具 | 1.0 | 消耗品 |
| 单手武器 / 单手防具 | 2.0 | `HandsRequired = 1` |
| 双手武器 / 双手防具 | 4.0 | `HandsRequired = 2` |
| 头部 / 身体 / 脚部 | 2.0 | 穿戴部位 |
| 饰品 | 0.5 | 最多 3 件 |
| 队伍上限 | 30.0 | 约"一件双手装备 + 全套部位装备 + 若干道具"的余量 |

- 负荷显示保留 1 位小数（0.1 与本项目已有的最小计量粒度量级一致，时间点同样按 0.1 计）。

## 六、数据模型与存档

- 背包条目 = **实例**：`InstanceId`（局内唯一；沿用 7 位数字前缀规则，见 [UniqueInGameId](../../../../功能说明文档/实体系统/UniqueInGameId.md)）+ `DefinitionId` + `Count`（可叠加物品 > 1；食物、装备、带独立效果的物品恒为 1）+ `Category` + 实例字段（食物有效期、稀有度等）。
- 兼容既有字段：`RunSaveData.Materials` / `Items` / `Equipment` 三个计数字典保留为**汇总视图**（材料等叠加型物品继续用它），带实例字段的物品进新列表 `RunSaveData.BagEntries`；迁移把现有字典内容按"多件同定义物品"展开，不丢数据。
- 新增字段（`RunSaveData`，与[装备系统交互案](装备系统交互案.md) §五同批迁移 `SchemaVersion 2 → 3`，见[代码需求清单](../玩法/代码需求清单.md) P0-3）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `BagEntries` | `List<RunBagEntrySave>` | 背包实例条目（§六 第一段） |
| `CarryItemSlots` | `List<string>`（长度 3） | 局外随身 3 格（空串 = 空位）；默认不写入战斗开场（§九 第 1 条） |
| 装备字段 | 见[装备系统交互案](装备系统交互案.md) §五 | 左右手 + 头部/身体/脚部 + 饰品列表 |

- 写档时机：每次拖动成功、每次奖励入账后立刻 `RunSession.Save()`（与战后拾取"每次成功后再落一次"的既有口径一致，见 9 月施工文档 §39）。

## 八、验收

1. 顶部按钮栏出现 `背包`，单实例开关；`背包` 与 `装备` 互斥；`Esc` 与 `关闭` 都能退出且不留状态。
2. 分类页签过滤正确（材料 / 道具 / 装备 / 食物），`全部` 页签含全部条目；每格显示数量与单件负荷。
3. 负荷条 = `Σ(单件负荷 × 数量)`，只统计背包内物品：把装备装到左右手位后负荷**下降**，卸下后**回升**。
4. 拖入使 `当前负荷 + 新负荷 > 上限` 时被拒绝并给出带具体数字的原因；奖励入账在超限时仍入账，负荷条显示超载并阻止新的拖入。
5. 背包 → 随身格：目标格已有物品时**交换**（原物回背包），不做满栏替换面板；随身格 → 背包收入而不落地。
6. 背包 → 手位：双手装备要求两槽同时可让位；非法组合（如已有双手装备再装单手）被拒绝并给出原因。
7. 手位 → 随身道具格默认被拒绝并提示许可原因；把该装备的 `AllowsWeaponInItemSlots` 置 true 后同一拖动合法（许可通道可用）。
8. 战斗 / 事件进行中、结算未关闭时打开界面为只读：拖动无响应，悬停给出原因。
9. 每次拖动成功立刻写档（退出重进状态一致）；旧档迁移后物品数量不丢。
10. `dotnet build` / `dotnet test`（238 例）/ `--battlefield-smoke` / `--run-flow-ui-smoke` 不回归；界面自身如需断言，按既有做法在烟测里加"打开 → 拖动 → 数值变化"的检查。

| 6 | 食物类目归属 | 单列「食物」页签，不与道具混排 | 并入「道具」页签，改页签列表即可 |
