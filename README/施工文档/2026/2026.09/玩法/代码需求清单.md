## P0 · 当前玩法已被卡住

### 1. 事件选项跳转 `next = Battle`（已落地，待复核）

- **需求**：事件选项除 `Close` 外支持 `Battle`，`referenceId` 指向 `LevelId`，选择后进入该关卡战斗。
- **涉及**：`Scripts/Story/StoryEventCatalog.cs`、`Scripts/Battlefield/Presentation/HexBattleScene.cs`、`Scripts/Run/RunEventScene.cs`
- **现状**：已实现并通过 `dotnet build 卡牌模拟器.csproj`（0 错误 0 警告）。实现方式：`StoryNextTypes` + `ResolveBattleLevelId()` 校验跳转；`HexBattleScene.PendingStoryBattleLevelId` 在选项回调里先记录意图再应用效果；`RunEventScene` 按请求构造 `StageEncounterRow{ NodeType = DangerousEvent }` 并 `BeginRunBattleEncounter`。
- **待复核**：① 战斗失败路径（清档）与事件节点状态的交互；② 退出重进时 `InBattleStart + PendingContentType="Level"` 的恢复是否与事件节点一致；③ 是否需要"战斗结束回到事件后续对话"的分支。
- **验收**：地图 → 危险事件 → 选战斗选项 → 进入指定关卡 → 胜利结算选卡 → 回地图；分档计数不增、节点被标记已访问。

### 2. 事件效果执行器扩展

- **需求**：`effects` 目前只执行 `HpDelta/SelectedPlayer` 与 `GoldDelta/Run`，其余一律打日志跳过。需要支持：
  `HpDelta/AllPlayers`、**`HpPercentDelta`（按最大生命百分比，向上取整；事件扣血 / 回复的统一写法）**、`TimePointDelta/Run`（0.1 精度、非负）、`MaterialDelta/Run`、`ItemDelta/Run`、`CardAdd`（指定卡或按稀有度）、`CardRemove`、`CardUpgrade`（卡牌永久升级）、`StatusCardAdd`、`RewardId`（按 DropTable 直接发奖）。
- **涉及**：`Scripts/Battlefield/Presentation/HexBattleScene.cs`（效果分发）、`Scripts/Story/StoryEventCatalog.cs`（效果校验）、`Scripts/Run/RunSession.cs`（卡组增删、时间点、材料/道具）
- **验收**：事件 JSON 可声明上述效果，且 `effectPreview` 与实际执行结果一致（预览是公开契约，不允许"预览显示、实际不生效"）。
- **阻塞**：事件选项的币种只能停留在金币 / 单角色生命，无法使用卡组、材料、道具、时间点。

### 3. 时间点存档精度 `int → float`（0.1 单位）

- **需求**：时间点最小计量单位为 **0.1**（= 战斗中 1 回合），一天固定 4 点、移动 0.3。`RunSaveData.MapState.TimePoints` 目前是 `int`（注释为"占位：本期不结算玩法，仅存取"）。
- **同时**：时间点进程**只能增加**，任何效果（含事件 `TimePointDelta`）都不得写入负值。"节省时间"由"该选项不消耗时间"表达，不做减法；主动结束当天只作废当天剩余额度并转入休息收益。
- **涉及**：`Scripts/Run/RunSaveData.cs`（改 `float`，`SchemaVersion 2 → 3` + 旧档迁移）、`Scripts/Run/RunSession.cs`、时间点消耗/显示相关 UI
- **验收**：能记录 0.3 / 0.5 这类小数；4 点满即跨天；负数写入被拒绝；旧存档可继续（迁移不丢进度）。
- **规则依据**：`玩法说明文档/系统规则/地图玩法/地图玩法.md §5.1–5.2`、`事件系统/事件系统.md §2.2`。

### 10. 怪物机制：窃取（状态）与逃跑意图（F1-006 劫匪团伙）

#### 10.1 窃取状态（挂在怪物身上）

> **状态：机制已接入（2026-09-22，施工文档 §25）**。已实现：命中扣款（当前为"**不足不扣**"，需按 2026-09-23 口径改为"**扣到归零**"）、**按怪物实例分开记账**（`StolenGoldEntry{InstanceId,MonsterId,Amount}`，`InstanceId` = 关卡 CSV 的实例 ID）、胜利结算只返还**被击杀实例**的那份（结算面板一行"追回被窃金币 +N"，直接入账）、初始层数经 `InitialValue` 的 `State=Steal:N` 写入。**仍未实现**：结算栏独立的「被窃取」tab（当前是结算页的一行说明 + 直接入账）。

- **状态**：新增 `21 窃取`（`DataBase/State/通用State.csv` **已落表**）：`DecayTiming=Never`、`DecayMode=None`、`StacksToRemove=0`、`IsDebuff=false`。
  - **它挂在怪物身上**，语义是"**该怪物每次攻击时窃取的金币数**" = 该状态的层数（近战劫匪默认 **1**）。
  - **不会衰减**；除特殊状态变更外，层数不变（不会因命中次数增加）。
- **行为**：拥有「窃取」N 层的怪物**造成伤害后**，从局内金币里**取走 N 金币**（`RunSaveData.Gold`；本局是单一钱袋，不存在"每个角色各自被窃"），并**按该怪物实例**记入账本（`RunSaveData.StolenGoldFromMonsters`）。
- **结算回收**：**击败该实例**后原额返还（已直接入账，结算页显示"追回被窃金币 +N"）；**未击败（存活/逃跑成功）不返还**。设计稿里的"独立『被窃取』tab、按角色列出"仍属后续需求；由于**本局是单一钱袋**（金币不归属角色），按角色列出缺数据维度 → **建议改为按怪物实例列出**。
- **口径更新（2026-09-23）**：窃取**直接以总金币为目标**，且**只有总金币归零后被窃金额才不再增长**——即余额不足以支付本次窃取额时应**部分扣除到 0**（例：余额 1、层数 3 → 扣 1、被窃 +1）。当前实现是 `if (run.Gold < amount) return 0;`（**一分不扣**）→ 需要改为 `take = min(amount, run.Gold)`。
- **初始层数来源**：关卡 CSV 的 `InitialValue` 列，例如 `F1-006.csv` 中 4 只近战劫匪填 `State=Steal:1`（解析/落地由 `UnitInitialStateConfig` 负责，已支持 `State=<枚举名或编号>:<层数>`）。早期草案里的 `窃取=1` 是未定义键，已废止。
- **涉及**：`Scripts/Run/RunGoldLedger.cs`、`Scripts/Battlefield/Runtime/BattlefieldSession.cs`（`MonsterHitPlayer` + `GetMonsterInstanceKey`）、`HexBattleScene`、`RunBattleScene`、`RunSaveData`。
- **验收**：F1-006 的近战劫匪出场即带「窃取」1 层；其每次命中后，局内金币 −1 且账本在该实例名下 +1；该状态不衰减、不因命中次数增加；击杀该实例后结算返还等额金币；同 ID 的其他实例若存活则不返还；若劫匪**逃跑成功则不返还**（逃跑本身待 10.2）。
- **已定参数**：默认层数 **1**（推算见 `F1-006劫匪团伙.md §四`：期望被窃 4–8 金 ≈ 该场金币掉落的 9–19%）。

#### 10.2 逃跑意图（Flee）—— 未实现，且存在配置表达阻碍

- **规则已落档**：`六边形战场玩法 §7.6`（行动时不攻击、向最近的地图边界方向移动、移动后位于边界格即离场；离场按 §7.4 折损奖励）。
- **阻碍项（需代码侧先定"表达方式"，配置才能落表）**：
  1. **意图选择规则不支持门槛/概率**：当前是"把所有非空意图**均匀随机**"（`BattlefieldSession.PrepareEnemyIntentions`、`MonsterIntentionService.SelectIntentionForMonster`），没有回合门槛、没有概率、没有"必定使用某意图"，也没有"锁定为某意图" → 需要可按配置表达的意图选择规则。
  2. **没有战斗回合计数器**："第 3 个敌方回合必定高攻"无法判定 → 需要暴露敌方回合数。
  3. **`Monster.csv` 无法表达"无效果意图"**：解析要求每段非空、首数为 `EffectType`（1=Damage / 2=Shield / 3=AddState）且参数非空；逃跑意图没有伤害/护盾/状态 → 建议新增 `4=None`（或 `4=Flee`）。
  4. **`EnemyIntent.csv` 没有行为类型字段**：`AttackMode` 只有攻击方式枚举 → 需新增 `Flee`，或加一列行为类型。
  5. **命中计数缺失**："某怪物成功攻击命中玩家 2 次"需要在该怪物实例上累计命中数（含被格挡）→ 需要新字段。
  6. **逃跑传染缺全局状态**：任一单位逃跑后"下一回合全体逃跑"需要战斗级状态与强制指定全员意图。
  7. **离场判定不能复用 `Defeated`**：结算返还按 `BattlefieldPresence.Defeated` 挑实例（`RunBattleScene.RefundStolenGold`）。若逃跑也用 `Defeated` 表示，会被当成"被击杀"从而**错误返还被窃金币** → 需要独立的 `Escaped` 存在性，并在结算时排除。
- **拟配内容（上述 1–4 定好后即可落表，以 `4=None` + `Flee` + 回合门槛列为例）**：

```csv
# Monster.csv：意图0=低攻、意图1=高攻、意图2=逃跑（无效果）
3115,近战劫匪,20,4,1,1;-2,1,4,,,,,,,,
3116,远程劫匪,16,3,2,1;-1,1;1,4,,,,,,,,
# EnemyIntent.csv：行为=Flee、移动预算 3 格/回合（不留反应窗口，意图显示为逃跑即当回合拼速度）
3115,2,KnownDamageKnownRange,Flee,0,1,0,MoveThenAttack,Nearest,0,MinTurn=1
3116,2,KnownDamageKnownRange,Flee,0,1,0,MoveThenAttack,Nearest,0,MinTurn=1
```

- **验收**：F1-006 第 6 回合起劫匪向边界移动；抵达边界即离场且不再行动；**离场实例的被窃金币不返还**，且结算按价值比例折损并显示触发原因。
