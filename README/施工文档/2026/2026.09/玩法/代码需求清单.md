## P0 · 当前玩法已被卡住

### 1. 事件选项跳转 `next = Battle`（已落地，待复核）

- **需求**：事件选项除 `Close` 外支持 `Battle`，`referenceId` 指向 `LevelId`，选择后进入该关卡战斗。
- **涉及**：`Scripts/Story/StoryEventCatalog.cs`、`Scripts/Battlefield/Presentation/HexBattleScene.cs`、`Scripts/Run/RunEventScene.cs`
- **现状**：已实现并通过 `dotnet build 卡牌模拟器.csproj`（0 错误 0 警告）。实现方式：`StoryNextTypes` + `ResolveBattleLevelId()` 校验跳转；`HexBattleScene.PendingStoryBattleLevelId` 在选项回调里先记录意图再应用效果；`RunEventScene` 按请求构造 `StageEncounterRow{ NodeType = DangerousEvent }` 并 `BeginRunBattleEncounter`。
- **待复核**：① 战斗失败路径（清档）与事件节点状态的交互；② 退出重进时 `InBattleStart + PendingContentType="Level"` 的恢复是否与事件节点一致；③ 是否需要"战斗结束回到事件后续对话"的分支。
- **验收**：地图 → 危险事件 → 选战斗选项 → 进入指定关卡 → 胜利结算选卡 → 回地图；分档计数不增、节点被标记已访问。

### 2. 事件效果执行器扩展

- **需求**：`effects` 目前只执行 `HpDelta/SelectedPlayer` 与 `GoldDelta/Run`，其余一律打日志跳过。需要支持：
  `HpDelta/AllPlayers`、**`HpPercentDelta`（按最大生命百分比，向上取整；事件扣血 / 回复的统一写法）**、`TimePointDelta/Run`（0.1 精度、非负）、`MaterialDelta/Run`、`ItemDelta/Run`、`CardAdd`（指定卡或按稀有度）、`CardRemove`、`CardUpgrade`（卡牌永久升级）、`StatusCardAdd`、`RewardId`（按 DropTable 直接发奖）。
- **涉及**：`Scripts/Battlefield/Presentation/HexBattleScene.cs`（效果分发）、`Scripts/Story/StoryEventCatalog.cs`（效果校验）、`Scripts/Run/RunSession.cs`（卡组增删、时间点、材料/道具）
- **验收**：事件 JSON 可声明上述效果，且 `effectPreview` 与实际执行结果一致（预览是公开契约，不允许"预览显示、实际不生效"）。
- **阻塞**：事件选项的币种只能停留在金币 / 单角色生命，无法使用卡组、材料、道具、时间点。

### 3. 时间点存档精度 `int → float`（0.1 单位）

- **需求**：时间点最小计量单位为 **0.1**（= 战斗中 1 回合），一天固定 4 点、移动 0.3。`RunSaveData.MapState.TimePoints` 目前是 `int`（注释为"占位：本期不结算玩法，仅存取"）。
- **同时**：时间点进程**只能增加**，任何效果（含事件 `TimePointDelta`）都不得写入负值。"节省时间"由"该选项不消耗时间"表达，不做减法；主动结束当天只作废当天剩余额度并转入休息收益。
- **涉及**：`Scripts/Run/RunSaveData.cs`（改 `float`，`SchemaVersion 2 → 3` + 旧档迁移）、`Scripts/Run/RunSession.cs`、时间点消耗/显示相关 UI
- **验收**：能记录 0.3 / 0.5 这类小数；4 点满即跨天；负数写入被拒绝；旧存档可继续（迁移不丢进度）。
- **状态（2026-10-01）**：**已落地**（由 B3 提前，见 [9 月施工文档 §48.2](../9月施工文档.md)）—— `RunMapStateSave.TimePoints` 改 `float`（0.1 步长、`Quantize` 消漂移），`CurrentSchemaVersion = 3` + `MigrateToCurrentSchema()` 读档统一升级（旧 int 档就地转、停在日界的档补一次待休息），`TryAddTimePoints` 拒绝负向写入、`TrySpendTimePoints` 透支整笔拒绝；新增 `PendingRestDay`（当天已耗尽待休息）与 `RestRemainingTimePoints`（休息取值来源）。效果名与 `TimePointDelta/Run` 对齐（`value` = 回合数，1 回合 = 0.1；`TimePoint` 为等价别名）。
- **规则依据**：`玩法说明文档/系统规则/地图玩法/地图玩法.md §5.1–5.2`、`事件系统/事件系统.md §2.2`。

### 5. 掉落表双轨接线

- **现状**：运行时读取 `DataBase/Map/DropTable.csv`（`DropTableId,Category,RewardParam,Amount,Weight`，由 `FilePathRegistry` 的 `Data.Map.DropTable` 注册）；而 `配表规范` 规定的正式表是 `DataBase/Reward/DropTableIndex.csv` + `Reward/Config/<DropTableId>.csv`（`RewardGroup,RewardType,ReferenceId,MinAmount,MaxAmount,Probability`，含卡牌稀有度分层）。目前 2001/2002/2003 三张表**两处都要维护**。

- **口径（已定稿）**：`六边形战场玩法 §7.4` + `单位数值平衡标准 §2.3 / §2.4`。
  - **综合价值点数 = 面板 HP + K × 意图加权价值**（K = 1.0，2026-09-27 定稿）。

  - **档位**：实际击败 ÷ 本场应击败 **> 70% 全额**；**≤ 70% 减 1 张**；**< 50% 再减 1 张**（最多减 2，保留 1 张）。分母 = **本场实际部署的敌人**，不按关卡配置全表；爪牙不计入分子分母；生存关豁免。

#### 10.4 怪物意图伤害修正值不生效（两元素写法）—— **已实现（2026-09-28）**

- **修复（2026-09-28）**：新增纯逻辑 `Scripts/Battlefield/Core/EnemyIntentDamageArgs.cs`（取参口径：两元素取 `effect[1]`、三元素及以上取 `effect[2]`；`ResolveDamageParams` 供执行侧），`BattlefieldSession` 的伤害段执行与三处预览（`GetEnemyIntentionText` / `GetEnemyIntentDisplay` / `GetLegacyEnemyIntentionText`）全部改走它 —— **执行与预览同一口径**。效果：3115 低攻 **4** / 高攻 **6**；3114 借势格挡 **18 → 13**、横扫 **18 → 15**；3106 / 3107 / 3111 的修正值一并生效。`Tests/EnemyIntentDamageArgsTests.cs` 锁死取参。`3003 / 3007` 的 `1;2` 歧义**收尾（同日）**：两元素写法本身无误（= 伤害修正值），但这两行的设计本意是「同意图共用同一随机目标」→ **配置已改写为三元素 `1;2;0`**（模式 2 + 修正 0），`MonsterValue.csv` 随之由 `15|9` / `12|6` 改为 **`9|9` / `8|6`**，并同步 `单位数值平衡标准 §2.4 / §四 / §五 / §六`、`怪物总表 §二`、`行为与属性价值估算 §六`、`怪物属性与强度`；`EnemyIntent.csv` 补上原先缺失的 `3007` 两行（取值 = 原隐式回退规格，行为不变）。落地记录见 [9 月施工文档 §36](../9月施工文档.md)。

- **现象**：`Monster.csv` 意图段用两元素写法 `1;<修正值>`（如 3115 低攻 `1;-1` / 高攻 `1;1`、3114 `1;-5` / `1;-3`、3106 `1;-2`、3107 `1;-1`、3111 `1;1`）时，**修正值在六边形战场被整段丢弃**：3115 低攻 / 高攻都算 5、3114 借势格挡算 18（配置 13）、横扫算 18（配置 15）。
- **根因**：`Scripts/Battlefield/Runtime/BattlefieldSession.cs` 的 `ExecuteEnemyIntentionEffect` 对 Damage 段取参写的是 `int[] args = effect.Length > 2 ? effect.Skip(2).ToArray() : Array.Empty<int>();`，而 `EffectSystem` 的 `AttackEffect` 是 `damage = Math.Max(0, Source.Attack + context.GetParam(0))` → 两元素写法取到空数组，`GetParam(0) = 0`。**同一方法里护盾段用的是 `Skip(1)`（`2;1` 能生效），伤害段与护盾段取参口径不一致**。
- **正确语义（另一条路径已按此实现）**：旧卡牌战斗的 `MonsterIntentionService.ParseMonsterDamageTargetMode` 规定「额外参数只有 1 个时视为伤害修正值；≥2 个时首参才是 `MonsterDamageTargetMode`」，与 `效果系统 §4.1`、`怪物配置` 的文档一致。旧路径行为正确，**只有六边形战场分叉**。
- **修复方向（择一）**：① 取参改为「`Length == 2` → `effect[1]`；`Length > 2` → `effect[2]`；其余 → 0」，同时把 `GetEnemyIntentionText` / `GetEnemyIntentDisplay` / `GetLegacyEnemyIntentionText` 三处预览取值同步（否则界面与实际伤害不一致）；② 或把全部配置改写为三元素 `1;<MonsterDamageTargetMode>;<修正值>`（如 `1;1;-1`），废弃两元素写法。推荐 ①（不动数据，且与旧路径、与 `单位数值平衡标准` 的口径统一）。
- **影响**：F1-006 的「第 3 个敌方回合高攻爆发」（表内 6 伤害）在实机不出现（恒为 5）；F1-004 的「借势格挡 13 + 5」与「横扫 15」实机是 18 + 5 / 18，与关卡数值设计不符；3106 / 3107 / 3111 的修正值同样失效。修复前，`单位数值平衡标准 §2.4` 的意图价值口径与实机不一致（口径按配置语义，代码对齐后一致）。
- **涉及**：`Scripts/Battlefield/Runtime/BattlefieldSession.cs`（执行 + 3 处预览取值）。
- **验收**：F1-006 里 3115 第 3 回合的意图预览与实伤都显示 6；3114 三个意图分别造成 18 / 13 伤害 + 5 护盾 + 1 层反击 / 15；3106 荷具冲撞为 5 伤害 + 7 护盾；3107 投掷为 1 伤害 + 1 层虚弱；3111 蓄力劈砍为 6 伤害 + 4 护盾。

  2. `3;3;…`（`AllEnemies` = 全体角色）→ **退化为单体**：`3125 导师威压`的"全体 3 层易伤"实际只打 1 人；
  3. 友方（怪物）增益**没有载体**：`TargetPolicy = AllyRange` 只在 `Shield` 分支被特判（`ExecuteEnemyIntentionEffect` 护盾段按半径遍历友方），而 `EnemyIntentPlanner.Plan` 的候选目标永远是玩家 → `3;5;…`（`AllAllies`）无法落地；
  4. 恰好吃对的只有 `3;0;…`（`Auto` = 随机一名角色，与 `BATTLEFIELD_MONSTER_STATE_TARGET_PASS` 口径一致）。
- **需求**：① `AddState` 段按 `effect[1]` 通过 `BattleUnitRegistry.ResolveEffectTargets`（或等价阵营解析）取目标，支持 `0 Auto / 1 Self / 2 SelectedTarget / 3 AllEnemies / 4 AllUnits / 5 AllAllies`；② `AllEnemies` / `AllAllies` 在六边形战场按**怪物 ↔ 角色**阵营解析（怪物出牌时 `AllEnemies` = 全体角色、`AllAllies` = 其余怪物）；③ 把 `AllyRange` + `AreaRadius` 的半径迭代**提升为通用规则**（`AddState` 与 `Shield` 同口径），使"半径 3 友方各 +1 层力量"可写；④ 顺带统一 `EffectType.Shield` 的目标口径（现在写死 `AllyRange` 特判 + 否则自身）；⑤ 更新 `功能说明文档/数据系统/数据配置/怪物.md` 的目标类型说明（现在只列到 `4`，且把 `3` 描述为"全体角色"而实现是单体）。
- **涉及**：`Scripts/Battlefield/Runtime/BattlefieldSession.cs`（`ExecuteEnemyIntentionEffect`）、`Scripts/System/Battle/BattleUnitRegistry.cs`（`ResolveEffectTargets`，已是六边形战场可用的纯逻辑）、`Scripts/Battlefield/Core/EnemyIntentPlanner.cs`（若把友方索敌做进 `Plan`）、`README/功能说明文档/数据系统/数据配置/怪物.md`。
- **验收**：① `3123` 的"自身加攻"落在**怪物自己**身上（三名角色 0 层）；② `3125` 的"全体角色 3 层易伤"落在**3 名角色**身上；③ 新增的 `3124`「伴侣共鸣」（`3;1;6;1|3;5;6;1`）只给**女方自己与半径内友方**加层、玩家 0 层；④ 未改动写法的旧行（`3;0;…`）行为不变（`BATTLEFIELD_MONSTER_STATE_TARGET_PASS` 继续 PASS）；⑤ 单测覆盖目标类型解析的 6 个分支。

### 26. 条件意图（血线 / 回合 / 命中 / 状态）与意图次数限制的配置化

> 登记：2026-10-02（归档汇总时的程序向梳理）。依据：[关于意图系统的讨论](../../../2026/2026.05/战斗/关于意图系统的讨论.md)（2026-05 已给出「意图内容 / 触发条件 / 选择策略 / 次数限制」四层拆分，**至今未落地**）；现役需求点见下。

- **现状**：**条件与次数都是 C# 里的特例，不是配置** ——
  1. 意图选择只有关卡级 `BattleRule`（第 13 列）+ `IBattleRule.TrySelectIntention` 一个钩子；唯一实现 `BanditEscalationRule` 把「第 N 批次起高攻」「命中达阈值后按概率逃跑」「同模板传染」**硬编码**在规则里（`Scripts/Battlefield/Core/BattleRule.cs`）。
  2. `Monster.csv` 的 `Intention1..10` **只承载「做什么」**（效果段），`EnemyIntent.csv` 的 12 列（`MonsterId / IntentionIndex / PreviewCertainty / AttackMode / AttackRange / MoveBudget / ActionBudget / ActionOrder / TargetPolicy / AreaRadius / PreviewDirection / Behavior`）只承载移动预算 / 索敌 / 落点 / 行为 —— **两张表都没有任何条件列或次数列**。
  3. `IntentSelectionContext` 只暴露 `Round` / `IntentBatch` / `EnemyId` / `Monster` / `Candidates` / `HitPlayerCount` / `Random` —— **读不到自身 HP、自身状态、场上存活 / 已退场单位**（与 P2-24 同一个缺口）。
  4. 数值侧目前按**等概率**记账、并把条件意图排除在权重口径外（[单位数值平衡标准 §六](../../../../玩法说明文档/系统规则/数值平衡/单位数值平衡标准.md)：「条件意图（3115 第 3 回合必高攻、命中 2 次后 50% 逃跑等）暂不设独立权重」）→ **条件一旦配置化，价值 / 档位口径要一并回填**。
- **需求（按 2026-05 讨论案的四层，最小可用优先）**：① **条件层** —— `生命值 ≤ 阈值` / `生命百分比 ≤ 阈值` / `首次进入某血线（一次性）` / `第 N 回合或批次起` / `命中次数 ≥ N` / `自身或目标存在某状态`；② **选择策略** —— 优先级 / 权重随机 / **命中排他条件的意图时只在排他集合里选 1 条**；③ **次数限制**（与条件分开）—— 作用域 `单实例` / `同模板本场共享` / `全场共享`，计数键建议 `MonsterId + IntentId`（或允许自定义共享键，为将来的 Boss 机制池留口）；④ **载体** —— `EnemyIntent.csv` 追加条件 / 限制列（或 `Monster.csv` 意图段扩第 4 段），**缺列 = 现状行为不变**；⑤ **规则层 `BattleRule` 保留**（关卡级特例走规则），条件意图走表 —— 避免把 `BanditEscalation` 式的硬编码继续复制（**P2-24 就是下一个特例**）。
- **为什么现在要提**：`P2-24 AllyLossEnrage` 本质是「条件 = 同伴退场」的一条特例规则；F1-009 的「主讲退场 → 学徒溃散」（本轮已裁定**现在不做**）、第二层 / 精英 / Boss 的「血线技 / 狂暴 / 一次性大招」都属同一能力。**再打两个特例规则，不如先把条件层做出来。**
- **涉及**：`Scripts/Battlefield/Core/BattleRule.cs`（枚举 / 注册 / 条件求值入口）、`Scripts/Battlefield/Core/EnemyIntentPlanner.cs`（表解析 + 候选过滤）、`Scripts/Battlefield/Runtime/BattlefieldSession.cs`（填 context：自身 HP / 状态 / 存活与退场集合 / 共享计数池）、`DataBase/Battlefield/EnemyIntent.csv`（条件与限制列）、`README/功能说明文档/数据系统/数据配置/怪物.md`（写法文档）。
- **验收**：① 一条「HP ≤ 50% 且只能放 1 次」的血线意图**纯配置**可实现（放完不再出现）；② 「同模板本场共享 2 次」可配置（场上 2 只共用一个计数池）；③ 不含条件 / 限制列的旧行行为**逐字节一致**（复跑 `--battlefield-smoke`，含 `BATTLEFIELD_MONSTER_STATE_TARGET_PASS`）；④ 读档重进后条件与已用次数一致；⑤ 条件意图的取值口径回填[单位数值平衡标准](../../../../玩法说明文档/系统规则/数值平衡/单位数值平衡标准.md) §六。
