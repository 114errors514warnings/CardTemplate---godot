## §2 执行设计

### 2.1 模块划分

拟新增 `Scripts/Battlefield/`，其中 `Core/` 保存无 Godot 依赖的逻辑，`Runtime/` 桥接现有单位和效果，`Presentation/` 保存场景视图。独立类按职责拆分，避免继续扩大 `BattleSytem`。

| 模块 | 职责 |
|------|------|
| `BattleBoard`、`BattleCell` | 坐标集合、格点数据、版本号与查询 |
| `BattleDeploymentService` | 校验场地、玩家部署和随机怪物部署 |
| `BattleOccupancyService` | 单位注册、占格、逐步位置提交、移出战场 |
| `GroundObjectPlacementService` | 同格物品堆、排他触发物件、最近合法接收格安置、陷阱投放校验 |
| `BattlePathfinder`、`BattleMovementService` | 可达区域、路径、移动资源结算与中断 |
| `BattleRangeResolver` | 射程、区域形状、方向、阵营和遮挡规则 |
| `BattleAttackTraceResolver`、`ForcedMovementResolver` | 远程/突进拦截、穿透/爆炸、连锁击退与回弹事件 |
| `BattleActionCoordinator` | 输入行动提交、执行顺序、事件与终局检查 |
| `BattleCellEffectService` | 永久改变、地形状态、机关与陷阱触发 |
| `BattleEquipmentService`、`BattleItemService` | 装备实例、选手、临时道具转移与使用 |
| `BattleObjectiveEvaluator`、`BattleRewardCalculator` | 目标结果、击败台账、奖励份额 |
| `BattlefieldView`、`BattleHud` | 地图、单位、提示与手牌装备 UI |

表现层新增 `BattlePresentationConfig`（玩家/怪物移动速度、轨迹延伸速度、轨迹追终点速度、投掷抛物线速度）与 `BattlePresentationQueue`。怪物意图按稳定队列逐个执行：前一怪物的移动、攻击轨迹、命中闪烁、伤害跳字与状态占位图标全部完成后，才允许下一怪物开始。默认攻击表现由 `WeaponAttackMode` 映射，卡牌空间模板只决定受影响格；特殊卡可保留显式覆盖接口。

预览和实际结算共用查询服务；UI 不自行计算第二套距离、可达区域或伤害目标。

### 2.2 坐标、密铺与鼠标拾取

1. 复用 `AxialHex(Q,R)`，隐式第三轴 `S=-Q-R`。六邻格偏移为 `(1,0)、(1,-1)、(0,-1)、(-1,0)、(-1,1)、(0,1)`。
2. 距离 `max(|dq|, |dr|, |dq+dr|)`；距离与寻路步数分开，绕行不会擅自改变射程。
3. 拟采用尖顶密铺六边形，外接圆半径 R：`x=√3R(q+r/2)`，`y=3Rr/2`。相邻中心距为 `√3R`，没有冒险图格间连接线。美术朝向变化只调整布局转换。
4. 逆变换：`q=(√3x/3-y/3)/R`，`r=2y/(3R)`；转换到立方坐标并四舍五入，再修正误差最大的轴保持三轴和为零。
5. 屏幕位置先逆变换到战场局部空间，再拾取格坐标；地图平移不能改变单位坐标或点击命中。格边界采用稳定的取整顺序。
6. 先判断是否命中 HUD；战场只处理视口内且存在于地图字典中的格。地图外坐标返回无目标。
7. 战场 R 固定，不根据窗口大小重新 FitRadius，不开放缩放和旋转。窗口变化调整可视区域及 HUD，镜头平移范围按战场包围盒约束。

### 2.3 地图定义与初始化

拟使用 JSON 描述二维地图与嵌套配置，CSV 继续保存单位、卡牌等扁平定义。地图字段：`MapId、Version、CellRadius、Shape、Dimensions、SeedPolicy、DefaultCellDefinitionId、CellOverrides、PlayerSpawnCoords、EnemySpawnRegions、ObjectPlacements、ObjectiveId、WavePlanId`。

- `Shape` 适配器产生坐标集合；支持显式坐标列表，地图形状与尺寸最终值不写死。先用测试地图验证，不把测试半径当正式关卡数值。
- 先读取 JSON 基础地形（边界、坐标、固定地形和生成禁区），再随机布置障碍物与道具；机关和陷阱通过物件配置放置，不写入格点 Kind。每场克隆运行时数据，不能修改共享配置模板。
- 随机规则拟包含候选区域、物件/障碍定义池、权重、数量区间、间距及连通性限制。先保留玩家出生三格，再生成障碍并计算通行连通分量，最后布置物件与单位；不允许以随机内容覆盖出生保留区。
- 允许生成封闭区域，采用 BFS 标记静态可通行格的连通分量，不依赖当前单位占格来判断地形连通。拟将与地图外侧边界相连、且包含玩家出生三格的分量作为单位出生区域；玩家三格所在分量若被障碍完全封闭则重试或报告错误。其他孤立分量保留地形，但不生成任何单位。
- 玩家、怪物、保护目标及增援都复用该出生筛选。运行中地形改变后，增援出生前重算相关连通性；单位暂时堵路不导致其后方区域被误判为地形封闭区。特殊地图封闭外墙需显式指定开放区域/出口锚点后使用，不能把全封闭出生区默认为合法。
- 机关仅初始化时布置，陷阱可初始化及行动投放。开局道具排除机关/陷阱，可加入已有道具或装备的物品堆；陷阱/机关生成要求空堆及无其他触发物件。
- 障碍生成产生格点障碍覆盖并引用障碍定义；可破坏性和表现标识属于障碍定义。机关和陷阱使用同一触发物件结构，类型只区分内容与效果。
- 不满足约束时有限次重试，失败返回具体配置错误；不无限重抽，不静默减少必须生成的数量。数量、权重、最小间距和应保留哪些通道仍待内容定案。
- 外观变体、装饰和表现资源随机选择仅记录为后续阶段，本期不实现。未来使用独立外观随机流，不能影响逻辑布局或占格。
- 先验证地图坐标唯一、引用有效、玩家三格存在且两两相邻、可通行且无冲突，再初始化运行时单位。
- 玩家槽位固定映射 `(0,0)、(1,0)、(0,1)`；视图以三格重心作为初始镜头中心。坐标基点可由地图定义整体平移。
- 怪物候选格先排除占用、不可通行和部署禁区，再按本场部署随机流打乱并不放回取样。安全距离作为待定配置，不从其他规则推断。
- 校验可用部署格数量与出生可达性。空间不足时报告地图 ID、缺少数量、限制条件，禁止重叠出生或无限重抽。
- 波次生成复用部署服务，处理已占用出生格的策略待定；至少返回明确的“没有合法出生格”结果。
- 地图、部署、意图和奖励使用独立随机流；种子与布局版本持久化，避免奖励抽样改变部署结果。

### 2.4 格点完整数据结构

| 数据层 | 拟字段 | 设置与用途 |
|--------|--------|------------|
| 基础定义 | `DefinitionId、Kind、BaseWalkable、BaseBlocksSight、BaseMovementCost、VisualKey` | Kind 仅普通/障碍；机关与陷阱不作为格点类型；通行、遮挡、移动成本分别配置 |
| 坐标实例 | `Coord、DefinitionId、Revision` | 每个现存格唯一，字典按 Coord 查找 |
| 永久改变 | `SurfaceOverride、ObstacleDestroyed、WalkableOverride、VisualOverride` | 摧毁障碍或形成坑洞；本场不自动到期，不默认跨战斗保留 |
| 地形状态 | `InstanceId、DefinitionId、SourceUnitId、Stacks、TriggerTiming、LifetimePolicy、RemainingTriggers、AppliedSequence` | 独立于单位状态；持续和叠加策略另行配置 |
| 格上物品堆 | `GroundItemInstanceIds` | 道具/装备实例列表，可多件混放；保持实例身份和稳定顺序 |
| 格上触发物件引用 | `TriggerObjectInstanceId?` | 陷阱或机关最多一件；非空时物品堆必须为空；可与单位共存 |
| 触发物件实例 | `InstanceId、DefinitionId、Coord、TriggerMode、Consumed、LastEntryEventId` | 陷阱与机关共用；TriggerMode 为 Once 或 EveryEntry，无默认冷却 |
| 占格信息 | 通过 Occupancy 查询 | 格点不保存另一份可自由写入的 UnitId |
| UI 标记 | 视图侧 `Selected、Reachable、PreviewAffected` | 不写入地图规则数据或存档 |

有效属性查询顺序：基础定义 → 永久改变 → 当前有效地形状态 → 占格限制。叠加优先级由属性策略明确指定；实现支持优先级及稳定排序，内容未定前不采用“最后写入碰巧胜出”。

坑洞表示现存格上的不可通行表面，地图外表示坐标不存在。单位脚下形成坑洞时先查询 `IFallPolicy`，默认立即坠落死亡，记录 `DeathCause=Fall、SuppressWorldDrops=true、KillKind=Mechanism`。非爪牙按已有价值计通关贡献；掉落抑制与计奖独立，不触发淬炼攻击斩杀。飞鸟等免坠落仅预留能力接口。死亡回调链不能绕过无掉落标记，也不能以普通伤害抵扣护盾模拟即死。

所有改变通过命令提交，增加格/地图版本并发布 `CellChanged`；寻路与范围缓存随相关版本失效。只重画受影响格及边界，避免每次悬停重建整张地图。

### 2.5 给单位定位与维护占格

- 每场创建 `BattleUnitPlacement`：`UnitId、Coord、Faction、Role、Presence`。Role 区分角色、怪物、保护目标；爪牙为目标属性。默认攻击模板固定邻接单格，额外空间能力由武器/卡牌提供，不在 Placement 增加成长型基础射程。
- 单位 ID 连接现有 `IUnitInstance`，生命、护盾、状态继续从原实例读取。逻辑坐标唯一存放在 Placement，视图只订阅位置变化。
- `UnitId → Placement` 与 `Coord → UnitId` 两个索引由同一占格服务维护。只开放 `TryPlace、TryMoveStep、RemoveFromBoard、TryGetUnitAt`，调用方不得直接写索引。
- 一次移动在同一提交中释放原格、更新 Placement、占用目标格；失败时两个索引都保持原值。
- Presence 区分在场、被击败、已离场；移出后保留台账和永久卡组写回所需实例，不能把所有退出都当死亡。
- 死亡立即释放单位占位，再处理死亡后效果与允许的掉落，不等待死亡动画结束。死后形成阻挡障碍通过独立后处理接口预留，当前不实施；普通死亡释放单位层不删除原格物件。坠落死亡抑制掉落。
- 单位与物件分开查询：`Occupants[Coord]` 最多一个单位；格点物件内容为道具装备列表或单个陷阱/机关，两者互斥。单位可与其中任一种共存。位移需先腾出目标格，不允许中间帧逻辑叠放。
- 原 `posx/posy` 在调用审计前保留；如果仍用于动画，只作为表现值，禁止作为路径或攻击判定依据。

定位示例：`Placements[UnitId].Coord = (2,-1)` 表示该单位位于轴向坐标 `(2,-1)` 的格点；`Occupants[(2,-1)] = UnitId` 用于反查格上单位。跨场识别时使用 `(BattleInstanceId,Q,R)`，无需另设与坐标竞争的格点编号。单位姓名、数组顺序和小人像素位置均不承担定位职责。

从 `(2,-1)` 移动到 `(3,-1)` 时占格服务校验目的格，再统一提交位置与两个索引；小人根据坐标转换结果播放移动。动画途中不逐帧反推单位属于哪格，逻辑归属以已经提交的移动步骤为准。选中边框是该坐标的表现标记，不是位置数据。

### 2.6 路径、移动能量与次数

1. 相同格成本时使用 BFS 求可达范围；配置不同成本时使用 Dijkstra；指定目的地可用 A*，启发式为六边形距离乘最小步成本。
2. 阻挡查询包含边界、障碍、坑洞、地形状态和任何其他单位。起点自身占用可忽略，目标其他单位不可忽略。
3. 可达范围返回每格最小成本、路径和不可达原因。相同代价路径使用固定邻格顺序，保证复现。
4. 人物配置新增 `MovesPerTurn`，运行时保存 `MovesUsedThisTurn`。移动动作的基础移动距离为 1 格；基础距离下，单次移动动作固定 `EnergyCost=1、MovesConsumed=1`。玩家可一次提交包含多次移动动作的路径。后续装备或状态可提高单次移动动作距离，因此费用与次数按移动动作计，不能永久按移动格数计。有效额度由人物与装备计算，装备变更立即刷新；剩余 `max(0, EffectiveMovesPerTurn - MovesUsedThisTurn)`。回合开始重置已用次数，换装不重置。
5. 提交前校验整条路径可由当前移动动作距离规则分段，每个经过格地形可进入且无其他单位，并校验总能量与总剩余次数。通过后按移动动作串行结算；非法路径无副作用。路径预览显示经过格、动作分段、总费用和每格风险。
6. 拟事件顺序：离开原格 → 原子位置提交 → 到达新格 → 处理该格触发 → 处理死亡 → 继续下一步。每一步进入都产生唯一 EntryEventId；普通移动、击退、拉拽、传送均走统一进入事件。逐格位移触发途经格，传送仅触发实际落点。
7. 自身回合内串行执行单格移动，无机会攻击或敌方插入；动画期间锁定战场修改命令。进入后结算陷阱/机关和死亡；已完成的一格不因其后触发效果而退款。玩家没有待执行的多步路径，不建立普通移动打断/退款机制。
8. 动画等待与逻辑提交由行动协调器串行驱动；暂停期间逻辑计时、怪物行动和动画均暂停。场景退出取消待执行任务。

### 2.7 永久改变、地形状态与格上触发

- `CellEffectDefinition` 配置目标格集合、触发时机、敌我过滤、优先级、重复规则、状态叠加和调用的 Effect；不直接重写单位状态系统。
- 环境效果桥接需保留环境来源及可选施加者 ID。灼烧地形的伤害类型沿用已有伤害语义，是否吃攻击力、能否触发反击由该效果定义，不虚构一个角色作为来源。
- 地形状态按显式战斗事件递减；“角色回合结束”与“全局一轮结束”分别定义，避免三角色每人调用一次导致衰减三次。
- 同一次触发先取稳定排序快照，再执行并收集增删，最后提交；避免遍历途中增删导致漏触发。新附加状态是否本事件立即触发需明确配置。
- 已有单位状态的先效果后衰减顺序保持；新增地形触发与弃牌、单位状态、胜负检查的相对顺序在规则表确定后统一挂接。
- 陷阱与机关共用进入触发规则：Once 首次有效触发后销毁并释放物件位，EveryEntry 每次进入都触发且保留；离开再返回属于新事件。一次性效果执行前标记已消费并释放物件位，效果使用来源快照防止重入；同一 EntryEventId 去重。普通、强制位移、传送均触发，持续站立不产生新事件。永久改变不参加状态衰减。
- 陷阱投放范围以自身一圈为默认值，引用装备/增益修正接口；目标必须无单位且无任何物件（也不能有另一陷阱）。机关定义标记 `CreationPhase=BattleInitialization`，运行时生成命令直接拒绝新增机关。
- 每次记录事件号、来源格、单位、效果、前后值，方便验证移动途中触发顺序及去重。

### 2.8 空间范围与现有战斗管线

`BattleActionContext` 拟包含来源 ID、卡实例 ID、选定手位/装备 ID、源坐标、目标单位/格、方向、范围定义、地图版本和行动号。

每个效果段引用自己的空间定义，支持自身、手牌、单敌、单友、邻友、邻敌、扇扫、索敌。卡牌范围计算只输入所选武器攻击距离（无武器为 1）与卡牌模板参数，不输入武器自身攻击范围形状。具体距离到范围尺寸映射仍待逐卡定案。

扇形空间模板按轴向坐标计算：选定前方方向后，取左右两条相邻 120 度边界向量 `L`、`R`，攻击者坐标为 `O`、范围为 `n`，解析出 `O + a × L + b × R`（`a,b ∈ 0..n`）的全部格，排除 `a=b=0` 的自身格。预览、鼠标红色高亮和结算必须调用同一个 `ResolveFanCells`，不可分别用“目标周围一圈”或固定三格代替。例：`O=(0,0)`，正向 `(1,0)`，范围 2 时为 `(0,1),(0,2),(1,1),(1,0),(2,0),(2,-1),(2,-2),(1,-1)`。

目标处理顺序：射程与方向 → 有序路径 → 拦截/穿透 → 实际命中 → 爆炸/击退扩展 → 按原公式执行效果。友方会阻挡己方路径攻击并承受完整攻击效果；敌方会阻挡敌方路径攻击并承受完整攻击效果。不能先按阵营过滤路径上的单位，再追踪弹道。普通非路径范围仍按模板筛选。预览与结算共用解析器。

- 审计 `Card.cs`、`BattleSytem.cs`、`BattleUnitRegistry`、怪物意图、状态牌管线、反击与代打的所有目标入口，统一委托，避免仅拖牌入口限制距离。
- 多效果卡不能用一次全局目标集合过滤所有段；例如攻守兼备的敌方攻击受射程约束，自身防御不因敌人离场被错误筛掉。
- 多段效果中的目标死亡/移动、是否重新选目标由效果策略确定。费用只在提交点扣一次，卡牌生命周期与永久升级沿用。
- 反击、旋风斩、蓄势待发代打、城墙和到我身后均复核空间条件；保留施加者和来源卡标识，不能删除检查来换取通过。
- 无武器、双防具、双手防具均可攻击；无可用武器时默认距离 1，不强制选手。卡牌引用武器距离而非武器范围。新增穿透、爆炸词条和免疫强制位移特性，均为待实施设计；词条来源、叠加和生命周期需随定义明确。

#### 2.8.0 武器默认攻击规格

`WeaponAttackSpec` 增加 `AttackRange、DefaultAttackMode、HandsRequired、DefenseValue、ProjectileBlockRule、TargetCellRule`。普通攻击读取该规格；卡牌只读取所选武器的攻击距离。

| 武器 | 规格实现 |
|------|----------|
| 长刀 | 单手，攻击距离 2，近战单体攻击，含防御值。|
| 长枪 | 双手，攻击距离 3，近战直线或扇形模式；两模式都需选择方向，含防御值。|
| 魔典 | 双手，攻击距离 4，远程投掷单体；直接选定落点，中间单位与障碍均不阻挡，防御值为 0。|
| 弓 | 双手，攻击距离 5，远程直线；路径首个单位或障碍唯一命中，防御值为 0。|

防御技能牌结算时通过 `DefenseValueProvider` 汇总当前近战武器防御值；魔典、弓不贡献该值。双手武器实例只计一次，不能因占用左右手被重复叠加。

普通攻击默认不消耗资源。武器规格或战斗牌只有显式携带成本字段时才扣除相应资源；战斗牌必须选择实际使用的武器并套用其效果，无武器时允许打出但走最低效果分支。

#### 2.8.1 拦截、穿透与爆炸

- `AttackTrace` 返回经过格、首个阻挡、实际命中、剩余距离，并保留阻挡者阵营。远程直线止于首个单位或障碍；近战直线逐格攻击，直到障碍或本次攻击后护盾仍未击破的敌人；突刺只处理首次接触对象。友方与敌方均可成为阻挡者并承受完整攻击效果。穿透则不因单位/障碍停止攻击追踪。
- 爆炸中心取实际命中处；范围与伤害用独立定义，不默认等于武器范围或固定一圈。穿透是否每个途经单位均命中、每个命中是否爆炸仍待定；保留命中序号以支持最终策略。
- 突进本体运动、攻击传播、强制击退分开处理：攻击穿透不能自动创建穿墙站立、叠放单位或免疫位移失效。穿透本体的通过与落点规则未定前标记阻塞，不默认为取消穿透。

#### 2.8.2 连锁击退与回弹

`ForcedMovementContext` 保存原攻击者、当前受推单位、当前推动者、方向、请求格数、来源伤害、阶段、事件号与已访问碰撞。新增 `ImmuneToForcedMovement` 特性查询；障碍返回不可推动。

1. 从目标格沿推动方向检查：空格可移；可推动单位则先解析更远端，再逐个腾空并移动；免疫单位/障碍进入回弹分支。任何提交均不得两个单位同格。
2. A 攻击 B，B 撞 C：C 可推动时，B 推 C，C 承受 B 所受伤害的一半；继续链按相同规则传播。伤害基数是护盾前还是实际扣血、奇数取整仍需定案，保留各阶段伤害快照，不现在写死。
3. C 免疫或为障碍时，B 反向回弹一格；占用前一格的此前推动者需被向后推出以腾位。B 接受配置的碰撞弱化/额外伤害；原攻击者 A 不接受本次碰撞反向伤害或弱化，原攻击者 ID 在整条链不变。
4. 不能把回弹简化成“B 留在原地、只受伤”而漏掉反向推人；也不能强推免疫单位。后方再次被堵或原攻击者自身免疫的冲突列待决策，返回明确解析状态。
5. 每次实际入格都走现有陷阱/机关/坠落逻辑；死亡立即释放格并刷新后续计划。原攻击者后移进入有害格与“无任何负面影响”的优先级未定，不静默免除全部环境效果。
6. 同一碰撞计划保留方向和已访问关系，防止左右回弹无限递归。无法完成的计划不能提交一半后强行叠放；正常死亡/环境事件不回滚，以实时状态重新评估。
7. UI 同步显示推进链、回弹箭头和各目标预期惩罚。所有边界定案后才能把组合机制标为实测完成。

### 2.9 怪物规划、增援与离场

- 意图定义增加空间模板、移动前后顺序、索敌策略、最大移动预算和失去目标策略 ID。
- 规划结果保存目标、路线、预计落点、攻击区域；执行前复核占格和目标。展示预计信息不意味着固定命中。
- 意图第一阶段仅展示攻击数值和攻击类型，不在己方回合中锁定具体目标、路径或最终命中格。己方回合结束后按该意图的 CSV 索敌优先级即时规划。
- 索敌在意图可用移动次数内评估能否合法命中保护目标；若能命中，保护目标高于全部默认策略。不能命中保护目标时，突刺选择最近且同线、可接触的目标；投掷范围依次比较可命中单位数、范围内最低生命、攻击者到落点距离；投掷单体依次比较目标生命、攻击者到目标距离。其他攻击方式必须显式配置 `TargetPolicy`。
- 仅当上述全部比较项完全并列时，才用本场意图随机流随机选取；无合法目标时执行意图的等待、改路或离场策略，不可沿用上回合目标。
- 先攻击后移动：执行前按索敌结果复核目标必须在自身合法攻击范围内；不满足时按该意图的无目标策略处理。
- 先移动后攻击：逐步移动，抵达后重新索敌与复核；改路或放弃行为由意图配置决定。
- 多怪物串行执行，各自依据实时占格复核；不能让两只怪物落在同格。
- 波次由全局回合事件触发一次；记录已生成和待生成，不以场上暂时为空提前结束生存关卡。
- 按怪物特性记录失联回合和离场过程。离场通过专用事件登记，不走击杀与死亡奖励回调。
- 保护目标需可被敌方索敌，但不能作为玩家手牌角色；是否移动、是否行动另行配置。保护目标优先不允许绕过障碍、单位阻挡、攻击距离或意图移动次数。

### 2.10 装备与临时道具

装备定义包含类型、占用手数、允许部位、属性和被动效果引用；装备实例拥有独立 ID。左右手占用同一双手实例 ID，属性只计算一次。头盔、护甲、鞋单独保存，饰品列表容量来自配置，当前为 3。

- 换装免费，先从当前格物品堆取出指定实例，再把卸下的一件或两件装备加入同格堆；堆内已有物件不迫使卸装换格。目标格有触发物件时才寻找最近合法接收格；全部校验后一次性提交，不丢失任何实例。移动额度立即刷新但已用次数不重置。
- 手位防具与护甲部位区分。临时状态与装备属性分别维护来源，卸下装备不能清除其他来源的增益。
- 行动记录实际使用装备和手位，交替判定可据此实现；增益量、重置时点未定前不激活虚构增益。
- 物件位置用互斥类型表示：`Ground(coord)、Carried(unitId,slotIndex)、Equipped(unitId,slots)、Consumed`。每个实例只在一个位置；双手装备是一件实例占用两个手位，不可变成两个掉落。
- 当前格槽是查询结果，不建立第四个库存；离开清显示不移除地上物件。
- 直接使用：确认合法目标和成本后消费地上实例；拾取：确认随身空槽后原子转移；拖动取消不修改归属。
- 格点保存道具装备列表与可空触发物件 ID，强制不变量为“触发物件存在则列表为空”。同格道具装备不限于一件，各自有唯一实例 ID；重复物品也不自动合并实例。随身仍为三个槽。
- 地上武器/防具与道具共用当前格入口，拾取必须放入手位；默认禁止进入随身道具槽。`IInventorySlotPermission` 预留装备赋予“允许武器进入道具栏”的能力，不默认开启，也不借该接口取消物件层互斥。
- 战斗结束清理临时道具；战斗外材料、永久道具和装备不得被误清除。

#### 2.10.1 同格物品堆与最近接收格

1. 所有放置调用统一 `GroundObjectPlacementService`，命令注明来源：InitialSpawn、Discard、Throw、DeathDrop、Unequip、TrapPlacement。
2. 初始道具、丢弃、扔出、掉落、卸装备共用 CanReceivePile：合法地面且没有触发物件。允许已有单位与已有道具装备；不沿用无单位/空堆的筛选。
3. 目标可接收则直接加入物品堆；有陷阱/机关时按距离逐环找最近可接收格，同距离随机。候选允许已有物品堆，不需寻找完全空格。
4. 同距离候选按坐标稳定排序，再使用独立的物件落点随机流取一格，保存随机状态或落点结果。最近采用格距，不擅自改为单位寻路距离；障碍/坑洞是否为可接收地面、跨墙散落是否允许仍待定。
5. 搜索上限为地图现存坐标的最大距离，保证有限终止。无合法位置返回 NoLandingCell；玩家换装/丢弃等尚未提交的事务保持原状。已发生的怪物死亡不能回滚，掉落无处安置的最终保留/销毁策略待定。
6. 多个掉落可同格追加，稳定顺序与事件去重保证不会重复追加同一实例；不能用字典赋值覆盖原物品堆。并发陷阱投放与物品追加必须原子校验互斥。
7. 陷阱投放使用独立合法性检查：范围内、地形合法、无单位、无任何物件；失败不自动散落到附近格。不得给机关开放战斗中投放入口。
8. 坠落死亡禁止 DeathDrop，仍登记机制杀与通关价值；不调用淬炼斩杀升级。统计登记与掉落生成分开。

### 2.11 关卡目标、终局顺序与奖励

新增显式 `BattleOutcome`：进行中、胜利、本关失败、整局失败；包含原因、目标进度和奖励资格。`RunBattleScene` 接收结果事件，不再从 Players/Monsters 是否被清空猜测胜负。

- 歼灭：全部必杀非爪牙均被击败或离场时判胜，最后一名非爪牙离场也可以胜利；离场只影响奖惩比例，不冒充击败。
- 生存：在第 N 回合完成后检查存活条件并全额获奖，不在第 N 回合开始结束。提前胜利必须无在场敌人（含爪牙）、无未来增援。
- 保护：目标死亡触发本关失败，不清整局；保存后续负面结果标记，具体村庄/事件效果待定。与全队死亡同时发生时终局优先级待确认。
- 事件边界统一评估目标；多目标攻击不能因首个目标死亡立刻清理集合而截断剩余效果。动作结束及回合事件结束执行最终清理，必要时先标终局阻止后续行动。
- 击败台账保存敌人实例 ID、是否爪牙、出生来源、冻结价值、被击败/离场状态、死亡原因、击杀类别与掉落资格。坠落登记机制杀，非爪牙计通关价值且无掉落，不触发淬炼；每实例只统计一次。
- 非生存比例为已击败非爪牙价值/本场计奖非爪牙总价值；离场仍在分母。价值采用单位平衡案哪一种口径需明确，不能混用 HP 与回合产出；零分母需显式策略。
- 生存胜利跳过比例减奖，直接全额。其他关卡以可配置阈值决定失去 0/1/2 份卡牌奖励，示例 70%/50% 不作为正式平衡结论。
- 每个玩家槽位生成一份卡牌奖励，重复角色也按槽位区分。随机取消不同槽位奖励，候选、归属、减奖结果与领取状态一起持久化。
- 本关失败不领取通关奖励；保护失败标记进入后续事件数据，实际负面内容未定时不得宣称惩罚功能完成。

### 2.12 场景、输入与界面

拟新增 `Scenes/Battle/HexBattleScene.tscn`；地图在固定裁剪区域中平移，HUD 固定在 CanvasLayer。内部顺序为地表、地形改变、物件、单位、范围覆盖、特效；单位脚下状态图标随单位移动，tooltip 避让屏幕边缘。

- 可复用现有卡牌 prefab；单位改用地图小人视图，保留生命、护盾、意图、状态信息绑定。不同高度立绘锚点统一到格中心脚底。
- 双手装备等尺寸上下对齐；当前格道具位于三随身槽上方；三角色 Tab 位于手牌上方；手牌右侧结束回合/移动按钮上下排列。
- 普通左键：点玩家切角色，其他单位只悬停。选目标中合法单位点击提交目标；非法点击显示原因，不偷换行动来源。
- 需要切人时先取消尚未提交的行动，再刷新手牌、装备、道具和范围；已提交的不可逆多步效果不允许通过切人取消。
- 右键按住移动只平移；释放不取消。`Esc` 取消最内层预览；无预览时再进入暂停。地图拖动状态是输入修饰状态，不能清空行动上下文。
- 左键仅点击的限制针对地图平移；卡牌、道具和装备均允许拖动。拖动命中手位、随身位或战场时，按相应命令验证，不各写一套结算。
- Tooltip 读取当前悬停对象，鼠标离开关闭；HUD 不向地图透传点击。隐藏单位或释放场景后立即清理悬停引用。
- 场景退出解除事件、取消延时任务；暂停时怪物计时使用可暂停定时器。地图预览与表现动画不改规则状态。

### 2.13 配置、存档与迁移

`DataBase/Battlefield/` 存放地图定义 JSON、格点定义 CSV、地形状态 CSV、物件 CSV、空间模板 JSON、关卡目标/波次 JSON；武器定义实际位于 `DataBase/Equipment/Weapon.csv`，并登记为 `Data.Equipment.Weapon`。其字段为 `WeaponId、DefinitionId、HandsRequired、AttackMode、AttackRange、DefenseValue、DamageBonus、MoveBonus、ResourceCost`；`AttackMode` 必须是 `WeaponAttackMode` 枚举名称。路径登记到 FilePathRegistry；结构化字段按命名字段解析，避免继续扩大位置型整数参数。

- 卡牌效果段引用空间模板 ID；人物定义新增每回合允许移动次数及装备修正入口，默认攻击固定邻接单目标；单位空间特性只预留免坠落等能力接口。怪物意图绑定有序移动/效果段及对应攻击空间定义。解析器、字段文档、CSV 同步变更。
- 加载时校验不存在引用、坐标重复、负成本、范围方向、双手占槽、目标配置、增援合法性；生产关卡缺少关键策略时给出具体错误，禁止自动当全屏攻击。
- 旧调试场景通过显式 Legacy 模式保持原行为；新场景要求空间配置。正式切换前逐卡验收，不静默让缺字段的新卡无限射程。
- 51 张是设计映射范围；法师和精灵尚未实现的非空间机制单列依赖，不因存在设计表就标已移植完成。
- 沿用当前“战斗中继续=战前重新开局”的保存语义。战前存初始地图/布局版本、部署种子或部署快照、角色槽映射、装备、遭遇、目标和波次定义版本。
- 重开应恢复相同初始地图和部署，清除上一尝试的临时道具/地形变化。仅靠随机种子不足以跨配置版本复现，版本不匹配应走明确迁移或提示。
- 如果未来要求战斗中原地恢复，另增快照：格点改变/状态、物件位置、占格、单位状态、牌堆、波次、意图、随机流状态和行动边界。当前不把完整中途续战当已授权需求。
- 结算先写回角色生命、永久卡组、装备及目标结果，再保存奖励快照；重复打开结算不得重复领取。旧存档缺新增字段时按版本迁移，不自行给玩家发装备。

### 2.14 实施批次与完成标准

| 顺序 | 执行内容 | 完成标准 |
|------|----------|----------|
| 1 | 坐标/格点/密铺布局/配置加载/部署/占格 | 三角色三角部署；地图拾取准确；任意单位不能重叠；配置错误明确返回 |
| 2 | 固定镜头、单位视图、角色切换、HUD | 图与文档布局一致；仅右键拖图；状态悬停；窗口变化不改变格大小 |
| 3 | 路径与移动能量/次数接入 | 预览执行一致；不可达不扣费；逐格触发；单位死亡不继续移动；具体成本定案后验收 |
| 4 | 空间模板、卡牌上下文、效果桥接 | 单敌/邻友/扇扫等正确过滤；原伤害和状态结果回归通过 |
| 5 | 装备实例与选手、怪物移动意图 | 保留所有装备部位；双手只计一次；敌我攻击均受范围限制 |
| 6 | 道具、装备落地、机关陷阱、格点改变和状态 | 两层占位一致；最近空格安置；陷阱投放严格校验；坠落无掉落；无重复消费 |
| 7 | 特殊目标、增援、离场、逐角色奖励 | 三类目标及爪牙组合正确；本关失败不误删整局；奖励可续领不重复 |
| 8 | 逐卡迁移、存档、数值验证与正式接线 | 已实现卡全部空间适配；未实现设计卡单列；回归入口保留；未决项不冒充完成 |

各批次按依赖推进；先完成歼灭闭环是开发顺序，不取消生存、保护和离场范围。

| 占格路径 | 单位独占、物品堆与单触发物件互斥；单步 1 能量/1 次；额度换装立即改变但已用次数不重置；死亡立即释放格 |
| 范围 | 各方向环扇线；敌我过滤；边界裁切；射程和区域分开；无目标不全屏回退 |
