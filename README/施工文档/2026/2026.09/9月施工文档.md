## §25 窃取金币机制接入（2026-09-22）

### 25.1 规则（本轮落地）

1. 怪物**每次攻击命中玩家**时，按其 `StateType.Steal` 层数偷取等额金币；
2. **金币不足则一分不扣**（不做部分扣除，也不会扣成负数）；
3. 偷走的金额**按怪物实例分开记账**：每只怪物各一条 `StolenGoldEntry{InstanceId, MonsterId, Amount}`，存在 `RunSaveData.StolenGoldFromMonsters`（`List<StolenGoldEntry>`）里，战斗内实时落盘；`InstanceId` 取关卡 CSV 的对象实例 ID（如 `F1-006-M01`），**同一 `MonsterId` 的多只互不合并**；
4. **胜利结算**按"该**实例**是否被击杀"返还：被击杀实例原额返还（结算面板显示"追回被窃金币 +N"，已直接入账）；未被击杀的实例（存活/离场）其名下金币不返还，结算后清账；
5. 击杀奖励（掉落表金币/材料/卡牌）规则不变。

### 25.2 实现位置

- 新增 `Scripts/Run/RunGoldLedger.cs`（纯逻辑）：`Steal(run, instanceId, monsterId, amount)`（不足不扣 + 按实例记账）、`RefundDefeated(run, defeatedInstanceIds)`（只返还被击杀实例并删除该条）、`Find`、`Clear`、`TotalStolen`。
- `RunSaveData`：新增 `List<StolenGoldEntry> StolenGoldFromMonsters` + 记录类型 `StolenGoldEntry`（进存档，跨场景/读档可用）。
- 实例键来源链：关卡 CSV `InstanceId` → `BattleLevelCatalog.ApplyMonstersTo` 填 `BattleMapDefinition.MonsterInstanceIds`（与 `MonsterIds` 一一对应；缺失时退回 `<关卡Id>#<序号>`）→ `BattlefieldSession` 建 `unitId → 实例键` 映射并在建怪时登记，对外暴露 `GetMonsterInstanceKey(unitId)`（非关卡路径退回 `unit-<UniqueInGameId>`，同一场战斗内唯一）。
- `BattlefieldSession` 新增事件 **`MonsterHitPlayer(attacker, victim)`**：怪物攻击命中玩家时每次攻击只触发一次（战斗层不认识金币）；`ExecuteEnemyIntentionEffect` 的 Damage 分支在伤害结算后触发。
- `HexBattleScene.OnMonsterHitPlayer`：读 `StateType.Steal` 层数 + `GetMonsterInstanceKey(attacker.UnitId)` → `RunGoldLedger.Steal` → 有实际扣款才落盘，并把结果写进战斗消息（"窃取了 N 金币（剩余 M）；击杀它可在结算时追回" / "金币不足，未被扣"）。
- `RunBattleScene`：`ShowVictoryResult` 里在写回角色后调用 `RefundStolenGold`（遍历战场取 `BattlefieldPresence.Defeated` 的怪物 → `GetMonsterInstanceKey` 收集实例键 → 返还 + 清账）；结算面板加一行"追回被窃金币 +N"。

### 25.3 验证

### 25.5 待定 / 取舍

- 实例键用关卡对象的 `InstanceId`（配表规范要求**本关卡内唯一**）；非关卡路径（烟测/程序化地图）退回 `unit-<UniqueInGameId>`，读档重开该场战斗实例键会变——但这些路径不涉及跨档结算。
- 战斗失败不返还（本局结束、存档清空）。
- 结算面板的"追回"行只是说明：金额在进入结算时已入账，不需要手动领取；读档重进结算页不会再显示该行（账本已清）。

## §23 怪物初始化状态机制（2026-09-22）

### 23.1 机制

- 配置位置：单关卡 CSV `DataBase/Level/Config/<LevelId>.csv` 的 **`InitialValue`** 列（配表规范本来就把它定义为"初始生命、层数、耐久等"，此前**代码完全没读**）。语法为 `|` 分隔的 `Key=Value`：
  - `HP=<正整数>`：初始生命，超过模板上限时按上限截断；
  - `State=<StateType>:<层数>`：初始状态，可重复出现并依次叠加；层数省略按 1 层；**不可叠加状态落地时只按 1 层**（`StateSystem` 的既有规则）；
  - `StateType` 可写枚举名（`Ignite`）或 `通用State.csv` 的编号（`3`）；`None` 被拒绝。
- **未定义的键不报错、也不丢弃**：原样保留（供后续机制读取，例如关卡 `F1-006` 已在使用 `窃取=1`）。已知键的值非法（`HP=0`、层数 ≤0、StateType 不存在）或条目缺少 `=` 会抛错并带出该行文本。
- 作用范围：关卡 CSV 中 `ObjectType=Monster` 的行；开局在 `BattlefieldSession` 实例化怪物后立即写入，随后才进 `Occupancy` 与玩家回合。

### 23.2 实现位置

- 新增 `Scripts/Battlefield/Core/UnitInitialStateConfig.cs`：`Parse(raw, context)`（纯函数，未知键进 `Extras`）+ `Apply(unit, raw/state)`（HP 截断后依次 `StateSystem.AddOrUpdateState`）。
- `BattleLevelCatalog`：`Load` 拆出纯函数 `Parse(levelId, csvLines)` 并读取第 11 列 `InitialValue` 到 `BattleLevelObject.InitialValue`；新增 `ApplyMonstersTo(definition, level)` 统一写怪物 ID / 固定出生点 / 逐只初始值（战斗场景与烟测共用），并把非数字 `DefinitionId` 的报错换成了带关卡 ID 的明确提示。

- `BattlefieldSession`：怪物实例化时按 `MonsterInitialValues[i]` 应用初始值。
- `HexBattleScene.ConfigureRunDefinition`：改用 `ApplyMonstersTo`。

### 23.3 验证

## §22 卡牌攻击方式 × 武器类型叠加（2026-09-22）

### 22.1 规则（本轮落地）

1. 卡牌**没有声明特殊攻击方式**（`Single` / 通用牌无空间列 / `SelfMove` / `Trap`）→ 完全按**武器**攻击方式结算。
2. 卡牌**声明了特殊攻击方式**且**武器类型匹配**（近战型特殊方式 → 近战武器；远程型 → 远程武器，依据 §21 的 `EquipmentType`）→ 采用**卡牌**的攻击方式。
3. 条件不匹配 → 回落到**武器**的攻击方式。
4. **攻击范围类数值一律取武器攻击距离**（射程、直线长度、扇形/环形半径、突刺的击退攻击范围）；**爆炸半径**与**突刺位移格数**保持卡牌配置（与攻击距离无关）。
5. 卡牌形状归类：`Fan` = 近战型；`Line + MeleeLine/Thrust/AdjacentSingle` = 近战型；`Line + RangedLine/未声明`、`Burst` = 远程型；`Single/None` = 无特殊方式。

### 22.2 突刺定义（本轮补充实施）

- 突刺 = **位移 + 击退攻击**两部分。
- 位移：沿选定方向直线前进，直到用完**卡牌规定的位移格数**（与每回合移动次数无关，也不消耗移动额度），或前方目标已经落在**攻击范围**内即停。
- 击退攻击：角色**原地不动**，攻击目标并把目标击退一格；撞到障碍、其他怪物或坑洞时沿用既有连锁/回弹规则。

### 22.3 实现位置

- `Scripts/Battlefield/Runtime/BattlefieldSession.cs`：新增 `CardSpecialModeType` / `CardModeApplies` / `UsesWeaponGeometry` / `EffectiveSpec`（武器距离换算）/ `WeaponIsRay` / `WeaponIsThrown`；`GetCastCandidates`、`GetAffectedCells`、`GetAttackTraceCells`、`GetFriendlyAffectedTargets` 全部改走这套判定；`TryCastCard` 用 `thrustApplies = 突刺 && 类型匹配` 决定位移与击退是否执行；`ExecuteDash` 改为"位移格数取卡牌 `MaxRange`、目标进入攻击范围即停"（不再用 `Length`、不再按点击距离截断）。
- 黄色/红色高亮口径不变：黄=武器（远程直线）六方向完整直线或卡牌形状的方向可选格；红=被首个阻挡截断的弹道段。
- 近战类武器（`AdjacentSingle`/`MeleeLine`/`Fan`/`Ring`）"按武器方式"的几何细化仍未落地（长枪直线/扇形切换在待完善清单），当前这类武器下不匹配的卡牌仍沿用卡牌形状 + 武器距离。

### 22.4 验证

## §20 弓箭远程直线：卡牌攻击改为六方向射线（2026-09-22）

### 20.1 问题与根因

- 现象：装备弓箭后，攻击牌可以打到“攻击距离边长的六边形内的任意格点，除非被阻挡”，而不是沿六个方向射直线、命中直线上的第一个阻挡。
- 根因：六方向射线规则只写在**普通攻击**里（`GetDefaultAttackCandidates` / `TryPerformDefaultAttack`），而普通攻击目前没有 UI/命令入口；玩家局内实际走的是**卡牌出牌**路径，那条路径是 `GetSpatialSpec` 回退成 `Single/MaxRange=1` → `GetCastCandidates` 取 `CellsWithinRange(origin, max(卡牌范围, 武器攻击距离))`（= 整片射程六边形）再用 `HasClearTrace` 判遮挡，而 `HasClearTrace` 用 `BattleRangeResolver.PickLineDirection` 把目标**吸附**到最近方向后再沿线检查阻挡 → 于是“只要那条被吸附出来的线没被挡就能选”。
- 精灵（角色 1003）的牌组是 `10000001 攻击`（`通用Card.csv`，没有空间列）+ `20000001 护盾`，弓箭为 `RangedLine / 距离 5`，所以局内弓箭攻击完全落在这个错误分支上。

### 20.2 修改（只动弓箭这一条链路，按 A 口径）

- `Scripts/Battlefield/Core/BattleAttackSystem.cs`：新增 `ResolveAxialRay`（六个轴向射线，非轴向直接返回空，**绝不吸附**；含首个阻挡格后截断，`penetrates` 可穿过）与 `ResolveRayCandidates`（六条射线并集，按方向顺序、由近到远）；`ResolveFromDirection` 的相邻单体/远程直线/突刺分支改为委托它，近战直线保持“不因单位停、只因地形停”。
- `Scripts/Battlefield/Runtime/BattlefieldSession.cs`：
  - 新增 `UsesRayWeapon`（当前手位 `RangedLine`）、`IsRayAimed(spec)`（射线武器且卡不是突刺）、`EffectiveCastRange(spec)`、`RayCandidates(spec)`、`RayAffectedCells(spec, target)`。
  - `GetCastCandidates`：射线武器下 `Single/Burst/Line` 直接返回六个方向的**完整直线**（`ResolveRayCandidates(..., penetrates: true)`，只受地图边界限制；高亮不被途中的单位/障碍截断）；`Fan` 仍取六个邻格作为方向选择；投掷武器与近战保持原状。
  - `GetAffectedCells`（“红色”= 受影响的格 = 弹道段）：射线武器下先取方向（非轴为空），沿射线求**被首个阻挡截断**的线；单体/直线=该弹道段（含阻挡格）、爆发=以命中格为爆心、扇形=以射手为顶点朝该方向。它与黄色候选刻意不同：黄=能瞄哪里，红=打出去会经过/命中哪里，因此红会被单位与障碍截断。
  - 新增 `GetAttackTraceCells`：弹道格（表现用），`TryCastCard` 把“结算影响格”与“弹道格”分开传入 `ApplyCardThroughExistingPipeline(affectedCells: trace, presentationCenter: impact)`，打空也会飞满整条射线；选阻挡前后任意格点出牌，命中与弹道都会落到该方向的第一个阻挡（`selected` 的既有兜底逻辑）。
  - `GetFriendlyAffectedTargets` 对射线武器改用 `GetAffectedCells`，友伤确认框不会漏掉真正的命中单位。
- 不改动：普通攻击 UI（仍未接入）、长刀等近战距离 >1 的 `HasClearTrace` 吸附问题、怪物意图与投掷武器规则（留待后续批次）。

### 20.3 验证

## §18 运行局交互现状与事件/关卡结束后的地图表现（2026-09-21）

> 本节记录**当前实现**的交互逻辑与本次两条瑕疵的修复。设计意图见[运行局地图 UI 独立化执行案](交互/运行局地图UI独立化执行案.md)（执行案保留为方案文本，不随实现同步）。

### 18.1 运行局结构与层级

```text
RunFlowScene
├─ ContentLayer (CanvasLayer 10) → ContentHost (Control, MouseFilter=Ignore)
│  └─ RunBattleScene / RunEventScene（同时最多一个）
│     ├─ HexBattleScene（战场视图 MapView + 战斗 UI + 剧情浮层 ZIndex=300）
│     └─ 结算界面层 CanvasLayer(40)（RunBattleScene 自持）
├─ WorldMapLayer (CanvasLayer 30) → MapScene（常驻单例，EmbeddedMode=true）
├─ ModalLayer (CanvasLayer 40) → HexBattleDebugPanel（唯一实例，按当前内容重建）
└─ GlobalButtonLayer (CanvasLayer 50) → 常驻顶部按钮栏（通用行 + 剧情专属行）
另有 PauseLayer (CanvasLayer 60)：暂停界面（内容自持，全局最高层，压过以上所有层）
```

- 层级只用 `CanvasLayer.Layer`，层号统一定义在 `Scripts/Run/RunUiLayers.cs`（内容 10 < 世界地图 30 < 模态 40 < 常驻按钮 50 < 暂停 60）；跨层不得用 `ZIndex` 抢占（`ZIndex` 只在同一 CanvasLayer 内生效，`CanvasLayer.Layer` 才是视口级全局排序）。
- 世界地图**不重挂**进内容子树（始终是 `WorldMapLayer` 的直接子节点）；嵌入模式不创建地图自身的顶部/底部信息条、返回按钮与调试按钮，按钮统一由常驻栏提供。
- 结算层（40）高于世界地图（30），会压住地图并吞掉点击，因此结算确认后必须隐藏它（`RunBattleScene.OnReturnToMap()`）。

### 18.2 常驻顶部按钮栏

右上两行：**通用行**（上，右对齐）`地图`、`定位当前角色`、`调试`、`暂停`；**剧情专属行**（正下方同一条带，左右分开）左侧 `Log`、`隐藏`、`Auto: 关闭`，右侧 `跳过`。

| 运行局状态 | 可见按钮 | 说明 |
|---|---|---|
| 无内容（刚进根场景 / 只看地图） | `地图` `调试` | 点 `地图` 只保证“地图可见且可选” |
| 战斗中、结算未确认 | `定位当前角色` `地图` `调试` `暂停` | 打开的是只读地图 |
| 剧情事件中 | 通用行全部 + 剧情专属行（`跳过` 仅可跳过时） | 不显示 `定位当前角色`；**世界地图打开时剧情专属行整行隐藏** |
| 内容已完成（地图叠加其上） | 通用行按内容形态显示；剧情专属行仅在地图关闭时显示 | 与局内按地图完全一致，不退回选点形态 |

- `地图` 按钮恒可用；文本：地图已打开且存在内容时为 `返回`，否则为 `地图`。
- 内容自带的右上按钮在运行局内隐藏（`SetBuiltInTopActionsVisible(false)` / `SetBuiltInTopControlsVisible(false)`），行为由常驻栏接管。
- 按钮栏按内容形态重配时先解绑再绑定 `StoryOverlayOpened` / `DebugRequested`，避免重复触发。
- 剧情专属按钮只属于剧情 UI：排在通用按钮下方的同一条带内，左 `Log` / `隐藏` / `Auto`、右 `跳过`；**世界地图打开时整行隐藏**（`RunFlowScene.ApplyStoryRowVisibility()` 统一控制），关闭地图后按剧情状态原样恢复。
- `跳过` 只在“剧情仍在推进”时出现（`EventStoryOverlay.CanSkipNow` = 事件允许跳过且未进入选项/结束面板），与浮层内置跳过按钮规则一致：进入选项或结束面板后两侧同时隐藏（此时没有可跳内容，`Skip()` 在 `waitingChoice` 时也直接返回）。
- 暂停界面独立挂在 `RunUiLayers.Pause = 60`：地图、模态窗、常驻按钮栏或任何内容 UI 打开时都压在最上面，“继续”始终可点（`SetPaused(false)`）。

### 18.3 世界地图开合与只读规则

- 唯一入口 `RunFlowScene.SetWorldMapVisible(bool)`：改 `map.Visible` 的同时通知内容让出/收回 UI（`HexBattleScene.SetWorldMapOpen()`）。调用方：`ToggleMap()`（按钮）、`ReturnToSelectableMap()`（内容完成）、`StartLevel()` / `StartEvent()` / `AttachMapToContent()`（隐藏）。
- `mapSelectable`：内容进行中 = 只读；内容完成或尚未开始 = 可选。
- 可选态：左键点可达节点进入对应内容；不可达节点不响应。
- 只读态：节点点击被 `MapScene.OnNodeClicked` 拦下（当前直接 return，**没有视觉反馈**，见 §18.7）。
- 无内容时点 `地图`：只保证“地图可见且可选”，不会关成空屏，也不会把地图置为只读。
- 调试窗打开时地图根节点 `MouseFilter` 切 `Ignore`，关闭后恢复 `Stop`；该状态由 `RunFlowScene` 独占管理。

### 18.4 内容生命周期

```text
地图点节点 → RunFlowScene.StartLevel / StartEvent
→ 清空 ContentHost（销毁旧内容）、隐藏地图并置只读
→ 新内容入 ContentHost，CallDeferred 接入常驻按钮栏
→ 进行中：按钮栏 = 内容形态；地图按钮可开只读地图
→ 完成（ContentFinished）→ 不销毁内容、不清空 ContentHost
   → 地图以“已打开”覆盖层叠上，节点变为可选
   → 按钮栏按同一内容形态重新配置
→ 在地图上选下一个节点 → 重复上述流程
```

- 内容完成 = “地图可选 + 内容留存”：已完成内容仍在地图之下（事件只露战场与剧情 UI）。
- 事件选项 `next.type = Battle`：事件完成时直接 `LevelRequested → StartLevel`，销毁事件内容、地图保持只读，不经过“返回地图”。
- 读档重进结算：内容可能没有战场视图，`AttachMapToContent()` 最多重试 180 帧后放弃接管并保留现有按钮栏（修复过 deferred 无限自旋导致的退出崩溃）。
- `ClearHost()` 只在开始新内容时调用；完成时不再调用。

### 18.5 事件中的战斗 UI 与剧情 UI

- 进事件时 `HideBattleHudForStory()` 隐藏除 `MapView` 与调试面板外的**全部**战斗 UI，并**在事件内容存活期间保持隐藏**（`RestoreBattleHudAfterStory()` 仅用于剧情加载失败）。
- 剧情浮层完成时 `EventStoryOverlay.Close()` 只隐藏自身、不销毁；`HexBattleScene.OpenStoryEvent()` 仅在旧浮层“已完成且不显示”时回收后再开新剧情。
- 地图开合经 `HexBattleScene.SetWorldMapOpen()` → `EventStoryOverlay.Visible = !open`：地图打开时剧情 UI 整体让位，关闭后原样恢复（台词、选项、结束面板状态保留）。
- 浮层隐藏期间 `_Process` 直接返回：不会在幕后继续逐字或 Auto 推进。
- 结束面板（等待“前往地图”）不再提供跳过：`EventStoryOverlay.CanSkipNow` 同时控制浮层内置跳过与常驻栏 `跳过`。

## §17 运行局地图覆盖层与顶部操作区（2026-09-21）

- 根因：此前 `AttachMapToContent()` 将世界地图重挂为 `HexBattleScene` 的子节点，使它与剧情浮层处于同一子树并依赖节点插入顺序；这违反了局内固定层级，且剧情浮层是延迟创建，导致顶部栏按战斗态错误配置。
- 固定树结构：`RunFlowScene/ContentHost` 承载战斗地图、战斗 UI 与剧情 UI（剧情层全局 `ZIndex = 300`）；`RunFlowScene/WorldMapOverlay` 为其直接子节点且全局 `ZIndex = 500`；常驻按钮为直接子节点且全局 `ZIndex = 1000`。因此层级恒为 `战斗地图 < 战斗UI < 剧情UI < 世界地图UI < 按钮UI`。
- 世界地图不再重挂或拆回内容场景；只读状态改为截获底层剧情/战斗输入。剧情浮层创建完成后通过事件重新配置常驻按钮，避免其延迟创建时被误判为战斗态。
- 选点态保留地图与调试入口；暂停仅在存在可暂停的战斗/剧情内容时显示。嵌入地图的调试跳转改走 `RunFlowScene` 的事件/关卡流程，避免旧场景切换。
