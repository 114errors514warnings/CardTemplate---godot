## 根因与修复（2026-08-31 简化版）

每条 = 根因 + 修复。**P0 #8 顺带修问题 1 / 6；其他 5 条独立修复**。

### 问题 1：大地护盾异常（重剑手 9 / 勇者 12）
- **根因**：传递护盾时调 Defend 效果，extraShield = 累积的 9 → 勇者 3 + 9 = 12（多算 9）
- **修复**：**新增一个不添加防御力的 DefendEffect 方式**——只把累积的 9 作为友军最终护盾，不叠加友军自己的防御力（友军得 9，不是 12）

### 问题 2：怪物结算时没有高亮
- **根因**：放大效果**过渡时长** 0.15s 太短；过渡完成后 Scale 保持 1.15 倍直到下一只开始结算时缩回，但玩家视觉已经跟着下一只走了，**等于没看到**
- **修复**：调 `UnitInstanceView.SetHighlighted` 的 tween 时长（0.15s → 0.4s），让玩家肉眼能看到放大

### 问题 3：燃血 没触发失去生命值
- **根因**：卡牌 EffectType 只配了 `AddState`（施加状态），没配"失去 1 点生命"效果
- **修复**：CSV 改 EffectType 为 `Damage|AddState`——Params 改前 `1;11;1,,`、改后 `1;1|1;11;1,1;1,`（先扣 1 滴血，再施加 1 层 GainAttackOnHpLoss），让"扣血"触发状态机制里的"+1 攻击"

### 问题 4：缺怪物受伤害日志
- **根因**：`EffectSystem.ApplyAttack` 末尾没直接调 `AppendConsoleInfo`，日志只在高层 `BuildSummary` 里间接显示，信息不完整
- **修复**：加 3 处日志（**不改时序**）：
  - `ApplyAttack` 末尾："X 攻击 Y，造成 N 伤害，HP a→b"
  - 反击触发时："Y 反击 X，造成 N 伤害"
  - 燃血状态扣血时："X 失去 1 HP（燃血），攻击力 +1"

### 问题 5a：蓄力 没显示选牌 UI
- **根因**：`SelectHandCards` 和 `RandomHandCards` 当前共用同一段代码（直接随机抽 count 张），不弹选牌 UI
- **修复**：按用户原话"**卡牌描述没强调'随机'就视为'选'**"，把 `SelectHandCards` 走 `CardPlayController.HasPendingCardSelection` 选牌流程（弹 UI + 等用户选 + 再 ApplyKeyword），**不**走随机抽

### 问题 5b：被添加关键词的卡牌 没显示关键词
- **根因**：`CardDisplayPrefab` 只画名字/费用/描述/类型，**完全没读** `AppliedKeywords` 字段
- **修复**：`CardDisplayPrefab` 加 VBoxContainer 读 `AppliedKeywords`，从**上到下**排版——位置"描述上方、其他文本下方"，**不**重叠（按用户原话要求）

### 问题 6：预判 下回合给护盾失败
- **根因**：CSV TurnStartEffect 配 `IsPermanent=FALSE + TurnStartDecayAmount=1` + `OnTurnStart` 内部"先衰减后给资源"时序错 → 衰减 1 层 Stacks=0 → 给资源条件不满足 → 永远不给
- **修复**：P0 #8 顺带修（CSV 配 `Never, None, 0` + 调点顺序改）
- **附带**：修问题 1 后，预判实际给"本回合 4 护盾 + 下回合 2 护盾 = 6"（用户期望 8，差 2）—— 选项 B 调 `turnStartAmount=1→2` 补偿"不叠加 Defend"的差异

### 问题 7：紧咬不放 没生效
- **根因**：`AddOrUpdateState` 没接收 `ownerUnit` 参数，`StateStackSegment.OwnerUnit` 始终 null；`OnMonsterAttackPlayer` 检查 `seg.OwnerUnit != null` 永远 false → 永远不触发反击
- **修复**：`AddOrUpdateState` 接受 `ownerUnit` 参数 + `StateRuntimeData` 持久化 + `ApplyAddStateEffect` 传 `source`——保留"对 ownerUnit 反击"核心语义（**不**砍 OwnerUnit 检查）

## P0#9 问题修复（2026-09-04）

### 问题 1：地图形式（连接线段 = 边长、flat-top 顶点布局）
- **根因**：旧版把六边形满铺蜂窝（中心间距 ≈ 1.732R），边画成整条中心连线，不符合「连接线方向与中心连线平行、长度与边长相同」的规格。
- **修复**：
  - 新增 `Scripts/Map/MapLayout.cs`（纯逻辑可单测）：六边形 flat-top（顶点 0° 起算，东向顶点 (R,0)）；中心间距 = 3R；相邻两格相对顶点间空隙 = R；连接线段端点 = `a+R·e → b−R·e`，长度恰为边长 R，方向平行中心连线。坐标公式 `P(q,r)=3R·(q·u0 + r·u60)`。
  - `Scripts/Map/MapScene.cs`：中心/顶点/连接线/拾取全部改用 MapLayout；按视口自动反推合适半径（FitRadius 留 2% 余量），不再画中心整线、改为画顶点间短线段。
  - 新增 `Tests/MapLayoutTests.cs`（5 条）：用户示例 (0,0)→(3,0)、端点 (1,0)/(2,0)、线段长=1、三方向 60° 夹角、全图格点最小中心距 ≥ 2.5R 无重叠、FitRadius 界内。
  - 几何连通图（`MapGeometry`）与数据配置**未变**，仅渲染布局层变化。

### 问题 2：多怪物纵向拉伸超出屏幕
- **根因**：`CardBattleScene` 怪物区列数固定 3、`UnitInstanceView` 最小尺寸 210×360，怪物多时行数增多且父级容器按最小尺寸膨胀，撑破 1600×900。
- **修复**（`Scripts/UI/CardBattleScene.cs`，向后兼容）：
  - 怪物列数自适应：≤3 → 3 列；4–6 → 3 列；7–10 → 5 列（尽量 2 行内）；
  - `ApplyUnitAreaScale` 增加列宽收敛（≤ 660px）+ 行数档位压缩（2 行以上 ≤ 0.62 / 0.5）；
  - `CompactMonsterRows` + `ShrinkUnitPanelContents`：多行时按 `470/(rows*360)` 等比压缩每个单位面板的最小尺寸、立绘/意图/状态区最小尺寸与内边距/间距，阻断父级最小尺寸链增长。
