## 三个方向权衡

| 方向 | 工作量 | 风险 | 价值 | 依赖 |
|------|--------|------|------|------|
| ① 战斗系统打磨 | 5 天（推荐 P0 一次做完）| 低 | 中 | 几乎独立，影响全局 UI 文本/颜色 |
| ② 动效系统 | 5.5 天（推荐 P0 一次做完）| 中 | 中-高 | 依赖 ① 的状态/血条统一抽象 |
| ③ 游戏剩余系统 | 14-17 天（P0+P1 严格按 8月文档）| 中 | 极高（demo 化必需） | 几乎独立，需要新场景/新 UI 体系 |

### 推荐执行顺序：**① → ② → ③**

理由：

1. **① 是基础设施** — 状态名中文化、血条护盾统一、状态描述统一等，会被 ② ③ 复用
2. **② 提升体验** — 动画让 ③ 的新场景不至于"裸奔"
3. **③ 是 demo 化** — 没主菜单/地图/结算/战利品，就不是"完整游戏"；按 8月文档严格做 14-17 天可跑通基础闭环

### 反向方案：**③ → ① → ②**

如果项目目标是"尽快能跑完整流程"（哪怕 UI 丑），可以先做 ③ 的 P0 最小版本（主菜单→关卡→战斗→战利品），再回头打磨 ① 和 ②。

**选择哪个看产品定位**：
- **要 demo 给别人看** → ③ → ① → ②
- **要 demo 给核心玩家玩** → ① → ② → ③
