# P0#9 完整关卡闭环施工方案：主界面 → 选人 → 大六边形地图 → 战斗 → 结算选卡 → 返回地图

> **本文档用途**：记录 2026-09 提出的「完整关卡流程闭环」具体执行案——把项目从「默认直达战斗场景」扩展为可玩的单局流程：
> 主界面（开始 / 继续 / 放弃 / 退出）→ 选人（3 槽位，当前 2 名角色，预留扩展）→ 大六边形地图（箭头定位、可达格放大高亮、格点类型图案、特殊节点底纹）→ 进入战斗（新建界面复用原战斗逻辑，原战斗场景保留）→ 战斗结束结算弹窗（多 Tab 掉落，掉落物由新 CSV 配置；「卡牌奖励」Tab 支持随机对应角色卡牌并选卡）→ 再次回到地图界面。
>
> 本文档只做**方案记录与排期**，不含代码改动清单之外的实现代码。文档写完后的执行动作以「六、实施任务拆解」为准。

## 〇、已确认项与默认口径（先列后述）

1. **第一层地图为完整大六边形版图**：按《README/系统规则/地图玩法/地图玩法数值设计.md》口径，半径 R=6、**共 127 个格点**、每条外边含 7 个格点（含两角，奇数保证中心有格）。玩家从左端走到右端 Boss，路线较长（本期战斗量较大，属用户已知风险）。
2. **「点击格点是否进入战斗」的判定 = 该格是否存在遭遇配置**，而不是按格点类型判断（用户原话）。当前仅有「普通敌袭」存在遭遇配置 → 只有配置了遭遇的格点点击后才进战斗；其余格点点击后**仍然停留在地图界面**（当前位置移动、格点标记完成，但不出战斗）。后续高危敌袭 / 精英 / Boss / 村庄等补上配置后即自动生效，**无需改判定逻辑**。
3. 原战斗场景 `Scenes/Battle/CardBattleScene.tscn` 及其调试入口**不删除、不改坏**；新战斗界面通过「实例化原场景为子场景 + 外层包装」复用其逻辑。
4. 战斗外「移动后无配置的格点」不产出奖励、不进入战斗；配置了遭遇的格点获胜后进入结算弹窗。
5. **有存档时主界面隐藏「开始游戏」**（已确认）：有存档 → 仅显示 [继续游戏 / 放弃当前进度 / 退出]；无存档 → 显示 [开始游戏 / 退出]。
6. **战斗失败直接回主界面并清除存档**（已确认）：回主界面时处于「无存档」状态 → 显示 [开始游戏 / 退出]。
7. **遭遇配置按「关卡层数 × 节点类型」文件化**（已确认）：`DataBase/Stage/{第一层|第二层|第三层}/{节点类型}.csv`。有选取规则的类型**规则优先**（如普通敌袭按难度档 Low/Mid/High），无规则类型从该文件全部行中随机选取（可按 Weight 加权）；**当前仅普通敌袭有真实配置行，其余类型仅新建表头占位 CSV**（占位骨架已落地，见 §十 记录）。
8. 其余默认假设（见 §八）：3 槽位允许重复角色；事件 / 商人 / 村庄功能 / 时间点 / 夜晚 / 每日 Debuff / 精英钥匙本期仅占位（这些类型暂无配置行 → 点击不触发战斗）。

- 普通事件 / 危险事件 / 商人的**玩法内容**（仅地图渲染 + 无配置不触发）

## 四、分模块设计

### 4.1 主界面（MainMenuScene）

- 场景结构：全屏 `Control`（深色底）+ 居中 `VBoxContainer`：标题「卡牌模拟器」、副标题（当前局信息，可选）、按钮区、版本号。
- 按钮逻辑（`MainMenuScene.cs`）：
  - `_Ready` 里先调 `LoadingSystem` 数据预热（新增统一入口 `LoadingSystem.EnsureAllDataLoaded()`，见 §五）再刷新按钮态；
  - `RunSession.HasSave()` 为假 → 显示 `开始游戏 / 退出`；
  - 为真 → 显示 `继续游戏 / 放弃当前进度 / 退出`（「开始游戏」隐藏，需先放弃才可开新局——已确认，见 §〇 第 5 条）；
  - 开始游戏 → `ChangeSceneToFile(CharacterSelectScene)`；继续游戏 → `RunSession.LoadSave()` 后进 `MapScene`；放弃当前进度 → `RunSession.DeleteSave()` 后留在主界面刷新按钮态；退出 → `GetTree().Quit()`。

### 4.2 存档层（RunSession + RunSaveData）

- **RunSaveData（纯 DTO，JSON 序列化目标）**：

```text
SchemaVersion=1
SavedAt
CharacterSlots[ { CharacterId, CurrentHp, MaxHp } ]            // 与 3 槽位一一对应
DeckSlots[ [ { CardId, PermanentUpgradeLevel } ] ]             // 每槽一副永久卡组（含升级级数）
Gold / Keys
MapState { Act, Seed, LayoutVersion, CurrentNodeId,
           VisitedNodeIds[], NormalEncounterIndex,              // 用于普通敌袭难度分档计数
           TimePoints }                                         // 占位：本期不结算，仅存取
// 说明：PendingEncounter（NodeId + 已解析的 Stage 遭遇行，含怪物列表/DropTableId）
// 为运行时字段不入档——存档点均在格点结算完成后，无需恢复战斗中间态。
```

- **读写**：路径 `user://run_save_v1.json`；写用 `FileAccess` + `Json.Stringify`（或 `System.Text.Json` 序列化 DTO）。保存策略：
  1. 选人确认 → `StartNewRun()`（生成地图种子、重建初始卡组快照 = CharacterDefaultDeck 展开 + 首轮全量写入）并立即 `Save()`；
  2. 每次移动/格点结算后 `Save()`（保证「继续游戏」落在最近一次结算完成点）；
  3. 战斗胜利选卡后 `Save()`；**失败 → `DeleteSave()` 后直接回主界面**——此时为无存档状态，主界面显示 [开始游戏 / 退出]（已确认，见 §〇 第 6 条）。
- **「继续游戏」语义**：读档后 `CurrentNodeId` 停留在最近一次已结算格点（未再移动），玩家从该格继续选下一格——移动本身不存档，只有结算完才存档。
- RunSession 作为 autoload 在 `project.godot` 注册（见 §五），脚本需 `partial class RunSession : Node`。

### 4.3 选人界面（CharacterSelectScene）

- 数据源：`LoadingSystem.CharacterDictionary`；**可用角色池**在场景导出字段 `AvailableCharacterIds`（编辑器配 `[1001, 1002]`，后续新角色只需在该数组追加 id——即「留扩展空间」的实现点）。亦可后续升级为 `DataBase/Unit/PlayableCharacter.csv`。
- 布局：3 个并排槽位卡 + 下方可用角色列表。
  - 每个槽位点击后弹出可选角色卡（名称 / MAX_HP / Ini_Attack / Ini_Defend / drawCardNum / 默认卡组张数）；
  - **默认允许重复角色**（当前 2 名角色要填满 3 槽必须可重复）；
  - 槽位卡上显示当前所选角色与「重选」按钮。
- 确认按钮：校验每个槽位都已选 → `RunSession.StartNewRun(slots, AvailableCharacterIds)` → 进 `MapScene`。
- 从主界面「开始游戏」进入时，若已有存档残留需提示（正常流程下不会出现，因为开新局前必先放弃）。
### 4.4 地图界面（MapScene）

#### 4.4.1 版图几何口径与生成（MapGeometry.cs，纯逻辑、可单测）

- 采用**六边形轴向坐标（axial，q,r）**建模；生成「半径 R=6 的环形六边形版图」：满足 `max(|q|,|r|,|q+r|) ≤ R`，格数 = `3·R·(R+1)+1 = 127`，六条外边每边恰含 **R+1=7 个格点**（含两角），中心存在格点。与《地图玩法.md》「每边为奇数」一致。
- 格点 = `MapBoardData.Node`：`NodeId(int)`、`(q,r)`、`NodeType`、`IsSpecial`、`Visited`（**不预绑配置**，点击时再解析，见下方判定）。
- 固定特殊格（生成时先摆放，再从随机池剔除）：
  - 村庄 = 中心格 `(0,0)`；
  - 起点 = 版图最左格、Boss = 版图最右格：按《地图玩法数值设计.md》需满足「距村庄各 6 步」且「村庄—Boss 连线中点（距村 3 步）落格」——实现期按此**约束反推坐标朝向**（以 `地图示意图.png` 为准对齐），不可违背该三条数值约束；
  - 精英① = 村庄与 Boss 连线中点（距村 3 步）；精英②、精英③ = 版图右上角、右下角两处角格（距村 6 步，与玩法表三行精英一致）。
- 边：与版图内**全部相邻格点（≤6）**连边（六边形相邻，不区分方向）。移动规则：可从当前格前往**任一相邻格**，已访问格可再次经过（不重复触发该格遭遇/奖励）（用户 2026-09-04 要求“相邻格点都要可以到达”，取代早期“每格 3 个前向边”的草案口径）。
- 非特殊格类型按《地图玩法.md》占比分配（草案：空白 10% / 普通敌袭 ~40% / 高危敌袭 ~12% / 普通事件与危险事件其余，商人固定 1 个或由事件刷出），随机源 = 局种子。
- **「是否有遭遇配置」判定（运行时解析，与格点类型无关）**：点击可达格时调 `TryResolveEncounter(层, NodeType, rng)`——在 `DataBase/Stage/<当前层>/<节点类型>.csv` 中按 §4.5.1 选取规则取一行（普通敌袭按难度档位规则优先；无规则类型按 Weight 随机）。**取到行才算「有配置」** → 进战斗；取不到（空表 / 仅表头占位）→ 停留地图。后续高危 / 精英 / Boss / 事件等只需往对应类型 CSV 补行即自动生效，判定逻辑不变。

### 4.5 遭遇 / 掉落 / 卡池配置（CSV）

#### 4.5.1 遭遇配置：`DataBase/Stage/<层>/<节点类型>.csv`（按关卡层数 × 节点类型分类）

- 新增目录 `DataBase/Stage/`，按关卡层数分子目录（顺序固定）：`第一层 / 第二层 / 第三层`。
- 每层内含 8 个**以节点类型命名**的 CSV（占位骨架已建，见 §十）：

| 每层文件 | 本期内容（2026-09-04 状态） |
|----------|------------------------------|
| `普通敌袭.csv` | `第一层`：真实配置 3 行（Low / Mid / High 各 1 行，怪物组合为占位值）；`第二 / 三层`：表头占位，随关卡开放再填 |
| `高危敌袭.csv` / `普通事件.csv` / `危险事件.csv` / `商人.csv` / `村庄.csv` / `精英.csv` / `Boss.csv` | 仅表头占位（0 行数据 → 视为无配置，点击不触发） |

- 列设计（各类型 CSV 共用，后续某类型有专属字段再追加列）：

```text
Name,Difficulty,MonsterIds,DropTableId,Weight,Note
普通敌袭-低等,Low,3001|3001,2001,1,占位组合（待数值对齐）
普通敌袭-中等,Mid,3003,2001,1,占位组合（待数值对齐）
普通敌袭-高等,High,3005|3003,2001,1,占位组合（待数值对齐）
```

- `MonsterIds` 用 `|` 分隔，多个同 id 表示同怪多只；解析后给 `BattleSetupData.AddMonsterId`。`DropTableId` 引用 `DataBase/Map/DropTable.csv`（§4.5.2）；`Weight` 用于随机权重；`Note` 仅备注。
- **选取规则（有规则优先按规则；无规则则随机）**：
  - `普通敌袭`：按本局已打普通敌袭次数分档——第 1–3 场 `Low`、4–5 场 `Mid`、6+ 场 `High`（来源《地图玩法数值设计.md》§四；计数存 `RunSession.MapState.NormalEncounterIndex`）。先按档位筛行，档内如有多个候选再按 `Weight` 随机；档位规则为**内置代码映射**（Low/Mid/High），CSV 只提供各档候选行；
  - 其余类型：暂无内置规则 → 从该文件**全部行按 Weight 加权随机**；文件仅表头（0 行）→ 无配置、不触发。
- 层映射：`RunSession.MapState.Act`（当前=1）→ 目录名 `第一层`；后续开放二 / 三层时只需向对应层目录补配置行。
- **数值备注**：现 `Monster.csv`（HP 5~30）与数值文档档位表（45/66/90、6/9/12）不一致，上表为**占位组合**，正式数值另案对齐（见 §八）。

#### 4.5.2 `DataBase/Map/DropTable.csv`（掉落物配置 —— 结算弹窗 Tab 的数据源）

```text
DropTableId,Category,RewardParam,Amount,Weight
2001,Card,0,3,1
2001,Gold,0,50,1
2002,Gold,0,120,1
2002,Material,101,2,1
```

- `Category ∈ { Card, Gold, Material, Item, Key }`：
  - `Gold`：`RewardParam=0`，`Amount` 为金币数；
  - `Card`：`RewardParam` 表示角色过滤——`0` = 当前队伍所有角色的卡池并集，或填具体 `CharacterId`（多个 `|`）；`Amount` = 弹出可选张数（默认 3）；
  - `Material / Item`：先落到 `RunSession` 背包计数（本期仅显示与计数，不做使用/合成）；`Key`：精英/Boss 掉落钥匙位（本期不配）。
- **Tab 生成规则**：同一 `DropTableId` 内按 `Category` 分组，一组即一个 Tab；**只有出现 `Card` 类条目时才出现「卡牌奖励」Tab**（满足需求「可能出现对应关卡中配置的掉落物」）。
- 掉落表当前全局存放于 `DataBase/Map/DropTable.csv`（不按层拆分）；后续如需按层差异化掉落，可为 `DropTableId` 分配层区间或再拆目录，本期不加机制。

#### 4.5.3 `DataBase/Card/CharacterRewardPool.csv`（角色可获得卡池来源）

```text
CharacterId,CardSource
1001,通用/通用Card.csv
1002,通用/通用Card.csv
1002,重剑手Card.csv
```

- `CardSource` = `DataBase/Card/` 下相对 CSV 路径；解析后展开为该角色卡池模板 id 集合（读取 `LoadingSystem.CardDictionary`）。
- 作用：选卡面板从「当前队伍并集或指定角色」的卡池里抽候选；同时约束后续角色只需「在对应文件夹建卡 CSV + 该表加行」，即完成扩展。

#### 4.5.4 LoadingSystem 扩展（小增量）

- `FilePathRegistry.csv` 增加 2 行：`Data.Map.DropTable`、`Data.Card.CharacterRewardPool`。**Stage 目录不逐文件注册**：加载器按固定根目录 `res://DataBase/Stage/` 用 `DirAccess` 扫描层目录（显式顺序：第一层 / 第二层 / 第三层），每层读取 8 个 `<节点类型>.csv`（文件名→类型映射）。
- 新增常量：`StageRootPath`、`StageLayerNames[]`、类型 ↔ 文件名映射（普通敌袭 / 高危敌袭 / 普通事件 / 危险事件 / 商人 / 村庄 / 精英 / Boss）。缓存结构：`stageEncounterCache[层][类型][行…]`。
- 新 API：`LoadStageEncounters()`（预热三层全缓存）、`TryPickEncounter(layer, nodeType, difficultyRuleValue?, Random rng, out StageEncounterRow)`——普通敌袭传 `NormalEncounterIndex` 对应档位，其余类型不传（全行加权随机）。解析器做单文件解析（首行表头，空文件=0 行），参考 `LoadCardCsv / LoadMonsterCsv` 的字段解析写法（`LoadCsv.ParseCSVFields`）。

### 4.6 新战斗界面（RunBattleScene，复用原战斗逻辑）

- 场景结构：根 `RunBattleScene : Control`，含：
  - `BattleHost`（Container / 或直接子节点位置）→ 代码动态实例化 `res://Scenes/Battle/CardBattleScene.tscn` 为子场景；
  - `ResultLayer`（CanvasLayer，初始隐藏）→ 结算弹窗 / 失败面板；
  - `RunBattleScene.cs` 为外层控制器。
- **实例化参数**（复用点）：
  - 实例化前直接给导出字段赋值：`AutoStartBattle = false`、`SetupWindowScene = null`、`DebugPanelScene = null`（原场景 `_Ready` 中 `ShowSetupWindow()` 对 null 无操作，自然不弹战前配置；原战斗场景本体零改动）。
  - `AddChild` 后等一帧（子场景 `_Ready` 已完成、`BattleSytem.Current` 已指向自身）。
- **注入本局数据**（向 `BattleSytem` 暴露/设置）：
  1. `BattleSetupData data = battle.EnsureSetupData()`：`CharacterOrder` = 本局 3 槽位角色 id（可重复）；`MonsterIds` = `PendingEncounter` 解析出的怪物列表；`DropTableId` 记录到本地。
  2. **永久卡组快照注入**：`data` 设置每槽 `DeckSlots` 快照（CardId + PermanentUpgradeLevel）；配合 §五 的 `BattleSytem.EnsurePlayerDefaultDeckInitialized` 增量改动，当快照存在时**用它替代** CharacterDefaultDeck 默认卡组重建 `DefaultDeck`。
  3. 调 `battle.StartGameFromSetupData()` 开局（返回 true 表示成功）。
  4. 开局后按 `RunSession.CharacterSlots` 的 `CurrentHp` 回填 `battle.Players` 中对应角色 `HP`（含最大值钳制）。
- **胜负监听（首选零核心改动方案）**：`_Process` 轮询 `battle.IsBattleStarted`（true→false 且已开局）：
  - `battle.Monsters == null && battle.Players != null` → 胜利（`EndBattle` 清怪留角色）；
  - `battle.Players == null` → 失败（`EndGame` 清角色与怪）；
  - 再兜底判断：若 `Players` 中存活角色为 0 同样判失败。
  - 判定一次后置 `resolved` 标记防止重复触发。
- 备选方案（若轮询判定出现时序不可靠，再采用）：在 `BattleSytem` 加 `public event Action<bool> BattleResolved` + `public bool IsRunBattle` 开关，由 `CheckBattleEndAndHandle`（胜）与全体角色死亡回调（败）触发；对原有调试流程零影响（无人订阅、`IsRunBattle=false` 不触发）。两方案互斥，实施时选其一并在本文件「实际改动」记录。
- 原战斗场景顶部「战前设置 / 调试面板」按钮在实例化后可 `Visible=false` 隐藏，避免运行局误点。
- 战斗内战斗结束（怪物全灭）后：等待 0.8s（让死亡结算/横幅播完）→ 显示结算弹窗。

### 4.7 结算弹窗与选卡（胜利路径）

- **触发**：RunBattleScene 判定胜利后置 `ResultLayer` 可见。
- 结算数据：按 `PendingEncounter.DropTableId` 读 `DropTable.csv` 分组。
- 弹窗结构（全屏半透明遮罩 + 居中 Panel）：
  - 顶部：大字「胜利」+ 该格名 / 遭遇名；
  - 中部：`TabContainer`，每组 `Category` 一个 Tab（金币 / 材料 / 卡牌奖励…），Tab 内以 `CardDisplayPrefab` / 行文本展示条目（金币、材料行直接文本+图标）；
  - 底部按钮：「返回地图」（进入前要求把已配置掉落写入 `RunSession`：金币累加、材料计数、卡牌选择已入卡组则落档）。
- **「卡牌奖励」Tab 与选卡界面**：
  - 点击该 Tab → 在弹窗上叠一个选卡子面板；
  - 候选生成：解析该 DropTable 的 Card 行 → 角色过滤（0=当前队伍并集 / 指定角色）→ 从对应角色卡池模板中**随机抽 Amount(3) 张不重复**（随机源用 `BattleSytem.RandomGenerator` 或种子随机，保证同一局可复现）；
  - 渲染：复用 `CardDisplayPrefab`（`SyncFromCard(template)`）横向排布；悬停放大、点击选中、再点「确认选择」；
  - 入组：把所选 `CardId`（永久升级级数=0）**追加**到 `RunSession.DeckSlots[对应槽位]`，下一场战斗开局全量快照自动包含；
  - 已拥有卡的排重：候选若已在永久卡组中存在 N 张，显示数量徽标「已有 ×N」；同局内连续多次战斗抽卡不会把候选限制在「未拥有」，仅提示（v1 简单口径）。
- **失败路径**：`ResultLayer` 显示「失败」，按钮「返回主界面」（默认 = 结束本局并清档）。

### 4.8 返回地图与局内延续

- 「返回地图」→ `RunSession` 落档（`VisitedNodeIds += CurrentNodeId`、`CurrentHp` 更新为战后存活 HP、金币/材料/钥匙入账、`PendingEncounter` 清空）→ `ChangeSceneToFile(MapScene)`。
- `MapScene._Ready`：由 `RunSession` 恢复 `Seed/LayoutVersion` → `MapGeometry` 确定性重建同一版图 → 高亮当前位置（`CurrentNodeId`）+ 计算可达格。角色 HP 显示于 HUD。
- 「返回主菜单」（HUD 按钮，非失败）→ `ChangeSceneToFile(MainMenuScene)`（不删档，主界面按「有存档」显示继续/放弃）。

## 十一、存档三态方案（2026-09-04 v2，已实现）

> 目标：进战斗即存档（重进=重新开局）、胜利结算未领取也能存档（重进=重现同款结算弹窗），并修复“存档不记录位置/字段丢失”。

### 状态机
| GameMode | 含义 | 继续游戏路由 |
|----------|------|--------------|
| `OnMap` | 地图上已结算完 | `MapScene`（位置不变） |
| `InBattleStart` | 已点进战斗、胜负未决 | `RunBattleScene` 用存档重新开局（发牌顺序可不同） |
| `InSettlement` | 战斗胜利、结算弹出、**未领任何奖励** | `RunBattleScene` 直接重现同款结算弹窗（不开战） |

### 已实现要点
- `System.Text.Json` 序列化显式 `IncludeFields`：`CurrentNodeId / Seed / HP / Gold / Keys / GameMode / 卡组条目级数 / 难度计数` 等 public 字段全部落盘（`Scripts/Run/RunSaveJson.cs`）。
- `RunSaveData`（v2）新增：`GameMode`、`PendingEncounter*`（层/类型/名称/怪物/掉落表）、`Settlement*`（名称/掉落表/候选卡 Id 列表）。
- `RunSession`：`BeginRunBattleEncounter`（置 InBattleStart 并落盘）、`EnterSettlement`（胜利弹出前落盘为未领奖）、`CompleteSettlementToMap`（领奖后清态回 OnMap）、`BuildPendingEncounterRowFromSave`（读档重建遭遇）。
- `MapScene`：点击有配置格 → `BeginRunBattleEncounter`（先存后进战斗）。
- `RunBattleScene`：`_Ready` 按模式分流（InSettlement 直接弹结算 / 其余开局）；胜利时先 `WriteBackLiveCharacters`（HP + DefaultDeck 全量写回，含永久升级级数）→ `EnterSettlement` → 弹窗；领奖（金币/卡）统一在确认键执行 → `CompleteSettlementToMap` → 回地图。
- `MainMenuScene` 继续游戏按模式路由到 Map / RunBattle。

### 待测试项（完整清单）
基础与位置存档：
1. 新开局→退出→继续：回主菜单显示“继续游戏”，进地图为起点，JSON 含 `CurrentNodeId/Seed` 字段。
2. 地图走到某格（无配置）后返回主菜单→继续：回到**该格**而非起点；金币/HP 不变。
3. 打完一格的战斗后回地图→退出→继续：回到该格，`VisitedNodeIds` 含该格，正常亮起下一格。
4. 战斗开战后退出→继续：进入同一遭遇**重新开局**（角色 HP=战前、卡组=战前含已得奖励、怪物与掉落表相同；发牌顺序可不同）。
5. 开战后退出→继续→再退出→再继续：每次都重新开局，不重复结算/不叠加难度计数。
6. 胜利弹出结算（未领任何奖励）后直接退出→继续：**不重新开战**，直接重现结算弹窗；弹窗候选与存档内 3 张候选一致；金币未加、卡未入组、该格未标记完成。
7. 结算中选 1 张卡→确认→回地图：该格已完成；再次退出→继续直接回地图（不再弹结算）；奖励只发一次。
8. 结算弹窗状态下反复退出/重进多次：状态始终为未领取，不重复发奖、场次计数不重复增加。
9. 战斗中永久升级（淬炼）→胜利结算→回地图→再打下一场：该升级级数保留（写回全量卡组生效）。
10. 结算领取新卡→下一场战斗默认卡组出现该卡。
11. 战斗失败→清档回主界面，显示“开始游戏/退出”。
12. 任意模式删除 `user://run_save_v1.json` 后重开：主界面显示“开始游戏”，流程正常。
13. 旧版（无字段）存档读档不崩溃（可回起点，属可接受兼容行为）；新局后按 v2 正常。
