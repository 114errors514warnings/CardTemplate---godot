# 开发记录规则

## 月度完成事项记录

进行代码或配置更改后，必须将**主要修改内容**记录到 `README/施工文档/已完成事项/` 下对应月份的文件中。

### 记录原则

1. 记录内容应**完整而简洁**，覆盖本次改动的主要结果与规则变化。
2. 记录位置应写入**当前日期**对应的小节下。
3. 若当月文件中**已有对应日期**，则直接在该日期下继续追加编号条目。
4. 若当月文件中**没有对应日期**，则在文件末尾**隔一行**新增该日期小节后再写入内容。

### 示例

- 当前日期为 `2026.5.18`，则记录到 `README/施工文档/已完成事项/2026.5.md` 的 `5.18` 小节下。
- 当前日期为 `2026.5.19`，若 `2026.5.md` 中还没有 `5.19`，则先隔一行新增：

```md
5.19
1、这里写本次主要修改内容
```

### 适用范围

- 代码逻辑修改
- 配置表结构或语义修改
- UI/交互行为修改
- 重要规则实现或规则调整
- 影响后续开发的关键修复

### 备注

- 记录重点是“本次完成了什么”，不是逐文件变更清单。
- 若一次改动覆盖多个点，可合并为 1~3 条高信息密度描述。
- 默认按当前自然月对应文件记录，例如 `2026.5.md`、`2026.6.md`。
